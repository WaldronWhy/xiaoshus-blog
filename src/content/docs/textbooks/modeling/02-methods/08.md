## 8.1 图的基本概念与建模表示

### 8.1.1 图的定义

**图（graph）** $G=(V,E)$ 由顶点集 $V$ 与边集 $E\subseteq V\times V$ 构成。若边有方向称为**有向图（directed graph）**，否则为**无向图（undirected graph）**；边上带数字 $w(e)$ 称为**权（weight）**——权可以是距离、时间、费用、容量，建模时要明确写出它的物理含义。

竞赛中常见的图类型与典型赛题对应关系：

| 图类型 | 典型赛题语言 | 例 |
|---|---|---|
| 无向带权图 | 双向道路、对称费用 | 城市间公路网 |
| 有向带权图 | 单行道、有向输送 | 管网、航线 |
| 二分图 | "两类对象 + 关联" | 学生—课题、工人—岗位 |
| 网络流图 | "供—转运—需" + 容量 | 物资调配、交通分配 |
| 一般复杂网络 | "关系/相互作用"数据 | 社交网络、 citation 网络 |

**建模的第一步永远是回答**：顶点是什么？边是什么？权是什么？这三个问题想清楚了，算法只是查表。

### 8.1.2 三种计算机表示：邻接矩阵、边表、邻接表

设 $n=|V|$，$m=|E|$。

- **邻接矩阵（adjacency matrix）** $A$：$A_{ij}=1$（或权重 $w_{ij}$）表示 $i,j$ 相邻。空间 $O(n^2)$，判断"是否相邻"$O(1)$，适合**稠密图**与需要矩阵运算的场合（如与第 3 章特征值方法联动：谱聚类、PageRank）。
- **边表（edge list）**：直接列出 $(u,v,w)$ 三元组，空间 $O(m)$，Kruskal 算法天然吃边表。
- **邻接表（adjacency list）**：每个顶点存一个"邻居 + 权"列表，空间 $O(n+m)$，Dijkstra/BFS 的标准载体，`networkx` 内部即用此结构。

```python
# -*- coding: utf-8 -*-
"""8-1 三种图表示方法与 networkx 基本操作"""
import networkx as nx
import numpy as np

# 构造无向带权图：4 个村庄间的道路长度（km）
edges = [('v1','v2',5),('v1','v3',2),('v2','v3',1),('v2','v4',6),('v3','v4',7)]
G = nx.Graph()
G.add_weighted_edges_from(edges)

# 表示一：邻接矩阵（nodelist 指定行/列顺序，保证可复现）
A = nx.to_numpy_array(G, nodelist=sorted(G.nodes()))
print("邻接矩阵:\n", A)
# 预期输出：
# [[0. 5. 2. 0.]
#  [5. 0. 1. 6.]
#  [2. 1. 0. 7.]
#  [0. 6. 7. 0.]]

# 表示二：边表
print("边表:", [(u, v, d['weight']) for u, v, d in G.edges(data=True)])
# 预期输出：[('v1', 'v2', 5), ('v1', 'v3', 2), ('v2', 'v3', 1), ('v2', 'v4', 6), ('v3', 'v4', 7)]

# 表示三：邻接表（字典形式）
print("邻接表:", {n: dict(G[n]) for n in G.nodes})
# 预期输出：{'v1': {'v2': {'weight': 5}, 'v3': {'weight': 2}}, 'v2': {...}, ...}
```

**选择建议**：$n\le 500$ 且要写数学式子（论文里出现 $A_{ij}$）→ 邻接矩阵；图大、只跑算法 → 邻接表/边表；两者在 `networkx` 里一条命令互转，不必纠结。

## 8.2 最短路问题

### 8.2.1 问题与两类需求

给带权图 $G=(V,E,w)$（$w\ge 0$），求顶点 $s$ 到 $t$ 的路径使 $\sum w(e)$ 最小。竞赛中分两种需求：

1. **单源/单对**：只要从一个出发点到其他各点 → **Dijkstra 算法**，复杂度 $O(m\log n)$（堆优化）；
2. **全对**：任意两点间都要（如"每个消防站到每个小区"）→ **Floyd–Warshall 算法**，复杂度 $O(n^3)$，代码仅 5 行。

### 8.2.2 Dijkstra：贪心 + 优先队列

思想：维护"已确定最短距离"集合 $S$。每轮从堆中取出距离最小的未定顶点 $u$（贪心：$d(u)$ 已不可能再变小，因为 $w\ge 0$），用它松弛（relax）其邻居：

$$
d(v) \leftarrow \min\{\,d(v),\ d(u)+w(u,v)\,\}.
$$

**适用红线**：权必须非负。有负权边（现实中"补贴""收益"）时改用 Bellman–Ford（$O(nm)$）或 SPFA。

### 8.2.3 Floyd：动态规划

递推（$d^{(k)}$ 表示只允许经过前 $k$ 个中转点的最短距离）：

$$
d^{(k)}_{ij}=\min\bigl\{\,d^{(k-1)}_{ij},\ d^{(k-1)}_{ik}+d^{(k-1)}_{kj}\,\bigr\}.
$$

"假设如何变成方程"：第 $k$ 个点要么不在 $i\to j$ 的路径上（左项），要么把路径拆成 $i\to k$ 与 $k\to j$ 两段（右项）。

### 8.2.4 选型对比与代码

```python
# -*- coding: utf-8 -*-
"""8-2 最短路：Dijkstra（单源）与 Floyd（全对）"""
import networkx as nx

DG = nx.DiGraph()
DG.add_weighted_edges_from([('s','a',2),('s','b',5),('a','b',1),
                            ('a','c',6),('b','c',2),('c','t',3),('b','t',8)])

# Dijkstra：单源最短路 + 路径还原
path = nx.dijkstra_path(DG, 's', 't')
dist = nx.dijkstra_path_length(DG, 's', 't')
print("Dijkstra s->t:", path, " 最短距离 =", dist)
# 预期输出：Dijkstra s->t: ['s', 'a', 'b', 'c', 't']  最短距离 = 8

# 多源单汇：把图反转后从 t 跑 Dijkstra（"到哪个医院最近"类问题）
print("所有点到 t 的最短距离:", nx.single_source_dijkstra_path_length(DG.reverse(), 't'))
# 预期输出：{'t': 0, 'c': 3, 'b': 5, 'a': 6, 's': 8}

# Floyd：全对最短距离矩阵（n 小、要算所有点对时最省事）
D = nx.floyd_warshall(DG)
print("Floyd s->t =", D['s']['t'], "  a->t =", D['a']['t'])
# 预期输出：Floyd s->t = 8   a->t = 6
```

| 方法 | 复杂度 | 适用场景 | 坑 |
|---|---|---|---|
| Dijkstra（堆） | $O(m\log n)$ | 单源；$w\ge 0$；图大（$n>1000$） | 负权直接错；无向图别忘双边 |
| Floyd | $O(n^3)$ | 全对；$n\le 500$；可处理负权（无负环） | $n=2000$ 就跑不动；注意 `inf` 判定 |
| Bellman–Ford | $O(nm)$ | 有负权、判负环 | 慢，能不用就不用 |

## 8.3 最小生成树

### 8.3.1 问题

给连通无向带权图，选 $n-1$ 条边把所有顶点连成**无环连通子图（树）**，总权最小。典型赛题：铺设光缆/管道/道路使总造价最小——注意它回答的是"**连通** everyone 的最小代价"，与最短路（"某两点间最近"）是两个不同的问题，赛场上混用是高频错误。

### 8.3.2 Kruskal 与 Prim

- **Kruskal（全局贪心，吃边表）**：边按权排序，从小到大取边，用并查集（union-find）判断是否成环，成环则弃。复杂度 $O(m\log m)$，适合稀疏图。
- **Prim（局部生长，吃邻接表）**：从任一点出发，每次把"树外离树最近"的点拉进树。复杂度 $O(m\log n)$，适合稠密图。

两者都得最优的原因：割性质（cut property）——对任意把顶点集分成两半的割，横跨割的最小权边一定属于某棵最小生成树。

```python
# -*- coding: utf-8 -*-
"""8-3 最小生成树：Kruskal 与 Prim"""
import networkx as nx

G = nx.Graph()
G.add_weighted_edges_from([('v1','v2',5),('v1','v3',2),('v2','v3',1),
                           ('v2','v4',6),('v3','v4',7)])

T = nx.minimum_spanning_tree(G, algorithm='kruskal')   # 也可换 'prim'
print("MST 边:", sorted(T.edges(data='weight')), " 总权 =", T.size(weight='weight'))
# 预期输出：MST 边: [('v1', 'v3', 2), ('v2', 'v3', 1), ('v2', 'v4', 6)]  总权 = 9.0

# 扩展：k 小生成树、限制直径的生成树等变体，networkx 提供
print("生成树算法可选:", ['kruskal', 'prim', 'boruvka'])
```

**进阶提示**：若赛题要求"树还要满足额外约束"（如直径限制、度限制），最小生成树失效，应转为整数规划（第 5 章）或启发式。

## 8.4 最大流与最小割

### 8.4.1 网络流模型

**网络**：有向图 $G=(V,E)$，每条弧有**容量** $c(e)\ge 0$，指定源点 $s$（发货）与汇点 $t$（收货）。**可行流** $f$ 满足：

$$
0\le f(e)\le c(e)\quad(\text{容量限制}),\qquad
\sum_{e\text{ 入}u}f(e)=\sum_{e\text{ 出}u}f(e),\ \forall u\ne s,t\ (\text{流量守恒}).
$$

最大流问题：最大化从 $s$ 流出到 $t$ 的净流量 $|f|$。**它本质是一个线性规划**——决策变量是各弧流量，目标与约束全线性，见 8.9 节与第 5 章的衔接讨论。竞赛价值在于：专用组合算法比通用 LP 求解器快几个量级，且结构清晰便于写论文。

### 8.4.2 增广路思想与最大流最小割定理

**增广路（augmenting path）**：残量网络（剩余容量 $c(e)-f(e)$，加上反向弧 $f(e)$）中一条 $s\to t$ 的通路。只要找得到增广路，流量还能增大；找不到时，当前流即最大。这就是 **Ford–Fulkerson 方法**（Edmonds–Karp 用 BFS 找最短增广路，复杂度 $O(nm^2)$；Dinic 更快）。

**割（cut）**：把 $V$ 分成 $S\ni s$ 与 $T\ni t$ 两部分，割容量 $=\sum_{e:\,S\to T}c(e)$。

**最大流最小割定理（max-flow min-cut）**：

$$
\max_f |f| \;=\; \min_{(S,T)} \sum_{e:\,S\to T} c(e).
$$

对建模者的含义：**"最多能运多少"等于"最窄的瓶颈"**。最大流给出运输方案，最小割给出瓶颈诊断（哪些路段扩容才有效），这是赛题分析里最有解释力的一对结论。

### 8.4.3 三个必备技巧

1. **节点拆分（node splitting）**：约束"中转站吞吐量 $\le U$"时，把 $u$ 拆成 $u_{in},u_{out}$，加弧 $u_{in}\to u_{out}$，容量 $U$。不拆分而只在进站弧上设容量，会出现"多进绕行"错误（详见 8.8 案例的调试记录）。
2. **多源多汇**：加超级源 $S^*$ 连所有源（容量=供应量），所有汇连超级汇 $T^*$（容量=需求量）。
3. **最小费用最大流（min-cost flow）**：每条弧再加单位费用 $w(e)$，在最大流中挑总费用最小的——`network_simplex` 一步求解，是运输/调配类赛题的主力工具。

### 8.4.4 最大流、最小割与最小费用最大流（程序 8-4）

```python
# -*- coding: utf-8 -*-
"""8-4 最大流、最小割与最小费用最大流"""
import networkx as nx

FG = nx.DiGraph()
FG.add_edges_from([('s','a',{'capacity':10}), ('s','b',{'capacity':5}),
                   ('a','b',{'capacity':15}), ('a','t',{'capacity':10}),
                   ('b','t',{'capacity':10})])

# 最大流
v, flow = nx.maximum_flow(FG, 's', 't')
print("最大流 =", v, " 各弧流量 =", {u: {w: q for w, q in d.items() if q > 0}
                                   for u, d in flow.items() if u != 't'})
# 预期输出：最大流 = 15  各弧流量 = {'s': {'a': 10, 'b': 5}, 'a': {'t': 10}, 'b': {'t': 5}}

# 最小割：瓶颈诊断
cutv, (S, Tset) = nx.minimum_cut(FG, 's', 't')
cut_edges = [(u, w) for u in S for w in Tset if FG.has_edge(u, w)]
print("最小割 =", cutv, " S =", S, " 割边 =", cut_edges)
# 预期输出：最小割 = 15  S = {'s'}  割边 = [('s', 'b'), ('s', 'a')]
# 解读：瓶颈在源点出发的两条弧；只有扩大 s 的出弧容量，总运量才能提升。

# 最小费用最大流：给每条弧加单位运费
for (u, w) in FG.edges:
    FG[u][w]['weight'] = {('s','a'):2, ('s','b'):3, ('a','b'):1,
                          ('a','t'):2, ('b','t'):1}[(u, w)]
flow = nx.max_flow_min_cost(FG, 's', 't')
print("最小费用 =", nx.cost_of_flow(FG, flow))
print("费用最优的流量分配 =", {u: {w: q for w, q in d.items() if q > 0}
                              for u, d in flow.items() if u not in ('t',)})
# 预期输出：最小费用 = 60
# 预期输出：费用最优的流量分配 = {'s': {'a': 10, 'b': 5}, 'a': {'b': 5, 't': 5}, 'b': {'t': 10}}
# 解读：10 车走 s->a->t 与 s->a->b->t 混合路径，单位费用同为 4，比全走直达弧更均衡。
```

### 8.4.5 运输/调配类赛题的标准建模套路

"产地—中转—销地"型问题（第 5 章的运输规划是其特例）统一写法：

$$
\min \sum_{(i,j)\in E} w_{ij}x_{ij}
\quad\text{s.t.}\quad
\sum_{j}x_{ij}-\sum_{j}x_{ji}=b_i\ (\text{净流出}=b_i),\ \ 0\le x_{ij}\le c_{ij}.
$$

供应点 $b_i>0$，需求点 $b_i<0$，转运点 $b_i=0$。`network_simplex` 直接求解；需要"选址 + 调运"两阶段决策时，外层枚举/启发式选址、内层最小费用流检验，见 8.8 案例与第 5 章。

## 8.5 二分图匹配

### 8.5.1 模型

**二分图（bipartite graph）**：顶点分成 $X,Y$ 两类，所有边横跨两类。**匹配（matching）**是没有公共端点的边集；最大匹配 = 最多能配几对。典型赛题：$n$ 名学生选 $m$ 个课题（每人有意愿集合）、翻译人员—语种、工作—机器。

### 8.5.2 匈牙利算法思想

对每个左部点 $x$：走"交错树"找一条从未匹配点出发、非匹配边与匹配边交替的**增广路**；找到则把匹配边与非匹配边互换（匹配数 +1），找不到则 $x$ 无缘增配。复杂度 $O(nm)$。带权版即**指派问题（assignment problem）**，可用 Kuhn–Munkres 算法（scipy 的 `linear_sum_assignment`），也是第 5 章整数规划的经典特例。

```python
# -*- coding: utf-8 -*-
"""8-5 二分图最大匹配（匈牙利算法思想，networkx 内置实现）"""
import networkx as nx

B = nx.Graph()
students = ['s1', 's2', 's3', 's4']; projects = ['p1', 'p2', 'p3']
B.add_nodes_from(students, bipartite=0)          # 左部：学生
B.add_nodes_from(projects, bipartite=1)          # 右部：课题
B.add_edges_from([('s1','p1'), ('s1','p2'), ('s2','p1'),
                  ('s3','p2'), ('s3','p3'), ('s4','p3')])

from networkx.algorithms.bipartite import maximum_matching
m = maximum_matching(B, top_nodes=students)
pairs = {u: v for u, v in m.items() if u in students}
print("最大匹配数 =", len(pairs), " 方案 =", pairs)
# 预期输出：最大匹配数 = 3  方案 = {'s1': 'p1', 's3': 'p2', 's4': 'p3'}

# 带权指派：scipy 的匈牙利算法一行解决（成本矩阵）
import numpy as np
from scipy.optimize import linear_sum_assignment
cost = np.array([[9, 2, 7], [6, 4, 3], [5, 8, 1], [7, 6, 9]])[:3]   # 3 人对 3 岗
r, c = linear_sum_assignment(cost)
print("最小总成本 =", cost[r, c].sum(), " 指派 =", list(zip(r, c)))
# 预期输出：最小总成本 = 9  指派 = [(0, 1), (1, 0), (2, 2)]
```

**建模提醒**：最大匹配只保证"对数最多"，不保证每个人的偏好——若题目有满意度，用带权匹配或转向多目标（第 5、6 章）。

## 8.6 复杂网络指标初步

当赛题给的是"真实关系数据"（微博转发、论文引用、道路网），而不是干净的小图时，进入了**复杂网络（complex network）**分析。四个最常用的抓手：

1. **度分布（degree distribution）** $P(k)=P(\text{随机取一点度数为 }k)$：社交网多为右偏（少数枢纽点度极大），接近幂律 $P(k)\propto k^{-\gamma}$；与均匀随机网络（泊松度分布）对比可说明网络的"枢纽依赖"结构。
2. **聚类系数（clustering coefficient）**：节点 $i$ 的两邻居互为邻居的比例，衡量"朋友圈抱团"程度；全局平均高 → 小世界特征。
3. **中心性（centrality）**：谁是关键节点？
   - **度中心性**：直接联系最多（直观但抓不住"桥梁"）；
   - **介数中心性（betweenness）**：多少最短路经过该点（瓶颈/桥梁，削"桥头堡"最有效）；
   - **接近中心性（closeness）**：到全网平均距离最短（消息扩散最快）；
   - **特征向量中心性（eigenvector）**：与重要的人相连才重要（PageRank 的思想，联动第 3 章特征值方法）。
4. **连通分量与鲁棒性**：删除若干节点后网络是否分裂——应急类赛题的"关键基础设施识别"即由此展开。

```python
# -*- coding: utf-8 -*-
"""8-6 复杂网络指标：以 Zachary 空手道俱乐部网络（34 节点，78 边）为例"""
import networkx as nx
import numpy as np

G = nx.karate_club_graph()          # 经典社会网络：34 个成员、78 条友谊关系
print("节点数 =", G.number_of_nodes(), " 边数 =", G.number_of_edges())
# 预期输出：节点数 = 34  边数 = 78

degs = np.array([d for _, d in G.degree()])
print("平均度 =", round(degs.mean(), 2), " 最大度 =", degs.max(),
      " 度序列前 10 =", sorted(degs.tolist(), reverse=True)[:10])
# 预期输出：平均度 = 4.59  最大度 = 17  度序列前 10 = [17, 16, 12, 10, 9, 6, 6, 5, 5, 5]
# （右偏的度序列 -> 存在枢纽节点，不是均匀随机网络）

print("全局平均聚类系数 =", round(nx.average_clustering(G), 4))
print("传递性(三角形密度) =", round(nx.transitivity(G), 4))
# 预期输出：全局平均聚类系数 = 0.5706 / 传递性(三角形密度) = 0.2557

deg_c = nx.degree_centrality(G)                       # 度中心性
bet_c = nx.betweenness_centrality(G)                  # 介数中心性
clo_c = nx.closeness_centrality(G)                    # 接近中心性
eig_c = nx.eigenvector_centrality_numpy(G)            # 特征向量中心性
top = lambda c: sorted(c, key=c.get, reverse=True)[:3]
print("度中心性 Top3 节点:", top(deg_c))              # [33, 0, 32]
print("介数中心性 Top3 节点:", top(bet_c))            # [0, 33, 32]
print("接近中心性 Top3 节点:", top(clo_c))            # [0, 2, 33]
print("特征向量中心性 Top3 节点:", top(eig_c))        # [33, 0, 2]
```

## 8.7 关键公式与方法速查

| 方法 | 适用场景 | 关键公式/思想 | 优缺点与坑 |
|---|---|---|---|
| Dijkstra | 单源最短路，$w\ge 0$ | 松弛 $d(v)\leftarrow\min(d(v),d(u)+w(u,v))$ | 负权即错；$O(m\log n)$ |
| Floyd | 全对最短路，$n\lesssim 500$ | $d^{(k)}_{ij}=\min(d^{(k-1)}_{ij},d^{(k-1)}_{ik}+d^{(k-1)}_{kj})$ | $O(n^3)$；代码短，写论文方便 |
| Kruskal | 最小生成树（稀疏） | 边排序 + 并查集防环 | 只管"连通"，不管点对距离 |
| Prim | 最小生成树（稠密） | 最近点生长 | 同上 |
| Ford–Fulkerson / Edmonds–Karp | 最大流 | 增广路 + 残量网络 | 实现交内置函数；重点在建模 |
| 最大流最小割 | 瓶颈诊断 | $\max|f|=\min_{(S,T)}\sum_{S\to T}c(e)$ | 解释力强；务必报告割集 |
| 节点拆分 | 节点容量约束 | $u\to u_{in}\to u_{out}$，容量 $U$ | 不拆会"绕行超载"，静默出错 |
| 最小费用最大流 | 运输调配 | network_simplex | 费用要整数化避免浮点误差 |
| 匈牙利算法 / Kuhn–Munkres | 二分图（带权）匹配 | 交错路增广 | 有偏好时须带权 |
| 度分布/聚类系数/中心性 | 复杂网络分析 | 见 8.6 | 结论要挂回问题语境 |

## 8.8 典型例题与样例程序：地震应急物资中转站选址与调运优化

按竞赛论文八股完整走一遍（可直接当模板改数据复用）。

### （1）问题重述

某地发生地震，现有 3 个救援物资集散点 $S_1,S_2,S_3$（已确定位置与可供应量），4 个受灾点 $D_1$–$D_4$（位置与需求已知），另有 5 个候选中转站 $H_1$–$H_5$ 可启用（建站费与吞吐能力已知）。要求：

1. 恰选 2 个中转站启用，使"运输费 + 建站费"总费用最小，且所有受灾点需求全部满足；
2. 给出最优调运方案（各路段运量）；
3. 分析需求与吞吐能力扰动时方案的稳健性。

### （2）模型假设

1. 物资以"车"为离散单位，同型车辆，1 车即 1 单位流量（整数运输简化为可分，最优解取整后由规模小保证可执行）；
2. 运输费用与"距离 × 运量"成正比，比例系数 $F=0.05$ 万元/(km·车)，不考虑车辆返空与装载折扣；
3. 中转站单位时间吞吐能力上限为 60 车，超出则拥堵不可行；
4. 道路通行能力在本阶段不构成约束（第 3 问的时限校验中再放宽/收紧）；
5. 需求必须全部满足（硬约束）；若不可满足，方案判为不可行。

### （3）符号说明

| 符号 | 含义 |
|---|---|
| $a_i$ | 集散点 $i$ 的供应量（车），$i\in\{S1,S2,S3\}$ |
| $b_j$ | 受灾点 $j$ 的需求量（车），$j\in\{D1,\dots,D4\}$ |
| $d^{S}_{ih},\ d^{D}_{hj}$ | 集散点→中转站、中转站→受灾点的距离（km） |
| $c_h$ | 中转站 $h$ 的吞吐上限（车），建站费 $e_h$（万元） |
| $x_{ih},y_{hj}$ | 决策变量：路段运量（车） |
| $z_h\in\{0,1\}$ | 中转站 $h$ 是否启用 |

### （4）模型建立

**双层结构：外层选址（0-1 决策）+ 内层调运（最小费用流）。**

外层：

$$
\min_{z}\ \sum_{h}e_h z_h \;+\; T(z),\qquad \text{s.t. } \textstyle\sum_h z_h = 2,
$$

其中 $T(z)$ 是给定选址下的最优运输费。内层：建网络流图——超级源 $\to$ 集散点（容量 $a_i$）$\to$ 中转站 $\to$ 受灾点（容量 $b_j$）$\to$ 超级汇；把中转站 $h$ **拆成 $h_{in},h_{out}$**，中间弧容量 $c_h$，即吞吐约束。弧费用为 $F\cdot d$。则

$$
T(z)=\min \sum_{\text{弧}} w(e)\,f(e)\quad \text{s.t. 容量与守恒约束},\ \sum_{\text{入 }SNK} f = \sum_j b_j .
$$

这是一个**最小费用最大流**问题；选址候选只有 $\binom{5}{2}=10$ 种，直接枚举即得全局最优（规模大时换贪婪/拉格朗日松弛/遗传算法，见拓展延伸）。注意该模型也是第 5 章混合整数规划的特例——此处用"枚举 + 网络流"的组合求解，规模小时更稳更快。

### （5）求解算法与程序

```python
# -*- coding: utf-8 -*-
"""案例：地震应急物资中转站选址与调运优化（枚举选址 + 最小费用流调运 + 灵敏度分析）"""
import networkx as nx
from itertools import combinations

# ---------------- 数据（符号说明见正文） ----------------
supplies = {'S1': 40, 'S2': 35, 'S3': 25}                      # 集散点供应量 a_i（车）
demands  = {'D1': 25, 'D2': 30, 'D3': 25, 'D4': 20}            # 受灾点需求量 b_j（车）
hubs = ['H1', 'H2', 'H3', 'H4', 'H5']                          # 候选中转站
CAP_HUB = 60                                                   # 单站吞吐能力上限（车）
open_cost = {'H1': 50, 'H2': 60, 'H3': 55, 'H4': 45, 'H5': 65} # 建站固定费用（万元）

# 距离矩阵（km）：集散点 -> 中转站
d_SH = {'S1': {'H1': 8, 'H2': 12, 'H3': 20, 'H4': 15, 'H5': 25},
        'S2': {'H1': 10, 'H2': 7, 'H3': 14, 'H4': 22, 'H5': 18},
        'S3': {'H1': 24, 'H2': 19, 'H3': 9, 'H4': 11, 'H5': 13}}
# 距离矩阵（km）：中转站 -> 受灾点
d_HD = {'H1': {'D1': 6, 'D2': 14, 'D3': 22, 'D4': 18},
        'H2': {'D1': 12, 'D2': 8, 'D3': 17, 'D4': 21},
        'H3': {'D1': 19, 'D2': 13, 'D3': 7, 'D4': 10},
        'H4': {'D1': 15, 'D2': 21, 'D3': 12, 'D4': 8},
        'H5': {'D1': 26, 'D2': 18, 'D3': 11, 'D4': 14}}
F = 0.05   # 单位运输成本系数（万元/km/车）

# ---------------- 求解：枚举 C(5,2) 组合 + 最小费用流 ----------------
def solve(chosen, cap_hub=CAP_HUB, dem=demands, sup=supplies):
    """给定选中中转站集合，用最小费用流求最优调运；若无法满足全部需求返回 None。
    节点拆分技巧：h 拆成 h_in / h_out，中间弧容量 = 单站吞吐上限。"""
    G = nx.DiGraph()
    for s, a in sup.items():
        G.add_edge('SRC', s, capacity=a, weight=0)
        for h in chosen:
            G.add_edge(s, h + '_in', capacity=a, weight=int(F * d_SH[s][h] * 100))
    for h in chosen:
        G.add_edge(h + '_in', h + '_out', capacity=cap_hub, weight=0)   # 单站吞吐约束
        for dj, b in dem.items():
            G.add_edge(h + '_out', dj, capacity=b, weight=int(F * d_HD[h][dj] * 100))
    for dj, b in dem.items():
        G.add_edge(dj, 'SNK', capacity=b, weight=0)
    try:
        flow = nx.max_flow_min_cost(G, 'SRC', 'SNK')
    except nx.NetworkXUnfeasible:
        return None
    # 关键检验：送达总量必须等于总需求（max_flow_min_cost 求的是"能送达多少就送多少"）
    delivered = sum(flow[dj]['SNK'] for dj in dem)
    if delivered < sum(dem.values()) - 1e-9:
        return None
    return nx.cost_of_flow(G, flow) / 100.0, flow               # (运输费万元, 调运方案)

results = []
for chosen in combinations(hubs, 2):
    r = solve(set(chosen))
    if r is not None:
        tc, _ = r
        results.append((tc + sum(open_cost[h] for h in chosen), tc, chosen))
results.sort()
print("=== 选址枚举结果（总费用 = 运输费 + 建站费，万元）===")
for total, tc, ch in results:
    print(f"  {ch}: 运输费 {tc:6.2f} + 建站费 {sum(open_cost[h] for h in ch)} = 总费用 {total:7.2f}")

best = results[0]
print("\n最优方案:", best[2], "总费用 =", round(best[0], 2), "万元")

tc, flow = solve(set(best[2]))
print("\n=== 最优调运方案（车次）===")
for s in supplies:
    for h in best[2]:
        if flow[s][h + '_in'] > 0: print(f"  {s} -> {h}: {flow[s][h + '_in']} 车")
for h in best[2]:
    for dj in demands:
        if flow[h + '_out'][dj] > 0: print(f"  {h} -> {dj}: {flow[h + '_out'][dj]} 车")

# ---------------- 检验 1：守恒性与容量 ----------------
print("\n容量检验: 到站流量 =",
      {h: sum(flow[s][h + '_in'] for s in supplies) for h in best[2]},
      "<= 单站上限", CAP_HUB)

# ---------------- 检验 2：灵敏度分析（供需同步上浮模拟应急动员）----------------
print("\n=== 灵敏度分析（最优组合 %s，供需同步上浮 20%%）===" % (best[2],))
sup2 = {k: round(v * 1.2) for k, v in supplies.items()}         # 供给上浮 20%
dem2 = {k: round(v * 1.2) for k, v in demands.items()}          # 需求上浮 20%
for cap in (60, 58, 55, 50):
    r = solve(set(best[2]), cap_hub=cap, dem=dem2, sup=sup2)
    print(f"供需+20%、单站容量{cap}: " + (f"可行，运输费 {r[0]:.2f} 万元" if r else
          f"不可行（两站吞吐和 {2*cap} < 需求 {sum(dem2.values())}，需启用第 3 个中转站）"))
```

### （6）结果与检验

1. **最优方案**：启用 $H_1,H_4$，总费用 200.75 万元；亚军组合 $(H_1,H_3)$ 仅差 0.25 万元——说明解对建站费不敏感，论文中应指出这一"次优也几乎最优"的稳健区间。
2. **可行性检验**：调运方案中每个受灾点恰好分得需求量（守恒），到站流量 55/45 车均低于 60 车上限，方案可执行。
3. **灵敏度分析**：供需同涨 20% 后，原方案在容量 60 车时仍可行；容量一旦低于 60（吞吐和 < 需求 120），两站结构不可行，**触发条件是"两站吞吐和 ≥ 总需求"**——这就把"要不要预留第三站"变成了清晰的阈值判据，是论文的加分结论。
4. **调试记录（写进论文的"模型修正"环节反而加分）**：初版模型把中转站直接连向超级汇设为 0 费用，导致物资"绕过受灾点直达汇点"的虚假最优；改为节点拆分 + 送达量校验后修正。竞赛中保留此类修正过程体现建模严谨性。

### （7）模型评价

- **优点**：内层最小费用流有全局最优保证、求解瞬时完成；节点拆分把节点容量自然并入网络结构；枚举规模仅 10 种，解的全局最优性无争议；最小割/最大流校验可扩展回答"12 小时内最多送达多少"等时限问题。
- **缺点**：外层枚举在候选点增多时组合爆炸（$k$ 中位数问题本身 NP-难）；假设费用线性、忽略车辆路径细节（未做 VRP 级别的路径规划）。
- **改进方向**：候选点多时外层换贪婪增选 + 局部搜索或拉格朗日松弛；加入时间窗（车辆调度）后转 VRP 变体；不确定性需求下用本章第 13 章仿真方法对需求抽样、评估方案的分位数表现。

## 8.9 常见误区与竞赛扣分点

1. **把最短路当最小生成树用**（或反之）。"铺设管网总长最短"是 MST，"从仓库到各灾区最省"是最短路树，评委一眼识破。
2. **Dijkstra 忽略负权**。费用含"补贴/收益"为负时结果全错；论文须声明权值非负的假设依据。
3. **容量约束只设在边上、忘设节点上**，或干脆漏掉吞吐上限——方案"最优"但物理不可行。节点拆分是标准修正。
4. **最大流论文里只报数值不报最小割**。最大流-最小割这对结论的瓶颈诊断价值才是评委想看的。
5. **无向图当有向图建、有向图当无向图建**。道路双向 vs 单行道；`Graph` 与 `DiGraph` 用错，所有结论失真。
6. **二分图匹配问题里写"贪心配对"**。贪心不保证最大匹配（会陷入局部阻塞），必须说明用的是匈牙利算法/最大流建模。
7. **复杂网络分析"指标堆砌"**：算了一堆中心性却不回答"所以该封锁谁、该修哪条路"，会被评语写"分析与应用脱节"。
8. **整数化陷阱**：流量问题要求整数解时，纯 LP 可能给出 0.5 车；networkx 的流算法天然整数解，改用第 5 章 LP 求解器时要声明整型变量。

## 8.10 拓展延伸

- **与[第 5 章优化模型](/xiaoshus-blog/textbooks/modeling/02-methods/05/)的组合**：网络流是线性规划的特例（完全单模（TU）约束矩阵保证 LP 松弛天然取整），所有网络流问题都能丢给第 5 章的整数规划求解器；反过来，当网络结构被破坏（固定建站费、流量下限），就退化成一般 MILP，此时"枚举/启发式外层 + 网络流内层"的分解框架（如 8.8 案例）仍然成立。这是最值得在论文里点明的建模观点。
- **与[第 3 章线性代数方法](/xiaoshus-blog/textbooks/modeling/01-foundations/03/)**：特征向量中心性 = 邻接矩阵主特征向量；PageRank = 随机游走的平稳分布；谱聚类 = 拉普拉斯矩阵特征分解 + K-means（联动[第 10 章](/xiaoshus-blog/textbooks/modeling/02-methods/10/)）。
- **与[第 13 章仿真](/xiaoshus-blog/textbooks/modeling/02-methods/13/)**：网络上的流量分配若考虑随机到达（车辆、订单），用排队论/仿真评估网络在扰动下的可靠性，比确定性最大流更贴近现实。
- **进阶算法**：Dinic（二分图/单位容量更快）、Stoer–Wagner 全局最小割、k-短路与遗传/模拟退火（第 5 章）处理带复杂约束的网络设计；社区检测（Louvain）用于复杂网络划分。
- **前沿阅读**：网络传播动力学（疫情谣言扩散，联动第 2 章微分方程）；多层网络与级联失效（电网—通信网耦合）。

3. 将 8.8 案例改造为"3 个中转站、建站费未知、需要反推：当 $H_3$ 建站费降为多少时 $(H_1,H_3)$ 反超 $(H_1,H_4)$？"（提示：对参数做一维扫描，画总费用差曲线）
4. 有 6 名翻译、4 个语种组，每人可胜任的语种集合已知。建模并求解：(a) 最多安排多少人到组（最大匹配）；(b) 若每人到组的"适配分"已知，如何让总适配分最大（带权匹配）？两问的最优解一定一致吗？
5. 下载任一真实网络数据（如 networkx 内置的 `nx.powergrid_dataset` 或自行抓取微博转发链），计算度分布（双对数坐标画图）、聚类系数与三种中心性，回答"若要阻断信息扩散，应优先控制哪些节点？"并说明选择介数中心性而非度中心性的理由。
6. **（真题改编）** 出租车网约平台的"派单"可视为二分图带权匹配。若订单与车辆实时到达，静态匈牙利算法每秒重算一次是否可行？提出两种加速思路（提示：增量匹配/滑动时间窗批处理），并用小规模数据对比两种策略的匹配率与等待时间。
