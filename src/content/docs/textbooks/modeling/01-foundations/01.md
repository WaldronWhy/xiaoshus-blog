## 1.1 数学模型是什么

### 1.1.1 定义

**数学模型**（mathematical model）：对现实对象的信息进行提炼、分析、归纳后，用数学语言（变量、方程、不等式、图、算法）对对象的内在规律进行的近似描述，并可用于解释现象、预测未来或提供决策。

一句话记住三要素：**现实问题 →（抽象/翻译）→ 数学结构 →（求解/解释）→ 回到现实**。模型的价值不在于"像不像"，而在于回答你要的那个问题。

### 1.1.2 分类

从竞赛实用角度，按"数学结构从哪里来"分三类：

| 类型 | 别称 | 数学结构来源 | 典型赛题特征 | 章节去向 |
|---|---|---|---|---|
| 机理模型 | 白箱 | 物理定律、守恒关系、机理推导 | "建立……的数学模型并求解" | 第 2 章（微分方程）、第 5 章（优化） |
| 统计模型 | 黑箱 | 数据中"拟合/学习"出来 | 大量附件数据、回归/分类/预测 | 第 4 章、第 7 章、第 10 章 |
| 仿真模型 | 灰箱 | 机理骨架 + 随机模拟 | 排队、交通流、蒙特卡洛 | 第 13 章 |

另可按问题任务分：**评价**（排序/分级，第 6 章）、**预测**（外推，第 7 章）、**优化**（求最优决策，第 5 章）、**机理分析**（解释规律，第 2 章）、**综合**（多问串联，近年主流）。

> 国赛（CUMCM）三题大致分工：A 题偏物理/工程机理，B 题偏运筹/离散优化，C 题偏数据统计，但边界越来越模糊；美赛（MCM/ICM）六题（A–F）同样覆盖连续、离散、数据洞察、运筹、环境可持续、政策六类。

## 1.2 建模的一般步骤（竞赛八股详解）

竞赛论文的骨架就是下面这条流水线。**每一问、每个模型都各走一遍**，而不是整篇论文走一遍。

### 第一步：问题分析 / 问题重述

- **不是抄题**，而是用自己的话把题目要求转述为数学问题清单：第 X 问要的是"最大值？排序？预测值？还是规律解释？"
- 明确四要素：**已知什么（数据/参数）→ 求什么（目标量）→ 受什么限制（约束）→ 什么可以自己定（自由度）**。
- 竞赛技巧：把题目拆成"递进链"——前一问的输出往往是后一问的输入。

### 第二步：模型假设

假设的作用是**把无穷复杂的现实裁剪成可解的问题**。每条假设必须：

1. 有明确内容（"服务台数量为 1"比"系统较简单"好）；
2. 有合理性论证（来自题设、常识、数据或"影响可忽略"的说明）；
3. 与后面建立的方程一一对应——**评委检查的就是"这条假设用在了模型哪个地方"**。

常用假设套路：均匀性/各向同性、独立到达、比例效应、外推平稳、忽略次要因素（附量化理由，如"占总能耗 <1%"）。

### 第三步：符号说明

符号表：符号 | 含义 | 单位。**单位必写**，且全文符号唯一（变量 $x$ 不要在两处含义不同——这是低级扣分点）。

### 第四步：模型建立（假设 → 方程，关键一步，不能跳）

这一步的核心是"**逐条假设落成数学结构**"。例如假设"到达是独立随机的、与时间无关、平均每分钟 $\lambda$ 人"，翻译成数学就是：在 $[t, t+\Delta t]$ 内到达人数 $N(t+\Delta t)-N(t) \sim \mathrm{Poisson}(\lambda \Delta t)$。再如假设"变化速率与当前数量成正比"，翻译成微分方程就是 $\frac{dN}{dt}=kN$。**假设与方程之间的每一处翻译必须写出推理过程**，公式不能凭空出现。

### 第五步：模型求解

- 解析解优先（能推就推，体现功力）；推不动就数值解（第 2、11、12 章工具）；
- 写清**算法名、输入输出、参数取值及来源**；
- 结果用图表呈现：一张好图胜半页文字（第 16 章）。

### 第六步：模型检验（与求解同样重要，很多队漏掉）

至少做两类：

- **误差/拟合检验**：与真实数据对比（残差、$R^2$、相对误差）；
- **灵敏度分析**（sensitivity analysis）：关键参数上下浮动 10%–20%，看结论是否翻车。结论稳健 → 模型可信；特别敏感的参数 → 要在论文里指出并建议精确测定。

### 第七步：模型评价与应用

优点（真实、具体）、缺点（诚实但有补救方向）、改进方向（引入哪个新模型/新数据）。最后回答题目原问——**结论要用题目问的语言陈述，不能只给数学符号**。

## 1.3 什么是"好模型"

评委眼中好模型的三条核心标准：

1. **合理性（validity）**：与题设、常识、数据不矛盾；边界情形正确（如人口模型里 $N(t)\ge 0$、概率落在 $[0,1]$）。检验法：代入特殊值、量纲分析（量纲（dimension）不一致的方程必错）。
2. **简洁性（simplicity）**：奥卡姆剃刀——同样解释力下选结构简单的。堆砌十个未检验的神经网络不如一条有物理解释的方程。
3. **可检验性（testability）**：模型给出**可被数据或实验反驳的预测**；说不出"什么结果出现说明我错了"的模型不是科学模型。

外加两条竞赛加分项：**稳健性**（参数扰动下结论不剧变）与**可解释性**（每个系数有现实含义，如"$\beta=0.5$ 表示每个感染者在全员易感时每天平均传染 0.5 人"）。

| 机理类 | "建立……的数学模型并分析规律" | 微分方程、稳定性分析 | 第 2 章 |

### 1.4.2 审题三遍法

- **第一遍（10 分钟，通读）**：不抠细节，画出问题结构图——几问？每问的输入/输出是什么？给了哪些附件数据？
- **第二遍（逐句精读）**：给每个句子标注类型——【条件】【约束】【数据定义】【任务】【陷阱】。特别注意"不能""至少""恰好""有效期内"等硬约束词。
- **第三遍（翻译成数学）**：把每问改写成一句话的数学命题。例如"设计一条调头曲线" → "在半径 9 m 圆域内找一条由两段圆弧（或贝塞尔曲线）构成的光滑曲线，满足曲率连续且切线段最短"。**如果第三遍完成后你仍然说不出目标函数和约束，说明还没读懂题**。

## 1.5 真题解剖：2024 年国赛 A 题"'板凳龙'闹元宵"审题示范

（本题是极佳的审题教材：题面全是生活语言，但每一句都对应一个数学对象。以下为审题示范，侧重"如何翻译"，不含完整解答。）

**背景翻译**：元宵节"板凳龙"由许多节板凳用铰链（转动轴）连接，每节板凳有两个把手孔。舞龙时队伍沿等距螺线盘入再盘出。

| 题面语言 | 数学翻译 |
|---|---|
| 螺距 0.55 m 的等距螺线 | 阿基米德螺线（Archimedean spiral）$r = \dfrac{p}{2\pi}\theta,\ p=0.55$ m |
| 龙头前把手以 1 m/s 沿螺线运动 | 弧长参数化：$s(t)=t$，由 $ds = \sqrt{r^2+(r')^2}\,d\theta$ 得 $\theta(t)$ 的微分方程 |
| 223 节板凳、各节把手孔距已知 | 相邻把手沿螺线（近似）落在同一螺线上，且**弦长**（直线距离）等于孔距 $L_i$ —— 这给出逐节求解 $\theta_i$ 的非线性方程 $|\,\gamma(\theta_{i-1})-\gamma(\theta_i)\,|=L_i$ |
| 板凳不能碰撞 | 几何约束：每节板凳是宽 0.3 m 的线段（矩形），需检测非相邻线段间的距离 $\ge$ 安全距离——一个随时间变化的**碰撞检测约束** |
| 求终止时刻 | 把"约束被破坏的最早 $t$"变成一个**约束满足问题**：对时间扫描/求根 |
| 调头空间半径 9 m、设计调头曲线 | **带约束的曲线设计/优化**：在圆域内构造两段圆弧拼接的光滑曲线，最小化调头曲线长度或调头时间 |

**审题得到的启发**：

1. 第一问（给定时刻各把手位置与速度）是**递推 + 非线性方程求根**；第二问在其上加时间扫描；第三、四问进入**曲线设计与优化**——题目的"阶梯"非常清晰，前一问的求解代码直接是后一问的子程序。
2. 隐藏约束往往比显式约束更致命：题目明说的是孔距，暗说的是"板凳宽度导致的碰撞"，第二问的整个难度就在把暗约束形式化。
3. 这类"几何 + 递推 + 优化"的题目，审题阶段就应确定数值精度与时间步长策略（步长太粗会漏掉碰撞时刻）。

## 1.7 典型例题与样例程序：食堂排队问题（完整八股）

**① 问题重述**：某高校食堂中午高峰单一窗口排队严重。学生平均每分钟到达 0.8 人，窗口平均每分钟服务完 1 人。问：学生平均要等多久？队平均多长？若要"平均等待不超过 2 分钟"，服务速度需提高到多少？

**② 模型假设**（每条附合理性）：

1. 学生到达相互独立、到达率恒定 $\lambda=0.8$ 人/分钟——高峰期内人流平稳，"独立随机"来自不同学院下课时间错开的常识；
2. 服务时间服从负指数分布、平均 $\mu=1$ 人/分钟——"服务快慢随机"合理；严格恒定服务时间对应 M/D/1，结果可作对比；
3. 单窗口、容量无限、先到先服务——题设情景；
4. 系统达到平稳态（$\rho=\lambda/\mu=0.8<1$，队列不发散）——建模前提。

**③ 符号说明**：$\lambda$ 到达率（人/分钟）；$\mu$ 服务率（人/分钟）；$\rho=\lambda/\mu$ 服务强度；$W_q$ 平均排队等待时间（分钟）；$W$ 平均逗留时间；$L_q$ 平均队长；$L$ 系统平均人数。

**④ 模型建立**：由泊松到达 + 负指数服务得生灭过程（birth-death process），平稳分布为几何分布 $P_n=(1-\rho)\rho^n$，于是

$$L=\sum_{n=0}^{\infty}n(1-\rho)\rho^n=\frac{\rho}{1-\rho},\qquad
W=\frac{L}{\lambda}\ \text{(Little 公式)},\qquad
W_q=W-\frac{1}{\mu},\qquad
L_q=\lambda W_q .$$

**⑤ 求解**：$W_q=4.000$ 分钟，$W=5.000$ 分钟，$L_q=3.2$ 人，$L=4$ 人。要 $W_q\le 2$：$\dfrac{\rho}{\mu-\lambda}\le 2 \Rightarrow \mu \ge \lambda+\sqrt{\lambda/2}\approx 1.432$，即服务速度至少提高约 43%。

**⑥ 模型检验**：用蒙特卡洛仿真（蒙特卡洛方法 Monte Carlo method）独立验证解析解——两种途径结果吻合到小数点后一位（见代码），且系统参数变化时仿真与公式同步变化，说明建模无误。仿真还给出解析解难给的信息：等待时间的分布（90 分位数远大于均值，说明"运气差的人要等很久"）。

**⑦ 模型评价**：优点——推导透明、可解析、灵敏度一目了然（$W_q$ 对 $\rho$ 极敏感：$\rho\to 1$ 时爆炸）。缺点——到达率恒定假设与"高峰/平峰交替"不符；未考虑学生看到队长就离开（放弃行为）。改进——时变到达率 $\lambda(t)$ 的非平稳 M/M/1（第 13 章排队仿真）。

```python
# -*- coding: utf-8 -*-
"""
第1章样例：食堂排队问题的 M/M/1 解析模型 + 蒙特卡洛仿真验证
建模流程：问题重述 -> 假设 -> 符号 -> 建模 -> 求解 -> 检验 -> 评价
运行环境：Python 3.x（仅需 numpy）
"""
import numpy as np

rng = np.random.default_rng(2024)

# ---------- 参数（单位：人/分钟）----------
lam = 0.8      # 到达率 lambda：平均每分钟 0.8 人到达（负指数分布）
mu = 1.0       # 服务率 mu：平均每分钟服务完 1 人（负指数分布）
rho = lam / mu # 服务强度（利用率）
print(f"服务强度 rho = {rho:.2f}")          # 预期: 0.80

# ---------- M/M/1 解析公式 ----------
Wq = rho / (mu - lam)   # 平均排队等待时间
W = 1 / (mu - lam)      # 平均逗留时间（等待+服务）
Lq = lam * Wq           # 队长（排队人数）
L = lam * W             # 系统内人数
print(f"解析解: 平均等待 Wq={Wq:.3f} min, 平均逗留 W={W:.3f} min")
print(f"        平均队长 Lq={Lq:.3f} 人,  系统人数 L={L:.3f} 人")

# ---------- 蒙特卡洛仿真（单服务台，先到先服务）----------
N = 20000   # 模拟 20000 名顾客
arrive = np.cumsum(rng.exponential(1 / lam, N))    # 到达时刻
service = rng.exponential(1 / mu, N)               # 每人所需服务时长
start = np.empty(N); start[0] = arrive[0]          # 开始服务时刻
for i in range(1, N):                              # 前一人服务完与自己到达取较晚者
    start[i] = max(start[i - 1] + service[i - 1], arrive[i])
wait = start - arrive                              # 排队等待时间
stay = wait + service                              # 逗留时间
# 前 2000 人为"暖机"期丢弃，避免初态偏差
print(f"仿真解: 平均等待 Wq={wait[2000:].mean():.3f} min, 平均逗留 W={stay[2000:].mean():.3f} min")
print(f"        系统平均人数 L={stay[2000:].sum() / (arrive[-1] - arrive[2000]):.3f} 人")
```

**运行结果（已实测）**：

```
服务强度 rho = 0.80
解析解: 平均等待 Wq=4.000 min, 平均逗留 W=5.000 min
        平均队长 Lq=3.200 人,  系统人数 L=4.000 人
仿真解: 平均等待 Wq=3.953 min, 平均逗留 W=4.958 min
        系统平均人数 L=3.978 人
```

解析解与仿真解误差 <1.2%，属于蒙特卡洛正常统计涨落；将 `lam` 调成 0.95 再跑，会看到 $W_q$ 从 4 分钟飙升到约 19 分钟——排队系统在接近满负荷时的非线性恶化，这正是灵敏度分析要揭示的。

## 1.8 常见误区与竞赛扣分点（评委视角）

1. **问题重述 = 抄题**。评委一眼看穿。重述必须出现"数学问题清单"。
2. **假设与模型脱节**：写了十条假设，方程里一条都没用到；或假设"忽略 X"却根本没说为什么可忽略。
3. **符号混乱**：同一符号两个含义、单位缺失、图中变量与正文不一致。
4. **只有求解没有检验**：不做误差对比、不做灵敏度分析，结论悬空。
5. **结果不回答题目原问**：最后一页只有符号和数字，没有一句"人话结论"。
6. **模型越复杂越好**：评委偏好"假设最少、能解决问题"的模型；把简单问题套深度学习属于过度建模。
7. **M/M/1 类公式闭眼套**：不看 $\rho<1$ 前提、不看到达/服务分布是否近似——公式都有适用域。
8. **伪代码当真代码**：论文附录里给跑不通的程序；本书所有样例均实测可跑，赛场上照此标准。

## 1.10 课后练习

1. **审题训练**：找 2024 年国赛 C 题（农作物种植策略类数据题）或任一年度真题，按 1.4.2 三遍法逐句标注，写出每问的"一句话数学命题"。（提示：重点标出所有"不能/至少/恰好"。）
2. **假设改写**：把"系统比较稳定，客流变化不大"改写成 3 条可检验的规范假设，并各配一条合理性论证。
3. **排队续问**：在 1.7 案例中，若食堂增开第二个窗口（两个独立队伍、平均分流），平均等待变为多少？（提示：每队 $\lambda=0.4$、$\mu=1$；也可用多服务台 M/M/c 公式对照。）
4. **灵敏度计算**：对 $W_q=\rho/(\mu-\lambda)$ 求 $\partial W_q/\partial\lambda$，讨论 $\lambda\to\mu$ 时的行为，并说明为什么"提高到达效率"比"提高服务效率"更该被管理。（提示：看偏导在 $\rho\to1$ 的发散速度。）
5. **建模设计题**：自习室"占座"现象严重。请完成一个微型建模：定义"座位利用率"与"有效利用率"两个指标，各建一条计算公式，并设计数据采集方案。（提示：区分"被占用"与"被使用"。）
6. **真题改编**：将 2024 年 A 题板凳龙的碰撞检测改写为一个优化问题：以"龙头最大行进速度"为决策变量，写出目标函数与全部约束的数学表达（不必求解）。
