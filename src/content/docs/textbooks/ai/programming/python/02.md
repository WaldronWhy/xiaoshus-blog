# 第 2 章 函数式与面向对象：两种组织代码的方式

> **本章定位**：本章解决"代码如何组织"的问题。函数式（高阶函数、闭包、装饰器）与面向对象（类、继承、魔术方法、dataclass）是 Python 生态并存的两大组织范式；PyTorch 的 `nn.Module`、sklearn 的 `fit/transform` 接口都建立在本章机制之上。前置要求：第 1 章的对象模型与作用域规则；本章将同时为第 3 章（迭代协议靠魔术方法）和第 4 章（NumPy 的向量化函数）铺垫。

## 2.1 函数是一等公民

### 2.1.1 高阶函数

**一等公民（first-class citizen）**意味着函数可以：赋值给名字、存入容器、作为参数传入、作为返回值返回。接收或返回函数的函数称为**高阶函数（higher-order function）**。

```python
import math

def square(x):
    return x * x

funcs = {"square": square, "sqrt": math.sqrt}   # 函数存入字典
print(funcs["square"](5))    # 预期输出: 25

def apply(f, xs):            # 函数作为参数
    return [f(x) for x in xs]

print(apply(math.sqrt, [1.0, 4.0, 9.0]))  # 预期输出: [1.0, 2.0, 3.0]
```

内置的 `map`/`filter`/`sorted(key=...)` 都是高阶函数。工程中最常用的形式是 **key 函数**：

```python
words = ["banana", "fig", "cherry"]
print(sorted(words, key=len))            # 预期输出: ['fig', 'banana', 'cherry']
print(max(words, key=lambda w: w[-1]))   # 预期输出: 'banana'（按末字符最大）
```

### 2.1.2 lambda 与闭包

`lambda 参数: 表达式` 创建匿名函数，只能含单个表达式。更强大的机制是**闭包（closure）**：内层函数"记住"了外层作用域的变量，即使外层函数已经返回（第 1 章 1.5.2 节的 `make_counter` 就是闭包）。闭包让"部分参数已固定的函数"成为可能——这正是**柯里化/偏函数**思想的来源：

```python
from functools import partial

def power(base, exponent):
    return base ** exponent

square = partial(power, exponent=2)
print(square(9))   # 预期输出: 81
```

## 2.2 闭包与装饰器

### 2.2.1 装饰器的本质

**装饰器（decorator）**是"接收函数、返回新函数"的语法糖。理解它的关键只有一句话：`@dec` 等价于 `f = dec(f)`，发生在**定义时**（而非每次调用时）。

```python
import time
import functools

def timer(func):
    """计时装饰器：测量被装饰函数的运行时间。"""
    @functools.wraps(func)          # 保留原函数的 __name__/__doc__
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        dt = time.perf_counter() - t0
        print(f"{func.__name__} 耗时 {dt * 1000:.3f} ms")
        return result
    return wrapper

@timer                     # 等价于 sum_squares = timer(sum_squares)
def sum_squares(n):
    return sum(i * i for i in range(n))

print(sum_squares(10_000_000))
# 预期输出（量级示例，具体数值因机器而异）:
# sum_squares 耗时 320.5 ms
# 333333283333335000000
```

`functools.wraps` 不是可有可无的：没有它，`sum_squares.__name__` 会变成 `"wrapper"`，调试器和文档工具都会失效。

### 2.2.2 带参数的装饰器

带参数的装饰器是"三层函数"：参数 → 装饰器 → 包装函数。

```python
import functools

def retry(times):
    """失败自动重试 times 次：包装网络请求/文件下载等不稳定操作。"""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第 {attempt} 次失败: {e}")
            raise RuntimeError(f"{func.__name__} 重试 {times} 次后仍失败")
        return wrapper
    return decorator

@retry(times=3)
def flaky():
    import random
    if random.random() < 0.7:
        raise ConnectionError("网络抖动")
    return "ok"
```

### 2.2.3 缓存装饰器：把指数复杂度降到线性

`functools.cache`（3.9+）以函数参数为键做记忆化（memoization）：

```python
import functools

@functools.cache
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(80))   # 预期输出: 23416728348467685 —— 瞬时完成；无缓存则是数十亿次调用
```

手写一个简化版缓存装饰器，体会其机制（也是第 7 章可测试代码的素材）：

```python
import functools

def my_cache(func):
    _store = {}                    # 闭包变量充当缓存（对比 1.6 节：这里共享是故意的）
    @functools.wraps(func)
    def wrapper(*args):
        if args not in _store:
            _store[args] = func(*args)
        return _store[args]
    wrapper.cache_clear = _store.clear
    return wrapper
```

注意：缓存以参数为键，**参数必须可哈希**——传 ndarray 会直接报错，这是科学计算中使用缓存的常见坑。

### 2.2.4 `@property`：把方法伪装成属性

`@property` 让"计算属性"看起来像普通属性，同时保留封装（外部无感知地把字段换成计算）：

```python
class Temperature:
    def __init__(self, celsius=0.0):
        self.celsius = celsius

    @property
    def fahrenheit(self):          # 像属性一样访问：t.fahrenheit
        return self.celsius * 9 / 5 + 32

    @fahrenheit.setter
    def fahrenheit(self, value):   # 像属性一样赋值：t.fahrenheit = 100
        self.celsius = (value - 32) * 5 / 9

t = Temperature(25)
print(t.fahrenheit)     # 预期输出: 77.0
t.fahrenheit = 212
print(t.celsius)        # 预期输出: 100.0
```

AI 代码中的典型用法：`model.flops`、`dataset.num_classes` 这类" Derived quantity"（派生量）用 `@property` 暴露，而不是每次都调方法。

## 2.3 类与继承

### 2.3.1 类的基本形态

Python 的类是"名字空间 + 函数"的组合；实例方法第一个参数 `self` 就是第 1 章所讲的**对象引用本身**（1.1.3 节 call by object reference 的体现——`self` 上原地修改对调用者可见）。

```python
class LinearModel:
    """y = w @ x + b 的最小实现，方法一节将扩展它。"""

    def __init__(self, n_features):
        self.n_features = n_features
        self.w = [0.0] * n_features     # 实例属性
        self.b = 0.0

    def predict(self, x):
        return sum(wi * xi for wi, xi in zip(self.w, x)) + self.b
```

类属性与实例属性要区分：`LinearModel.kind = "linear"` 是类属性（所有实例共享），`self.w` 是实例属性（每个实例独立）。给实例赋值同名属性会**遮蔽**类属性，这是第 1 章 LEGB 之外的又一层"遮蔽"关系。

### 2.3.2 继承与多态

```python
class Optimizer:
    def __init__(self, params, lr=0.01):
        self.params = params
        self.lr = lr

    def step(self):
        raise NotImplementedError      # 抽象约定：子类必须实现

class SGD(Optimizer):
    def step(self):
        for p in self.params:
            p["value"] -= self.lr * p["grad"]

class MomentumSGD(Optimizer):
    def __init__(self, params, lr=0.01, momentum=0.9):
        super().__init__(params, lr)   # 调用父类构造
        self.v = [0.0] * len(params)
        self.momentum = momentum

    def step(self):
        for i, p in enumerate(self.params):
            self.v[i] = self.momentum * self.v[i] + p["grad"]
            p["value"] -= self.lr * self.v[i]
```

调用 `opt.step()` 时按对象的**实际类型**分派到子类实现——这就是多态（polymorphism），是 sklearn `fit/transform`、PyTorch `nn.Module.forward` 统一接口的基础。

### 2.3.3 组合优于继承

继承表达"是一个"（MomentumSGD **是一个** Optimizer，合理）；组合表达"有一个"。经验法则：

- 复用**代码**时优先组合（`model.optimizer = SGD(...)`）；
- 复用**接口**时才用继承（保证"任何 Optimizer 子类都能被 trainer 调用"）；
- 继承层次超过两层、或子类大量重写而不再满足父类约定时，考虑改组合。这条原则将在第 7 章重构案例中再次出现。

## 2.4 魔术方法

**魔术方法（magic methods / dunder methods）**是 Python 解释器在特定语法下调用的协议钩子。`len(x)` 实际调用 `x.__len__()`；`for i in x` 实际调用 `iter(x)`（第 3 章展开）。掌握魔术方法，你的对象就能"原生地"参与 Python 的一切语法。

| 语法 | 触发的魔术方法 | 典型用途 |
|---|---|---|
| `repr(x)` / print | `__repr__` | 调试友好的字符串表示 |
| `len(x)` | `__len__` | 数据集大小 |
| `x[i]`、切片 | `__getitem__` | `dataset[i]`（PyTorch Dataset 协议） |
| `x(...) ` | `__call__` | `model(x)` 直接调用实例 |
| `a + b` | `__add__` | 数值/容器运算 |
| `with x:` | `__enter__`/`__exit__` | 资源管理（第 3 章） |
| `for i in x` | `__iter__` | 迭代协议（第 3 章） |

```python
class Vector:
    """二维向量：演示 __repr__/__add__/__len__/__call__。"""

    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __len__(self):
        return 2

    def __call__(self, scale=1.0):
        return (self.x * scale, self.y * scale)

v = Vector(1, 2) + Vector(3, 4)
print(v)              # 预期输出: Vector(4, 6)
print(len(v))         # 预期输出: 2
print(v(10))          # 预期输出: (40, 60)
```

`__call__` 值得特别注意：PyTorch 里写 `model(x)` 而不是 `model.forward(x)`，正是因为 `nn.Module` 定义了 `__call__`，它在 `forward` 之外还注册了钩子（hook）等机制——**语法糖背后是协议**。

## 2.5 dataclass：数据载体的标准答案

大量类存在的唯一目的就是"装数据"（样本、超参数、配置）。手写 `__init__`/`__repr__`/`__eq__` 冗长且易错，`@dataclass` 自动生成它们：

```python
from dataclasses import dataclass, field

@dataclass
class TrainConfig:
    lr: float = 1e-3
    batch_size: int = 32
    epochs: int = 10
    seed: int = 0
    metrics: list = field(default_factory=list)   # 可变默认值的正确写法（对比 1.6 陷阱 3）

cfg1 = TrainConfig(lr=0.01)
cfg2 = TrainConfig(lr=0.01)
print(cfg1)                     # 预期输出: TrainConfig(lr=0.01, batch_size=32, epochs=10, seed=0, metrics=[])
print(cfg1 == cfg2)             # 预期输出: True —— 自动生成 __eq__
print(cfg1.batch_size)          # 预期输出: 32
```

工程收益：① 类型注解即文档，mypy（第 3 章）可直接检查；② `asdict()` 一行导出配置用于实验记录（《实验设计与评估》的复现性要求）；③ `frozen=True` 一行变成不可变对象（对应第 1 章）。

## 2.6 示例与案例

### 案例 1：手算一个闭包的执行过程（数值算例）

推导下面代码每一步 `n` 的值，再运行验证：

```python
def make_accumulator():
    total = 0
    def add(x):
        nonlocal total
        total += x
        return total
    return add

acc = make_accumulator()
print(acc(10))   # total: 0 -> 10，预期输出: 10
print(acc(20))   # total: 10 -> 30，预期输出: 30
acc2 = make_accumulator()
print(acc2(1))   # 新闭包，独立 total，预期输出: 1
print(acc(5))    # 原闭包 total: 30 -> 35，预期输出: 35
```

校验值：`10, 30, 1, 35`。关键理解：每个 `make_accumulator()` 调用创建**独立**的 `total`；闭包捕获的是变量本身，不是值的快照。

### 案例 2：用 OOP 组织一个简单模型类（衔接《机器学习》）

综合本章全部机制：dataclass 配置 + property + 继承 + 魔术方法 + 装饰器。只依赖标准库与 numpy，可直接运行。

```python
import numpy as np
from dataclasses import dataclass, asdict

@dataclass
class GDConfig:
    """梯度下降超参数（dataclass：见 2.5 节）。"""
    lr: float = 0.1
    n_iters: int = 500
    tol: float = 1e-8

class LinearRegressionGD:
    """最小二乘线性回归的梯度下降实现。

    模型: y_hat = X @ w + b；损失: MSE = (1/n)||y - y_hat||^2
    梯度: dL/dw = (2/n) X^T (y_hat - y)，dL/db = (2/n) mean(y_hat - y)
    """

    def __init__(self, config: GDConfig = None):
        self.config = config or GDConfig()
        self.w = None
        self.b = 0.0
        self.loss_history = []

    @property
    def n_steps(self):                       # @property：派生量
        return len(self.loss_history)

    def fit(self, X: np.ndarray, y: np.ndarray) -> "LinearRegressionGD":
        lr, n_iters, tol = (self.config.lr,
                            self.config.n_iters,
                            self.config.tol)
        n, d = X.shape
        self.w = np.zeros(d)                 # 返回视图/拷贝的语义见第 4 章
        self.b = 0.0
        for _ in range(n_iters):
            y_hat = X @ self.w + self.b
            err = y_hat - y
            loss = float(np.mean(err ** 2))
            self.loss_history.append(loss)
            grad_w = (2 / n) * (X.T @ err)   # 向量化梯度：第 4 章展开
            grad_b = (2 / n) * np.sum(err)
            self.w -= lr * grad_w            # 原地更新（第 1 章可变对象语义）
            self.b -= lr * grad_b
            if loss < tol:
                break
        return self                          # 链式调用惯例

    def predict(self, X: np.ndarray) -> np.ndarray:
        return X @ self.w + self.b

    def __repr__(self):                      # 魔术方法：调试友好
        return (f"LinearRegressionGD(w={np.round(self.w, 4)}, "
                f"b={self.b:.4f}, steps={self.n_steps})")

# ---- 运行验证：真实规律 y = 3*x1 - 2*x2 + 1，加微小噪声 ----
rng = np.random.default_rng(seed=42)         # 随机数生成器：第 4 章展开
X = rng.normal(size=(200, 2))
y = 3.0 * X[:, 0] - 2.0 * X[:, 1] + 1.0 + 0.01 * rng.normal(size=200)

cfg = GDConfig(lr=0.2, n_iters=2000)
model = LinearRegressionGD(cfg).fit(X, y)
print(model)    # 预期输出: LinearRegressionGD(w=[3.0004 -2.0008], b=1.0027, steps=2000)（数值略有浮动）
print(f"参数估计 w={model.w.round(3)}, b={model.b:.3f}")
# 预期输出: 参数估计 w=[3.    -2.001], b=1.003（接近真值 [3, -2] 与 1）
```

设计要点逐条回指本章：`GDConfig` 用 dataclass（2.5 节）且可通过 `asdict(cfg)` 导出实验记录；`n_steps` 用 property（2.2.4 节）；`fit` 返回 `self` 支持 `LinearRegressionGD(cfg).fit(X, y)` 链式写法（sklearn 同款惯例）；`fit` 内部原地更新 `self.w` 依赖第 1 章引用语义；梯度推导衔接《高等数学》的偏导数与《最优化方法》的梯度下降。

### 案例 3：装饰器实战——实验计时与参数扫描

```python
import functools
import time

def timeit(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        out = func(*args, **kwargs)
        return out, time.perf_counter() - t0
    return wrapper

@timeit
def ridge_fit(X, y, lam):
    """闭式解岭回归：w = (X^T X + lam*I)^{-1} X^T y（衔接《最优化方法》）。"""
    n, d = X.shape
    A = X.T @ X + lam * np.eye(d)
    return np.linalg.solve(A, X.T @ y)

w, dt = ridge_fit(X, y, lam=1e-3)
print(w.round(3))   # 预期输出: [ 2.999 -1.999]（量级，与真值一致）
print(f"耗时 < 1ms: {dt < 1e-3}")   # 预期输出: True（numpy 闭式解远快于 GD）
```

## 2.7 常见误区与陷阱

1. **在装饰器里忘记 `functools.wraps`**。被装饰函数的名字/文档被 `wrapper` 覆盖，`pytest` 报错信息与 `help()` 全部失真。
2. **把 `@dec` 误解为"每次调用时装饰"**。装饰发生在 `def` 执行时，仅一次。装饰器内打印的语句在 import 时就会执行。
3. **类属性当实例默认值**。`class D: items = []` 让所有实例共享同一个列表（第 1 章可变默认参数的类版本）。正确做法是在 `__init__` 里 `self.items = []`。
4. **继承只为复用代码**。为了调用父类方法而继承不相关父类，会破坏多态约定（里氏替换原则）。"有一个"用组合，"是一个"才用继承。
5. **dataclass 的可变字段直接写 `= []`**。`dataclass` 会直接抛 `ValueError: mutable default`——这是它比普通默认参数更安全的地方，但要用 `field(default_factory=list)` 而不是绕过它（如写成元组）。

## 2.8 关键公式速查

| # | 定律/公式 | 适用条件与备注 |
|---|---|---|
| 1 | `@dec` ≡ `f = dec(f)`，定义时执行一次 | 所有装饰器；带参数则为三层：`@dec(args)` ≡ `f = dec(args)(f)` |
| 2 | 闭包捕获变量本身（晚绑定） | 循环生成 lambda 时需用默认参数固定值 |
| 3 | 线性回归 MSE 梯度：$\nabla_w L = \frac{2}{n} X^\top (Xw + b\mathbf{1} - y)$，$\frac{\partial L}{\partial b} = \frac{2}{n}\sum_i (\hat y_i - y_i)$ | 样本特征按行堆叠的约定；特征需先中心化否则 GD 收敛慢 |
| 4 | `len`/`[]`/`()`/`+` 分别调用 `__len__`/`__getitem__`/`__call__`/`__add__` | 让自定义对象接入 Python 语法的关键协议 |
| 5 | dataclass 自动生成 `__init__`/`__repr__`/`__eq__` | 可变默认字段必须用 `field(default_factory=...)` |
| 6 | 组合优于继承 | 复用实现用组合，复用接口（多态约定）才继承 |

## 2.11 进阶方向

1. **描述符协议（descriptor protocol）**：`@property` 的底层机制是 `__get__`/`__set__` 描述符；PyTorch 的 `Parameter` 注册、Django ORM 字段都基于它。前置：本章 2.2.4 与 Python 数据模型文档。
2. **抽象基类与 `Protocol`**：`abc.ABC` 与 `typing.Protocol` 把鸭子类型显式化、静态可查；是设计 DataLoader 自定义数据集接口的正统方式。
3. **元类（metaclass）**：`type` 的类型；PyTorch/SQLAlchemy 用它实现自动注册（如把模型类自动登记到注册表）。读源码前建议先掌握描述符。
4. **函数式数据管道**：`itertools` + 生成器（第 3 章）+ `pipe` 库构成声明式数据流水线，是 Unix 管道哲学在 Python 的体现。
