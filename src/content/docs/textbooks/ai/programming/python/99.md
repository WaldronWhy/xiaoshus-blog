# 99 综合项目：把八周所学拧成一股绳

> **本章定位**：本章是《Python 程序设计》的收官实践。三个项目分别对应课程的三大能力轴：语言机制与向量化心智模型（项目 1）、数据整理与工程化分析（项目 2）、内存安全与迭代协议（项目 3）。要求至少完成一个完整项目；所有项目按第 7 章的工程标准验收（测试、README、Git 历史）。前置要求：第 1–7 章全部完成；本项目的产出将被《机器学习》《数据工程》直接复用。

## 99.0 项目总则

- **验收硬标准**（三个项目通用，源自第 7 章）：
  1. `pytest` 全绿，核心逻辑有测试覆盖（每个公开函数至少 1 条正常 + 1 条边界用例）；
  2. `ruff check` 与 `black --check` 零告警；
  3. Git 历史干净：≥ 8 个有意义的提交，提交信息写明"为什么"；

## 99.1 项目一：从零实现一个 mini-NDArray 库

### 99.1.1 项目目标

自己写一个支持多维数组、广播与基本运算的库，实现后你将真正拥有 NumPy 的"轴"心智模型——第 4 章不再是记忆，而是你亲手构建过的机制。这也是《深度学习》第一天就能读懂 `torch.Tensor` 的路径。

### 99.1.2 功能规格（必须实现）

```
MiniArray
├── 构造与元数据
│   ├── MiniArray(data, dtype=None)      # 嵌套 list / 标量
│   ├── shape: tuple[int, ...]           # 形状
│   ├── dtype: type                      # 仅支持 float64 / int64
│   ├── ndim, size
│   └── __repr__                          # 与 NumPy 风格对齐
├── 创建函数
│   ├── zeros(shape) / ones(shape) / arange(n)
│   └── from_list(nested)                # 递归校验矩形性（每层长度一致）
├── 索引与切片
│   ├── __getitem__: 整数下标（降维）、切片、元组
│   └── 返回视图（共享内存）！提供 .copy()
├── 运算（全广播规则）
│   ├── __add__/__sub__/__mul__/__truediv__（元素级）
│   ├── matmul2d(a, b)                   # 仅 2 维矩阵乘
│   ├── sum(axis=None) / mean(axis=None) / max(axis=None)
│   └── 所有运算支持 MiniArray 与标量混合
└── 变换
    ├── reshape(new_shape)                # 元素总数不变时
    └── T（2 维转置）
```

### 99.1.3 任务分解（建议顺序）

1. **表示层**（3 h）：内部用一维 `list`（扁平存储）+ shape + **strides** 表示。先实现 `from_list`、`zeros`、`__repr__`。关键决定：扁平索引 $flat = \sum_i idx_i \cdot stride_i$——这正是第 4 章 4.1.1 的 stride 公式落地。
2. **索引与视图**（3 h）：实现 `__getitem__`：整数下标降一维，切片产生**新元数据 + 共享底层 list 的视图**（`MiniArray` 视图类共享 flat 存储对象）。用第 1 章 `id()` 验证共享。
3. **逐元素运算 + 广播**（4 h）：实现 `_broadcast_shapes(s1, s2)` 纯函数（从末维向前对齐，规则照抄第 4 章 4.2.1），再实现"索引映射函数"：把广播后的多维下标映射回原数组扁平下标（该维长度为 1 时下标取 0）。这是整个项目智力最密集的一步。
4. **归约与 matmul**（2 h）：`sum(axis=k)` 按"消维"规则（第 4 章 4.4.1）实现；`matmul2d` 允许用三重循环（性能不是本项目目标）。
5. **测试与文档**（3 h）：见 99.1.4。

### 99.1.4 验收标准（可逐条勾选）

- [ ] `MiniArray([[1, 2], [3, 4]]) + MiniArray([10, 20])` 得 `[[11, 22], [13, 24]]`（行广播）；
- [ ] `MiniArray([[1, 2], [3, 4]]) + MiniArray([[10], [20]])` 得 `[[11, 12], [23, 24]]`（列广播）；
- [ ] `(3, 4) + (4,)` OK；`(3, 4) + (3,)` 抛 `ValueError`（信息包含两个形状）；
- [ ] 视图语义：`v = a[:, 1:3]; v[0, 0] = 99` 后 `a` 同步变化；`v.copy()` 后互不影响；
- [ ] `sum(axis=0)`/`axis=1`/`axis=None` 三种形状与数值正确（对照 NumPy 断言）；
- [ ] `pytest` ≥ 25 条测试，含参数化的广播用例与异常用例；
- [ ] 与 NumPy 的对照测试：随机生成 100 组 `(shape1, shape2)`，广播结果 `allclose`；
- [ ] README 含广播规则的文字说明与一个"错误形状示例"。

**提示**：
- 广播映射函数可以只对每维支持"长度 1 -> 取 0"，不必做负步长/复杂 stride；切片步长默认 1 可接受，但要写进文档。
- 用生成器（第 3 章）递归遍历嵌套下标，`repr` 就不会失控。
- 对照测试用 `numpy as oracle`：`assert ma_to_numpy(ma + mb) == (npa + npb)`，这是"从零实现"项目最有效的安全网。

### 99.1.5 挑战扩展（选做）

- 支持负索引与步长切片；
- `sum` 支持 `keepdims=True`，并用它实现一行 `softmax`（对照第 4 章案例 2）；
- 把内部存储从 `list` 换成 `array.array('d')`，对比 10⁷ 元素逐元素加法的耗时（预期：比 list 快 3–10x，但仍比 NumPy 慢 50–200x——解释原因写在 README）。

## 99.3 项目三：用生成器实现内存安全的超大数据集读取器

### 99.3.1 项目目标

构建一个能流式读取远超内存规模的数据集、并输出训练用批次的读取器——即第 3 章 DataLoader 雏形的工业级完成版。它将直接服务于《深度学习》第一周的 DataLoader 实现与《数据工程》的批处理管道。

### 99.3.2 功能规格

```
StreamingJsonlReader
├── 数据源
│   ├── iter_lines(path)          # 惰性逐行（with 管理文件句柄）
│   └── iter_records(path)        # json 解析 + 容错
├── 管道算子（全部生成器）
│   ├── filter_records(records, predicate)
│   ├── map_records(records, fn)
│   ├── shuffle_buffer(records, buffer_size)   # 有界随机洗牌
│   └── batched(records, batch_size, drop_last=False)
└── 统计与容错
    ├── 统计类 BadRecordCounter    # 解析失败/缺字段/类型错误分类计数
    └── iter_batches() 汇总接口    # 生成 (batch, stats_snapshot)
```

`shuffle_buffer` 是本项目的核心算法：维护大小为 $B$ 的缓冲池，来一条记录就以随机概率替换池中一条并弹出该条——用 $O(B)$ 内存获得"局部随机"的洗牌（PyTorch iterable-style 数据集的同款思想）。

### 99.3.3 任务分解

1. **数据生成器**（1 h）：脚本生成 100 万行合成 JSONL（约 100 MB，模拟 10 GB 场景），按比例注入三类脏数据。
2. **基础管道**（2 h）：`iter_lines`/`iter_records`/`batched`（第 3 章已有雏形，补 `drop_last` 与类型注解）。
3. **容错统计**（2 h）：自定义异常层次（第 3 章 3.4.2），坏记录计数不中断管道；`stats_snapshot` 用 dataclass。
4. **洗牌缓冲**（3 h）：实现并**实证**其随机性质量（见验收）。
5. **内存与吞吐评估**（2 h）：`tracemalloc` 测峰值内存；对比不同 `buffer_size`/`batch_size` 的吞吐。
6. **测试与报告**（2 h）。

### 99.3.4 验收标准

- [ ] 峰值内存（`tracemalloc.get_traced_memory()` 报告）随数据总量 $N$ 不变，只随 `buffer_size` 与 `batch_size` 变化；在 README 给出 $N = 10^5/10^6$ 两档的实测数值表；
- [ ] 100 万行中 1% 脏数据被正确分类计数（三类各自数量与注入比例误差 < 0.1 个百分点），且好记录无一丢失；
- [ ] `shuffle_buffer(B=1000)` 输出批内"时间上相近的记录同批概率"显著低于顺序读取（给出一个可计算的相关性指标，如同批记录 id 差的均值：顺序版应接近 1，洗牌版应接近 $B$ 量级）；
- [ ] 全管道类型注解完整，`mypy` 通过；
- [ ] `pytest` ≥ 15 条：管道各算子的单元测试（用小文件 + 固定种子）+ 端到端测试；
- [ ] README：内存-吞吐随 `buffer_size` 变化的折线图（第 6 章出图标准）。

**提示**：
- `shuffle_buffer` 用 `random.Random(seed)`（注入种子，可复现）；缓冲不满时只入不出，保证开头也有随机性。
- 生成器无法支持 `len()`——统计总行数要么在流尾输出，要么单独跑一遍（这正是《数据工程》"两遍扫描 vs 单遍估计"话题的入口）。
- 与第 3 章案例 2 的 `DataLoader` 对比：把 `shuffle=True` 分支替换为 `shuffle_buffer`，说明 map-style 与 streaming-style 的取舍（写进 README 的"设计决策"一节）。

### 99.3.5 挑战扩展（选做）

- 多文件目录源：`iter_files(pattern)` 用 `glob` + `yield from` 串联，记录每个文件的坏记录占比；

## 99.8 课后思考与练习（项目思考题）
