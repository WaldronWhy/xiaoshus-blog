### 1.12 题 1【概念辨析｜对应正文 1.1.2、1.6 陷阱 1/3、1.7 定律 1】

> 题目：`a = b = [1, 2]` 之后执行 `a += [3]` 与 `a = a + [3]`，两种情况下 `b` 各是什么？

**答案**

- `a += [3]`：`b == [1, 2, 3]`。
- `a = a + [3]`：`b == [1, 2]`。

实跑验证：

```python
a = b = [1, 2]; a += [3]
print(b)   # [1, 2, 3]

a = b = [1, 2]; a = a + [3]
print(b)   # [1, 2]
```

**机制解释**：`a += [3]` 对 list 调用的是 `__iadd__`（就地扩展，等价于 `a.extend([3])`），`a` 仍绑定**原对象**，而 `b` 与 `a` 本指向同一对象，所以 `b` 一起变。`a = a + [3]` 先用 `__add__` 计算**新列表**，再把名字 `a` 重新绑定过去；`b` 仍指向旧列表，不受影响。

**常见错误答案为什么错**：

- 认为"`+=` 就是 `a = a + [3]` 的缩写，所以两种情况 `b` 都不变"——对 list 不成立，`+=` 走的是原地修改路径。
- 认为"两种情况 `b` 都会变"——忽略了 `a = a + [3]` 是**重新绑定**，只有引用同一对象才会被波及。
- 对**不可变**类型（int/str/tuple）`+=` 也会退化为重新绑定（没有 `__iadd__`），行为与 `a = a + [3]` 相同。所以结论依赖**操作数类型**，不能死记。

**复盘指引**：1.1.2（名字与绑定）、1.7 定律 1/3；做错请重做 1.8 案例 1。

### 1.12 题 2【概念辨析｜对应正文 1.4.1】

> 题目：为什么说"Python 是动态类型，但对象有类型"？与 `x = 42; x = "s"` 的合法性如何对应？

**答案要点**：

1. 类型属于**对象**而不属于**名字**。每个对象创建时就带着确定的 `type`（`type(42)` 是 `int`，且不可更改）；名字 `x` 只是一个可随时改绑的标签，本身没有类型。
2. 因此 `x = 42; x = "s"` 完全合法：第一步把 `x` 绑定到一个 int 对象，第二步把 `x` 重新绑定到一个 str 对象——没有任何"类型转换"发生，只是换了标签。`type(x)` 前后分别是 `int` 与 `str`。
3. "动态"的含义是**类型检查发生在运行时**：`x + 1` 是否合法，取决于 `x` 当前绑定的对象是否支持 `+`，解释器运行到这一行才知道。

**常见错误答案为什么错**：

- "Python 变量没有类型所以类型随便变"——错在把"名字无类型"说成"类型可变"；**对象的类型永远不可变**，变的是绑定关系。
- "Python 会自动把 42 转换成字符串"——没有转换发生；若写 `x + "s"` 会直接 `TypeError`（int 与 str 不支持 `+`），这正是"对象有类型"的体现。

**复盘指引**：1.4.1；延伸：1.4.2 鸭子类型"结构兼容 ≠ 语义兼容"。

### 1.12 题 3【计算推导｜对应正文 1.3.1、1.8 案例 1】

> 题目：对 1.8 节案例 1 的代码，若把 `c = copy.copy(a)` 改为 `c = a[:]`，输出是否变化？

**答案**：**不变**。`a[:]` 与 `copy.copy(a)` 都是**浅拷贝**：创建新的外层列表，但内层元素仍是同一批对象的引用。正文 1.3.1 明确列出 `a[:]`、`list(a)`、`a.copy()`、`copy.copy(a)` 四种写法等价（只复制一层）。

案例 1 数据下推导：`a[0] = 100` 只改外层槽位（`b` 同对象跟随，`c` 外层独立不跟随）；`a[1].append(4)` 原地改内层列表（`b`、`c` 的内层都指向它，都跟随；`d` 完全独立）。故输出仍为：

```text
[100, [2, 3, 4]]   # b
[1, [2, 3, 4]]     # c
[1, [2, 3]]        # d
```

**常见错误**：认为切片"复制了整个列表"——只复制了**槽位**（引用），内层可变对象仍共享。

**复盘指引**：1.3.1 浅/深拷贝定义；1.7 定律 4。

### 1.12 题 4【编程实现｜对应正文 1.6 陷阱 3】（已实跑验证）

> 题目：编写 `safe_default(key, value, store=None)` 实现"向字典累加"，杜绝可变默认参数陷阱。

**设计决策**：我选择"`store=None` 哨兵 + 每次调用独立新建"的语义：连续两次 `safe_default('a', 1)` 返回**各自独立的** `{'a': [1]}`（而不是 `{'a': [1, 1]}`）。理由：可变默认参数的本质危害是**调用者不可见的跨调用共享**；让"无 store 时新建"成为默认语义，函数就是无隐藏状态的纯函数，最容易测试（第 7 章判据）。需要累加时，调用者**显式传入**同一个 `store`——共享变成显式契约。

```python
def safe_default(key, value, store=None):
    """向 store[key] 累加 value；store 为 None 时新建。

    设计选择：None 哨兵使每次不带 store 的调用互相独立，
    避免 def f(key, value, store={}) 的"默认字典跨调用存活"陷阱。
    """
    if store is None:
        store = {}                        # 每次新建，绝不共享
    store.setdefault(key, []).append(value)
    return store

r1 = safe_default('a', 1)
r2 = safe_default('a', 1)
print(r1)          # 预期输出: {'a': [1]}   —— 独立
print(r2)          # 预期输出: {'a': [1]}   —— 不是 {'a': [1, 1]}

shared = {}       # 显式传入才共享
safe_default('a', 1, shared)
safe_default('a', 1, shared)
print(shared)      # 预期输出: {'a': [1, 1]}
```

**陷阱机制回顾**：`def f(store={})` 的默认字典在 `def` 执行时创建**一次**，之后所有调用共享同一对象——默认参数在定义时求值，而不是每次调用时（1.7 定律 6）。若你的题目预期是 `{'a': [1, 1]}`，那么正确写法就是上面"显式传入 shared"的用法。

**复盘指引**：1.6 陷阱 3；2.5 节 dataclass 的 `field(default_factory=list)` 是同一问题的类版本。

### 1.12 题 5【编程实现｜对应正文 1.3.1、1.8 案例 1】（已实跑验证）

> 题目：不用 `copy` 模块，手写 `my_deepcopy(obj)`，支持 list/dict/标量的嵌套组合，用案例 1 数据验证。

```python
def my_deepcopy(obj):
    """递归深拷贝：支持 list / dict / 标量（int/float/str/bool/None）的嵌套组合。"""
    if isinstance(obj, list):
        return [my_deepcopy(x) for x in obj]          # 每个元素递归复制
    if isinstance(obj, dict):
        return {k: my_deepcopy(v) for k, v in obj.items()}
    return obj        # 标量不可变，共享无副作用，直接返回即可

# ---- 用 1.8 节案例 1 的数据验证 ----
a = [1, [2, 3]]
b = a                  # 同一对象
c = a[:]               # 浅拷贝（内层共享）
d = my_deepcopy(a)     # 深拷贝

a[0] = 100
a[1].append(4)
print(b)   # 预期输出: [100, [2, 3, 4]]
print(c)   # 预期输出: [1, [2, 3, 4]]   —— 内层被波及
print(d)   # 预期输出: [1, [2, 3]]      —— 完全独立

# 与 copy.deepcopy 的语义一致性（嵌套 dict 情形）
import copy
x = {"k": [1, {"inner": [2, 3]}], "n": 5}
assert my_deepcopy(x) == copy.deepcopy(x)
y = my_deepcopy(x)
y["k"][1]["inner"].append(99)
print(x["k"][1]["inner"])   # 预期输出: [2, 3] —— 原对象未变
```

要点：递归的**基准情形**是标量（不可变，返回自身即可）；递归情形是容器（逐元素复制后再组新容器）。标准库 `copy.deepcopy` 还要处理循环引用（用 memo 字典记录已复制对象）——本题不支持循环引用即可，能说出这一点就是加分项。

**复盘指引**：1.3.1；进阶：`copy.deepcopy` 源码中的 memo 机制。

### 1.12 题 6【编程实现｜对应正文 1.5.1–1.5.2】（已实跑验证）

> 题目：写 LEGB 演示：全局、闭包、局部三层各有一个 `x`，输出顺序为 local、enclosing、global。

```python
x = "global"                      # G 层

def outer():
    x = "enclosing"               # E 层
    def show_local():
        x = "local"               # L 层（函数内赋值 -> 自动成为局部名）
        print("L:", x)            # L 优先命中: local
    def show_enclosing():
        # 注意：这里不能对 x 赋值，否则 x 变成 show_enclosing 的局部名而报
        # UnboundLocalError；只读时按 L->E->G->B 查找，L 无、E 命中
        print("E:", x)            # enclosing
    def show_global():
        # 想读 G 层必须显式越过 L/E：用 globals() 字典（或把读操作放到模块级）
        print("G:", globals()["x"])   # global
    show_local(); show_enclosing(); show_global()

outer()
```

运行输出（已验证）：

```text
L: local
E: enclosing
G: global
```

**关键机制**：① 函数体内**赋值**使名字自动成为局部名（除非 `global`/`nonlocal`）；② 名字查找"找到即停"——在 `outer` 内再嵌套的函数里直接 `print(x)` 会先命中 E 层的 `enclosing` 而**不是** `global`（我们实测过这一行为，这正是"找到即停"的证据）；③ 想跨过 E 层读全局，用 `globals()`；想写全局，必须声明 `global x`。

**复盘指引**：1.5.1–1.5.2、1.7 定律 5；做错请重读 1.5.2 的 `increment_buggy` 例子。

### 1.12 题 7【调试实战｜对应正文 1.2.3、1.8 案例 2、4.1.2】

> 题目：为什么 NumPy 数组 `b = a[0:2]` 修改 `b` 会影响 `a`，而列表 `b = a[:2]` 不会？

**答案**：切片返回的**对象类型与语义**不同。

1. **ndarray 切片返回视图（view）**：视图是新的 ndarray 对象，但它的数据**不是自己的**——只携带一组元数据（shape/strides/偏移）指向**原数组的同一块内存缓冲区**。`b[0] = 99` 写的是那块共享内存，`a` 立即可见。排查工具：`b.base is a` 为 `True`（视图的 `.base` 指向宿主）。NumPy 这样设计是为了零拷贝：大数据集上切片/转置若都复制内存，代价不可接受。
2. **list 切片返回新列表**：列表切片的语义规定为**复制槽位**（浅拷贝）：新列表有自己独立的槽位，存的是元素引用。`b[0] = 99` 把 `b` 的 0 号槽位改绑到新对象，`a` 的 0 号槽位不受影响。（注意：若元素本身是可变对象，如 `a = [[1],[2]]; b = a[:2]; b[0].append(9)`——内层仍共享，这与浅拷贝语义一致。）

实跑验证：

```python
import numpy as np
n = np.arange(5); s = n[:2]; s[0] = 99
print(n)                    # [99  1  2  3  4] —— 被波及
print(s.base is n)          # True —— 视图

l = [1, 2, 3]; t = l[:2]; t[0] = 99
print(l)                    # [1, 2, 3] —— 不受影响
```

**复盘指引**：1.2.3、1.8 案例 2；第 4 章 4.1.2 的"视图 vs 拷贝"表格是本题的完整版。

### 1.12 题 8【开放思考｜对应正文 1.3.2】

> 题目：结合引用计数解释为什么训练循环中"保留整个 batch 列表"会导致内存持续增长。

**解题路线与要点**：

1. `loss.backward()` 的自动微分需要**计算图记住前向传播的所有中间张量**（激活、`X @ W` 的结果等），因为反向传播要用它们算梯度。这些中间张量被计算图引用，只要图存活（`loss` 及其 grad_fn 链存活），引用计数就不为 0，无法回收。
2. 正常训练循环里，每个 `loss` 在下一轮被覆盖，引用归零 → 计算图和中间张量随即释放，内存稳定。但如果你 `batch_history.append(batch)`（保留整个 batch 的输入/输出张量列表），这些张量的引用计数**永远 ≥ 1**，与之相连的计算图（若有梯度引用）也连带无法释放。
3. 结果：内存占用随 step 数线性增长——不是"泄漏"（对象都是可达的、能查到谁引用它），而是**不该保留的引用被保留了**。这正是引用计数模型的可诊断性优点：`torch.cuda.memory_allocated()` 与引用链分析能定位到具体变量。

**正确做法**：日志只记标量——`float(loss.detach())` 或 `loss.item()`（脱离张量，留一个 Python float）；需要画图就存 `loss.detach().cpu().numpy()`，绝不存张量本身或整个 batch。

**复盘指引**：1.3.2 引用计数；延伸到《深度学习》的 `detach()`/`clone()` 选择。

### 1.12 题 9【挑战题｜对应正文 1.3.2】（已实跑验证）

> 题目：用 `sys.getrefcount` 测出引用计数在哪些代码行变化，并解释返回值为何总比预期多 1。

**参考实现与实测结果**（Python 3.13）：

```python
import sys

lst = [1, 2, 3]
print(sys.getrefcount(lst))       # 实测: 2
ref = lst; tmp = lst              # 又绑定两个名字
print(sys.getrefcount(lst))       # 实测: 4   —— 每个新引用 +1

before = sys.getrefcount(lst); p = lst
print(sys.getrefcount(lst) - before)    # 实测: 1（p = lst 使计数 +1）

before = sys.getrefcount(lst); q = [lst]
print(sys.getrefcount(lst) - before)    # 实测: 1（容器 q 持有一个引用）
```

**为什么多 1**：`sys.getrefcount(x)` 把 `x` 作为**参数传入**的那一刻，函数调用的实参本身临时持有一个引用——文档原话是 "the count returned is generally one higher than you might expect, because you can't know how many references there are to the argument object"。所以返回值 = 真实引用数 + 1（这次调用引入的临时引用）。上面的实测印证：刚创建、只有全局名 `lst` 一个引用时，`getrefcount` 返回 2 = 1（名字）+ 1（传参临时引用）。

**实验方法要点**：把"引用计数变化"定位到行的方法是**差分法**——在目标行前后各调一次 `getrefcount`，差值即该行引入的引用数。注意：`getrefcount` 本身会带来瞬时波动、CPython 小整数/常量缓存会干扰计数，实验对象应选普通容器对象。

**复盘指引**：1.3.2；进阶：1.11 的弱引用（weakref）。

### 1.12 题 10【挑战题｜对应正文 1.3.2、1.11 进阶】（核心行为已实跑验证）

> 题目：用 `weakref.WeakValueDictionary` 实现"实例缓存"：同参数共享实例，无外部引用时自动回收。

**参考实现**（已验证：同参数共享、释放后缓存自动清空）：

```python
import weakref, gc

class Point:
    # 注意坑：如果用 __slots__，必须显式包含 "__weakref__"，
    # 否则该类实例不能被弱引用（weakref 会抛 TypeError）——实测踩过。
    def __init__(self, x, y):
        self.x, self.y = x, y

_cache = weakref.WeakValueDictionary()   # 值是弱引用：不阻止对象被回收

def get_point(x, y):
    key = (x, y)
    p = _cache.get(key)                  # 弱引用查缓存：对象可能已被回收
    if p is None:                        # 不在缓存 -> 新建并登记
        p = Point(x, y)
        _cache[key] = p
    return p                             # 在缓存 -> 复用同一实例

a, b = get_point(1, 2), get_point(1, 2)
print(a is b)              # True —— 同参数共享同一对象
del a, b
gc.collect(); gc.collect()
print(len(_cache))         # 0 —— 无外部引用后自动回收

# 内存回落验证：持引用时缓存有内容，释放后回落
keep = [get_point(i, i) for i in range(1_000_000)]   # 100 万个实例
print(len(_cache) > 0)     # True —— 被外部列表引用着，活着
del keep
gc.collect(); gc.collect()
print(len(_cache))         # 0 —— 内存占用随之回落
```

**机制要点**：`WeakValueDictionary` 的值是**弱引用**——不增加目标对象的引用计数。对象的生命周期由**外部强引用**决定；外部引用全部消失 → 引用计数归零 → 对象回收 → 弱引用失效并自动从字典移除（`len` 变 0）。这正是"缓存不应延长对象生命周期"的标准实现；PyTorch 的 hook 管理、Django 的信号注册都用同一机制。

**复盘指引**：1.3.2、1.11 进阶 3；对照题 9：强引用计数 vs 弱引用的区别。

### 2.12 题 1【概念辨析｜对应正文 2.2.3、1.2.1】

> 题目：为什么 `@functools.cache` 装饰的函数不能接收 ndarray 参数？给出两种工程对策。

**答案要点**：`functools.cache` 以**参数元组为字典键**存结果（`_store[args]`）。ndarray **不可哈希**（`hash(np.array([1]))` 抛 `TypeError: unhashable type: 'ndarray'`）——NumPy 故意如此，因为 ndarray 是**可变**对象且相等语义是逐元素的，做哈希键既危险（可变）又昂贵（逐元素哈希）。所以第一次以 ndarray 为参调用缓存函数就报错。

另一个隐患（即使绕过哈希）：ndarray 可变，若调用者修改了"作为键"的数组，缓存的键就与实际值脱节。

**两种工程对策**：

1. **把数组转成可哈希的不可变摘要**：`arr.tobytes()`（或 `hashlib.sha256(arr.tobytes())`）作为键的一部分，同时记下 `shape`/`dtype` 以免不同形状碰撞；前提是数组不会被原地修改。
2. **结构上隔离**：只缓存标量/字符串参数，把 ndarray 处理放在缓存层之外；或自己写基于 `np.array_equal` 语义的缓存类（如 2.2.3 的手写 `my_cache` 改造，逐键比较），代价是 O(k) 查找。

**复盘指引**：2.2.3（缓存以参数为键、参数必须可哈希）；1.2.1（可变对象的哈希问题）。

### 2.12 题 2【概念辨析｜对应正文 2.2.4】（已实跑验证）

> 题目：`t.fahrenheit = 212` 与 `t.__fahrenheit = 212` 的区别？`@property` 如何实现"只读"？

**答案**（实测）：

- `t.fahrenheit = 212` 命中 **property 的 setter**（`@fahrenheit.setter`），执行 `self.celsius = (212-32)*5/9`，之后 `t.celsius == 100.0`、`t.fahrenheit == 212.0`。
- `t.__fahrenheit = 212` 是**普通的实例属性赋值**：在 `t.__dict__` 里新建一个名为 `__fahrenheit` 的属性，与 property 毫无关系——赋值后 `t.fahrenheit` 仍是按 `celsius` 算出的 `77.0`（实测确认），只是对象多了一个无关属性。
- 区别的本质：`fahrenheit` 是**类上的数据描述符**（property），实例属性查找时描述符优先级高于实例 `__dict__`，赋值被路由到 setter；`__fahrenheit` 没有对应的类级描述符，就是普通赋值。

**只读实现**：只定义 `@property` 的 getter、**不定义 setter**。此时对 `t.fahrenheit = x` 赋值会抛 `AttributeError: property 'fahrenheit' of 'Temperature' object has no setter`。

**常见错误**：以为"`__` 双下划线就是私有、赋值会被拦截"——Python 没有 private，`__` 只在**类体内**触发名称改写（name mangling → `_Temperature__x`），类体外的 `t.__fahrenheit = 212` 不做改写、不做拦截。

**复盘指引**：2.2.4；进阶：2.11 的描述符协议（`__get__`/`__set__` 优先级）。

### 2.12 题 3【计算推导｜对应正文 2.6 案例 2、2.8 公式 3】

> 题目：推导梯度 $\nabla_w L = \frac{2}{n} X^\top (Xw + b\mathbf{1} - y)$。

**推导**（每步的代数依据）：

设 $\hat y = Xw + b\mathbf{1}$，残差 $e = \hat y - y$，损失 $L = \frac{1}{n} e^\top e$（MSE 的向量写法，依据：$\|e\|^2 = \sum_i e_i^2 = e^\top e$）。

1. 链式法则：$\dfrac{\partial L}{\partial w} = \dfrac{1}{n}\cdot \dfrac{\partial (e^\top e)}{\partial e}\cdot \dfrac{\partial e}{\partial w}$。
2. 由标量对向量的微分规则 $\dfrac{\partial (e^\top e)}{\partial e} = 2e^\top$（依据：$d(a^\top a) = 2a^\top da$，二次型的微分）。
3. 由 $\hat y = Xw + b\mathbf{1}$ 对 $w$ 求微分得 $d\hat y = X\,dw$，故 $\dfrac{\partial e}{\partial w}$ 的雅可比为 $X^\top$（依据：矩阵乘法的微分 $d(Xw) = X\,dw$；$b\mathbf{1}$ 与 $y$ 与 $w$ 无关，微分为零）。
4. 合并：$\nabla_w L = \dfrac{1}{n}\cdot 2e^\top X \to$ 写成列向量形式即 $\dfrac{2}{n} X^\top e = \dfrac{2}{n} X^\top (Xw + b\mathbf{1} - y)$。

偏置同理：$\dfrac{\partial L}{\partial b} = \dfrac{2}{n}\mathbf{1}^\top e = \dfrac{2}{n}\sum_i e_i$（$d\hat y = \mathbf{1}\,db$）。

**校验方法**：数值梯度对照——对每个参数加 $\varepsilon$ 算 $(L(w+\varepsilon)-L(w-\varepsilon))/(2\varepsilon)$，与解析梯度误差应 $< 10^{-6}$。这是第 7 章"测试即规格"思想在数学上的应用。

**复盘指引**：2.6 案例 2 注释中的梯度公式；2.8 公式 3；《线性代数》矩阵微积分。

### 2.12 题 4【编程实现｜对应正文 2.2.1–2.2.3】（已实跑验证）

> 题目：写带参数的装饰器 `call_count(n)`：每被调用 $n$ 次打印累计统计；用 `fib(20)` 验证总调用次数。

```python
import functools

def call_count(n):
    """三层结构：参数 -> 装饰器 -> 包装函数（对应正文 2.2.2）。"""
    def decorator(func):
        state = {"count": 0}                    # 闭包变量存计数（故意的共享）
        @functools.wraps(func)                  # 保住 __name__/__doc__
        def wrapper(*args, **kwargs):
            state["count"] += 1
            if state["count"] % n == 0:
                print(f"[call_count] {func.__name__} 已被调用 {state['count']} 次")
            return func(*args, **kwargs)
        wrapper.get_count = state.get           # 暴露读数接口
        return wrapper
    return decorator

@call_count(5000)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(20))                       # 6765
print(fib.get_count("count"))        # 21891
```

**校验值**：`fib(20) = 6765`，**总调用次数 21891 次**（实测，远大于 20）。

**为什么这么多**：无缓存时 fib 是递归树，调用数满足 $C(n) = C(n-1) + C(n-2) + 1$，$C(0)=C(1)=1$，解得 $C(n) = 2\,\mathrm{fib}(n+1) - 1$。$n=20$：$2 \times \mathrm{fib}(21) - 1 = 2 \times 10946 - 1 = 21891$，与实测完全吻合。这正是 `functools.cache`（2.2.3）把指数降为线性的意义。

**复盘指引**：2.2.1–2.2.3；1.5.3（闭包捕获名字的共享是**故意的**此处）。

### 2.12 题 5【编程实现｜对应正文 2.4】（已实跑验证）

> 题目：给 `Vector` 补 `__sub__`、`__mul__`（标量乘）、`__eq__`，验证 `(Vector(1,2)*3 - Vector(1,1)) == Vector(2,5)`。

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)
    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)
    def __mul__(self, scalar):
        if not isinstance(scalar, (int, float)):
            return NotImplemented          # 不支持的类型交还解释器（尝试 other.__rmul__）
        return Vector(self.x * scalar, self.y * scalar)
    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented          # 与非 Vector 比较返回 False 而不是报错
        return (self.x, self.y) == (other.x, other.y)
    def __hash__(self):                    # 定义 __eq__ 会抹掉默认 __hash__，补回去
        return hash((self.x, self.y))

v = Vector(1, 2) * 3 - Vector(1, 1)
print(v)                                   # 预期输出: Vector(2, 5)
print((Vector(1, 2) * 3 - Vector(1, 1)) == Vector(2, 5))   # 预期输出: True
```

要点：① `__eq__` 里对"类型不对"返回 `NotImplemented` 而不是 `False`，让解释器有机会尝试对方一侧；② 定义了 `__eq__` 后默认 `__hash__` 失效（对象不可再放入 set/dict 键），语义上值相等的对象应可哈希时需补 `__hash__`。

**复盘指引**：2.4 魔术方法表、2.4 节代码。

### 2.12 题 6【编程实现｜对应正文 2.5、3.1.3】（已实跑验证）

> 题目：用 dataclass 定义 `Sample`，实现 `__getitem__`/`__len__` 使 `list[Sample]` 可迭代、可求长。

```python
from dataclasses import dataclass

@dataclass
class Sample:
    features: list[float]
    label: int

class Dataset:
    """最小数据集：只实现 __len__ 与 __getitem__（PyTorch Dataset 协议雏形）。"""
    def __init__(self, samples):
        self.samples = samples
    def __len__(self):
        return len(self.samples)
    def __getitem__(self, idx):
        return self.samples[idx]

dataset = Dataset([
    Sample([0.1, 0.2], 0),
    Sample([0.3, 0.4], 1),
    Sample([0.5, 0.6], 0),
])
print(len(dataset))       # 预期输出: 3
for s in dataset:         # __getitem__ 未配 __iter__ 时解释器退回下标协议（3.1.3）
    print(s)
# 预期输出:
# Sample(features=[0.1, 0.2], label=0)
# Sample(features=[0.3, 0.4], label=1)
# Sample(features=[0.5, 0.6], label=0)
print(dataset[1])         # 预期输出: Sample(features=[0.3, 0.4], label=1)
```

### 2.12 题 7【编程实现｜对应正文 2.3.2、2.6 案例 2】（已实跑验证）

> 题目：扩展出 `RidgeGD`（损失加 $\lambda\|w\|^2$，梯度加 $2\lambda w$，偏置不参与正则），验证 $\|w\|$ 更小。

```python
import numpy as np
from dataclasses import dataclass

@dataclass
class GDConfig:
    lr: float = 0.1
    n_iters: int = 500
    tol: float = 1e-8
    lam: float = 0.0            # 新增：正则强度

class LinearRegressionGD:       # 与 2.6 案例 2 相同（略，可复制正文代码）
    ...

class RidgeGD(LinearRegressionGD):
    """L2 正则岭回归。损失: MSE + lam*||w||^2；偏置不参与正则。"""
    def fit(self, X, y):
        lr, n_iters, tol, lam = (self.config.lr, self.config.n_iters,
                                 self.config.tol, self.config.lam)
        n, d = X.shape
        self.w = np.zeros(d); self.b = 0.0
        for _ in range(n_iters):
            y_hat = X @ self.w + self.b
            err = y_hat - y
            loss = float(np.mean(err ** 2) + lam * (self.w @ self.w))
            self.loss_history.append(loss)
            grad_w = (2 / n) * (X.T @ err) + 2 * lam * self.w   # 正则梯度
            grad_b = (2 / n) * np.sum(err)                      # b 不加 2*lam*b！
            self.w -= lr * grad_w
            self.b -= lr * grad_b
            if loss < tol:
                break
        return self
```

**实测结果**（seed=42，200×2 数据，`lr=0.2, n_iters=2000`）：

```text
lin:   w=[ 2.9998 -2.0005], b=0.9993, |w|_2 = 3.6057
ridge: w=[ 1.4477 -0.8644], b=1.0704, |w|_2 = 1.6861   (lam=1.0)
```

`‖w‖_ridge (1.686) < ‖w‖_lin (3.606)`，验证成立；且 `b` 仍在 1 附近——因为偏置**不参与正则**，不需要被压小（截距本身没有"过大"的方差问题，正则它反而引入偏差）。

**常见错误**：把正则梯度写成 `2 * lam * np.append(self.w, self.b)` 连偏置一起罚——违背岭回归定义；或忘记损失与梯度两处都要加正则项。

**复盘指引**：2.3.2 继承、2.6 案例 2；《机器学习》正则化一节。

### 2.12 题 8【开放思考｜对应正文 2.3.3】

> 题目：为什么 sklearn `Pipeline` 用组合、estimator 用继承统一接口？反过来会怎样？

**答案要点**：

1. **"是一个 vs 有一个"**：`Pipeline` **拥有**若干步骤（步骤是它的部件，可增删替换、可任意排序），这是"有一个"（组合）；每个 estimator **是一个** estimator（满足 `fit/transform/predict` 的统一约定），这是"是一个"（继承/接口）。继承的价值只在**多态**：trainer/Pipeline 只认接口，任何子类都能被无差别调用（里氏替换）。
2. 组合让 Pipeline 与具体步骤**解耦**：新增一种变换器不需要改 Pipeline；运行时可以自由替换步骤（网格搜索超参正是这么做的）。
3. **反过来（Pipeline 用继承）**：Pipeline 必须继承某个具体 estimator 才有 `fit` 等方法，于是"标准化管道"和"分类管道"要继承不同类、方法语义混乱（Pipeline 的 `fit` 到底是谁的？）；步骤被**写死**在类结构里，无法运行时替换；继承链爆炸且违反里氏替换——为了复用代码而继承不相关父类，正是正文 2.7 陷阱 4。

**复盘指引**：2.3.3 组合优于继承、2.7 陷阱 4；GoF 原则。

### 2.12 题 9【挑战题｜对应正文 2.4】

> 题目：阅读 PyTorch `Module.__call__` 与 `register_forward_hook`，写 300 字说明。

**解题路线**：① 打开 `torch/nn/modules/module.py`，定位 `__call__ : Callable[..., Any] = _wrapped_call_impl`（类属性赋值——把实例调用语法接到内部方法上，正是 2.4 节 `__call__` 协议）；② 读 `_call_impl`：先检查 `_forward_pre_hooks` / `_forward_hooks`（均为 `OrderedDict`，按插入序执行），无钩子时走快速路径直接返回 `forward_call(*args)`——钩子字典为空时的 `if not ...` 检查是为零开销；③ 注意 `Module.__setattr__`：给 `self.weight = nn.Parameter(...)` 赋值时被拦截、登记进 `self._parameters` 字典（这是**属性赋值协议 + 字典注册表**机制，与描述符同族）；④ 总结：`model(x)` 之所以优于 `model.forward(x)`，是因为 `__call__` 里织入了钩子分发，保证训练/调试插桩不侵入用户代码。

**关键步骤骨架**（300 字说明可按此展开）：

```text
1. class Module: __call__ = _wrapped_call_impl   # 语法糖 = 协议
2. _wrapped_call_impl -> _call_impl:
     for hook in self._forward_pre_hooks.values(): ...   # 前置钩子
     result = forward_call(*args)
     for hook in self._forward_hooks.values(): ...       # 后置钩子
3. 钩子容器: OrderedDict[int, Callable]，register_forward_hook 用
   全局计数器分配 key，remove_xxx_hook 按 key 删除 —— 字典当注册表
4. 参数注册: __setattr__ 拦截 Parameter 赋值 -> _parameters 字典
5. 结论: __call__(协议) + 字典注册表 + 属性赋值拦截 = 钩子机制的全部
```

### 2.12 题 10【挑战题｜对应正文 2.11 描述符协议】（已实跑验证）

> 题目：用描述符协议实现 `TypedField(int)`：赋非 int 值抛 `TypeError`。

**实现骨架（完整可运行）**：

```python
class TypedField:
    """类型检查版属性：代替 @property + 手写校验。"""
    def __init__(self, typ):
        self.typ = typ
    def __set_name__(self, owner, name):     # 定义时被类自动调用，拿到属性名
        self.name = "_" + name               # 数据实际存到带下划线的槽
    def __get__(self, obj, objtype=None):
        if obj is None:                      # 通过类访问时返回描述符自身
            return self
        return getattr(obj, self.name)
    def __set__(self, obj, value):
        if not isinstance(value, self.typ):
            raise TypeError(f"{self.name[1:]} 需要 {self.typ.__name__}, "
                            f"得到 {type(value).__name__}")
        setattr(obj, self.name, value)

class TrainConfig:
    epochs = TypedField(int)
    lr = TypedField(float)
    def __init__(self, epochs, lr):
        self.epochs, self.lr = epochs, lr    # 赋值也走 __set__，同样受检

cfg = TrainConfig(10, 0.1)
print(cfg.epochs)          # 预期输出: 10
try:
    cfg.epochs = "10"
except TypeError as e:
    print(e)               # 预期输出: epochs 需要 int, 得到 str
```

**关键步骤**：① `__set_name__` 在类创建时把属性名传给描述符实例，免去手工传名；② 数据存到 `_epochs` 避免无限递归（若 `__set__` 里再 `setattr(obj, self.name)` 指向同一描述符会自我调用）；③ 类访问（`TrainConfig.epochs`）时 `obj is None`，返回描述符本身。`@property` 的底层正是这套协议，`TypedField` 是它的最小复刻。

**复盘指引**：2.2.4、2.11 进阶 1；Python 数据模型文档的 descriptor howto。

### 3.12 题 1【概念辨析｜对应正文 3.1.1】（已实跑验证）

> 题目：list、生成器、文件对象分别是 iterable 还是 iterator？能否重复遍历？

**答案**（实测确认）：

| 对象 | iterable？ | iterator？ | 能否重复遍历 | 原因 |
|---|---|---|---|---|
| `list` | 是（有 `__iter__`） | 否（无 `__next__`） | **能** | `iter(lst)` 每次返回**新的**迭代器，各自从头开始 |
| 生成器 | 是 | **是**（`isinstance(g, Iterator)` 为 True） | **不能** | 生成器自身就是迭代器，状态机走完即耗尽 |
| 文件对象 | 是 | **是**（`hasattr(f,'__next__')` 为 True，`iter(f) is f`） | **不能** | 读到文件尾后 `__next__` 抛 `StopIteration`；要重读需 `f.seek(0)` 或重新 `open` |

判定口诀：`iter(obj) is obj` 成立 → 是 iterator（一次性）；不成立 → 只是 iterable（可反复 `iter()` 取新迭代器）。list 能重复 `for` 的关键就是**两种角色分离**；生成器把两个角色合并以换取代码简洁，代价是不可重复。

**常见错误**：把"能被 for 遍历"等同于"是 iterator"；或对生成器/`model.parameters()` 这类返回值 `for` 两次（第二次为空，正文 3.8 陷阱 1）。

**复盘指引**：3.1.1、3.6 公式 1/2；3.8 陷阱 1。

### 3.12 题 2【概念辨析｜对应正文 3.2.1、3.3.1】

> 题目：`JsonlDataset.__iter__` 里用 `with` 打开文件安全吗？生成器暂停在 `yield` 时文件会不会被提前关闭？

**答案要点**：**安全，但关闭时点要理解清楚**。

1. `with` 的语义是"进入时 `__enter__`，**离开 with 块时**（无论正常/异常）调用 `__exit__`"。对生成器而言，函数体在 `yield` 处**暂停但未离开 with 块**——控制权交给调用者时 `with` 块仍未结束，文件保持打开。暂停多久都行，`__exit__` 不会提前执行。
2. 文件真正关闭发生在生成器**终结**时：自然耗尽（抛 `StopIteration`）、被 `close()`、或生成器对象被垃圾回收（解释器向 `yield` 处注入 `GeneratorExit`，`with` 的 `__exit__` 随之执行）。
3. 风险点（回答"会不会提前关闭"的反面）：**迟迟不关闭**才是真风险——调用者拿走生成器却只消费一半又不丢弃，文件一直开着（句柄泄漏）。工程对策：把生成器的生命周期放进调用方的 `with contextlib.closing(...)`，或确保消费完毕/及时 `del`。

**复盘指引**：3.2.1（暂停-恢复）、3.3.1（with 展开式）；3.8 陷阱 4。

### 3.12 题 3【计算推导｜对应正文 3.2.2】（已实测校验）

> 题目：推导列表推导内存 Θ(N)、生成器表达式内存 Θ(1)，并估算 N=10⁹ 个 float64 的占用。

**推导**：

1. 列表推导**立即**物化全部元素：容器本身是"指针数组"，N 个指针 × 8 字节 = 8N 字节，再加每个 float64 元素的对象开销（CPython 的 float 对象头约 16–24 字节，仅小整数有缓存），总计 Θ(N)。
2. 生成器表达式不物化元素：只保存**一帧执行状态**（程序计数器、局部变量、一个待产出的值），大小与 N 无关，Θ(1)。
3. 实测（N=10⁷）：`sys.getsizeof([0.0]*10**7)` = 80 000 056 字节（≈80 MB，即 8N + 常数开销），`sys.getsizeof((0.0 for _ in range(10**7)))` = 192 字节。正文 3.2.2 用 `i*i` 推导时为 ≈89 MB，同一量级。

**N=10⁹ 估算**：指针数组 8×10⁹ = **8 GB**（再加元素对象开销，用 NumPy 才是紧凑的 8 字节/元素，纯 Python 对象更多）；生成器恒为**数百字节**。校验值"约 8 GB vs 数百字节"成立。

**复盘指引**：3.2.2、3.6 公式 3。

### 3.12 题 4【编程实现｜对应正文 3.2.1–3.2.2】（已实跑验证）

> 题目：用生成器实现无限素数流 `primes()`（增量筛），验证前 5 个素数。

```python
from itertools import islice

def primes():
    """埃拉托斯特尼筛的增量版：无限素数流，内存只存当前必需的合数表。"""
    composites = {}          # {即将被筛掉的合数: [产生它的素数们]}
    q = 2
    while True:
        if q not in composites:          # q 没被任何素数标记 -> 是素数
            yield q
            composites[q * q] = [q]      # 从 q^2 开始标记（更小的倍数已被标记）
        else:
            for p in composites.pop(q):  # q 是合数：把每个相关素数的下一个倍数推进
                composites.setdefault(p + q, []).append(p)
        q += 1

print(list(islice(primes(), 5)))    # 预期输出: [2, 3, 5, 7, 11]（实测一致）
assert list(islice(primes(), 5)) == [2, 3, 5, 7, 11]
print(list(islice(primes(), 20))[-3:])   # 预期输出: [61, 67, 71]（第 18-20 个）
```

要点：① 无限流只能用生成器——不能先"建好列表"再筛；② 状态（合数表）用闭包/函数局部变量维护，等价于 3.1.2 类实现里的 `self.n`，但代码短得多；③ `islice` 是"取无限流前 k 个"的标准零件。惰性 + 增量是"埃氏筛生成器化"的两个关键词。

**复盘指引**：3.2.1–3.2.2；《数据结构与算法》筛法与惰性序列。

> 题目：给 `batched` 加 `drop_last` 参数（对齐 DataLoader），100 条、batch_size=8 验证批数。

```python
def batched(records, batch_size, drop_last=False):
    """把迭代器切成批；drop_last=True 时丢弃不满批的尾部。"""
    batch = []
    for r in records:
        batch.append(r)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch and not drop_last:      # 尾批：默认保留，drop_last 丢弃
        yield batch

recs = iter(range(100))
full = list(batched(iter(range(100)), 8))                  # 13 批
trimmed = list(batched(iter(range(100)), 8, drop_last=True))  # 12 批
print(len(full), len(full[-1]))      # 预期输出: 13 4
print(len(trimmed), len(trimmed[-1]))  # 预期输出: 12 8
```

校验值 13 批 vs 12 批成立（100 = 12×8 + 4）。**语义说明**：PyTorch 的 `drop_last=True` 丢弃的是训练末尾不足一批的样本（避免最后一批统计量偏差），不是"少一批数据"的错误。

### 3.12 题 6【编程实现｜对应正文 3.3.2】（已实跑验证）

> 题目：实现 `temporary_seed(seed)` 上下文管理器，进入保存并设置随机状态、退出恢复。

```python
import random
from contextlib import contextmanager

@contextmanager
def temporary_seed(seed):
    """with 块内使用固定种子的随机流，块外序列不受影响。

    yield 之前 = __enter__（保存+设置），yield 之后 = __exit__（恢复）。
    """
    state = random.getstate()      # 保存完整 Mersenne Twister 状态
    random.seed(seed)
    try:
        yield
    finally:                       # finally 保证异常时也恢复
        random.setstate(state)

# ---- 验证 ----
random.seed(0)
outside_before = random.random()
with temporary_seed(42):
    inside1 = random.random()
random.seed(0)                      # 重建相同的外层序列再测一次
outside_before2 = random.random()
with temporary_seed(42):
    inside2 = random.random()
print(inside1 == inside2)           # 预期输出: True（块内可复现）
print(outside_before == outside_before2)  # 预期输出: True（块外不受影响）
```

要点：① `getstate/setstate` 保存的是**完整伪随机状态**，不是"当前值"；② `try/finally` 保证块内抛异常也会恢复（3.3.1 的异常安全保证）；③ 该工具的直接用途：给单个测试固定随机输入而不污染全局种子——第 7 章"随机性可注入"的落地。

### 3.12 题 9【挑战题｜对应正文 3.7 案例 2】

> 题目：重写 `DataLoader`，用定长记录/偏移索引使 `shuffle=True` 随机访问 O(1)。

**解题路线**：

1. **两遍扫描建索引**：第一遍顺序读文件，把每行**字节偏移**（`f.tell()`）记进列表 `self._offsets`（或 json.dumps 后 pad 到定长 L，第 i 条在 `i*L` 处）。索引只存整数，10 万条约 1 MB。
2. **O(1) 随机访问**：`__getitem__(idx)` 中 `f.seek(self._offsets[idx]); f.readline()`——seek 是文件系统级操作，成本与文件大小无关。
3. **洗牌只洗索引**：`__iter__` 里对索引 `random.shuffle`（或 `rng.permutation`），再按打乱后的索引逐个 `self[idx]`——这正是正文 3.7 案例 2 "诚实说明"中给出的正确补全。
4. **对比实验**：每 epoch 全量读取。朴素版（每条从文件头顺序扫到目标行）成本 O(N²) 行；索引版 O(N)。10 万条记录下预期快一个数量级以上。

**实现骨架**：

```python
import json

class IndexedJsonlDataset:
    def __init__(self, path):
        self.path = path
        self._offsets = []               # 每行起始字节偏移
        with open(path, "rb") as f:
            while True:
                off = f.tell()
                line = f.readline()
                if not line:
                    break
                self._offsets.append(off)

    def __len__(self):
        return len(self._offsets)

    def __getitem__(self, idx):          # O(1) 随机访问：seek 直接跳转
        with open(self.path, "rb") as f:
            f.seek(self._offsets[idx])
            return json.loads(f.readline())
```

工程提示：真实 DataLoader 会把文件句柄常开（避免每条 open/close）+ 用 `rng = np.random.default_rng(seed)` 注入种子（第 7 章"随机性可注入"判据）。

**复盘指引**：3.7 案例 2；《深度学习》map-style vs iterable-style Dataset。

### 3.12 题 10【挑战题｜对应正文 3.1、3.2】

> 题目：读 PyTorch `dataloader.py` 的 `_BaseDataLoaderIter` / `_SingleProcessDataLoaderIter`，写 400 字。

**解题路线与要点**（按此四点展开成文）：

1. **`__iter__` 返回新迭代器**：`DataLoader.__iter__` 每次被调用都新建 `_SingleProcessDataLoaderIter(self)`——对应 3.1.1 "iterable 每次产出新迭代器"。这就是"每个 epoch 从头迭代"的机制：epoch 循环里 `for batch in loader` 每轮拿到**全新**迭代器对象，互不共享耗尽状态。
2. **shuffle 每次 seed 不同**：`RandomSampler` 持有生成器（`torch.Generator`），其 `__iter__` 里 `yield from torch.randperm(n, generator=g)`——每次迭代现算一个新的随机排列，无需手工重置种子；`generator=None` 时用全局默认流，因此每个 epoch 顺序都不同。
3. **单进程迭代器 = 生成器管道**：`_SingleProcessDataLoaderIter._next_data` 依次做 `_next_index()`（sampler 出下标）→ `_dataset_fetcher.fetch`（取样本/组批）→ `_pin_memory`，与正文案例 2 的最小 DataLoader 逐级对应。
4. **`persistent_workers=True` 解决什么**：多进程模式下每个新 epoch 重建 worker 进程（fork/spawn 开销 + 预热阶段 worker 队列为空，GPU 等数据）；持久化 worker 让进程池跨 epoch 存活，`_MultiProcessingDataLoaderIter._reset` 只重置索引队列不杀进程，消除每 epoch 启动毛刺。代价：worker 的内存/随机状态持续占用。

**复盘指引**：3.1.1、3.2.3–3.2.4；《深度学习》DataLoader 一章。

### 4.13 题 1【概念辨析｜对应正文 4.1.2、4.2.4 错误 1】（已实跑验证）

> 题目：`a[:, 0]` 与 `a[:, 0:1]` 的 shape？谁是视图？为什么深度学习代码更常用后者？

**答案**（对 `a` 形状 `(3, 4)` 实测）：`a[:, 0]` 形状 `(3,)`（一维）；`a[:, 0:1]` 形状 `(3, 1)`（二维）。**两者都是视图**（实测 `x.base is not None` 均为 True）——基本切片永远返回视图，切片范围只决定取哪些列，降不降维取决于是否用整数下标。

**为什么深度学习更常用 `[:, 0:1]`**：

1. 保持二维让**广播意图显式**：`(n, 1)` 与 `(n, m)` 相加是"每列加同一个数"，语义清楚；而 `(n,)` 参与运算时按"右对齐"规则被广播到**行**上（正文 4.2.4 错误 1/2），n×n 时静默加错方向。
2. 与 PyTorch 的 `unsqueeze(1)`/`keepdim=True` 习惯一致：维度数不变，后续 `torch.cat`/`concatenate`、与原数组逐元素运算都对齐。

**复盘指引**：4.1.2 视图表、4.2.4 广播三类错误。

### 4.13 题 2【概念辨析｜对应正文 4.2.3】（已实跑验证）

> 题目：`np.vstack([a, b])` 与 `a[None] + b[None]` 各得什么形状？哪个复制了内存？

**答案**（设 a、b 均为 `(3, 4)`，实测）：

- `np.vstack([a, b])` → `(6, 4)`：**真复制**。vstack 分配新内存，把两个数组的元素逐个搬进去。
- `a[None] + b[None]` → `(1, 3, 4)`：`a[None]`、`b[None]` 只是**升维视图**（stride 技巧，零拷贝）；相加结果是新数组，但过程中**不复制输入**。

若题意是"两两组合所有行对"，应写 `a[:, None, :] + b[None, :, :]` → `(3, 3, 4)`（正文 4.2.2 末尾的例子）。本质区别：广播是**逻辑复制**（拉伸维 stride=0，无内存开销），`vstack`/`tile`/`repeat` 是**物理复制**——大数据集上后者能吃光内存（4.2.4 错误 3）。

**复盘指引**：4.2.2–4.2.3。

### 4.13 题 3【计算推导｜对应正文 4.4.1】（已实跑验证）

### 4.13 题 5【编程实现｜对应正文 4.2、4.5】（已实跑验证）

> 题目：成对欧氏距离矩阵：双层循环版 vs 广播版，测加速比并验证 allclose。

```python
import numpy as np
import time

def bench(fn, *args, repeat=3):
    best = float("inf")
    for _ in range(repeat):
        t0 = time.perf_counter()
        fn(*args)
        best = min(best, time.perf_counter() - t0)
    return best

def dist_loops(X):
    n = X.shape[0]
    D = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            D[i, j] = np.sqrt(((X[i] - X[j]) ** 2).sum())
    return D

def dist_vec(X):
    diff = X[:, None, :] - X[None, :, :]       # (n, n, d) 广播：所有行对做差
    return np.sqrt((diff ** 2).sum(axis=-1))

rng = np.random.default_rng(0)
X = rng.normal(size=(200, 8))
print(np.allclose(dist_loops(X), dist_vec(X)))  # 预期输出: True

t_loop = bench(dist_loops, X, repeat=1)
t_vec = bench(dist_vec, X)
print(f"循环 {t_loop*1000:.1f} ms, 广播 {t_vec*1000:.2f} ms, 加速 {t_loop/t_vec:.0f}x")
# 实测: 循环 77.9 ms, 广播 1.75 ms, 加速 45x（校验值"10x 以上"轻松达标）
```

机制：循环版每对 (i, j) 都要走一遍解释器分发；广播版把 O(n²d) 次减法/平方下放到 C 一次完成，中间量是 `(200, 200, 8)` 视图展开的临时数组。

**复盘指引**：4.5.1–4.5.2；4.13 题 10 给出省内存的 einsum 版。

### 4.13 题 6【编程实现｜对应正文 4.8 案例 3】（已实跑验证）

```python
    scores[r.random(n) < 0.05] = np.nan          # 5% 缺失
    return hours, scores

def slope_drop(h, s):                # 策略一：删行（正文案例 3 做法）
    valid = ~np.isnan(s)
    h2, s2 = h[valid], s[valid]
    x, y = h2 - h2.mean(), s2 - s2.mean()
    return float((x @ y) / (x @ x))

def slope_median_fill(h, s):         # 策略二：全表中位数填充
    s2 = np.where(np.isnan(s), np.nanmedian(s), s)
    x, y = h - h.mean(), s2 - s2.mean()
    return float((x @ y) / (x @ x))

hours, scores = make_case()
print(f"删行: {slope_drop(hours, scores):.3f}")          # 实测: 1.530
print(f"中位数填充: {slope_median_fill(hours, scores):.3f}")  # 实测: 1.442
```

**解释**：真实关系是"分数随时长增加"（斜率 1.5）。中位数填充把缺失样本的分数替换成一个**与时长的常数**（约 70 分的中位值），这些样本贡献 `(hours - mean) * const` 项——时长高于均值的缺失样本把斜率**往低拉**（填充值低于它们"应有的"分数），反之亦然，净效果是斜率向 0 方向稀释，实测 1.442 < 1.530。删行只在缺失**完全随机**（MCAR）时无偏。若缺失与时长相关，两种策略都会偏，且方向可分析。

**复盘指引**：4.8 案例 3；第 5 章 5.2.2 的统计代价表是同一主题。

### 4.13 题 7【编程实现｜对应正文 4.8 案例 2、3.5.1】（已实跑验证）

> 题目：实现按列标准化 `standardize`，处理全零列，验证不产生 NaN。

```python
import numpy as np

def standardize(X: np.ndarray) -> np.ndarray:
    """按列标准化。X: (n, d)；返回 (n, d)。

    约定（写进 docstring 即可被 mypy/协作者检查）：
    输入输出均为 float 二维 ndarray；常数列标准化后置 0。
    """
    mean = X.mean(axis=0)
    std = X.std(axis=0)
    std = np.where(std == 0, 1.0, std)    # 常数列：std=0，置 1 防除零
    return (X - mean) / std

X = np.array([[1.0, 5.0, 2.0],
              [2.0, 5.0, 4.0],
              [3.0, 5.0, 6.0]])          # 第 1 列是常数列
out = standardize(X)
print(np.isnan(out).any())               # 预期输出: False（实测）
print(out[:, 1])                         # 预期输出: [0. 0. 0.]（常数列 -> 0）
print(out.mean(axis=0).round(12))        # 预期输出: [0. 0. 0.]（各列均值 0）
```

不处理的后果：`(x - mean) / 0` 得到 inf/NaN，NaN 沿后续运算扩散——正文 4.9 陷阱 5 的"静默截断/污染"家族。第 7 章 `test_preprocess_constant_column_no_nan` 就是把本题固化成测试。

**复盘指引**：4.9 陷阱 5、3.5.1（正文同款函数）。

### 4.13 题 8【开放思考｜对应正文 4.5】

> 题目：为什么 `a.T @ a`（1000×1000）比 `sum(a[:, i] * a[:, j] for ...)` 快三个数量级？三个角度各一句话。

**答案**：

1. **内存布局**：`a.T @ a` 走 BLAS 的 dgemm，按分块顺序访问连续内存、缓存命中率高；生成器写法里 `a[:, i]` 每次都是跨 stride 的花式切片，要新分配一个 1000 元素临时数组，n² 次分配压垮缓存。
2. **解释器开销**：生成器写法有 n² = 10⁶ 次切片调用、乘法、加法、Python 层求和，每步都付"解释字节码 + 对象装箱"的税；`@` 只付一次调用税。
3. **BLAS 并行**：dgemm 内部用 SIMD 向量指令 + 多线程并行（OpenBLAS/MKL 按核数扩展），把 O(n³) 运算摊到所有核心；纯 Python 循环单核单指令。

**复盘指引**：4.5.1；4.11 Oliphant 关于 stride 与内存布局的深读。

### 4.13 题 9【挑战题｜对应正文 4.8 案例 2】（已实跑验证）

> 题目：实现数值稳定的 log-softmax，并在 z~1000 量级下对比直接版。

```python
import numpy as np

def log_softmax(z, axis=-1):
    """log_softmax(z) = z - max(z) - log(sum(exp(z - max(z))))。"""
    z = z - z.max(axis=axis, keepdims=True)      # 平移不变性，防 exp 上溢
    return z - np.log(np.exp(z).sum(axis=axis, keepdims=True))

z = np.array([1000.0, 1001.0, 999.0])

direct = np.log(np.exp(z) / np.exp(z).sum())     # 直接版
print(direct)        # 实测输出: [nan nan nan]（exp(1001) 上溢 -> inf/inf = nan）

stable = log_softmax(z)
print(stable)
# 实测输出: [-1.40760596 -0.40760596 -2.40760596]
print(np.exp(stable).round(4))   # 实测输出: [0.2447 0.6652 0.09  ] —— 与 softmax 一致
```

**关键步骤**：① 数学依据是平移不变性 `softmax(z) = softmax(z - c)`，取 `c = max(z)` 后最大分量的指数恰为 1，绝不溢出；② 直接版 `exp(1001)` 超出 float64 上限（约 1.8e308）得 inf，`inf/inf = NaN`；③ 稳定版还顺带是 log-sum-exp 技巧——交叉熵损失 `-log_softmax(z)[y]` 直接用它，避免"先 softmax 再 log"的下溢（小概率 log 后变 -inf）。

**复盘指引**：4.8 案例 2；交叉熵衔接《深度学习》分类一节。

### 4.13 题 10【挑战题｜对应正文 4.12 einsum】（已实跑验证）

> 题目：用 `np.einsum` 重写距离矩阵，n=1000 下三版对比耗时并解释。

```python
import numpy as np
import time

def bench(fn, *args, repeat=3):
    best = float("inf")
    for _ in range(repeat):
        t0 = time.perf_counter(); fn(*args)
        best = min(best, time.perf_counter() - t0)
    return best

def dist_vec(X):                       # 题 5 的广播版
    diff = X[:, None, :] - X[None, :, :]
    return np.sqrt((diff ** 2).sum(axis=-1))

def dist_einsum(X):
    """||xi-xj||^2 = ||xi||^2 + ||xj||^2 - 2 xi·xj 的向量化。"""
    sq = np.einsum("ij,ij->i", X, X)              # ||x_i||^2, (n,)
    cross = np.einsum("ik,jk->ij", X, X)          # X @ X.T, (n, n)
    d2 = sq[:, None] + sq[None, :] - 2 * cross
    np.maximum(d2, 0, out=d2)                     # 防浮点误差出现微小负数
    return np.sqrt(d2)

rng = np.random.default_rng(0)
X = rng.normal(size=(1000, 16))
assert np.allclose(dist_vec(X), dist_einsum(X))   # 实测 True

t_v = bench(dist_vec, X, repeat=2)
t_e = bench(dist_einsum, X, repeat=2)
print(f"广播 {t_v*1000:.1f} ms, einsum {t_e*1000:.1f} ms")
# 实测: 广播 66.9 ms, einsum 11.5 ms
```

**解释差异**：广播版要物化 `(1000, 1000, 16)` 的中间差值数组（约 128 MB×2 个临时量），内存带宽是瓶颈；einsum 版利用平方展开式把问题归约为一次矩阵乘 `X @ X.T`（n²d 次乘加，走 BLAS、内存 O(n²)），额外只做 O(n²) 的加减，故快数倍。循环版（题 5）在 n=1000 下慢两个数量级，三者排序：循环 ≫ 广播 > einsum。

**复盘指引**：4.12 进阶 1（einsum 与注意力打分 $S = QK^\top/\sqrt d$ 同款技巧）。

### 5.13 题 1【概念辨析｜对应正文 5.1.2】（已实跑验证）

> 题目：`df.loc[2]` 与 `df.iloc[2]` 何时不同？构造 Index 为 `["a","b","c"]` 的例子。

**答案**：`loc` 按**标签**、`iloc` 按**整数位置**。默认 RangeIndex（0,1,2,...）且有序时两者碰巧一致；一旦**标签不是 0..n-1 的整数或顺序被打乱**，语义就分道扬镳。

```python
import pandas as pd
df = pd.DataFrame({"v": [10, 20, 30]}, index=["a", "b", "c"])
print(df.loc["a":"b"]["v"].tolist())   # ['标签切片含端点'] -> 实测 [10, 20]
print(df.iloc[0:2]["v"].tolist())      # ['位置切片不含端点'] -> 实测 [10, 20]
df.loc[2]        # KeyError！没有标签为 2 的行（本题例子中）
df.iloc[2]       # 第三行（标签 'c', v=30）
```

两种典型分歧：① 标签是**非 0 起始整数**（如 index=[2,1,0]）——`loc[2]` 是标签 2 那行，`iloc[2]` 是第三行（标签 0）；② 标签是字符串（本题）——`loc[2]` 直接 KeyError，`iloc[2]` 正常取第三行。另注意 `loc` 切片**含端点**、`iloc` **不含端点**（实测确认）。

**复盘指引**：5.1.2 表格；5.8 案例 1 的 merge 后索引。

### 5.13 题 2【概念辨析｜对应正文 5.3.1–5.3.2】

> 题目：为什么 `transform("mean")` 结果行数与 `df` 相同而 `agg("mean")` 不同？各适合什么任务？

**答案**：`agg` 把每组**缩成一个数**（每组一行），输出行数 = 组数；`transform` 把组级结果**广播回组内每一行**，输出行数 = 原表行数（实测：3 行 2 组的数据，transform 3 行、agg 2 行）。

- `agg` 适合**汇总报告**：每个模型的平均准确率/标准差/次数（5.8 案例 2 的 summary 表、误差棒数据）。
- `transform` 适合**组内特征工程**：组内 z 分数 `(x - x.mean())/x.std()`、组均值填充、组内占比——结果要**对齐回原表**与原特征并列时，必须保长（正文 5.3.2 的 `acc_z` 列）。

**常见错误**：想做组均值填充却用了 `agg`，结果长度对不上原表而报错；或把 `transform` 的结果当汇总表打印。

**复盘指引**：5.3.1–5.3.2、5.7 公式 4。

### 5.13 题 3【计算推导｜对应正文 5.8 案例 2】

> 题目：手算 ViT 的 `acc_std`（样本标准差，除以 n−1）。

**答案**：ViT 两个种子准确率为 93.4、93.9。

1. 均值 $\bar x = (93.4 + 93.9)/2 = 93.65$；
2. 离差平方和 $(93.4-93.65)^2 + (93.9-93.65)^2 = 0.0625 + 0.0625 = 0.125$；
3. 除以 $n-1 = 1$：方差 = 0.125；
4. 开方：$s = \sqrt{0.125} \approx 0.3536 \approx$ **0.354**，与校验值一致（代码 `clean.groupby("model").agg(acc_std=("accuracy","std"))` 默认 ddof=1，就是样本标准差）。

注意用**除以 n**（ddof=0）会得 0.25——pandas 默认与数理统计的"样本标准差"一致，NumPy 的 `.std()` 默认 ddof=0，两者混用是实验报告常见错误（第 6 章误差棒话题）。

**复盘指引**：5.8 案例 2；《概率统计》样本方差的无偏估计（n−1）。

### 5.13 题 4【编程实现｜对应正文 5.2、5.3.2】（已实跑验证）

> 题目：含缺失两列（题目意为：两列含缺失的 DataFrame，下以一列分组一列数值实现），三种策略处理并对比均值方差。

```python
import numpy as np
import pandas as pd

df = pd.DataFrame({
    "group": ["A"] * 5 + ["B"] * 5,
    "x": [1.0, 2.0, np.nan, 4.0, 5.0, 10.0, np.nan, 12.0, 14.0, 16.0],
})

s_drop  = df.x.dropna()                                        # 策略一：删行
s_mean  = df.x.fillna(df.x.mean())                             # 策略二：全局均值填充
s_gmed  = df.x.fillna(df.groupby("group").x.transform("median"))  # 策略三：组内中位数

report = pd.DataFrame({
    "删除行":     [s_drop.mean(),  s_drop.var(ddof=1)],
    "均值填充":   [s_mean.mean(),  s_mean.var(ddof=1)],
    "组内中位数": [s_gmed.mean(),  s_gmed.var(ddof=1)],
}, index=["mean", "var"]).round(3)
print(report)
```

实测输出：

```text
      删除行   均值填充  组内中位数
mean  8.000   8.000   8.000
var  32.857  25.556  31.111
```

**解读**（这就是题目要的"对比表"背后的结论）：三种策略**均值相同**（8.0），因为缺失位置填充的正是均值类常数；**方差不同**——均值填充把缺失点钉在中心，方差被人为压低（32.86 → 25.56），会低估不确定性；组内中位数保留了组间结构，方差损失较小（31.11）；删行保留真实散布但丢样本、若缺失非随机则引入偏差。均值/中位数在此例数值上相同，一般数据下方差排序为：删行 ≥ 组内中位数 > 全局均值填充。

**复盘指引**：5.2.2 三种策略的统计代价；5.9 陷阱 5（填充统计必须在训练集上做）。

### 5.13 题 7【编程实现｜对应正文 5.4.1】（已实跑验证）

> 题目：订单表（customer_id 可重复）merge 客户表（唯一），用 `validate="many_to_one"` 防呆，并故意造重复键观察报错。

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
orders = pd.DataFrame({"order_id": range(1000),
                       "customer_id": rng.integers(0, 500, size=1000)})
customers = pd.DataFrame({"customer_id": range(500),
                          "city": [f"c{i}" for i in range(500)]})

m = orders.merge(customers, on="customer_id", validate="many_to_one")
print(len(m))    # 实测: 1000（左表行数不变，正常）

# 故意把客户表造出重复键
customers_dup = pd.concat([customers, customers.iloc[[7]]], ignore_index=True)
try:
    orders.merge(customers_dup, on="customer_id", validate="many_to_one")
except pd.errors.MergeError as e:
    print("MergeError:", e)
# 实测输出:
# MergeError: Merge keys are not unique in right dataset; not a many-to-one merge
```

**机制**：`validate="many_to_one"` 在 merge **执行前**断言右表键唯一；不防呆时，右表某键重复 k 次会让左表命中该键的每行复制 k 份——行数静默膨胀，且很难事后发现（5.9 陷阱 4）。报错信息直接指出"右表键不唯一"。左表键重复、右表唯一是合法的 many-to-one，所以 1000 行订单正常通过。

**复盘指引**：5.4.1、5.7 公式 5。

### 5.13 题 8【开放思考｜对应正文 5.2.2、5.9 陷阱 5】

> 题目：为什么目标列缺失通常删行、特征列缺失可填充？

**答案要点**：

1. **监督信号角度**：训练的目标是从 (X, y) 对中学习映射；y 缺失的样本**无法提供任何监督信号**——它既不能算损失，也不能验证。而它的 X 可能完全正常，但没有"答案"可用。
2. **填充目标等于伪造标签**：若用均值/回归去"填" y，等于让模型学习人造答案：填充值不携带该样本的真实信息，反而把人为的分布假设注入训练集，评估指标随之失真——这比丢样本严重得多。
3. **特征缺失可以修复**：X 缺失的样本仍有真实标签，损失可算；填充（均值/组内统计/模型插补）只影响该样本的特征取值，保留其余信息。代价是引入分布假设（5.13 题 4 的方差压缩问题），所以要**标记列**（`is_missing`）+ 在训练集上统计填充值（5.9 陷阱 5 的防泄漏纪律）。
4. 边界情况：目标缺失率极高、或缺失与类别强相关（缺失机制非随机）时，删行本身也会引入偏差——先分析缺失机制再动手（5.2.2）。

**复盘指引**：5.2.2、5.9 陷阱 5；《机器学习》数据泄漏与特征工程。

### 5.13 题 9【挑战题｜对应正文 5.5、3.12 题 5】（已实跑验证）

> 题目：分块读取下的全局均值与分块方差合并公式，编程验证与全量 var() 一致。

**公式证明**：设各块 $i$ 有 $n_i$ 个样本、均值 $\bar x_i$、样本方差 $s_i^2$（ddof=1），总均值 $\bar x = \frac{1}{N}\sum n_i \bar x_i$。由平方和分解 $\sum_{j \in i}(x_j - \bar x)^2 = \sum_{j \in i}(x_j - \bar x_i)^2 + n_i(\bar x_i - \bar x)^2$（对每组加、减 $\bar x_i$ 展开交叉项为零），对全部块求和再除以 $N-1$：

$$s^2 = \frac{\sum_i (n_i - 1)s_i^2 + \sum_i n_i(\bar x_i - \bar x)^2}{N-1}$$

**程序验证**（实测通过，误差 < 1e-9）：

```python
import numpy as np

rng = np.random.default_rng(0)
x = rng.normal(10, 3, size=10_000)
chunks = np.array_split(x, 17)          # 模拟 17 个 chunk（read_csv(chunksize) 的产物）

n_tot = sum(len(c) for c in chunks)
mu_tot = sum(c.sum() for c in chunks) / n_tot          # 分块累加 sum -> 全局均值
num = sum((len(c) - 1) * c.var(ddof=1)                  # 各块内平方和
          + len(c) * (c.mean() - mu_tot) ** 2           # 各块均值对总均值的偏移项
          for c in chunks)
s2 = num / (n_tot - 1)

print(abs(s2 - x.var(ddof=1)) < 1e-9)   # 实测输出: True
print(mu_tot, x.mean())                 # 实测输出: 10.0189356611439 10.018935661143898
```

要点：均值只需累加 $n_i$ 与 $\sum x$；方差需要额外的**块均值偏移项** $n_i(\bar x_i - \bar x)^2$——漏掉它就是分块统计最常见的 bug。这套"分块合并统计量"是 out-of-core 计算（5.12 进阶 4）的基石。

**复盘指引**：5.5、3.2.3（chunksize 返回迭代器）；5.12 进阶 4。

### 6.12 题 1【概念辨析｜对应正文 6.1.1】（已实跑验证）

> 题目：Figure 与 Axes 的关系？`fig, axes = plt.subplots(2, 3)` 中 axes 的类型与形状？遍历 6 个子图的惯用法？

**答案**（实测）：**Figure 是画布，Axes 是画布上的一块坐标系**——一个 Figure 可含多个 Axes（`add_subplot`），Axes 才是绘图真正载体（`ax.plot/set_xlabel/...`）；保存作用于 `fig`（`fig.savefig`）。`plt.subplots(2, 3)` 返回的 `axes` 是 **ndarray**，`type` 为 `numpy.ndarray`，`shape` 为 `(2, 3)`——它只是把 Axes 对象排成的二维数组。

遍历惯用法：

```python
for ax in axes.flat:      # flat 把 (2,3) 摊平成 6 个 Axes 的迭代
    ...
```

（也可 `axes.ravel()`。）单行单列时 `plt.subplots(1, m)` 返回一维数组，`plt.subplots(1, 1)` 直接返回单个 Axes——写通用代码时用 `np.ravel(axes)` 最稳。

### 6.12 题 2【概念辨析｜对应正文 6.1.1、6.7 陷阱 1】

> 题目：为什么 pyplot 接口"不适合写库"？构造循环画 10 张图却叠进一张图的例子。

**答案**：pyplot 用**全局状态机**——`plt.plot` 作用于隐式的"当前图/当前轴"，而"当前"是进程级全局变量。问题有三：① 隐式依赖全局状态，函数行为取决于"调用前谁动过当前图"，不可组合、不可测试（第 7 章可测试性判据）；② 库代码里无法知道调用者的"当前图"是什么，会画进别人正在建的图；③ 图不会被显式管理，内存泄漏（`plt._pyplot` 维持的 figure 栈需 `plt.close` 人工清理）。

典型事故（题目要的例子）：

```python
import matplotlib.pyplot as plt
import numpy as np

for i in range(10):                # 想画 10 张图
    x = np.linspace(0, 1, 50)
    plt.plot(x, np.sin(x + i))     # 没写 plt.figure()！
    plt.title(f"figure {i}")
    plt.savefig(f"f{i}.svg")       # 结果 10 个文件全是一样的叠加曲线
```

10 次循环全画进**同一张**图的当前 Axes，每次 savefig 存的是同一张叠加图。修复：循环内 `fig, ax = plt.subplots()`，或整体改 `fig, axes = plt.subplots(2, 5)` 后用 `axes.flat`。OO API 显式传递 `fig/ax`，无全局状态可污染。

**复盘指引**：6.1.1、6.7 陷阱 1。

### 6.12 题 3【计算推导｜对应正文 6.6 案例 1】（已实跑验证）

### 6.12 题 5【编程实现｜对应正文 6.5.1、2.6 案例 2】（已实跑验证）

> 题目：用 scipy.optimize 求第 2 章案例 2 的最小二乘，初值零向量，比较数值解与解析解。

```python
import numpy as np
from scipy import optimize

rng = np.random.default_rng(seed=42)
X = rng.normal(size=(200, 2))
y = 3.0 * X[:, 0] - 2.0 * X[:, 1] + 1.0 + 0.01 * rng.normal(size=200)

def loss(params):                     # params = [w1, w2, b]
    w, b = params[:2], params[2]
    return float(np.mean((X @ w + b - y) ** 2))

res = optimize.minimize(loss, x0=np.zeros(3), method="BFGS")
w_num, b_num = res.x[:2], res.x[2]

# 解析解（正规方程）对照
A = np.column_stack([X, np.ones(len(X))])
w_ls, *_ = np.linalg.lstsq(A, y, rcond=None)

print(f"数值解: w={w_num.round(4)}, b={b_num:.4f}, 迭代数 nit={res.nit}")
print(f"解析解: w={w_ls[:2].round(4)}, b={w_ls[2]:.4f}")
# 实测:
# 数值解: w=[2.9998 -2.0005], b=0.9993, 迭代数 nit=9
# 解析解: w=[2.9998 -2.0005], b=0.9993
print(np.allclose(w_num, [3, -2], atol=0.01) and abs(b_num - 1) < 0.01)  # True
```

数值解与解析解在 4 位小数内一致，校验值"误差 < 0.01"成立。凸二次损失下 BFGS 从零向量 9 步收敛；《最优化方法》视角：这正是"无约束光滑优化"，`jac=` 传入解析梯度（2.12 题 3 推导的 $\frac{2}{n}X^\top e$）还能更快。

**复盘指引**：6.5.1；2.12 题 3 的梯度、2.6 案例 2 的 GD 版本对比。

### 6.12 题 6【编程实现｜对应正文 6.6 案例 2】（已实跑验证）

> 题目：种子数 3 → 30，观察误差棒变化并解释。

```python
import numpy as np
import pandas as pd
from scipy import stats
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

sizes = np.array([100, 300, 1000, 3000, 10000])
rng = np.random.default_rng(seed=7)

def run(m, n):                       # 与正文案例 2 相同的模拟实验
    base = 100 / (1 + np.exp(-(np.log10(n) - 2.2) * 1.8))
    return float(np.clip(base + (2.0 if m == "B" else 0.0)
                         + rng.normal(0, 0.8), 50, 99))

def learning_curve(n_seeds):
    rows = [(m, n, run(m, n)) for m in ["A", "B"] for n in sizes
            for _ in range(n_seeds)]
    df = pd.DataFrame(rows, columns=["model", "n", "acc"])
    return df.groupby(["model", "n"])["acc"].agg(["mean", "std", "count"]).reset_index()

g3, g30 = learning_curve(3), learning_curve(30)
sem3  = (g3["std"]  / np.sqrt(g3["count"])).mean()
sem30 = (g30["std"] / np.sqrt(g30["count"])).mean()
print(f"平均 SEM: 3种子={sem3:.3f}, 30种子={sem30:.3f}, 比值={sem3/sem30:.2f}")
# 实测: 平均 SEM: 3种子=0.245, 30种子=0.108, 比值=2.28
```

**解释**：SEM = $s/\sqrt n$，种子数扩 10 倍 → SEM 期望缩短 $\sqrt{10} \approx 3.16$ 倍。实测比值 2.28 略小于理论值，原因要诚实说：**3 个种子的 std 估计本身极不稳定**（自由度只有 2，卡方分布重尾），单次实验的比值会大幅波动；多次重复实验取平均才趋近 3.16。结论不变：多种子把"点估计"变成"带区间的估计"，且种子数按平方反比缩小标准误——报告里 n 必须写清（6.7 陷阱 2）。

### 6.12 题 9【挑战题｜对应正文 6.2.2、6.6 案例 1】（已实跑验证）

> 题目：实现"双误差棒对比图"：mean±95%CI 的 `fill_between` 带状区间 + 区间重叠阴影，图注写明 n 与误差种类。

**实现骨架（完整可运行，实测出图）**：

```python
import numpy as np
import pandas as pd
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from scipy import stats

rng = np.random.default_rng(7)
sizes = np.array([100, 300, 1000, 3000, 10000])

def run(m, n):
    base = 100 / (1 + np.exp(-(np.log10(n) - 2.2) * 1.8))
    return float(np.clip(base + (2.0 if m == "B" else 0.0) + rng.normal(0, 0.8), 50, 99))

df = pd.DataFrame([(m, n, run(m, n)) for m in ["A", "B"] for n in sizes
                   for _ in range(30)], columns=["model", "n", "acc"])

fig, ax = plt.subplots(figsize=(6, 4))
bands = {}
t975 = stats.t.ppf(0.975, 30 - 1)                 # 每点 n=30，df=29
for model, color in [("A", "tab:blue"), ("B", "tab:orange")]:
    g = df[df.model == model].groupby("n")["acc"].agg(["mean", "std", "count"])
    sem = g["std"] / np.sqrt(g["count"])
    lo, hi = g["mean"] - t975 * sem, g["mean"] + t975 * sem
    ax.plot(g.index, g["mean"], "o-", color=color, label=f"model {model}")
    ax.fill_between(g.index, lo, hi, color=color, alpha=0.2)   # CI 带状区间
    bands[model] = (lo.values, hi.values)

# 两模型 CI 重叠处着灰色：重叠少 => 差异越可信
loA, hiA = bands["A"]; loB, hiB = bands["B"]
ax.fill_between(sizes, np.maximum(loA, loB), np.minimum(hiA, hiB),
                where=np.minimum(hiA, hiB) >= np.maximum(loA, loB),
                color="gray", alpha=0.4, label="CI overlap")
ax.set(xscale="log", xlabel="n", ylabel="acc (%)",
       title="mean +/- 95% CI (t-dist), n=30 seeds per point")
ax.legend()
fig.savefig("q6_9.svg")
```

**关键步骤**：① 每点独立算 SEM 并乘 $t_{0.975,\,29}$（样本量不同要逐点算 df）；② `fill_between` 下限/上限用逐点的 lo/hi 数组；③ 重叠区间 = $\max(\text{lo}_A, \text{lo}_B)$ 到 $\min(\text{hi}_A, \text{hi}_B)$，`where` 条件控制只在真重叠处着色——重叠消失的位置就是差异开始显著的位置（CI 重叠与显著性检验不等价，只是直观代理，caption 里应注明并引用 t 检验 p 值）。

**复盘指引**：6.2.2、6.6 案例 2；6.8 公式 3。

### 6.12 题 10【挑战题｜对应正文 6.5.1】（已实跑验证）

> 题目：对比 BFGS 与 L-BFGS-B 在 100 维 Rosenbrock 上的 `res.nit` 与耗时，写 200 字。

**实测**（scipy 1.16，经典初始点 $w_0=(-1.2, 1.0, -1.2, 1.0, \dots)$）：

```python
import numpy as np, time
from scipy import optimize

def rosen100(w):
    return np.sum((1 - w[:-1])**2 + 100.0 * (w[1:] - w[:-1]**2)**2)

w0 = np.full(100, -1.2); w0[1::2] = 1.0
r1 = optimize.minimize(rosen100, w0, method="BFGS")      # 实测 nit=543, f=7.5e-11, 0.9 s
r2 = optimize.minimize(rosen100, w0, method="L-BFGS-B")  # 实测 nit=119, f=7.4e+01, 0.16 s
```

**200 字（要点）**：BFGS 显式维护稠密 Hessian 逆近似 $B^{-1}$，n 维即 n×n 矩阵——100 维是 10⁴ 个数尚可，上千维时内存与每次更新的 O(n²) 开销成为瓶颈。L-BFGS 只保留最近 m 组 (s, y) 曲率对（默认 m=10），内存 O(nm)、每步 O(nm)，等价于隐式重建曲率。实测 100 维 Rosenbrock：BFGS 迭代 543 次收敛到 $10^{-11}$；L-BFGS-B 迭代 119 次、快约 5 倍，但因截断曲率历史，默认容差下终点精度稍逊（f≈74，收紧 `gtol/pgtol` 后可继续下降）。高维问题（深度学习、PDE 反演）几乎清一色 L-BFGS：**"用有限记忆换可扩展性"**，衔接《最优化方法》拟牛顿法一族的收敛率讨论。

**复盘指引**：6.5.1；2.12 题 3 的梯度可传 `jac=` 加速。

### 7.13 题 1【概念辨析｜对应正文 7.4.1】

> 题目：`print` 与 `logging.info` 在"第三方库引用你的代码"场景下的行为差异？为什么库代码不能调用 `basicConfig`？

**答案要点**：

1. **print**：无条件写 stdout。你的库被别人的应用 import 后，每次调用 `print` 都会污染对方的输出（管道、JSON 输出、进度条全被冲坏），且**消费方没有任何办法关闭或分级**。
2. **logging.info**：日志事件沿 logger 层级（`getLogger(__name__)` → root）向上传播，**由应用的入口决定是否显示、显示到哪、什么格式**。若应用从未配置 logging，Python 的兜底 `lastResort` handler 只输出 **WARNING 及以上**——库里的 `logging.info` 静默消失；应用 `basicConfig(level=INFO)` 后才出现。这个"默认静默、可分级开启"正是库与应用的正确契约。
3. **库为什么不能 `basicConfig`**：`basicConfig` 给 **root logger** 加 handler、设级别，且只在 root **尚无 handler 时**生效。库一旦调用它，就抢占了宿主应用的日志配置权（可能赶在应用配置之前执行，导致应用的配置看似"没生效"），影响所有其他库。正确分工（7.9 公式 4）：**库只 `getLogger(__name__)`，不配 handler；入口统一 `basicConfig`/`dictConfig`**。

**复盘指引**：7.4.1；Hynek Schlawack 的 logging 配置文（7.11 拓展阅读）。

### 7.13 题 2【概念辨析｜对应正文 7.3.3】

> 题目：为什么"把随机种子硬编码在函数内部"同时伤害测试与复现？给出参数注入写法。

**答案要点**：

1. **伤害测试**：种子写死 → 函数每次产生同一条随机序列 → 测试永远走同一条数据路径，碰不到其他随机输入下的边界（概率性 bug 被藏起来）；反过来，想构造"特定的坏随机情形"复现失败用例时，改不了种子。
2. **伤害复现**：调用者无法为"这次实验"指定种子——同一函数在不同实验里本该是不同的随机流；且函数内的种子是隐式的，读代码看不出随机性来源，实验记录里也就没有它的位置（7.4.2 的"种子进日志"无从谈起）。
3. **正确写法**：

```python
def make_dataset(n: int, seed: int | None = None) -> tuple[np.ndarray, np.ndarray]:
    rng = np.random.default_rng(seed)     # 种子作为参数注入（None = 系统熵源）
    ...
```

调用方决定：测试传固定 `seed=0`（确定性断言，7.3.3 "随机性通过参数注入"），实验入口传 CLI 参数 `--seed` 并写进日志（复现三件套之一）。正文 7.7 案例 1 的 `make_dataset(n, seed)` 就是标准答案。

**复盘指引**：7.3.3、7.4.2、7.7 案例 1。

### 7.13 题 3【计算推导｜对应正文 7.7 案例 1】

> 题目：证明当 $x, y$ 已中心化时 $\frac{x^\top y}{x^\top x}$ 等价于标准最小二乘斜率。

**证明**：一元最小二乘斜率为

$$\hat\beta_1 = \frac{\sum_i (h_i-\bar h)(s_i-\bar s)}{\sum_i (h_i-\bar h)^2}.$$

记 $x_i = h_i - \bar h$、$y_i = s_i - \bar s$（即已中心化，$\bar x = \bar y = 0$），则分子分母分别就是 $x^\top y$ 与 $x^\top x$，等价成立。**依据（中心化消去截距项）**：在带截距模型 $s_i = \beta_0 + \beta_1 h_i + \varepsilon_i$ 中，正规方程对 $\beta_0$ 求导得 $\sum_i (s_i - \beta_0 - \beta_1 h_i) = 0$，解出 $\beta_0 = \bar s - \beta_1 \bar h$；代回 $\beta_1$ 的方程后所有项自动变成离差形式——**截距被中心化吸收**，$\hat\beta_1 = \sum x_i y_i / \sum x_i^2$。这就是 `fit_slope` 里 `x = hours - hours.mean()` 两行的数学理由：中心化后不需要显式截距。

**复盘指引**：7.7 案例 1 的 `fit_slope`；《高等数学》最小二乘推导、4.8 案例 3。

```python
def preprocess(x: np.ndarray, eps: float = 1e-8) -> np.ndarray:
    """按行标准化输入矩阵。"""
    if not np.all(np.isfinite(x)):          # 新增：NaN/inf 一律拒绝
        raise ValueError("输入含非有限值 (NaN/inf)")
    mu = x.mean(axis=1, keepdims=True)
    sd = x.std(axis=1, keepdims=True) + eps
    return (x - mu) / sd
```

### 7.13 题 8【开放思考｜对应正文 7.3.3、7.8】

> 题目：为什么"测试通过"不能证明"实验结论正确"？至少两类测试覆盖不了的错误 + 对应防线。

**答案要点**：测试验证的是"**代码实现了我声明的行为**"，而实验结论依赖"**声明的行为就是科学上该做的行为**"——后者超出了代码契约。

至少两类覆盖不了的错误：

1. **数据泄漏**：测试集统计量泄漏进训练（全表归一化、按全表填充缺失），或验证集信息通过特征工程渗入。每个函数单测都"通过"，管道整体结论却是虚高的。**防线**：人工审查管道切分点、严格 train/val/test 分离的 API 设计（fit 在 train、transform 应用到 val/test，见 5.9 陷阱 5）、独立复跑者检查切分逻辑。
2. **统计语义错误**：误差棒画的是 std 还是 SEM 还是 95% CI 未注明/画错、多次比较不校正、p 值误读（6.7 陷阱 2）。代码完全符合实现者的（错误）意图。**防线**：统计方法预注册（先写分析计划再跑实验）、图表与 caption 的规范审查、双人核对。

其他可列：共享的 bug（错误假设同时进了实现和测试，测试"验证"了同一个错）、分布外泛化问题、随机种子选择偏差。**总防线**：代码测试（本章）+ 方法审查 + 预注册 + 独立复现（《实验设计与评估》的四层体系），缺一不可。

**复盘指引**：7.3.3、7.8 陷阱 5；《实验设计与评估》全课程主线。

## 使用建议：如何用答案册复盘

1. **先做后看，留痕**：每章练习独立完成后，把自己的答案与正确率记在题目旁（做对 / 有漏洞 / 错误）。对照答案时，重点不是抄写参考实现，而是回答"我的思路差在哪一步"。
2. **按"复盘指引"回溯正文**：每题末尾标注了出错概率最高的正文小节。做错概念题 → 回读对应小节并**重述机制**（如可变默认参数：默认值在 `def` 执行时求值一次）；做错输出预测题 → 把代码敲进解释器逐行验证，修正心智模型；做错编程题 → 对照参考实现，检查三点：正确性（边界与异常）、可读性（命名与职责）、健壮性（防共享内存、防除零、异常处理）。
3. **高频陷阱优先复盘**（各章汇总）：引用共享与浅拷贝（1.3）、可变默认参数（1.6）、迭代器一次性（3.1/3.8）、广播方向错误与 keepdims（4.2/4.4）、链式索引赋值与 merge 键爆炸（5.1/5.4）、误差棒语义（6.6）、测试与随机性注入（7.3）。这些点在后续《机器学习》《深度学习》课程中会以真实 bug 的形式再次出现。
4. **把答案变成长期资产**：把挑战题的骨架（TypedField 描述符、IndexedJsonlDataset、log_softmax、分块方差合并）收进自己的代码片段库；把第 7 章的 pyproject/CI 模板作为新项目起点。做题的终点是"下个项目直接复用"。
5. **间隔重测**：一周后重做所有"错误"标记题，只看自己的解答不看答案册；两周后再看标准答案。能独立复述机制（而不是背答案）才算通过——尤其是第 1 章，它决定了后面六章以及《深度学习》中一半的调试效率。
