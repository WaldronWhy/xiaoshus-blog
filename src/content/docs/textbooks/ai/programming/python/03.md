## 3.1 迭代协议

### 3.1.1 两个协议的区分

- **可迭代对象（iterable）**：实现了 `__iter__`，能返回一个迭代器的对象（list、dict、文件、ndarray……）。
- **迭代器（iterator）**：实现了 `__next__`（以及 `__iter__` 返回自身），表示"一次取一个、耗尽为止"的状态机。

`for x in obj` 的底层展开：

```python
# for x in obj: ...
_it = iter(obj)          # 调用 obj.__iter__()
while True:
    try:
        x = next(_it)    # 调用 _it.__next__()
    except StopIteration:
        break
    # 循环体
```

验证与自查：

```python
nums = [10, 20]
it = iter(nums)
print(next(it))        # 预期输出: 10
print(next(it))        # 预期输出: 20
next(it)               # StopIteration —— 迭代器耗尽
print(iter(it) is it)  # 预期输出: True —— 迭代器的 __iter__ 返回自身
```

**关键设计**：list 是 iterable 而不是 iterator——`iter(nums)` 每次返回**新的**迭代器，所以 list 可以反复 `for`；迭代器是**一次性**的，耗尽后再 `for` 什么也不会发生。这是经典 bug：

```python
it = iter([1, 2, 3])
print(list(it))   # 预期输出: [1, 2, 3]
print(list(it))   # 预期输出: [] —— 迭代器已耗尽！
```

### 3.1.2 自己实现迭代器

```python
class Countdown:
    """实现迭代协议的最小类：从 n 倒数到 1。"""

    def __init__(self, n):
        self.n = n

    def __iter__(self):
        return self          # 自身就是迭代器（可迭代的 + 迭代器）

    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1

print(list(Countdown(3)))    # 预期输出: [3, 2, 1]
```

注意：`Countdown` 同时是 iterable 和 iterator，代价是**不可重复迭代**（`Countdown(3)` 每次循环前要重新构造）。这就是为什么标准容器把这两个角色分开。

### 3.1.3 魔术方法的另一半：`__getitem__`

只实现 `__getitem__` 的对象也能被 `for` 遍历（解释器退回到旧式下标协议，从 0 开始递增直到 IndexError）。PyTorch 的 `Dataset` 协议正是只要求 `__getitem__` 与 `__len__`，DataLoader 在其上再叠加批量与打乱逻辑（本章 3.2.3 案例模拟）。

## 3.2 生成器与惰性求值

### 3.2.1 yield：可暂停的函数

带 `yield` 的函数是**生成器函数（generator function）**：调用它不执行函数体，而是返回生成器（一种迭代器）；每次 `next` 执行到下一个 `yield` 处**暂停并交出值**，下次从暂停点继续。

```python
def countdown_gen(n):
    while n > 0:
        yield n          # 暂停点：交出 n，等待下一次 next
        n -= 1

g = countdown_gen(3)
print(next(g))   # 预期输出: 3
print(next(g))   # 预期输出: 2
print(list(countdown_gen(3)))   # 预期输出: [3, 2, 1] —— 新生成器，可重新迭代
```

对比 3.1.2 的类实现：状态管理（`self.n`）与迭代逻辑合并在一个函数体里，**不需要手写 `__next__` 与 StopIteration**——这是生成器的核心价值。

### 3.2.2 惰性求值：只算需要的那部分

列表推导**立即**构造整个列表；生成器表达式**惰性**地产出元素。当数据源远大于内存时，这个差别是决定性的。生成器还有"流水线"用法：多个生成器串联，数据像在管道里逐个流过，任一时刻内存里只有一个元素在处理——这正是 Unix 管道哲学。

```python
import sys

squares_list = [i * i for i in range(10_000_000)]
squares_gen = (i * i for i in range(10_000_000))
print(sys.getsizeof(squares_list))  # 预期输出: 约 89095160（~85 MB，与 n 成正比）
print(sys.getsizeof(squares_gen))   # 预期输出: 200（~200 字节，与 n 无关）
print(sum(x for x in squares_gen))  # 预期输出: 333333283333335000000
```

### 3.2.3 案例：流式读取大文件数据集（DataLoader 的雏形）

假设有一个 10 GB 的文本数据集（每行一条 JSON 样本），内存只有 2 GB。下面实现"流式解析 → 过滤 → 批处理"的完整管道（本案例只依赖标准库，构造一份小文件模拟即可直接运行）：

```python
import json
import os

# ---- 构造一份模拟数据集（真实场景：文件大小 10 GB，逻辑完全相同）----
os.makedirs("data", exist_ok=True)
with open("data/samples.jsonl", "w", encoding="utf-8") as f:
    for i in range(100):
        f.write(json.dumps({"id": i, "text": f"sample-{i}",
                            "label": i % 3}) + "\n")

def read_lines(path):
    """逐行读文件：文件对象本身就是迭代器，内存占用 O(1)。"""
    with open(path, encoding="utf-8") as f:
        yield from f            # yield from：委托给子迭代器

def parse_json(lines):
    for line in lines:
        yield json.loads(line)  # 每次只解析一行

def filter_label(records, keep):
    for r in records:
        if r["label"] == keep:
            yield r

def batched(records, batch_size):
    """把任意迭代器切成批——DataLoader 的 batch 维度来源。"""
    batch = []
    for r in records:
        batch.append(r)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:                   # 别丢掉不满批的尾部
        yield batch

# ---- 组装流水线：注意每个组件都是惰性的 ----
pipeline = batched(
    filter_label(parse_json(read_lines("data/samples.jsonl")), keep=0),
    batch_size=4,
)

total = 0
for i, batch in enumerate(pipeline):
    total += len(batch)
    if i == 0:
        print(f"第一批: {batch[0]}")   # 预期输出: 第一批: {'id': 0, 'text': 'sample-0', 'label': 0}
print(f"label=0 的样本共 {total} 条")   # 预期输出: label=0 的样本共 34 条
```

要点：即使文件是 10 GB，这段代码内存占用也只有 `batch_size` 量级；且任何一步消费不到（例如中途 break），后面的解析根本不会执行——**惰性求值同时是内存优化和计算优化**。

### 3.2.4 生成器的进阶：`yield from` 与协程

`yield from it` 把子迭代器的产出"透传"（3.2.3 已用）。此外生成器支持 `send(value)` 向暂停点注入值，使其升级为**协程（coroutine）**——Python 的 `async/await` 正是从这里演化而来。AI 工程中主要用其"生产者-消费者"形态，深入留到进阶方向。

## 3.3 上下文管理器与资源管理

### 3.3.1 with 的语义

文件、数据库连接、GPU 资源、锁都遵循同一生命周期：**获取 → 使用 → 释放**。手工管理在异常发生时会漏掉释放；`with` 语句保证无论正常退出还是异常退出，清理代码都会执行：

```python
with open("data/samples.jsonl", encoding="utf-8") as f:
    line = f.readline()
# 离开 with 块时 f.__exit__ 被调用，文件必被关闭（即使块内抛异常）
print(f.closed)   # 预期输出: True
```

`with obj` 的展开：`obj.__enter__()` → 执行块 → 无论成败调用 `obj.__exit__(exc_type, exc_val, tb)`；`__exit__` 返回 `True` 可吞掉异常（慎用）。

### 3.3.2 两种实现方式

类实现（理解机制）与 `contextlib.contextmanager`（工程首选）：

```python
import time
from contextlib import contextmanager

# 方式一：类实现——呼应第 2 章魔术方法
class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                       # as 后拿到的对象
    def __exit__(self, exc_type, exc_val, tb):
        self.elapsed = time.perf_counter() - self.t0
        return False                      # False = 不吞异常

with Timer() as t:
    sum(i * i for i in range(1_000_000))
print(f"耗时 {t.elapsed * 1000:.1f} ms")   # 预期输出: 耗时 25.3 ms（量级示例）

# 方式二：生成器实现——更简洁
@contextmanager
def timer_block(name):
    t0 = time.perf_counter()
    try:
        yield                             # yield 之前=__enter__，之后=__exit__
    finally:
        print(f"[{name}] 耗时 {(time.perf_counter() - t0) * 1000:.1f} ms")

with timer_block("求和"):
    sum(i * i for i in range(1_000_000))
# 预期输出: [求和] 耗时 24.8 ms（量级示例）
```

AI 代码中最重要的上下文管理器是训练循环里的 `torch.no_grad():`（禁用梯度记录、省显存）与 `torch.cuda.amp.autocast():`（自动混合精度）——它们的思想与上面 20 行代码完全相同。

## 3.4 异常处理规范

### 3.4.1 语法回顾与三条规范

```python
def parse_label(raw):
    try:
        return int(raw)
    except (ValueError, TypeError) as e:      # 规范1：捕获具体异常，不裸 except
        raise ValueError(f"无法把 {raw!r} 解析为标签") from e   # 规范3：保留异常链
```

1. **捕获具体异常**。裸 `except:` 会连 `KeyboardInterrupt`（Ctrl+C）、程序 bug（`NameError`）一起吞掉，让"程序坏了"伪装成"没数据"。
2. **不吞异常、不打断恢复语义**。`except: pass` 是万恶之源；要么处理（降级、重试、默认值），要么重新抛出（可加上下文）。
3. **用异常链保留因果**。`raise ... from e` 让 traceback 同时显示原始异常与转换后的异常，调试数据管道时不可替代。

### 3.4.2 EAFP 风格与自定义异常

Python 惯用 **EAFP**（Easier to Ask Forgiveness than Permission）："先做、出错再处理"，优于反复预检查（LBYL, look before you leap）——因为预检查存在竞态且冗长：

```python
# LBYL（不推荐）             # EAFP（Pythonic）
if key in d:                  try:
    v = d[key]                    v = d[key]
else:                         except KeyError:
    v = default()                 v = default()
```

大型项目定义自己的异常层次，让调用方按类型分流处理：

```python
class DataError(Exception):          # 项目基类
    pass

class CorruptRecordError(DataError):
    pass

def load_record(line: str) -> dict:
    try:
        rec = json.loads(line)
    except json.JSONDecodeError as e:
        raise CorruptRecordError(f"坏行: {line[:50]!r}") from e
    if "label" not in rec:
        raise CorruptRecordError(f"缺 label 字段: {line[:50]!r}")
    return rec

bad_records = 0
for line in read_lines("data/samples.jsonl"):
    try:
        load_record(line)
    except CorruptRecordError:       # 单条坏数据不应杀死整个训练任务
        bad_records += 1
print(f"跳过坏记录 {bad_records} 条")   # 预期输出: 跳过坏记录 0 条（本模拟数据无坏行）
```

## 3.5 类型注解与 mypy 简介

### 3.5.1 注解是文档，也是静态检查的输入

Python 的类型注解（type hints，PEP 484）**不影响运行时**，但带来三重收益：IDE 补全与跳转、mypy 静态捕获 bug、接口即文档。AI 代码中数组形状约定尤其重要：

```python
import numpy as np
from typing import Iterator, Iterable

def standardize(X: np.ndarray) -> np.ndarray:
    """按列标准化。X: (n_samples, n_features)。"""
    mean = X.mean(axis=0)             # axis 语义：第 4 章展开
    std = X.std(axis=0)
    std = np.where(std == 0, 1.0, std)   # 防除零
    return (X - mean) / std

def iter_batches(records: Iterable[dict],
                 batch_size: int) -> Iterator[list[dict]]:
    """类型注解精确表达了本章的生成器管道契约。"""
    batch: list[dict] = []
    for r in records:
        batch.append(r)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:
        yield batch
```

`Iterable`（可被 for）与 `Iterator`（有 `__next__`）的区分正对应 3.1 节两个协议；返回 `Iterator` 而不是 `list`，就把"惰性"写进了类型签名。

## 3.6 关键公式速查

| # | 定律/协议 | 适用条件与备注 |
|---|---|---|
| 1 | `for x in obj` ≡ `iter(obj)` + 循环 `next()` 直到 `StopIteration` | iterable 只需 `__iter__`；iterator 额外需 `__next__` |
| 2 | 迭代器是一次性的 | 耗尽后再次遍历为空；需重复遍历请保留 iterable，每次 `iter()` 取新迭代器 |
| 3 | 生成器：调用即返回迭代器，`yield` 处暂停 | 内存占用 $O(1)$ 与数据总量 $N$ 无关；惰性：不消费就不计算 |
| 4 | `with obj` 保证 `__exit__` 必被调用 | 无论块内是否异常；`contextmanager` 用 `yield` 划分进入/退出逻辑 |
| 5 | 捕获具体异常、不裸 except、异常链 `raise ... from e` | 数据管道按"单条失败不杀死全局"设计 |
| 6 | 类型注解运行时无效，供静态检查与文档 | `Iterable`/`Iterator` 对应两个迭代协议；生成器函数返回 `Iterator[T]` |

## 3.7 示例与案例

### 案例 1：手算一个生成器的执行轨迹（数值算例）

逐行推导下面代码的打印顺序（这是理解"暂停-恢复"的关键练习）：

```python
def gen():
    print("A")
    yield 1
    print("B")
    yield 2
    print("C")

g = gen()          # 不打印任何东西！只创建生成器
print("---")
x = next(g)        # 打印 A，停在 yield 1
print("拿到", x)   # 打印 拿到 1
y = next(g)        # 从 yield 1 恢复 -> 打印 B，停在 yield 2
print("拿到", y)   # 打印 拿到 2
```

完整预期输出：

```
---
A
拿到 1
B
拿到 2
```

校验点：`gen()` 调用时**什么都不打印**；"A" 出现在 `next(g)` 时而非创建时。若与你的推导不符，重读 3.2.1。

### 案例 2：内存安全的数据集迭代器（为 DataLoader 铺垫）

把 3.2.3 的管道封装成协议化接口——`__len__` + `__iter__`，正是 PyTorch `Dataset`/`DataLoader` 的核心契约：

```python
import json
from typing import Iterator

class JsonlDataset:
    """内存安全的 JSONL 数据集：只在迭代时读盘。"""

    def __init__(self, path: str):
        self.path = path
        self._length = sum(1 for _ in open(path, encoding="utf-8"))  # 只数行数

    def __len__(self) -> int:
        return self._length

    def __iter__(self) -> Iterator[dict]:
        with open(self.path, encoding="utf-8") as f:   # with 保证关闭（3.3 节）
            for line in f:
                yield json.loads(line)                 # 逐条惰性产出

class DataLoader:
    """最小 DataLoader：批量 + 洗牌 + 逐 epoch 迭代。"""

    def __init__(self, dataset: JsonlDataset, batch_size: int = 8, shuffle: bool = False):
        self.dataset = dataset
        self.batch_size = batch_size
        self.shuffle = shuffle

    def __iter__(self) -> Iterator[list[dict]]:
        indices = list(range(len(self.dataset)))
        if self.shuffle:
            import random
            random.shuffle(indices)                    # 复现性：第 7 章引入种子参数
        batch = []
        for idx in indices:
            # 真实场景这里应做随机访问 dataset[idx]；JSONL 为流式格式，
            # 简化处理为顺序迭代（练习 9 要求改为随机访问版本）
            batch.append(next(iter(list(self.dataset)[idx:idx+1])))
            if len(batch) == self.batch_size:
                yield batch
                batch = []
        if batch:
            yield batch

ds = JsonlDataset("data/samples.jsonl")
print(len(ds))                     # 预期输出: 100
loader = DataLoader(ds, batch_size=8, shuffle=False)
batches = list(loader)
print(len(batches), len(batches[0]))   # 预期输出: 13 8 （100/8 = 12 余 4，末批 4 条）
print(batches[-1][-1]["id"])           # 预期输出: 99
```

诚实说明：上面 `DataLoader.__iter__` 中为教学简化了随机访问（`list(self.dataset)[idx:idx+1]` 会重复读盘）；高效做法见练习 9——把 `__iter__` 改为 `for idx in indices: batch.append(self.get(idx))`，并用索引文件实现 `get`。这正是《深度学习》中 map-style 与 iterable-style 两种 Dataset 的分野。

### 案例 3：异常安全 + 类型注解的批量预处理器

```python
import numpy as np
from typing import Iterator

def standardize_batches(path: str, batch_size: int = 16) -> Iterator[np.ndarray]:
    """流式标准化：用第一个批的均值近似全局均值（在线算法思想的简化版）。"""
    loader = DataLoader(JsonlDataset(path), batch_size=batch_size)
    first = next(iter(loader), None)
    if first is None:
        raise ValueError("数据集为空")
    feats = np.array([r["id"] for r in first], dtype=float)
    mu, sigma = feats.mean(), feats.std() or 1.0     # 防 sigma=0
    for batch in [first] + list(loader):
        vals = np.array([r["id"] for r in batch], dtype=float)
        yield (vals - mu) / sigma

for i, chunk in enumerate(standardize_batches("data/samples.jsonl", 32)):
    if i < 2:
        print(chunk.round(2))   # 预期输出: [-1.71 -1.65 -1.59 ... ]（首尾为标准化值）
```

## 3.8 常见误区与陷阱

1. **迭代器复用**。把生成器/迭代器存进变量后 `for` 两次，第二次为空。常见变体：把 `model.parameters()`（生成器）先 `print(len(...))` 再训练——参数已耗尽。需要多次使用时存 `list(...)` 或重新调用生成器函数。
2. **在生成器里"藏"副作用且不消费**。生成器函数体在第一次 `next` 前一行都不会执行。若函数开头有"打开日志/检查参数"，调用者不迭代就完全不生效——副作用必须放在非生成器外壳函数里。
3. **`except Exception: pass` 吞掉一切**。训练循环里这样写会把 OOM、NaN 梯度、维度错误全部静默化，最后得到一个"跑了 8 小时但什么都没学到"的模型。至少要 `logging.exception`（第 7 章）后重新抛出。
4. **用 `try/finally` 之外的方式管理文件**。`f = open(...); data = f.read(); f.close()` 在 `read` 抛异常时永远关不掉文件；长训练脚本累积泄漏句柄直至 `OSError: too many open files`。
5. **注解写成具体 list/tuple 而非抽象类型**。参数注解 `list[dict]` 会把所有可迭代对象拒之门外（鸭子类型被注解杀死）；接口处用 `Iterable[dict]`/`Sequence[dict]`，把具体类型留给内部实现。
