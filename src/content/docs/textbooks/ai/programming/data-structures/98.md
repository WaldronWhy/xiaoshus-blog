# 第 1 章 复杂度分析——衡量算法的尺子

## 1.1（概念辨析）｜出处：1.2 节

> **题目**：判断真假并说明理由——(a) $n^{100} = O(2^n)$；(b) $2^{2n} = O(2^n)$；(c) 若 $f = O(g)$ 且 $g = O(h)$，则 $f = O(h)$；(d) $\log(n!) = \Theta(n \log n)$（提示：用 $\sum_{k=1}^n \log k$ 的积分估计）。校验值：仅 (b) 为假。

**答案：a 真、b 假、c 真、d 真，与校验值一致。**

**(a) 真。** 用极限判别法：$\lim_{n\to\infty} \dfrac{n^{100}}{2^n} = 0$。取对数看分子分母：$\ln 2^n = n\ln 2$ 线性增长，$\ln n^{100} = 100\ln n$ 对数增长，$n$ 终将压倒 $100\ln n$，故指数压倒任何**固定次幂**多项式。给出具体的 $c, n_0$ 也可：$n \ge 997$ 时 $2^n > n^{100}$（数值验证：$2^{997}\approx 10^{300} > 10^{300} \ge n^{100}$）。

> **常见错误**：把"$O(2^n)$ 的算法很慢"直觉化成"多项式不可能属于它"。$O$ 是上界，多项式当然"不快于"指数。

**(b) 假。** $2^{2n} = (2^2)^n = 4^n$，而 $\dfrac{2^{2n}}{2^n} = 2^n \to \infty$，不存在常数 $c$ 使 $4^n \le c\cdot 2^n$ 对一切大 $n$ 成立。**指数的底数是增长阶的一部分，不能当作"常数"吸进 $O(\cdot)$**。

> **常见错误**：把 $2\cdot 2^n = O(2^n)$（这是对的，系数 2 可吸进 $c$）与 $2^{2n}$ 混淆。位置在指数上还是系数上，是天壤之别。

**(c) 真（传递性）。** 设 $f \le c_1 g\ (n\ge n_1)$，$g \le c_2 h\ (n \ge n_2)$，则对 $n \ge \max(n_1,n_2)$：$f(n) \le c_1 g(n) \le c_1 c_2 h(n)$，取 $c = c_1c_2$ 即得 $f = O(h)$。

**(d) 真。** $\log(n!) = \sum_{k=1}^{n}\log_2 k$。$\log_2 x$ 单调增，用积分夹逼：

$$\int_1^n \log_2 x\,dx \;\le\; \sum_{k=2}^{n}\log_2 k \;\le\; \int_1^n \log_2 x\,dx + \log_2 n,$$

左端 $= n\log_2 n - (\log_2 e)n + \log_2 e = \Theta(n\log n)$（详见第 5 章练习 3 的完整计算），上下界同阶，故 $\log(n!) = \Theta(n\log n)$。（这也是 Stirling 近似 $n! \approx \sqrt{2\pi n}(n/e)^n$ 取对数后的主项。）

**复盘指引**：错 (a)/(b) → 重读 1.2 节三条运算法则与极限判别法；错 (d) → 补《高等数学》定积分夹逼，并预看第 5 章 5.5 节。

## 1.2（计算推导）｜出处：1.5 节

> **题目**：求 $T(n) = 4T(n/2) + \Theta(n^2)$ 与 $T(n) = 2T(n/2) + \Theta(n\log n)$ 的解。校验值：均为 $\Theta(n^2\log n)$（第二个用情形 2 的推广或递归树求和验证）。

**第一问：$T(n) = \Theta(n^2 \log n)$，与校验值一致。**
$n^{\log_b a} = n^{\log_2 4} = n^2$，$f(n) = \Theta(n^2)$ 与其同阶，命中主定理**情形 2（$k=0$）**：$T(n) = \Theta(n^2\log n)$。直觉：递归树每层 $a^i$ 个规模 $n/2^i$ 的子问题，每层合并代价 $4^i\cdot(n/2^i)^2 = n^2$ 恒定，共 $\log_2 n$ 层。

**第二问：$T(n) = \Theta(n\log^2 n)$。⚠ 勘误：正文校验值"均为 $\Theta(n^2\log n)$"中的第二个有误。**

严格推导（递归树求和，设 $n = 2^L$，即 $L = \log_2 n$）：

- 第 $i$ 层有 $2^i$ 个子问题、每个规模 $n/2^i$，层代价 $= 2^i \cdot f(n/2^i) = 2^i \cdot \dfrac{n}{2^i}\log_2\dfrac{n}{2^i} = n\,(L - i)$；
- 层代价是 $nL, n(L-1), \dots, n\cdot 1, n\cdot 0$ 的**等差**递减（不是等比），求和：

$$T(n) = \sum_{i=0}^{L} n(L-i) = n\,\frac{L(L+1)}{2} = \Theta(n\log^2 n).$$

用主定理情形 2 的推广核对：$n^{\log_2 2} = n$，$f(n) = \Theta(n\log^{\color{red}1} n)$ 即 $k=1$，解为 $\Theta(n\log^{k+1} n) = \Theta(n\log^2 n)$。两法一致。

**数值模拟验证**（递归代价直接求和，CPython 实测）：

```python
import math
def T_cost(n):
    if n <= 1: return 1
    return 2 * T_cost(n // 2) + n * math.log2(max(n, 2))
for n in (2**10, 2**12, 2**14):
    c = T_cost(n)
    print(f"n=2^{int(math.log2(n))}: T/(n·log²n)={c/(n*math.log2(n)**2):.3f}, "
          f"T/(n²·log n)={c/(n*n*math.log2(n)):.2e}")
# 预期输出（实测）：
# n=2^10: T/(n·log²n)=0.560, T/(n²·log n)=5.47e-03
# n=2^12: T/(n·log²n)=0.549, T/(n²·log n)=1.61e-03
# n=2^14: T/(n·log²n)=0.541, T/(n²·log n)=4.62e-04
```

$T/(n\log^2 n)$ 收敛到常数（$\approx 0.5$），而 $T/(n^2\log n)\to 0$——证实 $\Theta(n\log^2 n)$，排除 $\Theta(n^2\log n)$。

**复盘指引**：第一问做错 → 重读 1.5 节主定理三种情形的判别表；第二问做错 → 动手画递归树，注意本题每层代价是"等差"而非 1.5 节归并例的"恒定"。

## 1.3（计算推导）｜出处：1.4.1 节 + 2.3 节

> **题目**：用势能法证明"两个栈模拟一个队列"的摊还代价为 $O(1)$（设总势能取第一栈中元素个数）。校验值：$n$ 次 enqueue + $n$ 次 dequeue 的总实际操作数 $\le 3n$。

**证明。** 记第 $i$ 次操作后的队列为 $D_i$，定义势函数

$$\Phi(D_i) = |\text{栈 A 中的元素数}|, \qquad \Phi(D_0) = 0,\ \Phi \ge 0.$$

**计数约定**：一次"元素搬移"（从 A 弹出并压入 B）计 **1** 个操作。三种操作的实际代价与势变化：

| 操作 | 实际代价 | $\Delta\Phi$ | 摊还代价 = 实际 + $\Delta\Phi$ |
|---|---|---|---|
| enqueue（push 进 A） | 1 | $+1$ | $1+1 = 2$ |
| dequeue，B 非空（pop B） | 1 | $0$ | $1$ |
| dequeue，B 空且 $|A| = k\ge 1$（先倒灌 $k$ 次再 pop） | $k + 1$ | $-k$ | $(k+1) - k = 1$ |

每次操作的摊还代价 $\le 2$，故 $m$ 次操作的总实际代价

$$\sum_{i=1}^{m} \hat c_i = \sum_{i=1}^{m} c_i + \Phi(D_m) - \Phi(D_0) \;\ge\; \sum_{i=1}^m c_i \quad(\Phi \ge 0)$$

即总实际代价 $\le \sum \hat c_i \le 2n + n = 3n$（$n$ 次 enqueue 每次 $\le 2$、$n$ 次 dequeue 每次 $=1$）。$\blacksquare$

**计数实验**（按上述约定逐操作计数，CPython 实测）：

```python
class MyQueue:
    def __init__(self):
        self._in, self._out = [], []
        self.ops = 0
    def enqueue(self, x):
        self._in.append(x); self.ops += 1          # 1 次 push
    def dequeue(self):
        if not self._out:
            while self._in:                         # 每个元素搬移计 1
                self._out.append(self._in.pop()); self.ops += 1
        self._out.pop(); self.ops += 1              # 1 次 pop
for n in (1000, 100000):
    q = MyQueue()
    for i in range(n): q.enqueue(i)
    for i in range(n): q.dequeue()
    print(f"n={n}: 总操作 = {q.ops}, 3n = {3*n}, ≤3n: {q.ops <= 3*n}")
# 预期输出（实测）：n=1000: 总操作 = 3000, 3n = 3000, ≤3n: True
#                  n=100000: 总操作 = 300000, 3n = 300000, ≤3n: True
```

恰好 $3n$：每个元素一生恰付出 push 1 + 搬移 1 + pop 1。

> **口径说明**：若把一次"搬移"拆成 pop+push 两个原子操作计数，总代价为 $4n$、摊还上界为 4——结论"摊还 $O(1)$"不变，正文"$\le 3n$"对应"搬移计 1"的约定（与第 2 章 2.3 节记账法"入队预存 2 个代币"的口径一致）。

**复盘指引**：不会设势函数 → 重读 1.4.1 节方法三（动态数组势能法），注意本题势函数选"A 的元素数"是因为它恰好度量"未来欠下的搬移债"。

## 1.4（代码标注）｜出处：1.3 节

> **题目**：为下面代码写出精确到求和式的复杂度：`for i in range(n): j = 1; while j <= i: j *= 2`。校验值：$\Theta(n)$。

**答案：$\Theta(n\log n)$。⚠ 勘误：正文校验值"$\Theta(n)$"有误**（疑与 1.3 节"段 C"混淆——段 C 的内层次数是 $n/2^i$ **递减**、等比求和为 $n$；本题内层次数是 $\log_2 i$ **递增**、求和为 $n\log n$）。

**推导**：对固定的 $i \ge 1$，$j$ 取值 $1, 2, 4, \dots$，循环体执行 $\lfloor \log_2 i \rfloor + 1$ 次（$i=0$ 时执行 0 次）。总次数

$$T(n) = \sum_{i=1}^{n-1} \left(\lfloor \log_2 i \rfloor + 1\right).$$

按 $\lfloor \log_2 i\rfloor = k$ 分组（满足者恰有 $2^k$ 个 $i$）：

$$T(n) = \sum_{k=0}^{\lfloor\log_2 n\rfloor - 1} 2^k (k+1) + O(\text{余段}) \;=\; \Theta\!\left(2^{K} K\right) \quad (K = \lfloor\log_2 n\rfloor) \;=\; \Theta(n \log n),$$

其中用了 $\sum_{k\le K} 2^k(k+1) = (K \cdot 2^{K+1} - 2^{K+1} + 2) + (2^{K+1} - 1) = \Theta(K 2^K)$。

**计数实验验证**：

```python
import math
def total_iters(n):
    tot = 0
    for i in range(n):
        j = 1
        while j <= i:
            j *= 2; tot += 1
    return tot
for n in (1000, 2000, 4000, 8000):
    t = total_iters(n)
    print(f"n={n}: t/(n·log2 n)={t/(n*math.log2(n)):.3f}, t/n={t/n:.1f}")
# 预期输出（实测）：
# n=1000: t/(n·log2 n)=0.901, t/n=9.0
# n=2000: t/(n·log2 n)=0.910, t/n=10.0
# n=4000: t/(n·log2 n)=0.917, t/n=11.0
# n=8000: t/(n·log2 n)=0.924, t/n=12.0
```

$t/(n\log_2 n)$ 稳定在 0.9 附近（常数），$t/n$ 随 $n$ 增长——确证 $\Theta(n\log n)$。

**复盘指引**：这也是正文 1.9 节误区 4（"双层循环不一定是 $O(n^2)$，必须求和而非相乘"）的另一面：**求和之前先看清内层次数随外层是增是减**。

## 1.5（编程实现）｜出处：1.4.1 节 + 1.8 案例 2

> **题目**：实现"倍率实验"框架，测量 `list.insert(0, x)` 与 `collections.deque.appendleft(x)` 的增长阶，并用摊还分析解释差异。输出目标：insert 的倍率趋近 4，deque 趋近 2。

```python
"""倍率实验：规模翻倍时看耗时倍率。Θ(n²)→×4，摊还 O(1)→×2。"""
import time
from collections import deque

def time_insert(n):
    xs = []
    t0 = time.perf_counter()
    for i in range(n):
        xs.insert(0, i)          # 头部插入：memmove 后续全部元素，Θ(n)
    return time.perf_counter() - t0

def time_deque(n):
    d = deque()
    t0 = time.perf_counter()
    for i in range(n):
        d.appendleft(i)          # 块状链表头插：O(1)
    return time.perf_counter() - t0

def ratios(fn, ns, reps=3):
    out, prev = [], None
    for n in ns:
        t = min(fn(n) for _ in range(reps))   # 取最优，压噪声
        if prev: out.append(t / prev)
        prev = t
    return out

ns = [4000, 8000, 16000, 32000]
print("insert 倍率(理论4):", [round(r, 2) for r in ratios(time_insert, ns)])
print("deque  倍率(理论2):", [round(r, 2) for r in ratios(time_deque, ns)])
# 预期输出（实测，本机 CPython 3.13）：
# insert 倍率(理论4): [3.45, 3.87, 3.89]
# deque  倍率(理论2): [1.93, 1.97, 2.08]
```

倍率分别趋近 4 与 2，与输出目标一致（校验值对照：✓）。

**摊还分析解释差异**：

- `list.insert(0, x)`：底层是连续指针数组，头部插入必须把已有 $n$ 个指针整体后移一格，单次 $\Theta(n)$、**无摊还改善**（移动是每次都要付的账，不是"偶尔昂贵"）。$n$ 次总代价 $\Theta(n^2)$，规模翻倍 → 耗时 ×4。
- `deque.appendleft(x)`：底层是块状链表（每块约 64 个指针 + 块间双向链表），头部常备空闲槽位，头插只需在头部块写一个槽，块满才分配新块——与动态数组 `append` 同型的摊还论证：每块容量 64，$n$ 次头插只分配 $O(n/64)$ 个新块，摊还 $O(1)$。总代价 $\Theta(n)$，翻倍 → ×2。

**复盘指引**：倍率不接近理论值 → 检查是否取了多次最优、$n$ 是否够大（常数项污染小 $n$）；机制层不清 → 回读第 2 章 2.1–2.2 节与第 1 章 1.4 节。

## 1.6（编程实现）｜出处：1.8 案例 2

> **题目**：写 `estimate_order(f, ns)`：输入可调用对象与一组倍增的 $n$，对 $\log T$ 与 $\log n$ 做线性拟合返回增长阶估计。用 $\Theta(n)$、$\Theta(n\log n)$、$\Theta(n^2)$ 三个真值函数自测。输出目标：斜率分别约 1、1.1–1.3、2。

```python
"""对 (log n, log T) 做最小二乘拟合，斜率即增长阶（实验测阶）。"""
import time, math

def estimate_order(f, ns, reps=3):
    ts = []
    for n in ns:
        best = min(_timeit(f, n) for _ in range(reps))   # 取最优，压系统噪声
        ts.append(best)
    xs = [math.log(n) for n in ns]
    ys = [math.log(t) for t in ts]
    xm, ym = sum(xs) / len(xs), sum(ys) / len(ys)
    slope = sum((x - xm) * (y - ym) for x, y in zip(xs, ys)) \
            / sum((x - xm) ** 2 for x in xs)
    return slope

def _timeit(f, n):
    t0 = time.perf_counter()
    f(n)
    return time.perf_counter() - t0

def f_lin(n):                 # Θ(n)：单循环
    s = 0
    for i in range(n): s += 1
def f_nlogn(n):               # Θ(n log n)：内层折半
    s = 0
    for i in range(n):
        j = 1
        while j < n: j *= 2; s += 1
def f_sq(n):                  # Θ(n²)：双重循环
    s = 0
    for i in range(n):
        for j in range(n): s += 1

ns = [2000, 4000, 8000, 16000]
print("线性:  ", round(estimate_order(f_lin,   ns), 2))
print("nlogn: ", round(estimate_order(f_nlogn, ns), 2))
print("平方:  ", round(estimate_order(f_sq,    ns), 2))
# 预期输出（实测）：线性: 1.06    nlogn: 1.13    平方: 2.02
```

三个斜率 1.06 / 1.13 / 2.02，与输出目标（约 1、1.1–1.3、2）一致（校验值对照：✓）。$\Theta(n\log n)$ 拟合值落在 1 与 2 之间偏下，因为 $\log(n\log n) = \log n + \log\log n$，$\log\log n$ 在此规模区间内近似常数，把斜率抬高约 0.1。

**复盘指引**：斜率系统性偏差 → 检查 $n$ 范围是否覆盖至少两个数量级、是否每次取最优、被测函数是否含 $O(n)$ 的数据准备（要移出计时区）。

## 1.7（开放思考）｜出处：1.2、1.6 节

> **题目**：有人说"NumPy 快是因为它把 Python 循环变成了 C 循环，复杂度没变"。这句话哪里对、哪里不对？

**答案要点（两个维度）：**

1. **"复杂度没变"——多数情况对，但不是定理。** 对同一算法的不同实现（如逐元素运算、`np.dot` 的朴素分块矩阵乘），渐近阶确实不变：NumPy 赚的是**常数因子**——绕过解释器（字节码分发、对象装箱、引用计数全部消失）、SIMD 向量化、多核并行、连续内存的缓存友好（第 2 章 2.1 节）。常数差 10–100 倍在工程上常常"等于换了复杂度"，但严格说增长阶未动。
2. **"复杂度没变"——有时错。** 库可能**换了算法**，阶真的会变：
   - `np.sort` 对整数数组走**基数式**路径（$O(d\,n)$），比比较排序 $O(n\log n)$ 低阶（第 5 章 5.5 节"绕开下界"）；
   - `np.linalg.solve` 用 LU 分解 $O(n^3)$，如果你手写的"逆序消元"是 $O(n^3)$ 但带巨大常数，或有人对最小二乘用正规方程 vs `lstsq`（SVD，$O(mn^2)$ 但数值稳定），阶各不相同；
   - 广播/向量化有时诱导你写出 $O(n^2)$ 的外积大数组，而手写循环本可用 $O(n)$ 递推——**向量化反而让坏算法更容易写出来**（内存也是 $\Theta(n^2)$）。
3. **结论句**：这句话作为经验法则大体成立（"先怀疑阶没变、再怀疑常数"），但正确的算账方式是分别核对"算法换了没有（阶）"与"实现差多少（常数）"——正是 1.6 节算账式的两项输入。

**常见错误答案**：只答"对，NumPy 就是快"（没区分两个维度）；或断言"永远同阶"（被 `np.sort` 的整数路径反例打脸）。

## 1.8（开放思考）｜出处：1.6 节（思路通向第 7 章）

> **题目**：$10^{12}$ 条用户行为日志，统计每个 URL 的出现次数，内存 256 GB。纯内存哈希计数是否可行？若不可行，复杂度的哪一项需要被改变？

**算账（1.6 节四步流程）：**

1. **计算量**：单遍扫描 $10^{12}$ 条、每条一次哈希 + 一次计数更新，$O(N)$，这部分可行（一台机器数小时、集群数分钟）。
2. **内存量**：瓶颈在"每个 distinct URL 一个精确计数器"。设 distinct URL 约 $10^9$（重尾分布下常见的量级），一条 dict 条目 ≈ 键字符串 ~60 B（URL 较长）+ 哈希表槽/条目开销 ~80 B ≈ 140 B，合计 $\approx 1.4\times10^{11}$ B = **140 GB**；还要留哈希表负载因子余量（$\alpha \le 0.75$ → 再 ×1.3 ≈ **180 GB+**）与工作内存。256 GB **没有安全余量**——何况 distinct 数一旦到 $2\times10^9$ 就爆。
3. **结论：纯内存精确计数不可行（临界且脆弱）。** 而且"精确到每个 URL"这个需求本身可能超需求——通常只关心 Top-K 热点。
4. **需要改变的是哪一项？** 不是计算量（$O(N)$ 已最优），而是**"每键 $O(1)$ 精确状态"这一项的空间因子**。两条路：
   - **近似计数**：Count-Min Sketch（第 7 章 7.3.1 节），内存 $O(dw)$ **与 distinct 数无关**，只给单侧过估计——Top-K/热点场景完全够用；
   - **外部聚合**：按 `hash(URL) % K` 把流切成 $K$ 个分区落盘，每分区独立装内存精确计数（MapReduce/数据工程的标准两趟方案，代价是多一遍 I/O）。

**复盘指引**：只会答"内存不够买机器" → 重读 1.6 节算账式，学会指出"复杂度的哪一项"要变；解法细节见第 7 章 7.3 节。

## 1.9（挑战题）｜出处：1.5 节

> **题目**：证明主定理情形 2 的 $k=0$ 版本：若 $f(n) = \Theta(n^{\log_b a})$，则 $T(n) = \Theta(n^{\log_b a}\log n)$。

**核心证明（含 $\Theta$ 的常数处理，这是"每层代价相同"论证容易含糊的地方）。**

记 $p = \log_b a$。设 $T(n) = aT(n/b) + f(n)$，$T(1) = \Theta(1)$；为清晰设 $n = b^L$（一般 $n$ 用单调性/补齐处理，不影响阶）。展开递归树：第 $i$ 层有 $a^i$ 个规模 $n/b^i$ 的子问题，层代价为 $a^i f(n/b^i)$，叶子层 $i = L$，叶子总数 $a^L = b^{L\log_b a} = n^{p}$。

由 $f(n) = \Theta(n^p)$：存在 $c_1, c_2 > 0$ 与 $n_1$，使 $x \ge n_1$ 时 $c_2 x^p \le f(x) \le c_1 x^p$；对 $x < n_1$，令 $C = \max_{x < n_1} f(x)$，则 $f(x) \le C \le C x^p$（因 $x \ge 1$），且 $f(x) \ge 0$。

**关键恒等式**：$a^i (n/b^i)^p = n^p \left(a / b^p\right)^i = n^p$（因 $b^p = a$）。即**每个子问题的"份额"折算到根规模后不变**。

*上界*：

$$T(n) \;\le\; \sum_{i=0}^{L-1} a^i \cdot c_1 \left(\tfrac{n}{b^i}\right)^p \;+\; a^L T(1) \;=\; c_1 L\, n^p + \Theta(n^p) \;=\; O(n^p \log n).$$

（深层 $n/b^i < n_1$ 的项用 $f(x) \le Cx^p$ 同样被 $c'_1 n^p$ 吸收。）

*下界*：取前 $\lfloor \log_b (n/n_1) \rfloor$ 层（这些层子问题规模 $\ge n_1$，下界常数 $c_2$ 有效）：

$$T(n) \;\ge\; \sum_{i=0}^{\lfloor \log_b(n/n_1)\rfloor} a^i \cdot c_2 \left(\tfrac{n}{b^i}\right)^p \;=\; c_2 \lfloor \log_b(n/n_1) \rfloor\, n^p \;=\; \Omega(n^p \log n) \quad (n \ge b\, n_1).$$

上下界夹逼得 $T(n) = \Theta(n^p \log n) = \Theta(n^{\log_b a}\log n)$。$\blacksquare$

**解读**：情形 2 的本质是"**每层代价被 $a^i(n/b^i)^p = n^p$ 冻结**"——分治既不让子问题代价指数衰减（情形 1），也不让合并代价指数膨胀（情形 3），于是 $\log_b n$ 层同价累加出一个 $\log$ 因子。

**复盘指引**：想再进一步，读 CLRS 第 4 章主定理的完整证明（含正则条件的处理），以及第 1 章 1.11 节《具体数学》对这类和式的求和工具。

## 1.10（挑战题）｜出处：1.6 节

> **题目**：查询两篇文献（Spielman & Teng 的 smoothed analysis 论文，及一篇 FlashAttention 论文），各写 200 字摘要：它们各自改变了 1.6 节算账式中的哪一项？

**参考摘要（供对照你的阅读；请务必自己读原文后改写）：**

**① Spielman & Teng, "Smoothed Analysis of Algorithms" (JACM, 2004)。** 经典复杂度分析只有两个口径：最坏输入（悲观到失真：单纯形法最坏指数步，实际却飞快）与平均输入（依赖不现实的均匀分布假设）。Smoothed analysis 引入第三个口径：对**每个**输入施加小幅随机扰动后取期望复杂度 $T'(n) = \max_{I}\ \mathbb{E}_{I'\sim I+\text{noise}}[T(n, I')]$。它改变的算账项是"**输入**"：把 1.6 节算账式中"规模 × 复杂度"里隐含的最坏情形输入替换为"扰动邻域内的期望输入"。结论：单纯形法在扰动意义下是多项式的，第一次从理论上解释了"最坏指数、实践线性"的二十年谜题。这提示我们：工程可行性评估中，"最坏"与"平均"之间还有一档更贴近现实的口径。

**② Dao et al., "FlashAttention" (NeurIPS 2022)。** 精确 attention 的计算量为 $\Theta(n^2 d)$ FLOPs，FlashAttention **没有降低它**——它改变的算账项是"**内存访问（I/O）**"：标准实现要把 $n\times n$ 相似度矩阵完整写入再读出 HBM（IO $\Theta(n^2 + nd)$，且显存 $\Theta(n^2)$），FlashAttention 用 tiling + online softmax 把计算重组为分块、全程只保留 $O(n)$ 级统计量，IO 降到 $\Theta(n^2 d / M)$（$M$ 为 SRAM 大小，实际远小于 $n^2$ 次访存），显存从 $O(n^2)$ 降到 $O(n)$。算账启示：当算术强度低时，**瓶颈项是访存不是 FLOPs**——换一本账（IO 复杂度）才能看清优化赚在哪。

# 第 2 章 线性结构——数组、链表、栈、队列与哈希

## 2.1（概念辨析）｜出处：2.1–2.2 节

> **题目**：为什么 CPython `list` 不实现 `insert(0, x)` 的 $O(1)$ 版本，而 `deque` 可以？两者的"缓存友好性"差异体现在哪？

**答案要点：**

1. **布局决定命运。** `list` 是**连续指针数组**：契约"下标 $i$ 的元素在首地址 + $i\times 8$ 字节处"，$O(1)$ 随机访问、切片零拷贝语义、以及与 C 层 buffer 协议的互操作都建立在这条地址算术上。头部插入若要 $O(1)$，必须预留"头部空闲区"并维护偏移量——这就**不再是连续数组布局**，要么破坏地址算术，要么引入两级寻址。
2. **`deque` 选择了另一种布局：块状链表。** 约 64 个指针一块、块间双向链表 + 头尾块内预留空闲槽。头插/头删 = 在头部块挪一个槽，块满/空才增删整块——按第 1 章的摊还论证（每 64 次操作摊一次块操作），**头尾操作摊还 $O(1)$**。代价是：随机访问需要两级寻址（先算块号、再算块内偏移）且失去全局连续性。
3. **缓存友好性对比**：
   - `list`：完全连续，遍历是"顺序扫过缓存行"的最优形态（一次载入 64 B = 8 个指针全用上）；这也是 NumPy 连续数组和 `list` 遍历速度差的第二个来源（2.1 节）。
   - `deque`：**块内连续、块间跳转**——遍历时块内仍是顺序访问（局部性保留大半），但在块边界处有一次指针跳转 + 可能的缓存行切换；随机访问 `d[i]` 多一次间接层。
   - 结论：**头尾操作频繁 → deque；以随机访问/切片为主 → list**。这是"数组与链表折中"的现实案例，不是谁全面胜出。

**常见错误答案**：说"list 用链表实现所以 insert 慢"（恰好说反）；说"deque 是纯链表所以访问 $O(n)$"（块状结构使它近似 $O(1)$）。

## 2.2（概念辨析）｜出处：2.4 节 + 5.3 节

> **题目**：哈希表的"平均 $O(1)$"与快排的"平均 $O(n\log n)$"各依赖什么假设？哪个的假设在工程上更常被打破？

**答案要点：**

| | 哈希表 平均 $O(1)$ | 快排 平均 $O(n\log n)$ |
|---|---|---|
| 期望对什么取 | 对**键的分布/哈希函数的行为**（简单均匀哈希假设：每键独立等概率落桶） | 对**算法自身的随机性**（随机基准），对**每一个输入**都成立 |
| 假设被谁打破 | 外部：规律键（等差整数、相似字符串）或被恶意构造的键（HashDoS） | 内部随机性不存在才被打破——随机化后**没有坏输入**，只有坏运气（概率指数级小） |
| 工程防御 | 字符串哈希加盐、素数桶数、好哈希函数 | 随机基准/三数取中/内省排序兜底 |

**结论：哈希的假设更常被打破。** 因为它的均匀性假设是对"真实键分布"的外部假设，而真实数据充满结构性（连续 id、模板化 URL）；快排的随机化把期望转移到算法内部抛硬币上，与输入无关——这正是第 5 章 5.3 节"随机化使坏输入与坏行为解耦"的含义。补充口径区分：两者都是"平均/期望"，但**都不是最坏**；哈希最坏 $O(n)$（全撞一桶），快排最坏 $\Theta(n^2)$（固定基准 + 已排序输入）。

## 2.3（计算推导）｜出处：2.4 节（CLRS 11.2）

> **题目**：负载因子 $\alpha = 0.75$ 的链地址哈希表，一次不成功查找期望检查多少个槽？（简单均匀哈希下。）校验值：$1 + \alpha/2 = 1.375$（含定位桶）。

**⚠ 存疑/勘误**：按标准分析（CLRS 11.2），**不成功**查找要把目标桶的整条链扫完才能下结论"不存在"，故期望检查的元素数为链长期望 $= \alpha$（简单均匀哈希下每键独立等概率落 $m$ 桶，$n$ 键 $m$ 桶，$E[\text{链长}] = n/m = \alpha$），加上定位桶本身的一次开销：

$$\boxed{E[\text{不成功查找}] = 1 + \alpha = 1.75 \quad (\alpha = 0.75).}$$

而 $1 + \alpha/2 = 1.375$ 是**成功**查找的公式：要查的键等概率地是 $n$ 个键之一，落在某条链中，期望需要检查"链中它之前的一半"——CLRS 给出 $E = 1 + \frac{\alpha}{2}\left(1 - \frac{1}{n}\right)\cdot\frac{n}{n}$ 量级，即 $\Theta(1 + \alpha/2)$。直观：成功查找平均只扫半条链（找到就停），不成功必须扫全链（找不到才能停）。

**结论**：若题目问的是不成功查找，答案是 $1+\alpha = 1.75$；校验值 1.375 对应的是成功查找的口径。两个推导都要会——这正是 2.9 节误区 3（"`dict` 查找是平均 $O(1)$ 且与负载因子有关"）的定量版。

## 2.4（计算推导）｜出处：2.3 节 + 1.4 节

> **题目**：两栈队列中，最坏单次 dequeue 的代价是多少？$n$ 次 enqueue + $n$ 次 dequeue 的总代价上界是多少？校验值：最坏 $\Theta(n)$；总代价 $\le 3n$。

**答案：最坏 $\Theta(n)$（第一次 dequeue 触发整栈倒灌）；总代价 $\le 3n$**（"元素搬移计 1"口径，证明见第 1 章练习 3 的势能法，此处用记账法对偶表述）：

- 每元素一生最多经历：push 进 A（1）、A→B 搬移（1，至多一次——只有 B 空时才倒灌，搬完即离开）、pop 出 B（1）；
- 记账：enqueue 收 2 代币（1 付本次 push，1 存着付将来的搬移）；dequeue 收 1 代币（付本次 pop）。任何时刻账户非负（搬移发生时该元素的存款恰为 1）；
- 总收费 $= 2n + n = 3n \ge$ 总实际代价。$\blacksquare$

与校验值一致（✓）。直觉：**倒灌的昂贵是"攒出来的"**——能倒灌 $k$ 个元素说明之前攒了 $k$ 次便宜的 enqueue，摊还恰好扯平。这与动态数组扩容、哈希表再哈希是同一模式（1.4 节"偶尔昂贵、通常便宜"）。

## 2.5（编程实现）｜出处：2.5 节

> **题目**：运行并验证 2.5 节 `two_sum_sorted`：手工确认返回下标对应元素之和等于 target；再写暴力对拍函数，随机 1000 组数据验证正确性。输出目标：全部通过。

```python
import random

def two_sum_sorted(nums, target):
    """有序数组两数之和：对撞指针，Θ(n) 时间 O(1) 空间。"""
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target: return (lo, hi)
        if s < target: lo += 1      # 和太小，需要更大的左端
        else:          hi -= 1      # 和太大，需要更小的右端
    return None

def brute(nums, target):
    """朴素双循环：显然正确，作金标准。"""
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return (i, j)
    return None

print(two_sum_sorted([1, 3, 5, 8, 10, 14], 15))
# 预期输出（实测）：(0, 5)   手工核对：nums[0]+nums[5] = 1+14 = 15 ✓

random.seed(0)
ok, solved = 0, 0
for _ in range(1000):
    n = random.randint(2, 12)
    nums = sorted(random.randint(0, 20) for _ in range(n))
    t = random.randint(0, 25)
    r1, r2 = two_sum_sorted(nums[:], t), brute(nums[:], t)
    assert (r1 is None) == (r2 is None), f"存在性不一致: {nums} {t}"
    if r1 is not None:
        assert nums[r1[0]] + nums[r1[1]] == t, f"和校验失败: {nums} {t} {r1}"
        solved += 1
    ok += 1
print(f"1000 组对拍全部通过（其中有解 {solved} 组）")
# 预期输出（实测）：1000 组对拍全部通过（其中有解 389 组）
```

注意对拍只断言"**存在性**一致 + 返回对之和正确"，不断言下标相同——同一数组可能有多个解，两算法找到的解可以不同。

**复盘指引**：错在"对拍断言下标相等" → 想清楚多解情形；对撞指针正确性论证（为什么不会漏解）在正文 2.5 节。

## 2.6（编程实现）｜出处：2.3 节（栈/哈希综合）

> **题目**：实现"最大频率栈"（每次 pop 弹出当前频率最高的元素，同频弹最近压入的），输出目标：对序列 `push(5),push(7),push(5),push(7),push(4),push(5)` 依次 pop 得 `5,7,5,4,7`。

```python
class FreqStack:
    """哈希表(频率) + 按频率分桶的栈。push/pop 均 O(1)。
       关键不变式：同频桶是"按压入时间"的栈 → 同频弹最近；
       maxf 只增不减地跟踪最高频（pop 后桶空才 -1）。"""
    def __init__(self):
        self.freq = {}        # x -> 当前频率（第 2 章哈希表）
        self.group = {}       # 频率 f -> 该频率元素的栈（后进先出）
        self.maxf = 0
    def push(self, x):
        f = self.freq.get(x, 0) + 1
        self.freq[x] = f
        self.group.setdefault(f, []).append(x)
        self.maxf = max(self.maxf, f)
    def pop(self):
        x = self.group[self.maxf].pop()      # 最高频 + 同频最近
        self.freq[x] -= 1
        if not self.group[self.maxf]:        # 该频率桶空了
            del self.group[self.maxf]
            self.maxf -= 1
        return x

fs = FreqStack()
for x in (5, 7, 5, 7, 4, 5): fs.push(x)
print([fs.pop() for _ in range(5)])
# 预期输出（实测）：[5, 7, 5, 4, 7]
```

**逐 pop 解读**：pop 时频率 $\{5{:}3, 7{:}2, 4{:}1\}$，maxf=3 → 弹 5；此后 $\{5{:}2, 7{:}2, 4{:}1\}$，maxf=2，桶 2 = [5,7]（7 后入）→ 弹 7；再弹 5（同频栈顶）；maxf 降回 1 → 弹 4（桶 1 = [4,7,5] 的栈顶……注意 7 与 5 的频率已各降为 1，桶 1 中它们压在 4 之后——4 是最先压入桶 1 的，弹 4 之前它们已先后经桶 2 被弹走，故桶 1 栈顶恰是 4）。与输出目标 `5,7,5,4,7` 完全一致（校验值对照：✓）。

## 2.7（编程实现）｜出处：2.6 节（滑动窗口）

> **题目**：用滑动窗口解决"无重复字符的最长子串"：`"pwwkew"` 的答案为 3（`"wke"`）。输出目标：返回 3。

```python
def length_of_longest_substring(s):
    """变长滑动窗口 + 哈希表记"字符最后出现位置"。
       每个下标至多进出窗口各一次：O(n)。"""
    last, l, best = {}, 0, 0
    for r, ch in enumerate(s):
        if ch in last and last[ch] >= l:   # ch 在窗口内重复 → 左端跳过它
            l = last[ch] + 1
        last[ch] = r
        best = max(best, r - l + 1)
    return best

print(length_of_longest_substring("pwwkew"))     # 3
print(length_of_longest_substring("abcabcbb"))   # 3
print(length_of_longest_substring("bbbbb"))      # 1
# 预期输出（实测）：3 3 1
```

与输出目标一致（返回 3，✓）。**关键细节**：`last[ch] >= l` 判断重复字符是否仍在**当前窗口内**——若在窗口左边界之外（旧记录），不能收缩 $l$（否则 $l$ 会倒退，破坏"指针只单向移动"的摊还 $O(n)$ 论证）。这正是 2.6 节"每元素至多进出各一次"的边界情形。

**复盘指引**：写成朴素双循环 $O(n^2)$ → 重读 2.6 节变长窗口模板；$l$ 倒退 bug → 检查 `last[ch] >= l`。

## 2.8（编程实现）｜出处：2.6 节 + 2.8 案例 2

> **题目**：把 2.8 案例 2 扩展为"流式"版本：实现类 `NGramCounter(n)`，支持 `feed(token)` 与 `top(k)`，内存中只保留最近 $W$ 个 token 的窗口。输出目标：对 feed 流模拟验证与离线版本频次一致。

```python
from collections import deque, defaultdict, Counter

class NGramCounter:
    """流式 n-gram 计数，内存只保留最近 W 个 token 的窗口。
       新 token 进入 → 窗口末端多出一个新 n-gram，计数 +1；
       最老 token 滑出 → 以它开头的那个 n-gram 撤销计数（增量可撤销）。
       每步 O(1)——滑动窗口"统计量可增量维护"的直接应用。"""
    def __init__(self, n, W):
        assert W >= n, "窗口 W 必须不小于 n"
        self.n, self.W = n, W
        self.buf = deque()                 # 当前窗口
        self.counts = defaultdict(int)     # 窗口内 n-gram -> 频次
    def feed(self, token):
        self.buf.append(token)
        if len(self.buf) >= self.n:        # 新形成的 n-gram
            self.counts[tuple(self.buf)[-self.n:]] += 1
        if len(self.buf) > self.W:         # 窗口满：撤销滑出者的 n-gram
            old = self.buf.popleft()
            key = (old,) + tuple(self.buf)[:self.n - 1]
            self.counts[key] -= 1
            if self.counts[key] == 0:
                del self.counts[key]       # 防止冷 key 堆积
    def top(self, k):
        return Counter(self.counts).most_common(k)

toks = "我 喜欢 自然 语言 处理 我 喜欢 深度 学习".split()

# 对拍：每一步都与"当前窗口上的暴力重算"比较（W 取不同值）
import random
random.seed(0)
for W in (2, 3, 5, 20):
    n = 2
    st = NGramCounter(n, W)
    ok = True
    for i, t in enumerate(toks):
        st.feed(t)
        window = toks[max(0, i + 1 - W):i + 1]          # 最近 W 个 token
        brute = defaultdict(int)
        for j in range(len(window) - n + 1):
            brute[tuple(window[j:j + n])] += 1
        if dict(st.counts) != dict(brute):
            print(f"W={W} 第{i}步不一致"); ok = False; break
    print(f"W={W}: {'一致' if ok else '不一致'}, top1 = {st.top(1)}")
# 预期输出（实测）：
# W=2: 一致, top1 = [(('深度', '学习'), 1)]
# W=3: 一致, top1 = [(('喜欢', '深度'), 1)]
# W=5: 一致, top1 = [(('处理', '我'), 1)]
# W=20: 一致, top1 = [(('我', '喜欢'), 2)]
```

$W=20 \ge$ 全句长 9 时退化为离线版，top1 `('我','喜欢'): 2` 与正文 2.8 案例 2 一致（校验值对照：✓）；小 $W$ 时与"窗口内暴力重算"逐步一致，证明增量撤销的正确性。

**复盘指引**：撤销逻辑写错（漏删/多删）→ 回到 2.6 节"统计量必须能增量撤销"与 2.9 节误区 4。

## 2.9（开放思考）｜出处：2.4 节

> **题目**：词表大小 $|V| = 100{,}000$、嵌入维度 $d = 1024$ 时，Embedding 矩阵占多少显存（FP16）？若改为哈希技巧（feature hashing）直接映射到 $2^{18}$ 个槽，节省/损失各是什么？

**显存账**：$|V| \times d \times 2\ \text{B} = 10^5 \times 1024 \times 2 = 2.048\times10^8$ B ≈ **205 MB（FP16）**。（FP32 翻倍至 ~410 MB；对照第 7 章 7.2 节的 250k×4096 ≈ 2 GB，这是"小模型"量级。）

**Feature hashing 到 $2^{18} = 262{,}144$ 个槽：**

- **本例不省矩阵显存**——$2^{18} > 10^5$，槽矩阵反而大 2.6 倍（≈537 MB）。哈希技巧的省内存前提是**键空间开放/远大于槽数**（如十亿级 id 映射到 $2^{20}$ 槽）。
- **真正节省的是**：① 词表本身（token→id 的 dict、字符串存储、训练前定稿流程）全部消失，支持**流式/开放词表**（新 token 即来即算，无 OOV 问题）；② 分布式下无需中心词表同步。
- **损失**：① **冲突**——不同 token 撞同一槽，梯度互相污染。冲突对期望（生日问题）$\approx \binom{|V|}{2}/2^{18} = 4{,}999{,}950{,}000 / 262{,}144 \approx 1.9$ **万对**；② **不可解释/不可反查**（槽 → 无法还原 token，词向量分析、词典对齐都做不了）；③ 频率信息混叠后低频词的embedding质量受损更重。

**一句话**：哈希技巧是"**用可控的混淆换掉一张需要全局协调的表**"，适合开放/超大规模键空间，不适合本例这种"词表不大且需要可解释"的场景。

## 2.10（挑战题）｜出处：2.4 节（查阅 `dictobject.c` 后完成）

> **题目**：研究 CPython `dict` 的紧凑布局：解释 `d = {}; d[0]=0; del d[0]; len(d)` 之后 `list(d)` 为空但 `next(iter(d.values()), None)` 可能残留——提示：entries 数组的空洞（dummy 项）与 indices 的关系。写一段代码验证你的理解。

**机制分析（紧凑有序 dict，Python 3.7+）：**

- `dict` 不把 (key, value) 直接放在哈希桶里，而是：**稠密 `entries` 数组**（按插入序存条目）+ **稀疏 `indices` 数组**（哈希寻址，槽里存"该键在 entries 中的下标"）。
- **删除**条目时：`indices` 对应槽被标记为 `DKIX_DUMMY`（空洞标记，保证探测链不断裂），entries 中该条目作废。`len` 用独立计数器，`list(d)`/`iter(d.values())` 遍历 entries 时跳过空洞——所以**逻辑层看不到已删条目**。
- **物理层的真实残留**（这是本题要抓的点）：① `indices` 的 dummy 标记留在原地，**下一次插入会优先复用 dummy 槽**（探测链因此仍然有效）；② entries/indices 的**分配容量不回缩**——删光元素后 `sys.getsizeof` 不变小，直到下次扩容重排。这两个残留正是"删除很多的 dict 不主动缩容"这一工程坑的根源。

**⚠ 实测勘误**：教材提示语"`next(iter(d.values()), None)` 可能残留"在 **CPython 3.13 实测不成立**——空 dict 的迭代器不产出任何值，`next(..., None)` 返回 `None`；且删除时 key/value 的引用被立即清除（下述 weakref 实测弱引用死亡）。**残留的是"槽位与容量"，不是可迭代出的值。**

**验证代码（实测）：**

```python
import weakref, sys, gc

class Obj: pass

d = {}
v = Obj()
r = weakref.ref(v)              # 弱引用：不阻止对象回收，用于探测"是否仍被引用"
d["k"] = v
del d["k"]
del v; gc.collect()             # 除去本地变量与延迟回收的干扰
print("删除后 len(d) =", len(d), "| entries 仍持有 value(weakref 存活):", r() is not None)
# 预期输出（实测）：删除后 len(d) = 0 | entries 仍持有 value(weakref 存活): False
# → key/value 引用删除即释放；"残留"不在条目本身

d2 = {i: i for i in range(1000)}
size_before = sys.getsizeof(d2)
for i in range(1000):
    del d2[i]
print("清空前 getsizeof =", size_before, "| 清空后 getsizeof =", sys.getsizeof(d2))
# 预期输出（实测）：清空前 getsizeof = 36952 | 清空后 getsizeof = 36952
# → 容量与 indices/entries 分配不回缩；indices 里留有大量 DKIX_DUMMY，等待复用
```

# 第 3 章 树与堆——层次化数据

## 3.1（概念辨析）｜出处：3.4 节

> **题目**：为什么"用数组实现的完全二叉树"（堆）不需要存指针，而普通二叉树不行？这依赖于哪两条性质？

**答案：两条性质。**

1. **形状完全性**：堆是完全二叉树——除最后一层外每层全满、最后一层从左到右填充。于是 $n$ 个节点占据数组下标 $0..n-1$ **无空洞**，"哪里有节点"完全由 $n$ 决定，不需要任何额外信息。普通二叉树形状任意（甚至一条链），数组表示会留下大量空洞（最坏 $2^n$ 个槽放 $n$ 个节点），空间崩溃。
2. **父子下标的代数关系**：完全性使"父/孩子"由下标算术唯一确定：`parent = (i-1)//2`，`children = 2i+1, 2i+2`。导航不需要指针，只需要乘法加法（对比第 2 章 2.1 节数组下标访问的地址算术——同一思想的两次使用）。普通二叉树的父子关系无此规律，必须显式存 `left/right` 指针。

**推论（顺带要会说）**：也正因为数组无洞，堆的树高恰为 $\lfloor\log_2 n\rfloor$，`sift-up/down` 才有 $O(\log n)$ 保证；"满二叉树"（每节点 0 或 2 个孩子）是另一概念，堆要的是"完全"（3.8 节误区 4）。

## 3.2（概念辨析）｜出处：3.2、3.3、3.5 节

> **题目**：哈希表、平衡树、Trie 都能存词表，从"精确查找 / 前缀查找 / 有序遍历 / 最坏复杂度"四个维度填表对比，并指出 BPE 分词器为什么选 Trie（或其变体）而非哈希表。

**对比表：**

| 维度 | 哈希表 | 平衡树（AVL/红黑） | Trie |
|---|---|---|---|
| 精确查找 | 平均 $O(L)$（哈希键长 $L$）期望 $O(1)$ 次比较 | $O(\log|V|)$ 次比较，每次比较 $O(L)$ → $O(L\log|V|)$ | $\Theta(L)$，**与词表规模无关** |
| 前缀查找 | **不支持**（只能逐个枚举） | 支持：$O(\log|V| + \text{输出数})$（定位到前缀区间） | 天然支持：沿前缀下行 $\Theta(|\text{前缀}|)$，子树即所有候选 |
| 有序遍历 | 不支持 | 中序即字典序 | 按字符序 DFS 即字典序 |
| 最坏复杂度 | $O(n)$（全撞一桶/HashDoS） | $O(\log|V|)$ **有保证** | $O(L)$ 稳定；但空间 $\Theta(\text{总字符数})$ 可能膨胀 |

**BPE 分词器为什么选 Trie（或其变体）：**

1. 分词的核心动作是**最长前缀匹配**（正文 3.5 节案例语义）：从当前位置沿 Trie 贪心下行，走到不能再走即得最长可匹配片段——哈希表只能"整词精确查"，回答不了"最长的是哪个前缀"。
2. 词表大（几万到几十万）且查询极高频（每个 batch 数万次），Trie 的 $\Theta(L)$ 与 $|V|$ 无关且无哈希计算的冲突/加盐开销。
3. 分词还常需**枚举某前缀的全部延续**（BPE 的合并候选、WordPiece 的候选打分）——Trie 子树天然给出，哈希表做不到。
4. 现实工程（HuggingFace tokenizers）用 **Trie 的压缩变体 + 双数组**以兼顾空间（3.8 节误区 5：字符集大、前缀共享少时 Trie 会膨胀）。

## 3.3（计算推导）｜出处：3.4 节定理 3.3

> **题目**：含 $n$ 个节点的完全二叉树中，高度为 $h$ 的节点至多有多少个？据此重推建堆 $O(n)$。校验值：至多 $\lceil n/2^{h+1}\rceil$ 个；和为 $2n$。

**第一步：每层节点数上界。** 关键引理：**完全二叉树中，任何节点的子树仍是完全二叉树**（父层的左右填充顺序保证子树内部也是"逐层从左填满"）。于是"高度恰为 $h$"的节点，其子树是高度恰为 $h$ 的完全二叉树，至少含 $2^h$ 个节点（高度 $h$ 的完全二叉树节点数 $\ge 2^h$——前 $h$ 层全满）。这些子树**互不相交**，故

$$\#\{\text{高度为 } h\text{ 的节点}\} \;\le\; \left\lfloor \frac{n}{2^h} \right\rfloor \;\le\; \frac{n}{2^h}.$$

（更紧的 CLRS 界为 $\lceil n/2^{h+1}\rceil$（其练习 6.3-3，对 $h$ 归纳可证；$h=0$ 时给出叶子数 $\lceil n/2\rceil$ 恰好取等）。校验值写的是这个更紧的界，而"和为 $2n$"实际用的是上面较松的 $n/2^h$——两者都正确导出 $O(n)$，见下。）

**第二步：建堆求和。** 从最后一个非叶节点倒序对每个节点下沉，高度 $h$ 的节点下沉代价 $O(h)$：

$$\sum_{h=0}^{\lfloor\log_2 n\rfloor} \frac{n}{2^h}\cdot O(h) \;=\; n\sum_{h\ge 0}\frac{h}{2^h} \;=\; 2n \;=\; O(n),$$

其中 $\sum_{h\ge0} h/2^h = 2$（等比-算术混合级数：对 $\sum x^h = \frac{1}{1-x}$ 两边求导并乘 $x$ 得 $\sum h x^h = \frac{x}{(1-x)^2}$，代 $x = 1/2$ 得 2）。**与校验值"和为 $2n$"一致（✓）**；若用更紧的 $\lceil n/2^{h+1}\rceil$ 逐层界求和则得 $\le n$，同样 $O(n)$。$\blacksquare$

**一句话直觉**：一半节点是叶子（代价 0）、四分之一代价 1……**大多数节点在浅层干便宜的活**，与第 1 章段 C 的等比求和同型。

**对比**：用 $n$ 次 `push`（逐个上浮）建堆是 $\sum O(\log i) = O(n\log n)$——**倒序下沉法严格更快**（正文 3.4 节定理 3.3 的对比）。

## 3.4（计算推导）｜出处：3.3 节

> **题目**：一棵存有 $10^9$ 个键的 B+ 树，节点扇出 $m=1024$，树高至少多少（根不计）？每次 I/O 读 1 个节点，定位一个键需几次 I/O？校验值：高度 3，共 4 次 I/O（含叶子）。

**推导**：$m$ 叉树的第 $k$ 层至多 $m^k$ 个节点；叶子存键，每个叶子约 $m$ 个键，故能容纳的键数随高度**指数增长**：

- 高度 1（只有叶子）：$\le 1024$ 个键；
- 高度 2：$\le 1024^2 \approx 1.05\times10^6$；
- 高度 3：$\le 1024^3 = 2^{30} \approx 1.07\times10^9 \ge 10^9$ ✓；
- 高度 4 才必要当键数超过 $2^{30}$。

（用 $\lceil\cdot\rceil$ 精确算：叶子数 $\ge \lceil 10^9/1024\rceil \approx 976{,}563$，上一层 $\ge \lceil 976563/1024\rceil = 954$，再上一层 $\ge 1$——即根下 3 层内部节点 + 叶子层。）**与校验值一致：高度 3，共 4 次 I/O（✓）**——根不计入"高度"，但定位要从根走：根 → 两层内部节点 → 叶子 = **4 次节点读取 = 4 次 I/O**。

**这题的工程含义**（3.3 节）：$10^9$ 键只要 4 次 I/O，因为树高 $O(\log_m n)$ 中的 $m$ 是 1024 而非 2——**把扇出做大，就把树高摊薄到与 $\log_2 n$ 的 $1/\log_2 m$ 倍**。数据库索引按 16 KB 页对齐、页内二分，本质全是这笔账。

## 3.5（编程实现）｜出处：3.2 节

> **题目**：实现 BST 的"第 k 小元素"（中序第 k 个）与"范围查询 $[a,b]$"。输出目标：对 3.2 节的树，第 3 小为 3，范围 $[2,8]$ 输出 `[2,3,5,8]`。

```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

class BST:
    def __init__(self): self.root = None
    def insert(self, key):
        def _ins(node):
            if node is None: return TreeNode(key)
            if key < node.val:   node.left = _ins(node.left)
            elif key > node.val: node.right = _ins(node.right)
            return node
        self.root = _ins(self.root)

def kth_smallest(root, k):
    """中序迭代（显式栈），第 k 小（k 从 1 计）。O(h + k)——
       不必整棵中序（那要 O(n)），走到第 k 个即停。"""
    stack, node, cnt = [], root, 0
    while stack or node:
        while node:
            stack.append(node); node = node.left
        node = stack.pop(); cnt += 1
        if cnt == k: return node.val
        node = node.right

def range_query(root, a, b):
    """输出 [a,b] 内所有键（升序）。剪枝：节点值 < a 只走右子树，
       > b 只走左子树。O(h + 输出数)。"""
    out = []
    def dfs(node):
        if not node: return
        if a < node.val:   dfs(node.left)      # 左子树可能含 ≥ a 的键
        if a <= node.val <= b: out.append(node.val)
        if node.val < b:   dfs(node.right)
    dfs(root)
    return out

bst = BST()
for k in [5, 2, 8, 1, 3]: bst.insert(k)
print("第3小:", kth_smallest(bst.root, 3))        # 3
print("范围[2,8]:", range_query(bst.root, 2, 8))  # [2, 3, 5, 8]
# 预期输出（实测）：第3小: 3 / 范围[2,8]: [2, 3, 5, 8]
```

与输出目标一致（✓）。**要点**：第 k 小用**迭代中序**而非先全量中序取下标——前者 $O(h+k)$ 且可在大树上早停；范围查询的复杂度是 $O(h + |输出|)$ 而非 $O(n)$，靠的是剪枝（每个节点至多被"路过"常数次：正文 3.2 节"每节点常数 × 节点数"框架的变体）。

## 3.6（编程实现）｜出处：3.4 节（heapq）

> **题目**：用 `heapq` 实现合并 $k$ 个有序列表（$N$ 总长，$O(N\log k)$），并用它实现"从 1000 个已排序的分片文件中取全局 top-100 词频"。输出目标：与 `sorted` 全量合并结果一致。

```python
import heapq, random

def merge_k_lists(lists):
    """k 路归并：小根堆放 k 个"当前队头"，(值, 来源列表号, 位置)。
       每次 pop 全局最小、push 该列表的下一个：O(N log k)。"""
    heap = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(heap)                      # 建堆 O(k)（倒序下沉）
    out = []
    while heap:
        v, i, j = heapq.heappop(heap)
        out.append(v)
        if j + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][j + 1], i, j + 1))
    return out

def topk_across_shards(shards, k):
    """全局 Top-K：各分片已降序，堆放 (负词频, 分片号, 位置)。
       只需 k 次 pop——每个分片只需被读到第 ~k 个元素。O(k log k) 起。"""
    heap = [(-shard[0], si, 0) for si, shard in enumerate(shards) if shard]
    heapq.heapify(heap)
    out = []
    for _ in range(min(k, len(heap))):
        neg, si, j = heapq.heappop(heap)
        out.append(-neg)
        if j + 1 < len(shards[si]):
            heapq.heappush(heap, (-shards[si][j + 1], si, j + 1))
    return out

random.seed(1)
shards = [sorted(random.randint(0, 10**6) for _ in range(random.randint(5, 50)))
          for _ in range(1000)]
merged = merge_k_lists(shards)
print("1000 路归并与 sorted 全量一致:", merged == sorted(x for s in shards for x in s))

freqs = [sorted((random.randint(1, 5000) for _ in range(200)), reverse=True)
         for _ in range(1000)]
print("top-100 一致:",
      topk_across_shards(freqs, 100) == sorted((f for s in freqs for f in s), reverse=True)[:100])
# 预期输出（实测）：1000 路归并与 sorted 全量一致: True
#                  top-100 一致: True
```

与输出目标一致（✓）。**要点**：① 堆元素必须带"来源 + 位置"避免比较冲突，也指示下一个候选；② Top-K 版是"多路归并 + 提前终止"：每个分片最多被读到前 $k$ 个元素，I/O 量从 $O(N)$ 降到 $O(k\cdot\text{分片数})$——这正是外部排序/数据库 `ORDER BY ... LIMIT k` 的骨架（第 5 章 5.12 节）。

## 3.7（编程实现）｜出处：3.5 节 + 3.4 节 Top-K

> **题目**：给 3.5 节 Trie 增加"按词频的自动补全"：`complete` 返回频次最高的 5 个词（节点挂频次，末端用 Top-K 堆）。输出目标：自测词表上与暴力排序结果一致。

```python
import heapq

class Trie:
    def __init__(self):
        self.children = {}      # char -> Trie
        self.is_word = False
        self.freq = 0           # 挂频次（AI 词表的典型附加信息）
    def insert(self, word, freq=1):
        node = self
        for ch in word:
            node = node.children.setdefault(ch, Trie())
        node.is_word = True
        node.freq += freq
    def complete(self, prefix, limit=5):
        """先走到前缀末端，再 DFS 收集所有词尾及其频次，
           用大小 limit 的最小堆取频次 Top-5（O(M log 5)）。"""
        node = self
        for ch in prefix:
            if ch not in node.children: return []
            node = node.children[ch]
        cand = []
        def dfs(t, path):
            if t.is_word: cand.append((t.freq, path))
            for ch, sub in t.children.items():
                dfs(sub, path + ch)
        dfs(node, prefix)
        return [w for f, w in heapq.nlargest(limit, cand)]

vocab = {"deep": 30, "depth": 12, "deer": 25, "dense": 40, "cat": 7, "deepest": 18}
t = Trie()
for w, f in vocab.items(): t.insert(w, f)
got = t.complete("de")
want = [w for f, w in sorted(((f, w) for w, f in vocab.items()
                              if w.startswith("de")), reverse=True)[:5]]
print("complete('de') =", got, "与暴力一致:", got == want)
# 预期输出（实测）：complete('de') = ['dense', 'deep', 'deer', 'deepest', 'depth'] 与暴力一致: True
```

与输出目标一致（✓）。**要点**：① 同频的次序由元组比较决定，生产实现应再加次键（如字典序）保证确定；② 若候选总数 $M$ 极大（前缀命中数万词），堆取 Top-5 是 $O(M\log 5)$，优于全排序 $O(M\log M)$（第 3 章 3.4 节 Top-K 范式）；③ 更进一步可把频次 Top-K 缓存在前缀节点上（空间换时间）。

## 3.8（编程实现）｜出处：3.8 案例 3（对顶堆）

> **题目**：实现对顶堆支持 `delete_median()`，并保持所有操作 $O(\log n)$。输出目标：与"每次重排序求中位数"的朴素实现对拍 1000 组。

```python
import heapq, random

class MedianStream:
    """lo: 大顶堆（存较小半部，以负数模拟）；hi: 小顶堆。
       不变式：len(lo) == len(hi) 或 len(lo) == len(hi) + 1，
              且 max(lo) <= min(hi)。中位数在 lo 顶（奇数个）或两者均值。"""
    def __init__(self):
        self.lo, self.hi = [], []
    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))  # lo 的最大者去 hi
        if len(self.hi) > len(self.lo):                    # 保持 lo ≥ hi
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def delete_median(self):
        if not self.lo: raise ValueError("empty")
        heapq.heappop(self.lo)                # 中位数恰在 lo 顶（lo 多 1 或相等时取 lo）
        if len(self.lo) < len(self.hi):       # 重新平衡（O(log n)）
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def median(self):
        if not self.lo: raise ValueError("empty")
        return -self.lo[0] if len(self.lo) > len(self.hi) \
               else (-self.lo[0] + self.hi[0]) / 2

random.seed(2)
ok = 0
for _ in range(1000):
    s, data = MedianStream(), []
    for _ in range(random.randint(1, 40)):
        x = random.randint(-100, 100)
        s.add(x); data.append(x)
        sd = sorted(data)
        m2 = sd[len(sd)//2] if len(sd) % 2 else (sd[len(sd)//2-1] + sd[len(sd)//2]) / 2
        assert s.median() == m2, f"FAIL add: {data}"
        if random.random() < 0.5 and data:
            s.delete_median()
            data.remove(sd[len(sd)//2] if len(sd) % 2 else sd[len(sd)//2 - 1])
            if data:
                sd2 = sorted(data)
                m3 = sd2[len(sd2)//2] if len(sd2) % 2 else (sd2[len(sd2)//2-1] + sd2[len(sd2)//2]) / 2
                assert s.median() == m3, f"FAIL del: {data}"
    ok += 1
print("MedianStream 1000 组对拍通过:", ok == 1000)
# 预期输出（实测）：MedianStream 1000 组对拍通过: True
```

与输出目标一致（✓）。**要点**：中位数永远位于 `lo` 顶（本实现约定奇数时 lo 多 1），删除后只需一次跨堆搬运恢复大小不变式；`lo/hi` 之间无需重新排序——**两个堆各自维持内部堆序，跨堆只有"堆顶"界面接触**，这是所有操作保持 $O(\log n)$ 的原因。

## 3.10（挑战题）｜出处：3.2、3.3 节 + 文献

> **题目**：证明随机插入序的 BST 期望高度为 $O(\log n)$（提示：期望深度分析，参考 CLRS 12.4 节），再阅读 "Learned Index Structures"（Kraska et al., SIGMOD 2018）摘要，写 200 字：它用模型替换了树路径中的哪一步，为什么可行？

**证明路线与关键步骤（分层给出）：**

1. **建模**：按随机排列依次插入 $n$ 个键的 BST，等价于"随机二叉搜索树"：每个键成为根的概率均等 $1/n$，左右子树规模 $(i-1, n-i)$ 等概率——结构与"随机快排的递归划分树"同构。这是把 BST 高度问题翻译成快排递归深度的入口。
2. **期望深度 $O(\log n)$（热身）**：任一已存在键被比较的期望次数（成功查找代价）满足 $E[C_n] = 1 + \frac{1}{n}\sum_{i=1}^n \left(\frac{i-1}{n}\cdots\right)$，经典结果 $E[\text{成功查找比较数}] = 2\left(1 + \frac1n\right)H_n - 3 = O(\log n)$（$H_n$ 调和数）。平均深度受控。
3. **高度 $O(\log n)$（主体）**：平均深度不蕴含高度，需控制尾部。设 $Y_n$ 为随机 BST 高度，满足 $Y_n = 1 + \max(Y_{I}, Y_{n-1-I})$，$I$ 均匀于 $\{0..n-1\}$。CLRS 12.4 的策略：证 $P(Y_n > t)$ 关于 $t$ 指数衰减——用归纳法证明存在常数 $c$ 使 $P(Y_n \le c\ln n) \ge 1 - 1/n^{\alpha}$：把"深度超过 $t$"的事件分解到**路径上逐层分支**，每层"子问题规模缩小到 $\beta$ 倍以下"的概率有正常数下界（因为根的秩以概率 $\ge 1/4$ 落在中间一半，使两侧子树规模 $\le 3n/4$），$t$ 层连续不缩水才能让深度超过 $t$，概率 $\le (3/4)^t$ 量级；对 $n$ 条可能的路径做并集界，得 $P(h > c\log n) \le n(3/4)^{c\log n} \to 0$。取 $c$ 足够大即 $E[h] = O(\log n)$（严谨版本见 CLRS 12.4 的 $P(Y_n > t) \le \cdots$ 推导）。
4. **对照记忆**：这与快排"期望 $O(n\log n)$、最坏 $O(n^2)$ 但随机化后坏输入概率极小"是同一个数学（第 5 章 5.3 节）；BST 的"按有序序列插入退化为链"对应快排的"已排序输入 + 固定基准"。

**Learned Index 200 字参考摘要：** Kraska 等观察到：若把有序键看作单调函数 $key \mapsto position$，B+ 树做的事本质上是**用一棵树逐步逼近这个累积分布函数（CDF）**——树路径中的每一步比较都是对 CDF 的分段线性修正。Learned Index 用训练好的回归模型（CDF 估计器）直接预测键的位置，替换了树路径中的**"逐层下行比较定位"**这一步；预测误差（模型对 CDF 的偏差有界）用极小的备用区域/最后一层修正兜底。可行性的前提是数据分布**稳定且可学习**（静态、归档型索引），因此它对写入频繁的负载不友好——这是"模型换结构"的经典边界案例。

# 第 4 章 图算法——关系与结构

## 4.1（概念辨析）｜出处：4.2 节

> **题目**：BFS 用队列、DFS 用栈——交换容器会发生什么？分别举一个"必须 BFS"与"必须 DFS"的问题说明。

**答案要点：**

1. **BFS 换成栈**：失去"按层扩散"的 FIFO 语义，节点以深度优先的次序被扩展——你得到一个（遍历序不规范的）**DFS**。直接后果：`dist[v] = dist[u] + 1` 的赋值不再保证是最短跳数（首次到达 ≠ 最近层），**无权最短路失效**。有趣的是"连通分量/可达性"这类只问"到不到"的问题仍然正确——它们对遍历序不敏感。
2. **DFS 换成队列**：你得到一种"波状但乱序"的遍历：路径被频繁打断，**回溯语义消失**。依赖"当前路径"的结构信息全部失效——递归/迭代栈里保存的祖先链（判环的"回真祖先"、割点/桥的低链接计算、拓扑序的后序输出）无从谈起。
3. **必须 BFS**：无权图单源最短跳数（性质 4.1 由 FIFO 的按层处理保证）；多源头同步扩散（如多源泄漏模拟、社交度分层）。
4. **必须 DFS**：需要"完整走完一条路径再回头"的结构信息——拓扑排序的 DFS 版（完成时间的逆序）、有向图环检测（灰/白/黑三色 + 回真祖先）、割点/桥/强连通分量（Kosaraju/Tarjan 的第一遍必须按 DFS 完成时间）。

**常见错误**：认为"换容器只是遍历序变变"——对可达性成立，对**距离与结构性质**不成立；这正是 4.2 节"两种遍历，两种哲学"的要点。

## 4.2（概念辨析）｜出处：4.4 节

> **题目**：为什么 Dijkstra 的正确性证明在负权边下失效？构造一个 3 节点带一条负边的反例并手工执行 Dijkstra 展示错误结果。

**失效点**：定理 4.3 的贪心定型依赖"**往后走不会更便宜**"（$w\ge 0$）。取出当前 $d$ 最小的 $u$ 并永久定型时，论证用的是"任何绕路的替代路径必经过某个未定型节点 $y$，而 $d[y] \ge d[u]$"——负权边使 $d[y] + (\text{负边及后续})$ 可以**小于**已定型的 $d[u]$，"定型"失去了永久性。

**3 节点 + 1 下游节点的反例**（3 节点时惰性删除版 Dijkstra "碰巧"显示正确 dist，需加一个下游节点 $t$ 让"过早定型"造成真实错误）：

边：$s\to a = 1$，$s\to b = 2$，$b\to a = -5$，$a\to t = 1$。**正确最短路**：$d[a] = 2 + (-5) = -3$，$d[t] = -3 + 1 = -2$。

手工执行 Dijkstra（惰性堆版）：

| 轮 | 弹出 | 动作 |
|---|---|---|
| 1 | $s\,(0)$ | **定型** $s$；松弛：$d[a]=1$，$d[b]=2$ |
| 2 | $a\,(1)$ | **定型** $a$（此刻 $a$ 尚有更优路径 $s\to b\to a = -3$ 未被发现！）；松弛：$d[t] = 1+1 = 2$ |
| 3 | $b\,(2)$ | **定型** $b$；松弛：$d[a] = 2-5 = -3 < 1$，更新 $d[a]=-3$ 并入堆——**但 $a$ 已在 done 集合，此后被跳过** |
| 4 | $a\,(-3)$ | $a \in$ done → **跳过**：不再用它松弛 $t$ |

**结果（实测）**：$d[a] = -3$（碰巧 dist 表被更新），但 $d[t] = 2 \ne -2$——**$t$ 的答案错误**，因为 $t$ 的正确路径必须经过"已被定型"的 $a$ 的修正值。

```python
# 实测（CPython 3.13）：
# Dijkstra: {'s': 0.0, 'a': -3.0, 'b': 2.0, 't': 2.0}
# Bellman-Ford: {'s': 0.0, 'a': -3.0, 'b': 2.0, 't': -2.0}   ← 正确值
```

**复盘指引**：判断"敢不敢用 Dijkstra"的规则在 4.9 节误区 1——边权来自距离/时间/损失才敢用；负权（收益、对数概率）用 Bellman-Ford/Johnson。

## 4.3（计算推导）｜出处：4.4 节

> **题目**：对边集 $(s,a,4),(s,b,1),(b,a,2),(a,c,5),(b,c,8),(a,t,12),(c,t,3)$ 手工执行 Dijkstra，给出每个节点的定型顺序与最终距离。校验值：$d[s]=0,d[b]=1,d[a]=3,d[c]=8,d[t]=11$。

**完整执行表**（惰性堆，每行一次定型）：

| 轮 | 弹出（定型） | 松弛动作 | 堆中现存（含过期项） |
|---|---|---|---|
| 1 | $s=0$ | $d[a]=4$，$d[b]=1$ | $(1,b),(4,a)$ |
| 2 | $b=1$ | $d[a]=\min(4,\,1+2)=3$（更新，$(4,a)$ 作废）；$d[c]=1+8=9$ | $(3,a),(4,a)^*,(9,c)$ |
| 3 | $a=3$ | $d[c]=\min(9,\,3+5)=8$（更新，$(9,c)$ 作废）；$d[t]=3+12=15$ | $(8,c),(4,a)^*,(9,c)^*,(15,t)$ |
| 4 | $c=8$ | $d[t]=\min(15,\,8+3)=11$（更新，$(15,t)$ 作废） | $(11,t),(15,t)^*,\dots$ |
| 5 | $t=11$ | 无出边 | 残留过期项，全部作废 |

**定型顺序：$s, b, a, c, t$；最终距离 $d[s]=0,\ d[b]=1,\ d[a]=3,\ d[c]=8,\ d[t]=11$——与校验值一致（✓）。**

注意两个容易手算错的点：① 第 2 轮 $b$ 先于 $a$ 定型（$1 < 3$）——因为 $s\to b$ 直达比 $s\to a$ 便宜；② $c$ 的距离由 $a$ 松弛为 8 而非 $b$ 的直连 9——"直达边未必更短"是 Dijkstra 手算的第一陷阱。代码实测见第 4 章第 6 题脚本（同一 `dijkstra` 函数）。

## 4.5（编程实现）｜出处：4.3 节（Kahn）

> **题目**：实现"课程表问题"（LeetCode 210）：`numCourses` 门课、先修约束数组，返回一个合法修读顺序；若有环返回空。输出目标：`[[1,0],[2,0],[3,1],[3,2]]` 上输出 `[0,1,2,3]` 或 `[0,2,1,3]`。

```python
from collections import deque

def find_order(num_courses, prerequisites):
    """拓扑排序（Kahn）。prerequisites 中 [a, b] 表示先修 b 才能修 a → 边 b→a。
       O(n + m)。摘不完（有环）返回 []。"""
    adj = [[] for _ in range(num_courses)]
    indeg = [0] * num_courses
    for a, b in prerequisites:
        adj[b].append(a); indeg[a] += 1
    q = deque(i for i in range(num_courses) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return order if len(order) == num_courses else []

print(find_order(4, [[1, 0], [2, 0], [3, 1], [3, 2]]))   # [0, 1, 2, 3]
print(find_order(2, [[1, 0], [0, 1]]))                    # []（有环）
# 预期输出（实测）：[0, 1, 2, 3] / []
```

与输出目标一致（✓）。**要点**：① 边方向别弄反——约束 `[a,b]` 是"b 是 a 的先修"，边从先修指向后修（依赖箭头方向与"学习顺序"一致，Kahn 摘入度 0 = 先修已满足）；② 环的检测是"摘不完"：`len(order) < numCourses`，这正是正文 4.3 节"若摘不完说明有环"；③ 需要字典序最小的方案时把队列换成堆（4.9 节误区 4）。

## 4.6（编程实现）｜出处：4.6 节

> **题目**：实现 Prim 的惰性堆版本，并与 Kruskal 在 200 个随机点（欧氏距离）生成的完全图上比对总权一致（浮点容差内）。

```python
import random, heapq, math

def kruskal(n, edges):
    """edges: (w, u, v)。O(m log m)。DSU 判环。"""
    parent = list(range(n)); rank = [0] * n
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]; x = parent[x]   # 路径压缩（折半版）
        return x
    total, picked = 0.0, []
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:
            if rank[ru] < rank[rv]: ru, rv = rv, ru
            parent[rv] = ru
            if rank[ru] == rank[rv]: rank[ru] += 1
            total += w; picked.append((u, v, w))
    return total, picked

def prim_lazy(n, edges):
    """惰性堆 Prim：起点 0，横跨边全部入堆，弹出时过期跳过。O(m log m)。"""
    adj = [[] for _ in range(n)]
    for w, u, v in edges:
        adj[u].append((w, v)); adj[v].append((w, u))
    seen = [False] * n
    pq = [(0.0, 0, -1)]
    total, picked = 0.0, []
    while pq:
        w, u, p = heapq.heappop(pq)
        if seen[u]: continue          # 过期横跨边（惰性删除）
        seen[u] = True; total += w
        if p != -1: picked.append((p, u, w))
        for wv, v in adj[u]:
            if not seen[v]: heapq.heappush(pq, (wv, v, u))
    return total, picked

random.seed(3)
pts = [(random.uniform(0, 100), random.uniform(0, 100)) for _ in range(200)]
edges = []
for i in range(200):
    xi, yi = pts[i]
    for j in range(i + 1, 200):
        edges.append((math.hypot(xi - pts[j][0], yi - pts[j][1]), i, j))
t1, _ = kruskal(200, edges)
t2, p2 = prim_lazy(200, edges)
print(f"Kruskal={t1:.6f}  Prim={t2:.6f}  一致(1e-6): {abs(t1-t2) < 1e-6}, Prim 边数={len(p2)}")
# 预期输出（实测）：Kruskal=934.139108  Prim=934.139108  一致(1e-6): True, Prim 边数=199
```

与输出目标一致（✓；200 点的 MST 恰 199 条边）。**要点**：① 惰性堆 Prim 的"过期边"= 弹出时两端已同在树内的边，`seen` 检查等价于第 4 章案例 1 的"堆里两个 $b$"现象；② 完全图 $m = \Theta(n^2)$，两者都是 $O(m\log m)$——稠密图用朴素 $O(n^2)$ 数组版 Prim 更优（4.4 节复杂度讨论的对偶）。

## 4.7（编程实现）｜出处：4.8 案例 2

> **题目**：扩展案例 2，给 `Graph` 增加 tanh 激活节点（grad_fn 用 $1-\tanh^2$），构建两层小网络 $L=(\tanh(w_2\tanh(w_1 x+b_1))+b_2-1)^2$，数值梯度（中心差分）对拍解析梯度。输出目标：相对误差 $<10^{-6}$。

**⚠ 先勘误**：教材案例 2 的 `Graph.topo()` 把入度只建在 `self.nodes` 上，而叶子（`x, w`）从未注册为节点——`indeg` 中没有 0 度节点，`topo()` 返回空表，**原样运行 `forward` 即抛 `KeyError`**（本册已实测复现）。修正：`topo()` 只统计"**节点→节点**"的依赖边（叶子由 `forward` 预载入 `val`，不参与入度）。修正后教材案例输出 `L = 1.0`、`dL/dx = -2.0 dL/dw = -4.0`，与正文预期一致。以下用修正版完成本题：

```python
from collections import deque
import math

class Graph:
    """修正版迷你自动微分：topo 只统计节点→节点依赖（叶子不算入度）。
       约定：grad_fn 返回"列表"，与 inputs 一一对应（单输入节点也要包一层 [ ]）。"""
    def __init__(self):
        self.nodes = {}; self.adj = {}
    def add(self, name, op, inputs, grad_fn):
        self.nodes[name] = (op, inputs, grad_fn)
        for inp in inputs:
            if inp in self.nodes:                # 只有"已是节点"的才连边
                self.adj.setdefault(inp, []).append(name)
    def topo(self):
        indeg = {u: 0 for u in self.nodes}
        for name, (_, inputs, _) in self.nodes.items():
            for i in inputs:
                if i in self.nodes: indeg[name] += 1
        q = deque(u for u in self.nodes if indeg[u] == 0)
        order = []
        while q:
            u = q.popleft(); order.append(u)
            for v in self.adj.get(u, []):
                indeg[v] -= 1
                if indeg[v] == 0: q.append(v)
        return order
    def forward(self, leaf_values):
        val = dict(leaf_values)
        for name in self.topo():                  # 前向：拓扑序
            op, inputs, _ = self.nodes[name]
            val[name] = op(*[val[i] for i in inputs])
        return val
    def backward(self, leaf_values, output):
        val = self.forward(leaf_values)
        grads = {output: 1.0}
        for name in reversed(self.topo()):        # 反向：逆拓扑序
            if name not in grads: continue
            op, inputs, grad_fn = self.nodes[name]
            for i, g in zip(inputs, grad_fn(grads[name], val)):
                grads[i] = grads.get(i, 0.0) + g  # 多路径梯度累加
        return grads

g = Graph()
g.add("h",  lambda x, b1, w1: w1*x + b1, ["x", "b1", "w1"],
      lambda gh, v: [gh*v["w1"], gh, gh*v["x"]])               # 线性层梯度
g.add("t1", lambda h: math.tanh(h), ["h"],
      lambda gt, v: [gt * (1 - math.tanh(v["h"])**2)])         # d tanh = 1 - tanh²
g.add("z",  lambda t1, b2, w2: w2*t1 + b2, ["t1", "b2", "w2"],
      lambda gz, v: [gz*v["w2"], gz, gz*v["t1"]])
g.add("t2", lambda z: math.tanh(z), ["z"],
      lambda gt, v: [gt * (1 - math.tanh(v["z"])**2)])
g.add("L",  lambda t2: (t2 - 1)**2, ["t2"],
      lambda gL, v: [2*(v["t2"] - 1)*gL])

leaf = {"x": 0.7, "b1": 0.1, "w1": -0.4, "b2": -0.2, "w2": 1.3}
grads = g.backward(leaf, "L")

def num_grad(leaf, name, eps=1e-6):               # 中心差分数值梯度
    up, dn = dict(leaf), dict(leaf)
    up[name] += eps; dn[name] -= eps
    return (g.forward(up)["L"] - g.forward(dn)["L"]) / (2 * eps)

max_rel = 0.0
for k in ["x", "b1", "w1", "b2", "w2"]:
    ng = num_grad(leaf, k)
    rel = abs(grads[k] - ng) / max(abs(grads[k]), abs(ng), 1e-12)
    max_rel = max(max_rel, rel)
    print(f"{k:>4}  解析={grads[k]: .8f}  数值={ng: .8f}  相对误差={rel:.2e}")
print("最大相对误差 < 1e-6:", max_rel < 1e-6)
# 预期输出（实测）：
#    x  解析= 1.18230294  数值= 1.18230294  相对误差=5.53e-12
#   b1  解析=-2.95575736  数值=-2.95575736  相对误差=6.19e-11
#   w1  解析=-2.06903015  数值=-2.06903015  相对误差=7.89e-12
#   b2  解析=-2.34812512  数值=-2.34812512  相对误差=7.27e-11
#   w2  解析= 0.41815616  数值= 0.41815616  相对误差=9.08e-10
# 最大相对误差 < 1e-6: True
```

与输出目标一致（相对误差 $\sim 10^{-10} \ll 10^{-6}$，✓）。**要点**：① 逆拓扑序保证算 $\partial L/\partial u$ 时其所有下游梯度已累加完毕——4.3 节"反向传播 = 逆拓扑序"的亲手验证；② `zip(inputs, grad_fn(...))` 要求梯度**列表**与输入对齐；③ 数值梯度用中心差分 $O(\varepsilon^2)$ 精度，$\varepsilon=10^{-6}$ 是 FP64 的甜点。

## 4.8（编程实现）｜出处：4.5 节

> **题目**：用 DSU 判断无向图是否有环，并用 1000 组随机图与自写 DFS 判环对拍。

```python
import random

def has_cycle_dsu(n, edges):
    """无向图成环 ⟺ 某条边的两端已连通（加入它时 find 相同）。"""
    parent = list(range(n)); rank = [0] * n
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]; x = parent[x]
        return x
    for u, v in edges:
        ru, rv = find(u), find(v)
        if ru == rv: return True
        if rank[ru] < rank[rv]: ru, rv = rv, ru
        parent[rv] = ru
        if rank[ru] == rank[rv]: rank[ru] += 1
    return False

def has_cycle_dfs(n, edges):
    """DFS 判环（无向图）：遇"已着色且不是父亲"的邻居即成环。
       显式栈版；color: 0 未访问 / 1 在当前路径 / 2 完成。"""
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v); adj[v].append(u)
    color = [0] * n
    for s in range(n):
        if color[s]: continue
        stack = [(s, -1)]; color[s] = 1
        while stack:
            u, p = stack[-1]
            advanced = False
            while adj[u]:
                v = adj[u].pop()
                if v == p: continue          # 回父边不算环（4.9 节误区 2）
                if color[v] == 1: return True
                if color[v] == 0:
                    color[v] = 1; stack.append((v, u)); advanced = True; break
            if not advanced:
                stack.pop(); color[u] = 2
    return False

random.seed(4)
agree = 0
for _ in range(1000):
    n = random.randint(2, 10)
    m = random.randint(0, n * (n - 1) // 2)
    pairs = random.sample([(i, j) for i in range(n) for j in range(i + 1, n)], m)
    agree += (has_cycle_dsu(n, pairs) == has_cycle_dfs(n, pairs))
print("DSU vs DFS 1000 组随机图一致:", agree == 1000)
# 预期输出（实测）：DSU vs DFS 1000 组随机图一致: True
```

与输出目标一致（✓）。**要点**：① DSU 判环只需一次遍历，$O(m\,\alpha(n))$；DFS $O(n+m)$ 且必须处理"回父边"（无向图边在邻接表里出现两次）；② 重边/自环的语义要在实现前说清（本对拍用简单图）。

> **题目**：RAG 系统要从知识图谱抽取"实体 A 到实体 B 两跳内"的证据子图。估计当图有 $10^9$ 三元组、平均出度 10 时，从单个实体出发的两跳枚举代价；解释为什么工业界要加"关系类型过滤 + 度上限剪枝"。

**参考答案：** 平均意义下代价很小：一跳枚举出边 ~10 条，两跳 $10\times 10 = 100$ 次边访问，加上路径组织 $O(110)$——这是"平均出度 10"的**均值幻觉**。真实知识图谱的出度是**幂律**的：头部实体（"中国""美国""某明星"）出度可达 $10^5$–$10^7$。若 A 或中间实体撞上一个出度 $10^6$ 的 hub，两跳枚举膨胀到 $10^{12}$——单查询秒级到分钟级，且 P99 延迟由这些尾部查询决定（在线服务的关键指标恰是 P99 而非均值）。**关系类型过滤**把每跳的分支因子从"全部关系"压到"目标关系类型"（如只沿"出生于""属于"扩展），常把 10 降到 1–2；**度上限剪枝**在枚举时跳过/采样子数超阈值的实体（或预计算 hub 的"精选邻居"），把最坏代价封顶。两者共同把查询代价从"取决于图的全局幂律尾部"改造为"有界常数"——本质是 4.2 节 $O(n+m)$ 遍历在**局部子图**上做文章，用语义信息（关系类型）换遍历宽度。

## 4.10（挑战题）｜出处：4.6 节（+第 6 章交换论证）

> **题目**：证明 MST 的切割性质，并用它完整证明 Kruskal 的正确性（交换论证）。再证明：若边权互不相同，则 MST 唯一。

**一、切割性质。** 命题：$(S, V\setminus S)$ 是图 $G$ 的任一切割，$e$ 是横跨该割的**最小权**边，则存在一棵包含 $e$ 的 MST。

*证明*：设 $T$ 为任意 MST。若 $e \in T$，完毕。否则 $T + e$ 含唯一环，该环横跨切割的边数必为**偶数**（沿环走一圈，跨越割的次数必为偶数次），故环上除 $e$ 外还有另一条横跨边 $e' \ne e$。$T' = T - e' + e$ 仍是生成树（去掉环上一边仍连通），且 $w(T') = w(T) + w(e) - w(e') \le w(T)$（因 $e$ 是横跨最小权边，$w(e) \le w(e')$）。$T$ 是 MST → $T'$ 也是 MST 且含 $e$。$\blacksquare$

**二、Kruskal 正确性（交换论证/归纳）。** 命题：Kruskal 输出的边集是 MST。按 Kruskal 的接受顺序 $e_1, e_2, \dots, e_{n-1}$ 归纳证明：**前 $k$ 条被接受的边可扩充为某棵 MST**（即 $F_k \subseteq$ 某 MST）。

- $k=0$：空集平凡。
- 归纳步：设 $F_{k-1} \subseteq T^*$（某 MST）。Kruskal 接受 $e_k$ 时，$e_k$ 连接 $F_{k-1}$ 的两个不同连通块；考虑 $F_{k-1}$ 的连通块划分给出的切割，$e_k$ 横跨它。断言 $e_k$ 是该割的最小权横跨边：设权更小的横跨边 $f$ 存在，Kruskal 按权升序处理，处理 $f$ 时 $f$ 的两端尚未被 $F_{k-1}$ 连通吗？——$f$ 横跨当前切割意味着其两端属于 $F_{k-1}$ 的不同块，而 Kruskal 弃掉 $f$ 只能因为当时两端已连通，即已被**当时更早接受的边**连通；这些边都会被保留到 $F_{k-1}$（接受的边不撤销），矛盾。故 $e_k$ 是横跨最小（或并列最小）。
- 由切割性质，存在含 $e_k$ 的 MST $T'$；若 $e_k \notin T^*$：$T^* + e_k$ 的环横跨该割，取环上另一横跨边 $e'$（$e'\notin F_{k-1}$，因 $e'$ 横跨 $F_{k-1}$ 的块间切割），交换得 $T'' = T^* - e' + e_k$，$w(T'') \le w(T^*)$ → $T''$ 是含 $F_{k-1}\cup\{e_k\}$ 的 MST。归纳完成，$k = n-1$ 时 Kruskal 边集即 MST。$\blacksquare$

**三、边权互不相同 ⇒ MST 唯一。** 反证：设 $T \ne T'$ 均为 MST，$e$ 为 $T \triangle T'$ 中**权最小**的边，不妨 $e \in T$。考虑 $T' + e$：含唯一环，环上取一条不在 $T$ 中的边 $e'$（存在：若环上所有边都在 $T$ 中，则 $T$ 含环，矛盾）。由 $e$ 的最小性 $w(e) < w(e')$（互不相同且 $e\ne e'$）。$T' - e' + e$ 是生成树且权严格更小——与 $T'$ 是 MST 矛盾。$\blacksquare$

（顺带解释了第 4 章第 6 题中"若权有并列，不同算法的选边集合可能不同但总权必相同"。）

## 5.1（概念辨析）｜出处：5.3 节

> **题目**：给出一个具体的输入与基准选择，使固定末位基准的快排退化为 $\Theta(n^2)$；说明随机化如何以概率语言重新表述"最坏情况"。

**反例**：输入 $[1, 2, \dots, n]$（已升序），固定取末位为基准。每轮划分：基准 $n$ 是最大值，所有元素 $< n$，Lomuto 划分后 $p = n-1$，左段 $n-1$ 个、右段空——每层只把规模减 1，比较次数 $\sum_{k=1}^{n} k = \Theta(n^2)$。（降序输入同理；正文 5.10 案例 1 的不变式可逐行核对这一退化。）

**随机化的概率重述**：固定基准时"坏输入"是**确定的输入性质**（有序）；随机基准后，坏行为不再联系于输入，而是**随机变量**：对**每一个**输入，期望比较次数 $\mathbb{E}[C] \le 2n\ln n = O(n\log n)$（定理 5.1 的 $\sum_{i<j}\frac{2}{j-i+1}$ 分析），且尾概率有界（由 Markov 不等式 $P[C \ge 4n\ln n] \le 1/2$，更强的界可给出指数衰减）。**表述转换**："存在坏输入导致 $O(n^2)$" → "对任意输入，$O(n^2)$ 的概率 ≤ δ，可通过多次独立重跑把 δ 压到任意小"——拉斯维加斯式（结果总对，时间以高概率接近期望）。

## 5.2（概念辨析）｜出处：5.1 节

> **题目**：稳定性为什么在"先按时间排再按 id 排"这类需求中是**正确性**问题而非性能问题？

**答案要点：** 多关键字排序的规范语义是"按 (主键, 次键) 的字典序"。实现手法"先按次键（时间）排、再按主键（id）稳定排"之所以正确，依赖第二步**保留**第一步在同主键内部的次键序——这正是稳定性的定义（5.1 节：键相等的记录保持原有相对顺序）。若第二步不稳定：同 id 的记录在第二步中相对次序被打乱，**输出的"id 内时间有序"这一功能规格被破坏**——程序不是"慢一点"或"常数大一点"，而是**输出错误**。类比：这不是缓存未命中（性能），是算错答案（正确性）。补救手段（若没有稳定排序）：把原下标并入比较键 `(id, 原位置)` 或 `(主键, 次键)` 复合键排序——用额外空间与比较代价换回正确性；`np.argsort` 默认不稳定、需 `kind='stable'` 或 `np.lexsort`（5.1 节工程提示）。

## 5.3（计算推导）｜出处：5.5 节

> **题目**：用积分估计证明 $\log_2 n! = n\log_2 n - (\log_2 e)n + O(\log n)$，从而下界定理中的 $\Omega(n\log n)$ 是紧的。

**推导**：$\log_2 n! = \sum_{k=1}^{n}\log_2 k$。因 $f(x) = \log_2 x$ 单调增，对 $k = 2,\dots,n$ 有 $\int_{k-1}^{k}\log_2 x\,dx \le \log_2 k \le \int_{k}^{k+1}\log_2 x\,dx$，求和：

$$\int_{1}^{n}\log_2 x\,dx \;\le\; \log_2 n! \;\le\; \int_{1}^{n+1}\log_2 x\,dx.$$

由 $\int \log_2 x\,dx = \dfrac{x\ln x - x}{\ln 2} = x\log_2 x - (\log_2 e)\,x$：

- 下界 $= n\log_2 n - (\log_2 e)n + \log_2 e$；
- 上界 $= (n+1)\log_2(n+1) - (\log_2 e)(n+1) + \log_2 e = n\log_2 n - (\log_2 e)n + O(\log n)$（展开 $(n+1)\log_2(n+1) = n\log_2 n + \log_2 n + O(1)$）。

上下界之差 $O(\log n)$，故 $\log_2 n! = n\log_2 n - (\log_2 e)n + O(\log n)$。$\blacksquare$

（与 Stirling 主项 $n!\approx\sqrt{2\pi n}(n/e)^n$ 取对数 $= n\log_2 n - (\log_2 e)n + \frac12\log_2(2\pi n)$ 完全一致，常数项 $\frac12\log_2(2\pi n)$ 恰是这里的 $O(\log n)$。）**"紧"的含义**：比较排序下界 $h \ge \log_2 n! \approx n\log_2 n$，而归并/堆排实际花费 $n\log_2 n$ 次比较量级——上下界同阶，渐近意义上没有改进空间（定理 5.2 推论①）。

## 5.4（计算推导）｜出处：5.7 节

> **题目**：手算 `[5, 3, 8, 1, 9, 2]` 的快速选择（求第 3 小，下标 2），写出每轮划分结果与递归侧。校验值：答案为 3，共处理 2 轮划分。

**手算**（用确定性划分便于复核：每轮取当前区间**末位**为基准，Lomuto 划分；教材校验值"2 轮"正是按此口径）：

**第 1 轮**：区间 $[0,5]$，pivot $= a[5] = 2$。扫描：$5,3,8,1,9$ 中仅 $1 < 2$ → 交换到前端。数组变为 $[1, 3, 8, 5, 9, 2]$，$i=1$；最后交换 $a[1], a[5]$ → $[1, 2, 8, 5, 9, 3]$，返回 $p = 1$。$p = 1 < k = 2$ → **答案在右段**，$lo = 2$。

**第 2 轮**：区间 $[2,5]$，pivot $= a[5] = 3$。$8, 5, 9$ 均不小于 3 → $i$ 停在 2；交换 $a[2], a[5]$ → $[1, 2, 3, 5, 9, 8]$，返回 $p = 2$。$p = k = 2$ → **答案 $a[2] = 3$**。

**答案 3，共处理 2 轮划分——与校验值一致（✓）。**

**代码验证（含 1000 组随机对拍，实测通过）：**

```python
import random as rnd

def partition(a, lo, hi):
    r = rnd.randint(lo, hi); a[r], a[hi] = a[hi], a[r]   # 随机基准
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]; i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

def quickselect(a, k):
    """第 k 小（k 从 0 计），期望 Θ(n)：每轮只递归包含答案的一侧。"""
    lo, hi = 0, len(a) - 1
    while True:
        if lo == hi: return a[lo]
        p = partition(a, lo, hi)
        if p == k: return a[p]
        elif p < k: lo = p + 1
        else:       hi = p - 1

rnd.seed(8)
ok = 0
for _ in range(1000):
    xs = [rnd.randint(0, 100) for _ in range(rnd.randint(1, 30))]
    k = rnd.randrange(len(xs))
    ok += (quickselect(xs[:], k) == sorted(xs)[k])
print("quickselect 1000 组对拍:", ok == 1000)
# 预期输出（实测）：quickselect 1000 组对拍: True
```

## 5.5（编程实现）｜出处：5.6 节

> **题目**：实现"旋转数组找最小值"（LeetCode 153）：`[4,5,6,7,0,1,2]` 输出 0；写出循环不变式作为函数注释。

```python
def find_min(nums):
    """循环不变式：最小值始终位于闭区间 [lo, hi] 内。
       判断依据：右端 a[hi] 与中点 a[mid] 比较——
       · a[mid] > a[hi]：最小值在 mid 右侧（mid 处于"前段"上升坡），
         且 mid 本身不可能是最小 → lo = mid + 1；
       · a[mid] <= a[hi]：mid 到 hi 是（含断点的）非降段，最小值在 [lo, mid]，
         mid 可能就是最小 → hi = mid（不能 -1）。
       区间长度每轮严格缩小 → 终止时 lo == hi 即最小值。O(log n)。"""
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:
            lo = mid + 1
        else:
            hi = mid
    return nums[lo]

print(find_min([4, 5, 6, 7, 0, 1, 2]))   # 0
print(find_min([3, 4, 5, 1, 2]))         # 1
print(find_min([11, 13, 15, 17]))        # 17（未旋转）
# 预期输出（实测）：0 1 17
```

与输出目标一致（✓）。**易错点**（5.11 节误区 1 的实操版）：与 `nums[hi]` 而非 `nums[lo]` 比较（与 lo 比较无法区分"旋转点在右"与"整体有序"）；`hi = mid` 而非 `mid - 1`（mid 可能恰是最小值）——两处都由不变式推出，不是背出来的。

## 5.6（编程实现）｜出处：5.2 节

> **题目**：实现归并排序的**迭代版**（自底向上按宽度 1,2,4,... 归并），并对拍递归版 1000 组随机数据。

```python
import random

def merge_sort_rec(a):
    """递归版（金标准，正文 5.2 节）。稳定。"""
    if len(a) <= 1: return a
    mid = len(a) // 2
    l, r = merge_sort_rec(a[:mid]), merge_sort_rec(a[mid:])
    out, i, j = [], 0, 0
    while i < len(l) and j < len(r):
        if l[i] <= r[j]: out.append(l[i]); i += 1
        else:            out.append(r[j]); j += 1
    out.extend(l[i:]); out.extend(r[j:])
    return out

def merge_sort_iter(a):
    """自底向上迭代版：宽度 1,2,4,... 相邻两段归并。
       无递归栈（对大 n 不爆 RecursionError）；取等先取左段 → 同样稳定。"""
    n, src, width = len(a), list(a), 1
    while width < n:
        dst = []
        for lo in range(0, n, 2 * width):
            mid, hi = min(lo + width, n), min(lo + 2 * width, n)
            i, j = lo, mid
            while i < mid and j < hi:
                if src[i] <= src[j]: dst.append(src[i]); i += 1
                else:                dst.append(src[j]); j += 1
            dst.extend(src[i:mid]); dst.extend(src[j:hi])
        src = dst; width *= 2
    return src

random.seed(5)
ok = 0
for _ in range(1000):
    data = [random.randint(0, 99) for _ in range(random.randint(0, 60))]
    ok += (merge_sort_iter(data[:]) == merge_sort_rec(data[:]) == sorted(data))
print("迭代归并对拍 1000 组通过:", ok == 1000)
# 预期输出（实测）：迭代归并对拍 1000 组通过: True
```

**要点**：迭代版与递归版时间同阶 $\Theta(n\log n)$；区别在空间形态——递归版 $O(\log n)$ 调用栈 + $O(n)$ 辅助，迭代版去掉调用栈（对链表排序时归并可 $O(1)$ 额外空间，正文 5.2 节）。

## 5.7（编程实现）｜出处：5.3 节

> **题目**：实现三路划分快排（<, =, > 三区），在含 10% 唯一键 + 90% 重复键的数据上与普通快排比较比较次数。输出目标：三路版比较次数显著下降（约一个数量级）。

```python
import random as rnd, copy

def quick_sort_2way(a, lo=0, hi=None, counter=None):
    """普通快排（Lomuto，随机基准）。counter 累计键比较次数。"""
    if hi is None: hi = len(a) - 1
    while lo < hi:
        r = rnd.randint(lo, hi); a[r], a[hi] = a[hi], a[r]
        pivot, i = a[hi], lo
        for j in range(lo, hi):
            if counter: counter[0] += 1
            if a[j] < pivot:
                a[i], a[j] = a[j], a[i]; i += 1
        a[i], a[hi] = a[hi], a[i]
        quick_sort_2way(a, lo, i - 1, counter)
        lo = i + 1
    return a

def quick_sort_3way(a, lo=0, hi=None, counter=None):
    """三路划分：不变式 a[lo..lt-1] < pivot = a[lt..i-1] < ... < a[gt+1..hi]。
       与 pivot 相等的元素**一次性进入中段、不再参与递归**。"""
    if hi is None: hi = len(a) - 1
    while lo < hi:
        r = rnd.randint(lo, hi); a[r], a[hi] = a[hi], a[r]
        pivot = a[hi]
        lt, i, gt = lo, lo, hi
        while i <= gt:
            if counter: counter[0] += 1
            if   a[i] < pivot: a[lt], a[i] = a[i], a[lt]; lt += 1; i += 1
            elif a[i] > pivot: a[i], a[gt] = a[gt], a[i]; gt -= 1
            else: i += 1
        quick_sort_3way(a, lo, lt - 1, counter)
        lo = gt + 1
    return a

def gen(n, uniq_frac):
    n_uniq = max(1, int(n * uniq_frac))
    uniq = [rnd.randint(0, 10**9) for _ in range(n_uniq)]
    return [rnd.choice(uniq) for _ in range(n)]

for n, frac in [(20000, 0.10), (20000, 0.01), (20000, 0.005)]:
    rnd.seed(6)
    data = gen(n, frac)
    c1, c2 = [0], [0]
    quick_sort_2way(copy.deepcopy(data), counter=c1)
    quick_sort_3way(copy.deepcopy(data), counter=c2)
    print(f"n={n} 唯一键占比{frac:.1%}: 普通={c1[0]:,} 三路={c2[0]:,} 比值={c1[0]/c2[0]:.1f}x")
# 预期输出（实测）：
# n=20000 唯一键占比10.0%: 普通=382,056  三路=252,179  比值=1.5x
# n=20000 唯一键占比 1.0%: 普通=1,185,974 三路=178,728  比值=6.6x
# n=20000 唯一键占比 0.5%: 普通=2,154,412 三路=138,703  比值=15.5x
```

**⚠ 对输出目标的限定（实测勘误）**：教材说"约一个数量级"。实测显示收益**随重复集中度增长**：10% 唯一键 + 双方随机基准时只有 1.5×；唯一键降到 1% 时 6.6×，0.5% 时 15.5×（超过一个数量级）。原因：普通快排把与基准相等的元素留在递归段内反复扫描（每次划分只"消灭"基准自身的几份拷贝），三路划分把整段相等元素一次性吞入中段。**结论**：三路划分的比较次数增益介于 1.5× 与几十×之间，重复率越高越接近"一个数量级"的命题；若普通版不随机化（固定基准 + 有序重复数据，实测 ~70×），则远超一个数量级。

## 5.8（编程实现）｜出处：5.10 案例 2

> **题目**：完成 5.10 案例 2，并在 lengths 服从长尾分布（如 `int(rng.paretovariate(1.5) * 10)`）时重复实验，分析分桶收益如何变化。

```python
import random

def pad_waste(batches, lengths):
    """padding 浪费 = Σ(批内最大长度 × 批大小 − 批内真实长度和)"""
    return sum(max(lengths[i] for i in b) * len(b)
               - sum(lengths[i] for i in b) for b in batches)

def group_batches(lengths, bs, bucket=50, shuffle=True, seed=0):
    """全局按长度排序 → 桶内打乱（恢复随机性）→ 切 batch。
       "排序分桶 + 桶内洗牌"折中（5.11 节误区 6）。"""
    rng = random.Random(seed)
    order = sorted(range(len(lengths)), key=lambda i: lengths[i])
    for s in range(0, len(order), bucket):
        seg = order[s:s + bucket]
        if shuffle: rng.shuffle(seg)
        order[s:s + bucket] = seg
    return [order[s:s + bs] for s in range(0, len(order), bs)]

rng_u = random.Random(1)
lengths_u = [rng_u.randint(10, 300) for _ in range(4096)]          # 均匀
rng_p = random.Random(2)
lengths_p = [int(rng_p.paretovariate(1.5) * 10) for _ in range(4096)]   # Pareto 1.5
rng_p2 = random.Random(3)
lengths_p2 = [int(rng_p2.paretovariate(1.2) * 10) for _ in range(4096)] # 更重尾

for name, lengths in [("均匀 U[10,300]", lengths_u),
                      ("Pareto(1.5)×10", lengths_p),
                      ("Pareto(1.2)×10 更重尾", lengths_p2)]:
    naive = [list(range(s, s + 32)) for s in range(0, 4096, 32)]
    grouped = group_batches(lengths, 32)
    w1, w2 = pad_waste(naive, lengths), pad_waste(grouped, lengths)
    print(f"{name}: 随机={w1:>9,} 分桶={w2:>9,} 节省={1 - w2 / w1:.1%} "
          f"(max={max(lengths)}, 中位={sorted(lengths)[2048]})")
# 预期输出（实测）：
# 均匀 U[10,300]:   随机=  557,738 分桶=   10,762 节省=98.1% (max=300, 中位=156)
# Pareto(1.5)×10:   随机=  763,743 分桶=   88,479 节省=88.4% (max=2210, 中位=15)
# Pareto(1.2)×10 更重尾: 随机=3,115,021 分桶=1,524,781 节省=51.1% (max=47280, 中位=15)
```

**定性结论（输出目标）**：**分桶收益随分布重尾程度单调下降**（98.1% → 88.4% → 51.1%）。机制：重尾分布下存在极端长样本，任何一个 batch 只要混入它，整批就要 pad 到它的长度——**batch 的 padding 由 max 主导，max 由尾部决定**。工程对策（正文 5.8 节对策 3）：对超长样本设长度上限截断（可用快速选择取 P99 分位数作为截断点——5.7 节的分位数语义），或把超长样本单独成批。

## 5.9（开放思考）｜出处：5.8 节

> **题目**：训练大模型时语料按长度排序与 SGD 随机性的矛盾，工程上有哪些折中（批间洗牌、双缓冲、parquet 行组乱序）？各牺牲了什么？

**参考答案：**

| 折中方案 | 做法 | 牺牲什么 |
|---|---|---|
| **批间洗牌** | 长度分桶产生的 batch 整体随机排列后再喂给训练器 | 几乎不损失 padding 收益（批构成长度仍相近），只损失"批间长度梯度"的预取局部性；实现上需要缓存全部 batch 索引 |
| **桶内洗牌（sortish/bucket+shuffle）** | 全局排序后切成桶、桶内打乱再组批 | 相邻批的长度相近性下降 → padding 浪费回升（本册 5.8 题实测：均匀分布下从"全局排序"的理想值回升若干个百分点）；换来批内构成多样化 |
| **双缓冲 / 流水线预取** | 后台线程持续准备下一批（长度信息已知、可预 pad），训练与数据供给重叠 | 显存/内存多一份 batch 的占用；调度复杂度 |
| **parquet 行组乱序** | 落盘时按长度排序写入行组（row group），训练时以行组为单位随机读取顺序 | I/O 放大（随机行组读取 vs 顺序扫描）；需要能存储全局排序元数据；epoch 间若不重洗，批构成长期固定 |
| **每 epoch 重排** | 每个 epoch 重新做一次"排序分桶+洗牌" | 每 epoch 一次 $O(n\log n)$ 排序与全量 shuffle 的 CPU/带宽成本 |

**核心权衡句**：SGD 要求样本近似 i.i.d.（梯度估计无偏、方差可控），长度排序破坏的是"批间独立性"——所有折中都在"padding 算力"与"梯度估计质量"之间拨旋钮，5.11 节误区 6 的"loss 周期性毛刺"就是拨过头的声音。

## 5.10（挑战题）｜出处：5.7 节

> **题目**：证明 BFPRT（中位数的中位数）线性时间选择的递推 $T(n) \le T(n/5) + T(7n/10) + \Theta(n) = O(n)$。

**证明要点：**

1. **分组**：把 $n$ 个元素按 5 个一组分组（余组不足 5 不影响），每组插入排序取中位数，共 $\lceil n/5 \rceil$ 个"组中位数"；递归对它们取中位数，得基准 $m$（$T(n/5)$ 项）。
2. **至少淘汰 30%**：$m$ 是组中位数的中位数 → 至少一半的组（$\ge \lfloor n/10 \rfloor$ 个组）的组中位数 $\ge m$；这些组内各有 **3 个**元素 $\ge$ 自己的组中位数 $\ge m$（5 元素组的中位数两侧各 2 个）。故至少 $3\lfloor n/10 \rfloor \ge 3n/10 - O(1)$ 个元素 $\ge m$；对称地至少 $3n/10$ 个元素 $\le m$。于是以 $m$ 划分后，无论递归哪一侧，**规模至多 $7n/10 + O(1)$**（$T(7n/10)$ 项）。
3. **划分本身 $O(n)$**：一趟扫描（$\Theta(n)$ 项）。
4. **解递推**（关键：$\frac15 + \frac7{10} = \frac9{10} < 1$）：代入法，猜 $T(n) \le a\,n$（$n$ 大于常数阈值时）：

$$T(n) \;\le\; a\frac{n}{5} + a\frac{7n}{10} + cn \;=\; \frac{9a + 10c}{10}\,n \;\le\; a\,n \quad\Longleftrightarrow\quad a \ge 10c.$$

取 $a = 10c$（并对小 $n$ 用 $O(1)$ 基例校准），得 $T(n) = O(n)$。$\blacksquare$

**为什么快排式选择的 $1/2 + 1/2$ 不行而 $9/10$ 行**：递推 $T(\alpha n) + T((1-\alpha)n) + cn$ 线性的充要条件是 $\alpha + (1-\alpha)$……不，是**两支系数之和 < 1**（画出递归树：每层总规模按公比 $\alpha_1 + \alpha_2$ 收缩）。普通快速选择单侧递归 $T(n/2) + n$ 期望线性但最坏 $T(n-1) + n = \Theta(n^2)$；BFPRT 用 $O(n)$ 的代价**买断了最坏分支的大小**——"确定性最坏线性"的全部代价就是这个保证所需的分组开销，常数大（工程少见，5.7 节）。

## 6.1（概念辨析）｜出处：6.3 节

> **题目**：最长**公共子串**（连续）与最长公共子序列（可不连续）的状态定义差在哪里？各自写出转移方程。校验值：子串版为 $dp[i][j] = dp[i-1][j-1]+1$ 或 0，答案取表内最大值而非表角。

**答案（与校验值一致）：**

| | 最长公共子序列（LCS） | 最长公共子串 |
|---|---|---|
| 状态 | $dp[i][j]$ = $a[:i]$ 与 $b[:j]$ 的 LCS 长度 | $dp[i][j]$ = **以 $a[i-1]$、$b[j-1]$ 结尾**的公共子串长度 |
| 转移 | 相同：$dp[i-1][j-1]+1$；不同：$\max(dp[i-1][j],\ dp[i][j-1])$（丢 $a[i]$ 或丢 $b[j]$） | 相同：$dp[i-1][j-1]+1$；**不同：$0$**（连续性断裂，一切清零重来） |
| 答案 | $dp[m][n]$（**表角**——最优解可跨越末位失配继续延续） | $\max_{i,j} dp[i][j]$（**表内最大值**——最优子串未必在末尾结束） |

**状态定义差在哪**：子序列的 $dp[i][j]$ 是"前缀上的全局最优"（失配可以继承），子串的 $dp[i][j]$ 被强制定义为"**必须以当前位结尾**"的局部量——**正是这个"必须结尾"让连续性进入状态**，代价是答案不再在表角。这与 6.9 节误区 1（状态定义缺信息/多信息）同源：子串若照抄 LCS 的状态，转移就会在失配处错误地"跳过"，把不连续的也数进去。

```python
def lcsubstr(a, b):
    """最长公共子串（验证）：不同处清零，答案取表内 max。"""
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    best, endi = 0, 0
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
                if dp[i][j] > best: best, endi = dp[i][j], i
    return best, a[endi - best:endi]

print(lcsubstr("abcdxyz", "xyzabc"))   # (3, 'abc')
print(lcsubstr("pwwkew", "wkewx"))     # (4, 'wkew')
# 预期输出（实测）：(3, 'abc') / (4, 'wkew')
```

## 6.2（概念辨析）｜出处：6.5 节

> **题目**：为什么 0/1 背包的滚动数组必须倒序？用一次具体迭代（物品 $w=2,v=3$、$C=4$）展示正序时的错误更新。

**原理**：二维转移 $dp[i][c] = \max(dp[i-1][c],\ dp[i-1][c-w_i]+v_i)$ 的两项都来自**上一行 $i-1$**（保证每件只用一次）。一维滚动后，`dp[c-w]` 到底指 $i-1$ 行还是已被本行覆盖的 $i$ 行，取决于遍历方向：
- **倒序**（$c$ 从大到小）：更新 `dp[c]` 时 `dp[c-w]` 尚未在本轮被写 → 仍是"第 $i-1$ 行"的值 ✓；
- **正序**：`dp[c-w]` 已被本轮更新 → 已含"选过当前物品"的信息 → 物品可重复选取，**语义悄然变成完全背包**。

**具体迭代**（物品 $w=2, v=3$，$C=4$，初始 `dp = [0,0,0,0,0]`）：

| 遍历 | `dp[2]` | `dp[3]` | `dp[4]` | 说明 |
|---|---|---|---|---|
| 正序 $c=2$ | $\max(0, dp[0]+3)=\mathbf{3}$ | — | — | 本轮写入 |
| 正序 $c=3$ | — | $\max(0, dp[1]+3)=3$ | — | 用的是未污染的 $dp[1]$，碰巧无恙 |
| 正序 $c=4$ | — | — | $\max(0, dp[2]+\mathbf{3})=\mathbf{6}$ | **错误**：$dp[2]=3$ 是本轮刚写的（含该物品）→ 物品被用两次 |
| 倒序 $c=4$ | — | — | $\max(0, dp[2]+3)=3$ | 此时 $dp[2]$ 仍是初值 0 → 只用一次 ✓ |
| 倒序 $c=3$ | — | $3$ | | |
| 倒序 $c=2$ | $3$ | | | |

**实验验证**（正文 6.8 案例 3，实测）：正确倒序在教材数据 `[2,3,4,5],[3,4,5,6],C=8` 上得 **10**；方向写反得 **12**——"更大更漂亮"实则已变成完全背包（四件 $w=2$）。DP 的 bug 是静默的（6.9 节误区 3），务必暴力对拍。

## 6.3（计算推导）｜出处：6.4 节

> **题目**：手算 `edit_distance("kitten", "sitting")`。校验值：3（经典结果；对齐含 2 次替换 + 1 次插入）。

**手算**：$m=6$（kitten），$n=7$（sitting）。边界 $dp[i][0]=i$，$dp[0][j]=j$。填表关键行：

- $dp[1][1]$：`k≠s`，$1+\min(dp[0][1], dp[1][0], dp[0][0]) = 1+\min(1,1,0)=1$（替换 k→s）；
- $dp[2][2]$：`i=i` 免费，$dp[1][1]=1$；
- $dp[3][3]$：`t=t`，$dp[2][2]=1$；$dp[4][4]$：`t=t`，$dp[3][3]=1$；
- $dp[5][5]$：`e≠i`，$1+\min(dp[4][5], dp[5][4], dp[4][4])=1+1=2$（替换 e→i）；
- $dp[6][6]$：`n=n`，$dp[5][5]=2$；
- $dp[6][7]$：`n≠g`，$1+\min(dp[5][7], dp[6][6], dp[5][6]) = 1+\min(3,2,2)=\mathbf{3}$（插入 g）。

**距离 = 3，对齐：k→s（替）、i=i、t=t、t=t、e→i（替）、n=n、+g（插）——与校验值一致（✓）。**

```python
def edit_distance(a, b):
    """完整 DP 表版（正文 6.4 节）。O(mn) 时间/空间，支持回溯。"""
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = i
    for j in range(n + 1): dp[0][j] = j
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i-1] == b[j-1]: dp[i][j] = dp[i-1][j-1]
            else: dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
    return dp, dp[m][n]

dp, d = edit_distance("kitten", "sitting")
print(d)   # 预期输出（实测）：3
```

## 6.4（计算推导）｜出处：6.5 节 + 6.8 案例 3

```python
from itertools import product
def brute(ws, vs, C):
    best = 0
    for bits in product([0, 1], repeat=len(ws)):
        w = sum(b*wi for b, wi in zip(bits, ws)); v = sum(b*vi for b, vi in zip(bits, vs))
        if w <= C: best = max(best, v)
    return best
def knapsack_01(ws, vs, C):
    dp = [0]*(C+1)
    for w, v in zip(ws, vs):
        for c in range(C, w-1, -1):     # 倒序：0/1
            dp[c] = max(dp[c], dp[c-w] + v)
    return dp[C]
def knapsack_complete(ws, vs, C):
    dp = [0]*(C+1)
    for w, v in zip(ws, vs):
        for c in range(w, C+1):         # 正序：可复用
            dp[c] = max(dp[c], dp[c-w] + v)
    return dp[C]

ws, vs, C = [2, 3, 4, 5], [3, 4, 5, 6], 8
print(brute(ws, vs, C), knapsack_01(ws, vs, C), knapsack_complete([2, 3], [3, 4], 8))

```

## 6.5（编程实现）｜出处：6.4 节

> **题目**：实现编辑距离的**空间优化版**（两行滚动，$O(\min(m,n))$ 空间），并与完整表版对拍。

```python
import random

def edit_distance_full(a, b):
    """完整表版（金标准，可回溯对齐）。"""
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            if a[i-1] == b[j-1]: dp[i][j] = dp[i-1][j-1]
            else: dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
    return dp[m][n]

def edit_distance_rolling(a, b):
    """两行滚动：dp 只依赖上一行与本行左格 → O(min(m,n)) 空间。
       先把短串放列方向（b），行数组长度 = len(b)+1。"""
    if len(a) < len(b): a, b = b, a        # 让 b 为短串
    m, n = len(a), len(b)
    prev = list(range(n + 1))              # 第 0 行
    for i in range(1, m + 1):
        cur = [i] + [0] * n
        for j in range(1, n + 1):
            if a[i-1] == b[j-1]: cur[j] = prev[j-1]
            else: cur[j] = 1 + min(prev[j],      # 删除（上一行同列）
                                   cur[j-1],     # 插入（本行左格）
                                   prev[j-1])    # 替换（左上角）
        prev = cur
    return prev[n]

random.seed(9)
ok = 0
for _ in range(1000):
    a = "".join(random.choice("abc") for _ in range(random.randint(0, 12)))
    b = "".join(random.choice("abc") for _ in range(random.randint(0, 12)))
    ok += (edit_distance_rolling(a, b) == edit_distance_full(a, b))
print("滚动版对拍 1000 组:", ok == 1000)
print(edit_distance_rolling("kitten", "sitting"))   # 3
# 预期输出（实测）：滚动版对拍 1000 组: True / 3
```

与输出目标一致（✓）。**要点**：滚动版**丢失回溯能力**（表没存下来）——只要长度的场景（WER 数值）用它，需要逐词归因对齐的场景（WER 归因表）用完整表；这正是 6.4 节"复杂度 $O(mn)$ 时间、$O(\min(m,n))$ 空间（滚动行）"的实现。

## 6.6（编程实现）｜出处：6.3 节

> **题目**：实现最长公共子序列并输出**具体对齐**（回溯），对 `AGGTAB` 与 `GXTXAYB` 输出长度 4 与对齐结果（GTAB）。

```python
def lcs_with_alignment(a, b):
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(1, m+1):
        for j in range(1, n+1):
            if a[i-1] == b[j-1]: dp[i][j] = dp[i-1][j-1] + 1
            else:                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    # 回溯：从表角走回原点；相等取左上（对齐该字符），
    #       否则朝较大邻格移动（沿"贡献了长度"的方向）。O(m+n)。
    i, j, out = m, n, []
    while i > 0 and j > 0:
        if a[i-1] == b[j-1]:
            out.append(a[i-1]); i -= 1; j -= 1
        elif dp[i-1][j] >= dp[i][j-1]: i -= 1
        else: j -= 1
    return dp[m][n], "".join(reversed(out))

L, s = lcs_with_alignment("AGGTAB", "GXTXAYB")
print("LCS 长度:", L, "对齐:", s)
# 预期输出（实测）：LCS 长度: 4 对齐: GTAB
```

与输出目标一致（✓）。**要点**：① 回溯条件 `a[i-1]==b[j-1]` 足以判定"对齐"——LCS 的最优解可取到"所有相等位都对齐"；② `dp[i-1][j] >= dp[i][j-1]` 的取等方向只影响得到哪一个最优对齐（可能多条），不影响长度。

## 6.7（编程实现）｜出处：6.10 节 + 第 5 章 5.6 节（二分）

> **题目**：实现"最长上升子序列"的 $O(n\log n)$ 版（贪心维护 tails 数组 + 二分），对拍 $O(n^2)$ DP 版。

```python
import bisect, random

def lis_nlogn(a):
    """tails[k] = 所有长度为 k+1 的上升子序列中，末尾元素的最小值。
       tails 恒严格递增（反证可证）→ 可二分。
       对每个 x：找到第一个 >= x 的位置替换（延长/改良），或在末尾追加。
       注意 tails 数组本身不是某个 LIS！只有其长度是答案。"""
    tails = []
    for x in a:
        i = bisect.bisect_left(tails, x)   # 严格上升用 bisect_left
        if i == len(tails): tails.append(x)
        else: tails[i] = x
    return len(tails)

def lis_n2(a):
    """dp[i] = 以 a[i] 结尾的 LIS 长度。O(n²)。"""
    if not a: return 0
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i]: dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

random.seed(10)
ok = 0
for _ in range(1000):
    a = [random.randint(0, 50) for _ in range(random.randint(0, 40))]
    ok += (lis_nlogn(a) == lis_n2(a))
print("LIS 对拍 1000 组:", ok == 1000)
# 预期输出（实测）：LIS 对拍 1000 组: True
```

**要点**：① 若要求**非严格**上升（允许相等），改用 `bisect_right`；② "替换"的含义是改良未来：更小的末尾给后续元素更多延长机会——贪心 + 不变式"tails 严格递增"是这个算法正确性的全部（6.2 节四步法之外的"贪心维护 + 二分"混合范式，衔接第 5 章二分）。

## 6.8（编程实现）｜出处：6.8 案例 2

> **题目**：把案例 2 的 `wer` 接到一个小测试集上（自造 10 对 (ref, hyp)），统计总体 WER 与逐句归因表。输出目标：与手工核对一致。

```python
def wer(ref, hyp, sub_cost=1):
    """词级编辑距离 + 回溯归因。返回 (逐句 WER, 操作计数)。"""
    m, n = len(ref), len(hyp)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            if ref[i-1] == hyp[j-1]: dp[i][j] = dp[i-1][j-1]
            else: dp[i][j] = min(dp[i-1][j] + 1,           # 删（漏词）
                                 dp[i][j-1] + 1,           # 插（多词）
                                 dp[i-1][j-1] + sub_cost)  # 替换
    i, j, D = m, n, {"del": 0, "ins": 0, "sub": 0}
    while i > 0 or j > 0:
        if i > 0 and j > 0 and ref[i-1] == hyp[j-1] and dp[i][j] == dp[i-1][j-1]:
            i -= 1; j -= 1                                  # 匹配
        elif i > 0 and j > 0 and dp[i][j] == dp[i-1][j-1] + sub_cost:
            D["sub"] += 1; i -= 1; j -= 1
        elif i > 0 and dp[i][j] == dp[i-1][j] + 1:
            D["del"] += 1; i -= 1
        else:
            D["ins"] += 1; j -= 1
    return dp[m][n] / m, D

    ("deep learning rocks", "deep learning rocks"),        # 0
    ("open ai made gpt", "openai made gpt"),               # 1 删 + 1 替

    ("transformers changed nlp", "transformers changed nlp forever"),  # 1 插入
    ("speech recognition is hard", "speed recognition is hard"),       # 1 替换
]
total_err, total_len = 0, 0
for ref, hyp in pairs:

    w, D = wer(r, h)
    total_err += D["del"] + D["ins"] + D["sub"]; total_len += len(r)
    print(f"WER={w:.4f} {D}  ref={ref[:28]!r}")
print(f"总体 WER = {total_err}/{total_len} = {total_err/total_len:.4f}")
# 预期输出（实测，与手工核对逐条一致）：
# WER=0.1667 {'del': 0, 'ins': 0, 'sub': 1} ...
# WER=0.3333 {'del': 2, 'ins': 0, 'sub': 0}   ← 第 2 句：漏 sat、漏 the
# ... （中间各句与注释一致）
# 总体 WER = 11/40 = 0.2750
```

与输出目标一致（与手工核对一致，✓）。正文案例 2 的校验也复现：`wer(ref, hyp1)[0] = 0.1666…`、`wer(ref, hyp2)[0] = 0.3333…` ✓。

> **⚠ 勘误（第 6 章案例 2 的注释）**：正文注释称 hyp2 的分解为 `{'del': 1, 'ins': 0, 'sub': 1}`（"漏 sat、错 on the→on"）。**该分解不可达**：ref `the cat sat on the mat` 对 hyp `the cat on mat`，若用 1 替 + 1 删，则 4 个匹配词必须按序为 the/cat/on/mat，唯一可能的对齐使替换后余下 ref 词无法匹配，最少代价恰为 **2 次删除**（漏 sat、漏 the）。WER = 2/6 = 0.3333 本身正确，仅注释的操作分解有误（回溯的取等方向还会在不同最优对齐间选择，属正常现象）。

## 6.9（开放思考）｜出处：6.6 节

> **题目**：找零问题中，怎样的币值体系能保证贪心最优（"规范币制"）？查阅相关结论并说明人民币/美元面额是否属于规范币制。

**参考答案：** 称币制为**规范币制（canonical coin system）**：对任意金额，"先大后小"的贪心都给出最少硬币数。相关结论：① 贪心最优**不是**普遍性质——反例 $\{1,5,11\}$ 找 15：贪心 $11+1+1+1+1=5$ 枚，最优 $5+5+5=3$ 枚（6.6 节例 6.2）；② 存在**多项式判定定理**（Kozen–Zuckerman 的一点检验）：规范性只需对每个非最大币值检查一个特定金额上贪心是否最优，判定 $O(|\text{coins}|^2)$；③ 直观上，规范币制的面额要"足够稠密且相互兼容"——每个大面额的"余数"都能被小面额高效补齐。

**人民币/美元验证**：全量 DP 对拍实测（金额 1–500）：

```python
def greedy_always_optimal(coins, maxn=500):
    INF = float("inf")
    dp = [0] + [INF] * maxn
    for x in range(1, maxn + 1):
        dp[x] = 1 + min(dp[x - c] for c in coins if c <= x)
    for x in range(1, maxn + 1):
        cnt, rem = 0, x
        for c in sorted(coins, reverse=True):   # 贪心
            cnt += rem // c; rem %= c
        if cnt != dp[x]: return False, x
    return True, None

print(greedy_always_optimal([1, 5, 10, 25]))          # (True, None)
print(greedy_always_optimal([1, 5, 10, 20, 50, 100])) # (True, None)
print(greedy_always_optimal([1, 5, 11]))              # (False, 15)
# 预期输出（实测）：(True, None) / (True, None) / (False, 15)
```

**美元 $\{1,5,10,25\}$ 与人民币主币 $\{1,5,10,20,50,100\}$ 都是规范币制**（贪心总是最优，✓）；$\{1,5,11\}$ 在 $x=15$ 处贪心失败，与例 6.2 一致。

## 6.10（挑战题）｜出处：6.4 节 + 6.8 案例 2

> **题目**：实现"替换代价 2"的 WER 变体，并构造一个两种口径下排名相反的识别系统对比示例；写 200 字讨论指标口径如何影响系统选型。

**实现**：正文 `wer` 已带 `sub_cost` 参数（替换代价 2 即"替换 = 删+插"的口径）。**排名反转示例**（实测）：

```python
def wer_count(ref, hyp, sub_cost):
    m, n = len(ref), len(hyp)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            if ref[i-1] == hyp[j-1]: dp[i][j] = dp[i-1][j-1]
            else: dp[i][j] = min(dp[i-1][j]+1, dp[i][j-1]+1, dp[i-1][j-1]+sub_cost)
    return dp[m][n]

sents = {
  "A": [("w1 w2 w3 w4 w5 w6 w7 w8 w9 w10",
         "x1 x2 x3 x4 w5 w6 w7 w8 w9 w10")],                # A：一句 10 词错 4 个（全替换）
  "B": [("a1 a2", "a1"), ("b1 b2", "b1"), ("c1 c2", "c1"),
        ("d1 d2", "d1"), ("e1 e2", "e1")],                  # B：五句各漏一词（全删除）
}
for sub in (1, 2):
    scores = {}
    for name, ps in sents.items():
        errs = sum(wer_count(r.split(), h.split(), sub) for r, h in ps)
        total = sum(len(r.split()) for r, _ in ps)
        scores[name] = errs / total
    print(f"sub_cost={sub}: " + "  ".join(f"WER({k})={v:.2f}" for k, v in scores.items())
          + f"  -> 更优: {min(scores, key=scores.get)}")
# 预期输出（实测）：
# sub_cost=1: WER(A)=0.40  WER(B)=0.50  -> 更优: A
# sub_cost=2: WER(A)=0.80  WER(B)=0.50  -> 更优: B
```

**机制**：替换在口径 1 下算 1 个错、口径 2 下算 2 个——**替换密集的系统（A）在口径 2 下被加倍惩罚**，删除/插入密集的系统（B）不受影响，排名反转。

**200 字讨论**：指标口径不是"技术细节"，而是**内嵌了错误类型的价格体系**。替换代价 1（独立操作口径）对"同音错词"宽容，适合语音识别里同音替换普遍的场景；替换代价 2（替换=删+插）让"结构性的词序/选词错误"显形，机器翻译评测（BLEU 之外的人评替代）更倾向它。跨论文比较 WER 必须核对口径（6.9 节误区 5），否则会得出"系统 A 优于 B"的伪结论——本例中两个口径给出相反排名。工程上还应**分错误类型报告**（S/D/I 三计数，如本实验的归因表），让下游按业务代价（漏一个实体 vs 错一个修饰词）自行定价，而不是把定价权锁死在单一标量指标里。

## 7.1（概念辨析）｜出处：7.1 节

> **题目**：精确近邻（KD 树）与近似近邻（LSH/HNSW）各自的"不可行边界"是什么？写出你判断"该不该用 ANN"的三条准则。

**不可行边界：**

- **KD 树/球树（精确）**：失效边界是**维度**。$D \gtrsim 20$ 后"查询点到划分超平面的距离"与"点到点距离"同量级，剪枝判据失效，退化为近暴力且常数更差（维数灾难）；此外 $n$ 大到索引放不进内存时也不可行。
- **LSH/HNSW（近似）**：失效边界是**正确性要求**。只要业务要求 100% 召回（精确解），任何 ANN 都不可用；其次是**数据规模太小**（$n \le 10^5$ 时暴力 + Top-K 堆已经毫秒级，索引的构建与内存开销不划算）与**更新极频繁**（索引重建成本盖过查询收益的流式小规模场景）。

**判断"该不该用 ANN"的三条准则：**

1. **维度准则**：$D > 20$ 且数据量 $n > 10^5$–$10^6$ → 放弃精确空间树，进入 ANN 框架（7.1.1 节维数灾难）。
2. **召回容忍准则**：业务能接受召回率 < 100%（例如 RAG 取 top-10 有 95% 召回即可，漏检由重排/多路召回兜底）→ ANN 可用；漏检会直接造成资损（如违禁图精确匹配）→ 必须精确。
3. **延迟/吞吐准则**：在线毫秒级、QPS 高、$n$ 达 $10^6$–$10^9$ → 暴力 $O(nD)$ 算不过来（7.1 节的开场账：$10^7\times768$ ≈ $7.7\times10^9$ FLOPs/查询）→ ANN；离线批处理或小库 → 暴力/精确树。

## 7.2（概念辨析）｜出处：7.3、7.4 节

> **题目**：布隆过滤器"可能存在"与 CMS 的过估计，两者的误差方向分别是单侧还是双侧？为什么这种方向性在缓存防护与频次统计中恰好有用？

**答案：两者都是单侧误差，但方向相反的用途设计。**

- **布隆过滤器**：查询结果只有两种——"**一定不在**"（任一位为 0，绝无假阴性）与"**可能存在**"（可能假阳性）。误差只朝"多报存在"这一侧（假阳性），**永不漏报**。
- **Count-Min Sketch**：$\hat c \ge c$ 恒成立——**只过估计、永不低估计**（其他 key 的哈希碰撞只会把计数加上去，最小值操作压制但不消除过估计）。单侧（上侧）。

**为什么恰好有用：**

- **缓存防护**（布隆）：拦截"一定不存在"的 key 是**安全**的（省掉了打穿数据库的查询）；假阳性的代价只是"多查一次库、然后缓存空结果"——把灾难性穿透降级为可接受的冗余查询。**若误差是双侧的（假阴性），就会把真实存在的 key 挡在缓存外，直接造成数据错误。**
- **频次统计**（CMS）：热点识别、Top-K、异常检测要的是"**宁可信其大**"的保守上界——过估计保证**热 key 绝不会被低估而漏掉**（7.9 节误区 4 提到要配合重击者两级方案压冷 key 的过估计噪声）；若可低估计，头部流量可能被系统性漏计，监控与限流全部失守。

**共性**：单侧误差之所以"有用"，是因为误差方向与业务失败模式**对齐**——把不可接受的错误（漏报、低估）设计为零，把可容忍的错误（误报、过估计）留在可控侧。

## 7.3（计算推导）｜出处：7.4 节

> **题目**：布隆过滤器取 $m/n = 10$、最优 $k$，求假阳性率；若要求 $p_{\text{fp}} < 1\%$，$m/n$ 至少取多少？校验值：$m/n=10$ 时约 0.0082（$k=7$）；$1\%$ 需 $m/n \approx 9.6$。

**推导**：插入 $n$ 个元素、$k$ 个哈希后，任一位仍为 0 的概率 $\approx e^{-kn/m}$，假阳性率

$$p_{\text{fp}} = \left(1 - e^{-kn/m}\right)^k.$$

**最优 $k$**：对 $k$ 求导（令 $x = kn/m$，$p = (1-e^{-x})^{mx/\text{...}}$）得 $k^* = \frac{m}{n}\ln 2$，此时 $p_{\text{fp}} \approx 0.6185^{m/n}$。

**代入 $m/n = 10$**：$k^* = 10\ln2 \approx 6.93$，取整数 $k = 7$：

$$p_{\text{fp}} = \left(1 - e^{-7/10}\right)^7 = (1 - 0.4966)^7 = 0.5034^7 \approx 0.0082. \quad ✓$$

（整数 $k=6$ 时 $p\approx0.0084$，$k=7$ 略优——实测印证。）

**反解 $m/n$**：要求 $(1 - e^{-\frac{k}{m/n}})^k < 0.01$，在最优 $k = \frac mn\ln2$ 下解 $0.6185^{m/n} < 0.01$：

$$\frac{m}{n} > \frac{\ln 0.01}{\ln 0.6185} = \frac{-4.6052}{-0.4805} \approx 9.58 \;\Rightarrow\; m/n \approx 9.6. \quad ✓$$

（扫描验证实测：$m/n=9.6$、$k\approx6.65$ 时 $p \approx 0.0099 < 1\%$；$m/n=9.5$ 时 $p\approx0.0101$ 超标。与校验值一致 ✓。）

**工程换算**：每元素 10 bit、7 个哈希 → 1% 假阳性；内存即"每 key 约 1.25 字节"——对比哈希表每 key 数十字节，这是 7.4 节"省内存版哈希"的定量含义。

## 7.4（计算推导）｜出处：7.3.1 节

> **题目**：CMS 取 $\varepsilon = 0.001$、$\delta = 0.01$，求 $w$ 与 $d$，及总内存（计数器 8 字节）。校验值：$w \approx 2719$、$d = 5$，约 108 KB。

**推导**：误差界 $\hat c \le c + \varepsilon N$ 以概率 $\ge 1-\delta$ 成立，参数取 $\varepsilon = e/w$、$d = \ln(1/\delta)$：

- $w = \lceil e/\varepsilon \rceil = \lceil 2.71828/0.001 \rceil = \mathbf{2719}$ ✓；
- $d = \lceil \ln(1/0.01) \rceil = \lceil \ln 100 \rceil = \lceil 4.605 \rceil = \mathbf{5}$ ✓；
- 内存 $= w \times d \times 8\ \text{B} = 2719 \times 5 \times 8 = 108{,}760$ B $\approx 106.2$ KiB $\approx \mathbf{108.8\ kB}$（十进制）——**与校验值"约 108 KB"一致（按 1 kB = 1000 B 口径）✓**。

**验证代码：**


## 7.5（编程实现）｜出处：7.3.2 节（蓄水池的加权推广）

> **题目**：实现蓄水池采样的"有权重版"（A-Res：第 $i$ 个元素以 $u^{1/w_i}$ 进池，$w_i$ 为权重），并蒙特卡洛验证选择概率 ∝ $w_i$。输出目标：频率比与权重比一致（误差 < 2%）。

```python
import random
from collections import Counter

def a_res_sample(stream, k, rng):
    """A-Res（Efraimidis–Spirakis）：元素 (item, w) 依次到来，
       key = u^(1/w)（u~U[0,1)），维护 key 最大的 k 个。
       key 的分布使"逐个被抽取"的强度 ∝ w。"""
    pool = []                                  # (key, item)，按 key 升序
    for item, w in stream:
        key = rng.random() ** (1.0 / w)
        if len(pool) < k:
            pool.append((key, item)); pool.sort()
        elif key > pool[0][0]:
            pool[0] = (key, item); pool.sort() # 挤掉池中最小 key
    return [it for _, it in pool]

rng = random.Random(0)
weights = {0: 1, 1: 2, 2: 4, 3: 8}             # 概率应 ∝ 权重
W = sum(weights.values())
trials = 200_000

counts = Counter()
for _ in range(trials):                        # k=1：严格验证 P(i) ∝ w_i
    counts.update(a_res_sample(list(weights.items()), 1, rng))
freq = {i: c / trials for i, c in counts.items()}
exp = {i: w / W for i, w in weights.items()}
print("k=1 经验频率:", {i: round(f, 4) for i, f in freq.items()})
print("k=1 理论 w/W:", {i: round(e, 4) for i, e in exp.items()})
print("相对误差全部 < 2%:",
      all(abs(freq[i] - exp[i]) / exp[i] < 0.02 for i in weights))
# 预期输出（实测）：
# k=1 经验频率: {1: 0.1339, 2: 0.2661, 3: 0.5342, 0: 0.0658}
# k=1 理论 w/W: {0: 0.0667, 1: 0.1333, 2: 0.2667, 3: 0.5333}
# 相对误差全部 < 2%: True   （最大相对误差约 1.3%）
```

与输出目标一致（✓，频率比 ≈ 权重比 1:2:4:8）。

> **口径说明（重要）**：严格的"$P(i) \propto w_i$"在 **$k=1$** 时精确成立。$k>1$ 的**无放回**加权抽样中，各元素的**入选概率不再恰好等于 $k\,w_i/W$**（A-Res 保证的是"逐次抽取强度 ∝ 剩余权重"，即 successive PPA）——若实验在 $k=2$ 下拿 $k w_i/W$ 当真值会得到系统性偏差（如权重 {1,2,4,8}、$k=2$ 时实测入选率 {0.175, 0.343, 0.631, 0.849} ≠ {0.133, 0.267, 0.533, 1.067}）。验证 $\propto w_i$ 请用 $k=1$，或对 $k>1$ 比较"逐次抽取的权重比"。

## 7.6（编程实现）｜出处：7.8 案例 3

> **题目**：把案例 3 的 LSH 中 `kbits` 从 8 扫到 20，画召回率-候选集大小曲线。输出目标：召回率随 kbits 单调升、候选数单调降的交叉权衡图。

**⚠ 勘误：输出目标的单调性方向印反。** 实测（8 张哈希表、n=5000、D=32、Q=50、k=10，随机超平面 LSH，精确桶匹配）：

| kbits | 8 | 10 | 12 | 14 | 16 | 18 | 20 |
|---|---|---|---|---|---|---|---|
| 平均候选数 | 206.8 | 64.2 | 21.3 | 6.9 | 2.6 | 1.0 | 0.4 |
| 召回率@10 | 0.28 | 0.12 | 0.07 | 0.02 | 0.00 | 0.00 | 0.00 |

**召回率随 kbits 增大单调下降**（不是上升），候选数也单调下降。机制：kbits 越大，同码桶越"纯"（只含真近邻），但**查询向量与近邻撞码的概率也急剧下降**——近邻进不了候选集，召回崩塌。真实存在的交叉权衡是**召回率 ↔ 查询速度**（两个不同的量）：低 kbits → 候选多、慢、召回高；高 kbits → 候选少、快、召回低。教材想表达的应该就是这个权衡，但"召回率随 kbits 单调升"的表述与机制相反。

**验证代码（表只建一次的高效版）：**

```python
import numpy as np

rng = np.random.default_rng(0)
n, D, Q, k, L = 5000, 32, 50, 10, 8
X = rng.normal(size=(n, D)); X /= np.linalg.norm(X, axis=1, keepdims=True)
Qs = rng.normal(size=(Q, D)); Qs /= np.linalg.norm(Qs, axis=1, keepdims=True)
sims_all = Qs @ X.T
truth = [set(np.argsort(-sims_all[qi])[:k].tolist()) for qi in range(Q)]

planes = rng.normal(size=(L, 20, D))
codes = [(X @ planes[l].T) > 0 for l in range(L)]
qcodes = [(Qs @ planes[l].T) > 0 for l in range(L)]

print(f"{'kbits':>6} {'平均候选数':>10} {'召回@10':>8}")
for kbits in range(8, 21, 2):
    tables = []
    for l in range(L):                       # 每个位宽建一次桶表
        tb = {}
        c = codes[l][:, :kbits]
        for idx in range(n):
            tb.setdefault(c[idx].tobytes(), []).append(idx)
        tables.append(tb)
    hits, cand_total = 0, 0
    for qi in range(Q):
        cand = set()
        for l in range(L):                   # 只查同码桶
            cand.update(tables[l].get(qcodes[l][qi][:kbits].tobytes(), []))
        cand_total += len(cand)
        if cand:
            cl = list(cand)
            top = set(np.array(cl)[np.argsort(-sims_all[qi][cl])[:k]].tolist())
            hits += len(top & truth[qi])
    print(f"{kbits:>6} {cand_total/Q:>10.1f} {hits/(Q*k):>8.2f}")
# 预期输出（实测）：见上表——召回率与候选数均随 kbits 单调下降
```

## 7.7（编程实现）｜出处：7.2 节 + 第 4 章 4.4 节

> **题目**：用 `scipy.sparse` 把第 4 章的 Dijkstra 例子改写为 CSR 邻接矩阵上的实现，并验证结果一致。

```python
import numpy as np, heapq
from scipy.sparse import csr_matrix
from scipy.sparse.csgraph import dijkstra as sp_dijkstra

edges = [(0, 1, 2.0), (0, 2, 5.0), (1, 2, 1.0), (2, 3, 3.0), (1, 3, 7.0)]
n = 4
row, col, data = zip(*[(u, v, w) for u, v, w in edges])
A = csr_matrix((data, (row, col)), shape=(n, n))   # COO 三元组 → CSR
print("CSR indptr:", A.indptr, "indices:", A.indices, "data:", A.data)
d_sp = sp_dijkstra(A, indices=0, directed=True)
print("scipy:", d_sp)

def dijkstra_hand(adj, src):
    """教材 4.4 节版（惰性堆），作金标准。"""
    dist = {src: 0.0}; pq = [(0.0, src)]; done = set()
    while pq:
        d, u = heapq.heappop(pq)
        if u in done: continue
        done.add(u)
        for v, w in adj[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd; heapq.heappush(pq, (nd, v))
    return dist

adj = {u: [] for u in range(n)}
for u, v, w in edges: adj[u].append((v, w))
d_my = dijkstra_hand(adj, 0)
mine = [d_my.get(i, float("inf")) for i in range(n)]
print("教材版:", mine, "一致:", bool(np.allclose(d_sp, mine)))
# 预期输出（实测）：
# CSR indptr: [0 2 4 5 5] indices: [1 2 2 3 3] data: [2. 5. 1. 7. 3.]
# scipy: [0. 2. 3. 6.]
# 教材版: [0.0, 2.0, 3.0, 6.0] 一致: True
```

**要点**：① 三元组 `(row, col, val)` 是 COO（第 4 章边集数组的矩阵化），`csr_matrix(...)` 构造时自动转 CSR 并按行排序——`indptr` 的**差分**给出各行出边数（对照第 4 章邻接表 `adj[u]` 的长度）；② 结果与教材一致（$d = [0, 2, 3, 6]$，✓）；③ scipy 内部走 CSR 行遍历，SpMV/图遍历都是 $O(\text{nnz})$ 级（7.2 节）。

## 7.8（编程实现）｜出处：7.4 节（蒙特卡洛）

> **题目**：实现蒙特卡洛估计 $\pi$ 并绘制误差 $\sim N^{-1/2}$ 的对数坐标验证图。输出目标：斜率约 $-0.5$。

```python
import math
import numpy as np

rng = np.random.default_rng(0)
Ns = [10**3, 10**4, 10**5, 10**6, 10**7]
errs = []
print(f"{'N':>10} {'估计':>8} {'|误差|':>10}")
for N in Ns:
    pts = rng.random((N, 2))                       # 单位方形均匀撒点
    est = 4 * np.mean((pts**2).sum(axis=1) <= 1)   # 落入四分之一圆比例 ×4
    e = abs(est - math.pi)
    errs.append(e)
    print(f"{N:>10} {est:>8.4f} {e:>10.2e}")

xs = [math.log10(N) for N in Ns]
ys = [math.log10(e) for e in errs]
xm, ym = sum(xs)/len(xs), sum(ys)/len(ys)
slope = sum((x-xm)*(y-ym) for x, y in zip(xs, ys)) / sum((x-xm)**2 for x in xs)
print("log-log 斜率:", round(slope, 3), "（理论 -0.5）")
# 预期输出（实测，本机一次运行）：
#      N     估计     |误差|
#     1000   3.2440  1.02e-01
#    10000   3.1440  2.41e-03
#   100000   3.1436  1.97e-03
#  1000000   3.1398  1.84e-03
# 10000000   3.1418  1.91e-04
# log-log 斜率: -0.557 （理论 -0.5）
```

**要点与注意事项**：① 单次实验的误差是随机变量，不会严格逐点落在 $N^{-1/2}$ 直线上（中间两点几乎平齐是正常噪声）；正确做法是**每个 $N$ 重复多次取均值/中位数**或对多条独立轨迹平均后再拟合——多轨迹平均的斜率稳定在 $-0.5$ 附近（本例全序列拟合 $-0.557 \approx -0.5$，✓）。② $O(1/\sqrt N)$ 的根源：伯努利指示变量方差 $p(1-p)$ 有界，均值的标准误 $\sigma/\sqrt N$（中心极限定理）。③ 精度每翻倍需 4 倍采样——7.9 节误区 6 的"写报告给置信区间"的出处。

## 7.9（开放思考）｜出处：7.1.2、7.1.3 节

> **题目**：RAG 服务的检索层为什么普遍选 HNSW 而非 LSH？（从召回率曲线、内存、动态插入三个维度作答。）

**参考答案（约 250 字）：** 第一，**召回率-速度曲线**：HNSW 的贪心图下行利用**连续的向量距离**导航，每一步都朝更近的方向移动，同样的候选预算下召回率-QPS 的 Pareto 前沿显著优于 LSH；LSH 把连续相似度量化为 k 位哈希码，**量化边界两边的近邻被机械切开**，要么靠多表（L↑）补召回要么漏检，精度上限天然低一截。第二，**内存**：HNSW 只存一份向量 + 每点 M 条邻居边（$O(nM)$ 指针，M 典型 16–48），空间可控且随 ef/参数灵活；LSH 需要 L 张表的哈希码索引副本，且位宽/表数的调参往往在内存上再付一份。第三，**动态插入**：HNSW 在线插入 = 抛硬币定层 + 局部连边（逐层贪心找邻居），单点插入 $O(\log n)$ 级、无需全库重建；LSH 虽然也可插入（往各表桶里追加），但随机超平面是**固定**的——数据分布漂移后桶的区分度退化，需重建哈希族。三者叠加解释了 Faiss/向量数据库以 HNSW 为主力索引的现状；LSH 的剩余优势场景是超大规模、内存极敏感、可接受较低召回的流式去重类任务。

## 7.10（挑战题）｜出处：7.1.3 节 + HNSW 论文

> **题目**：写出 HNSW"启发式选边"（heuristic 2）如何避免"互连近邻抱团"导致的搜索死胡同；在简化实现中对比"朴素选最近 M 条边"与"启发式选边"的召回率差异并解释。

**机制解析：**

1. **朴素选边的问题**：为每个新点 $q$ 直接连"距离最近的 $M$ 个候选"。这会形成**近邻抱团**（mutual proximity clusters）：$q$ 的 $M$ 条边全部指向同一小簇内部——图在局部高度冗余、在全局却是"孤岛"。贪心搜索进入该簇后，簇内边都很短但**没有指向簇外的"出口边"**，卡在局部最优（死胡同），召回率随簇密度上升而下降。
2. **启发式 2（论文 Algorithm 4）**：把候选按到 $q$ 的距离**升序**逐一考察；候选 $e$ 被接受当且仅当

$$\text{dist}(e, q) \;<\; \min_{r \in \text{已选集}} \text{dist}(e, r).$$

   即：**若 $e$ 离某个已选邻居 $r$ 比离 $q$ 更近（被 $r$ "覆盖"），就丢弃 $e$**。效果——已选集彼此拉开距离，边集天然分散在 $q$ 周围的不同方向：既有指向近簇的短边，也有被保留的**长程边**（它们不落在任何已选邻居的覆盖范围内）。这正是"可导航小世界"中 navigable 的来源：底层保证短程精确、上层长程边提供跳出局部簇的高速通道（与第 3 章跳表"顶层稀疏长程边"同思想）。
3. **核心证明/论证骨架**（对比实验的预期）：对每个查询 $q$，设贪心路径必须经过的"搜索图最短路"上的关键跳 $u \to v$。朴素选边下，若 $u$ 的 $M$ 条边全在簇内，$v \notin N(u)$，路径中断；启发式 2 下 $v$ 若不被 $u$ 的更近已选邻居覆盖则必然入选——即"**到 $q$ 更近的方向不会被簇内边挤占**"（贪心下行恰好需要这些方向）。由此启发式图的贪心搜索收敛率不依赖簇密度，召回率显著更高。

**实现骨架（综合项目 1 的对比实验）：**

```python
def select_neighbors_naive(candidates, M):

    return [node for _, node in candidates[:M]]
```
