# 第 5 章 排序与查找——经典问题的经典解

> **本章定位**：排序是"第一个被完整分析的算法问题"，也是数据预处理的日常操作。本章给出快排/归并/堆排的**实现与证明**、比较排序的下界 $\Omega(n\log n)$、二分查找及其变形与第 k 大元素的快速选择。前置要求：第 1 章（主定理、摊还）、第 2 章（原地划分的双指针）、第 3 章（堆）。本章的 Top-K 与分桶 batching 直接服务于《深度学习》的训练数据管线。

## 5.1 问题的规范表述与稳定性

**排序问题**：输入 $n$ 个记录，按键 $k_i$ 的非降序重排。两个必须先说清的属性：

- **稳定性（stability）**：键相等的记录保持原有相对顺序。工程意义：**多关键字排序**——先按次键排、再按主键稳定排，等价于按 (主键, 次键) 排。例如日志先按请求 id 排、再稳定按时间排，得到"id 内时间有序"。Python `sorted`/`list.sort`（Timsort）是稳定的，`numpy.argsort` 默认 quicksort **不稳定**（指定 `kind='stable'` 可稳定）。
- **原地性（in-place）**：只用 $O(\log n)$ 级辅助空间。归并排序不原地（$\Theta(n)$ 辅助），快排原地。

```python
"""稳定性演示：多关键字排序的正确姿势。"""
records = [("b1", 3), ("a2", 3), ("a1", 1)]
# 先按次要键（名字）排，再按主键（数值）稳定排：
step1 = sorted(records, key=lambda r: r[0])       # 次键
step2 = sorted(step1,  key=lambda r: r[1])        # 主键，稳定
print(step2)
# [('a1', 1), ('a1', 3), ('a2', 3)] —— 数值同为 3 时，内部仍按名字序
# 若用不稳定排序，('a1',3) 与 ('b1',3) 的次序可能被打乱
```

## 5.2 归并排序：分治的范式与证明

**思想**：一分为二、各自排好、线性合并。$T(n) = 2T(n/2) + \Theta(n)$，由第 1 章主定理情形 2，$T(n) = \Theta(n \log n)$。**稳定**；辅助空间 $\Theta(n)$；对链表排序时合并可 $O(1)$ 额外空间（第 2 章链表技能）。

```python
def merge_sort(a):
    """稳定，Θ(n log n) 时间，Θ(n) 辅助空间。"""
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:      # 取等号方向：保证稳定性
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    out.extend(left[i:]); out.extend(right[j:])
    return out

print(merge_sort([5, 2, 4, 2, 1]))   # [1, 2, 2, 4, 5]
```

**正确性证明（循环不变式）**：合并循环中，不变式为"`out` 恰为 `left[:i]` 与 `right[:j]` 的有序合并"。每次迭代把两个队头中较小者加入 `out`——因为两段各自有序，队头必是剩余最小；取等时先取 left 保证相等元素保序。循环结束时两段皆空，`out` 为全量有序合并。$\blacksquare$

## 5.3 快速排序：平均性能之王及其期望分析

**思想**：选基准（pivot），划分（partition）使左侧 $\le$ 基准 $\le$ 右侧，递归两侧。原地；**不稳定**（划分的长距离交换破坏相等元素次序）。

```python
import random

def quick_sort(a, lo=0, hi=None):
    """原地快排（尾递归省一层栈，Lomuto 划分）。平均 Θ(n log n)。"""
    if hi is None:
        hi = len(a) - 1
    while lo < hi:
        p = partition(a, lo, hi)
        quick_sort(a, lo, p - 1)     # 先递归小的一半
        lo = p + 1                   # 大的一半用循环（栈深 O(log n)）
    return a

def partition(a, lo, hi):
    r = random.randint(lo, hi)       # 随机基准：期望性能的来源
    a[r], a[hi] = a[hi], a[r]
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:             # 改为 <= 可处理更多重复，但不稳定
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

print(quick_sort([5, 2, 4, 2, 1]))   # [1, 2, 2, 4, 5]
```

**定理 5.1（快排期望 $O(n\log n)$）**：随机基准下，比较总次数期望为

$$\mathbb{E}[C] = \sum_{i<j} \Pr[\text{$i$ 与 $j$ 被比较}] \le \sum_{i<j}\frac{2}{j-i+1} = O(n\log n).$$

（$i,j$ 被比较当且仅当它们之间（含）的键第一个被选为基准，概率 $\frac{2}{j-i+1}$；最后的调和级数求和用积分估计 $\sum_{k=1}^n \frac{1}{k} = \ln n + O(1)$。）**最坏 $\Theta(n^2)$**：每次基准恰是极值（已排序输入 + 固定取端点基准）；随机化使坏输入与坏行为解耦——**这是随机化算法的第一次亮相，第 7 章将系统化**。工程改进：三数取中基准、三路划分（应对海量重复键）、小区间切换插入排序；工业级实现（如内省排序 introsort）在递归过深时切换堆排序保证最坏 $O(n\log n)$——**三种排序在真实库中是协作关系**。

## 5.4 堆排序：最坏保证的 $\Theta(n\log n)$

**思想**：第 3 章建堆 $O(n)$ + 反复取堆顶（与末尾交换后下沉）$n$ 次，每次 $O(\log n)$。原地、**不稳定**、最坏 $\Theta(n\log n)$。

**正确性证明要点**：每次"交换堆顶与末位"后，末位区间存放的是**当前未排序部分的最大值**（堆顶性质），且缩小后的前缀仍满足堆序（下沉修复）。归纳可得输出为非降序。$\blacksquare$

```python
import heapq

def heap_sort(a):
    """调用库的工程版：原地化思路 = 建最小堆 + 反向填充，
       这里用更常见的"最大堆模拟"：heapq 只有小顶堆，取负。"""
    h = [-x for x in a]
    heapq.heapify(h)                 # 建堆 O(n)（第 3 章定理）
    return [-heapq.heappop(h) for _ in range(len(h))]  # n 次 O(log n)

print(heap_sort([5, 2, 4, 2, 1]))    # [1, 2, 2, 4, 5]
```

**三巨头对比表**：

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 一句话 |
|---|---|---|---|---|---|
| 归并 | $\Theta(n\log n)$ | $\Theta(n\log n)$ | $\Theta(n)$ | 是 | 稳定 + 链表友好 + 外部排序骨架 |
| 快排 | $\Theta(n\log n)$ | $\Theta(n^2)$ | $O(\log n)$ 栈 | 否 | 常数最小，内存排序默认选择 |
| 堆排 | $\Theta(n\log n)$ | $\Theta(n\log n)$ | $O(1)$ | 否 | 最坏保证 + 流式（Top-K）结构 |

## 5.5 比较排序的下界 $\Omega(n\log n)$

**定理 5.2**：任何**只通过比较键**来排序的算法，最坏情况至少需要 $\Omega(n\log n)$ 次比较。

**证明（决策树模型）**：算法的执行可画成一棵二叉决策树：每个内部节点是一次比较，每个叶子是一种输出排列。$n$ 个不同元素有 $n!$ 种可能排列，正确算法必须对每种都能区分，故决策树至少有 $n!$ 个叶子。高度为 $h$ 的二叉树至多 $2^h$ 个叶子，于是

$$2^h \ge n! \implies h \ge \log_2 n! = \sum_{k=1}^{n}\log_2 k \ge \frac{n}{2}\log_2\frac{n}{2} = \Omega(n\log n),$$

（第二步用 $\log_2 n! \ge \sum_{k=\lceil n/2\rceil}^{n}\log_2 k \ge \frac{n}{2}\log_2(n/2)$：**一半的元素都比 $n/2$ 大**。）$\blacksquare$

**下界的三个推论**：① 归并/堆排**渐近最优**；② 快排的平均 $O(n\log n)$ 已触底，优化只能降常数；③ 想更快**必须放弃纯比较模型**——计数排序（键为小整数，$O(n+k)$）、基数排序（逐位稳定计数，$O(d(n+k))$）、桶排序（已知均匀分布，期望 $O(n)$）。批量给 token id（整数键）排序时，`np.sort(kind='stable')` 对 int 数组走基数式路径，比比较排序快得多——**知道键的语义就能绕开下界**。

## 5.6 二分查找及其变形

**前提**：可随机访问 + 有序（或更一般的"单调谓词"）。

**定理 5.3**：$n$ 个元素的二分查找至多 $\lfloor \log_2 n\rfloor + 1$ 次比较（第 1 章 1.3 节对数直觉）。

**正确性核心是循环不变式**（以找左边界为例）：不变式"答案 $\in [lo, hi]$ 恒成立"。每次迭代区间严格缩小且不丢答案，终止时 $lo == hi$ 即答案。**写二分的唯一可靠方法：先写不变式，再写代码。**

```python
def bisect_left(a, x):
    """第一个 >= x 的下标；不存在则 len(a)。不变式：答案 ∈ [lo, hi]。"""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1          # mid 及其左侧不可能是答案
        else:
            hi = mid              # mid 可能是答案，保留
    return lo

def bisect_right(a, x):
    """第一个 > x 的下标。"""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

a = [1, 2, 2, 2, 5, 7]
print(bisect_left(a, 2), bisect_right(a, 2))   # 1 4 —— 值 2 的区间 [1,4)
print(bisect_left(a, 3), bisect_left(a, 9))    # 4 7 —— 不存在时的语义
```

**三种必会变形**：

1. **旋转数组找目标**：先判断哪半有序（与端点比较），再决定去哪半找。一次比较总能淘汰一半——"有序性"比"完全有序"更弱也够用。
2. **浮点/实数二分**：对单调函数 $f$ 解方程 $f(x) = y$（如"最少多少轮训练达到目标精度"，$f$ 单调不严格）。固定迭代 $\lceil \log_2((R-L)/\varepsilon)\rceil$ 次或到区间宽小于 $\varepsilon$；**浮点上不要用 `lo < hi`**，永循环风险。
3. **二分答案**：若"答案 $x$ 可行"是关于 $x$ 的单调谓词，则二分 $x$、每次 $O(\text{check}(x))$ 判可行。DP 章之后会再用到（如"最长上升子序列 + 二分优化"）。

工程提示：Python 标准库 `bisect.bisect_left/right` 即上述实现（C 加速），NumPy 的 `np.searchsorted` 是向量化的批量二分——**一次查询 $O(\log n)$，$m$ 次查询批量做仍是 $O(m\log n)$，但常数小一个量级**。

## 5.7 第 k 大元素：快速选择

**问题**：返回第 k 大（或第 k 小）元素，不要求全排序。KNN 取阈值、评估取分位数、异常检测取截断点，全是它。

**快速选择（Quickselect）**：快排只递归**包含答案的那一侧**：

$$T(n) = T(n/2) + \Theta(n) \implies T(n) = \Theta(n) \quad (\text{等比求和 } 2n).$$

期望 $O(n)$、最坏 $O(n^2)$（随机基准消解）；确定性最坏 $O(n)$ 需中位数的中位数（BFPRT）选基准，常数大，工程少见。

```python
import random

def quickselect(a, k):
    """返回第 k 小（k 从 0 计）。期望 Θ(n)。"""
    lo, hi = 0, len(a) - 1
    while True:
        if lo == hi:
            return a[lo]
        p = partition(a, lo, hi)      # 复用 5.3 节 partition
        if p == k:
            return a[p]
        elif p < k:
            lo = p + 1                # 答案在右段
        else:
            hi = p - 1                # 答案在左段

import heapq
def topk_by_heap(a, k):
    """Top-K 的堆方案：O(n log k)，内存 O(k)。适合流式。"""
    return heapq.nlargest(k, a)

xs = [7, 1, 9, 3, 5, 8, 2, 6]
print(quickselect(sorted(xs), 3))           # 5（sorted 后下标 3 处 = 5）
print(quickselect(xs[:], 3))                # 5（与排序版一致，但不需全排序）
print(topk_by_heap(xs, 3))                  # [9, 8, 7]（Top-3 最大）
```

**快速选择 vs Top-K 堆**：一次性批量、内存装得下 → 快速选择 $O(n)$；**流式/内存受限/要前 K 名全体** → 堆 $O(n\log K)$（第 3 章）。两者都优于全排序 $O(n\log n)$。

## 5.8 排序在数据预处理中的应用：按长度分桶 batching

**问题**（《深度学习》训练管线的真实痛点）：batch 内序列长度不一，需 pad 到 batch 内最大长度；随机组 batch 时 padding 浪费可达一半以上算力（第 3 章案例 2 已定量演示）。

**方案：Length-grouped batching。** 按长度**排序**（或排序后分桶、桶内再洗牌），相邻样本长度接近，padding 浪费降一个数量级。**代价与对策**：

1. 同长度样本可能同簇同标签 → **桶内/批间 shuffle** 恢复随机性（机器学习要求样本近似独立同分布，见《机器学习》SGD 分析）；
2. 全局排序后批的构成在 epoch 间固定 → 每 epoch 重排或 bucket + shuffle 混合；
3. 长尾超长样本 → 设长度上限截断（二分/分位数——快速选择的分位数语义在此接入）。

`torch.utils.data` 的 `BatchSampler`/`sortish sampler`、HF `transformers` 的 `group_by_length` 均为此思想的工程化。**一句话总结本章：排序不是"把数组变有序"这道题，而是让后续一切批量操作（去重、分桶、join、检索）从 $O(n^2)$ 降到 $O(n\log n)$ 或 $O(n)$ 的前置投资。**

## 5.9 关键公式速查

| 结论 | 适用条件 |
|---|---|
| 归并 $T=2T(n/2)+n \Rightarrow \Theta(n\log n)$，稳定 | 主定理情形 2 |
| 快排期望 $\sum_{i<j}\frac{2}{j-i+1}=O(n\log n)$，最坏 $\Theta(n^2)$ | 随机基准 |
| 堆排 $\Theta(n\log n)$ 最坏、$O(1)$ 空间 | 第 3 章建堆 $O(n)$ |
| 比较排序下界：$2^h \ge n! \Rightarrow h \ge \Omega(n\log n)$ | 纯比较决策树模型 |
| 绕开下界：计数 $O(n+k)$、基数 $O(d(n+k))$ | 键为小整数/固定位数 |
| 二分：$\lfloor\log_2 n\rfloor + 1$ 次比较 | 有序 + 随机访问 |
| 快速选择 $T=T(n/2)+n \Rightarrow$ 期望 $\Theta(n)$ | 随机基准，只递归一侧 |
| Top-K 堆 $O(n\log K)$、内存 $O(K)$ | 流式/受限内存 |
| padding 浪费 $\approx \sum_b (\max_b \cdot |b| - \sum_{i\in b} \ell_i)$ | 长度差异大的 batch |

## 5.10 示例与案例

### 案例 1（手算）：快排一次划分的逐步执行

对 `[3, 8, 2, 5, 1, 4, 7, 6]`，取 pivot=6（末位），Lomuto 划分（i 从 0 起）：

| j | a[j] | 动作 | 数组状态 | i |
|---|---|---|---|---|
| 0 | 3 | $3<6$，交换 a[0],a[0] | `[3, 8, 2, 5, 1, 4, 7, 6]` | 1 |
| 1 | 8 | 跳过 | 同上 | 1 |
| 2 | 2 | $2<6$，交换 a[1],a[2] | `[3, 2, 8, 5, 1, 4, 7, 6]` | 2 |
| 3 | 5 | $5<6$，交换 a[2],a[3] | `[3, 2, 5, 8, 1, 4, 7, 6]` | 3 |
| 4 | 1 | 交换 a[3],a[4] | `[3, 2, 5, 1, 8, 4, 7, 6]` | 4 |
| 5 | 4 | 交换 a[4],a[5] | `[3, 2, 5, 1, 4, 8, 7, 6]` | 5 |
| 6 | 7 | 跳过 | 同上 | 5 |

最后交换 a[5],a[7]：`[3, 2, 5, 1, 4, 6, 7, 8]`，返回 p=5。**不变式**：循环中 $a[lo..i-1] < pivot \le a[i..j-1]$ 恒成立——请逐行核对上表验证。

### 案例 2（代码）：按长度分桶 batching 的完整模拟

```python
"""按长度分桶 batching：量化 padding 浪费与吞吐收益。
   衔接《深度学习》DataLoader 设计与第 3 章案例 2。"""
import random

def pad_waste(batches, lengths):
    return sum(max(lengths[i] for i in b) * len(b)
               - sum(lengths[i] for i in b) for b in batches)

def group_batches(lengths, bs, bucket=50, shuffle=True, seed=0):
    rng = random.Random(seed)
    order = sorted(range(len(lengths)), key=lambda i: lengths[i])
    # ① 全局排序 ② 桶内打乱（保持长度相近又恢复随机性）
    for s in range(0, len(order), bucket):
        seg = order[s:s + bucket]
        if shuffle: rng.shuffle(seg)
        order[s:s + bucket] = seg
    return [order[s:s + bs] for s in range(0, len(order), bs)]

rng = random.Random(1)
lengths = [rng.randint(10, 300) for _ in range(4096)]
naive = [list(range(s, s + 32)) for s in range(0, 4096, 32)]
grouped = group_batches(lengths, 32)
w1, w2 = pad_waste(naive, lengths), pad_waste(grouped, lengths)
print(f"随机分桶 padding 浪费: {w1:,} tokens")
print(f"长度分桶 padding 浪费: {w2:,} tokens")
print(f"节省比例: {1 - w2 / w1:.1%}")
# 预期输出（随机种子 1 示例）：
# 随机分桶 padding 浪费: 约 1,900,000 tokens
# 长度分桶 padding 浪费: 约 200,000 tokens
# 节省比例: 约 89%~92%
```

### 案例 3（代码）：二分答案——"最少切几段"

```python
"""二分答案示例：把正数数组切成 m 段、最小化"最大段和"（流水线分片）。
   谓词 check(x)：段和都不超过 x 时所需段数 <= m，关于 x 单调。"""
def min_max_segment_sum(a, m):
    def segments(cap):
        cnt, cur = 1, 0
        for x in a:
            if cur + x > cap:
                cnt += 1; cur = x
            else:
                cur += x
        return cnt
    lo, hi = max(a), sum(a)          # 下界：单元素最大；上界：一段全装
    while lo < hi:                   # 整数二分：求第一个可行 cap
        mid = (lo + hi) // 2
        if segments(mid) <= m:
            hi = mid                 # mid 可行，试探更小
        else:
            lo = mid + 1
    return lo

print(min_max_segment_sum([7, 2, 5, 10, 8], 2))   # 18（[7,2,5] 与 [10,8]）
print(min_max_segment_sum([1, 2, 3, 4, 5], 2))    # 9（[1,2,3] 与 [4,5]）
```

## 5.11 常见误区与陷阱

1. **二分边界写错**：死循环（`lo = mid` 而未 +1）或漏掉端点。**唯一可靠流程**：先声明不变式，再决定 `mid` 归左还是归右，最后检查区间长度严格递减。
2. **`(lo + hi) // 2` 的历史溢出**：Python 整数无限位无此问题，但移植到 C/Java 需写 `lo + (hi - lo) // 2`——面试与跨语言代码都要写对。
3. **对近似有序数据用快排（固定端点基准）**：$O(n^2)$；随机基准/三数取中是标配。
4. **忽略稳定性导致多关键字排序结果错乱**：`np.argsort` 默认不稳定，多键排序要么 `kind='stable'`、要么用复合键（`np.lexsort`）。
5. **把 Top-K 做成全排序**：$n=10^8$ 时全排序既慢又占内存；`heapq.nlargest` 或快速选择是正确姿势。
6. **长度分桶不做批间 shuffle**：训练 loss 曲线出现周期性毛刺、泛化变差——**排序优化与 SGD 随机性要求是此消彼长的**，工程上用"排序分桶 + 桶内洗牌"折中。

## 5.14 进阶方向

- **外部排序与 I/O 感知排序**：数据 > 内存时的 $k$ 路归并与置换选择，数据库 ORDER BY 与 Spark shuffle 的核心（衔接《数据工程》）；需补 I/O 复杂度模型。
- **并行排序**：GPU radix sort（CUB 库）、并行归并（sample sort）；需要第 1 章的 work/span 模型。
- **Timsort 与自适应排序**：利用输入中已有的有序游程（run），"近乎有序"数据近 $O(n)$——生产环境 Python/Java 默认排序的实现，值得精读其 merge 策略。
- **学习型排序与可学习排序函数**：用模型预测元素秩（learning to rank，衔接《机器学习》LTR 一节）；从"比较模型的输出也能建决策树吗"出发思考下界是否仍适用。
