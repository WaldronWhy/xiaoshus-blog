# 第 3 章 树与堆——层次化数据

> **本章定位**：从线性的"前驱/后继"升级为层次化的"父/子"关系。上一章的哈希表提供精确匹配，本章的 BST/平衡树提供**有序匹配**（找大于 x 的最小元素），堆提供**按优先级出队**，Trie 提供**前缀匹配**。这四种能力分别是第 4 章 Dijkstra 的优先队列、第 5 章堆排序、第 7 章 KD 树与 HNSW、分词器前缀匹配的直接地基。

## 3.1 二叉树：结构、性质与遍历

**定义（二叉树，binary tree）**：每个节点至多有两个孩子的有根树，孩子区分左右。基本术语：深度（到根的边数）、高度（最深叶子深度）、满/完全二叉树。一个关键的计数事实：**$n$ 个节点的二叉树高度 $h$ 满足 $\lceil \log_2(n+1)\rceil - 1 \le h \le n-1$**——下界对应完全二叉树，上界对应每层只有一个节点的"链"。本章后半部分的所有努力，本质上都是**把 $h$ 压向 $\log n$**。

**四种遍历及其语义**：

- **前序**（根左右）：序列化、自顶向下传递信息（如决策树判断路径）；
- **中序**（左根右）：BST 中得到**升序序列**——"有序性"的提取器；
- **后序**（左右根）：自底向上聚合（子树大小、表达式树的求值、依赖先行者的处理）；
- **层序**（逐层，用队列）：广度优先视角，第 4 章 BFS 的树特例。

```python
from collections import deque

class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def inorder(t):
    return inorder(t.left) + [t.val] + inorder(t.right) if t else []

def level_order(t):
    if not t: return []
    out, q = [], deque([t])
    while q:
        node = q.popleft()            # 队列：FIFO = 层序
        out.append(node.val)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
    return out

t = TreeNode(2, TreeNode(1), TreeNode(3, None, TreeNode(4)))
print(inorder(t))       # [1, 2, 3, 4]（若为 BST 则有序）
print(level_order(t))   # [2, 1, 3, 4]
```

**深度语义**：递归遍历的空间代价是递归栈深 $O(h)$。一条重要的换算：把"子问题规模"从 $n$ 换成"深度"，遍历是每个节点 $O(1)$ 工作 × $n$ 个节点 = $\Theta(n)$ 时间——树问题的时间复杂度几乎都是"每节点常数 × 节点数"。

## 3.2 二叉搜索树：有序性的容器

**定义（BST）**：对每个节点，左子树所有键 < 该键 < 右子树所有键（无重复时）。

**性质 3.1**：BST 中查找、插入、删除均为 $\Theta(h)$（沿一条根-叶路径比较）。中序遍历输出升序序列（可对结构归纳证明：左子树全部先于根、右子树全部后于根）。

**定理 3.2（退化）**：按已排序序列依次插入 $n$ 个键，得到高度 $n-1$ 的链，操作退化为 $\Theta(n)$。反之随机插入序的期望高度为 $O(\log n)$（期望 $4.31\ln n$ 量级）。

**含义**：BST 的性能**由输入顺序决定**——这是不可接受的工程性质，催生了自平衡树。

```python
class BST:
    """无重复键 BST：search/insert 均为 Θ(h)。"""
    def __init__(self):
        self.root = None

    def insert(self, key, val=None):
        def _ins(node):
            if node is None:
                return TreeNode(key, val)      # TreeNode.val 复用为 value
            if key < node.val:  node.left = _ins(node.left)
            elif key > node.val: node.right = _ins(node.right)
            return node
        self.root = _ins(self.root)

    def search(self, key):
        node = self.root
        while node:
            if key == node.val: return True
            node = node.left if key < node.val else node.right
        return False

bst = BST()
for k in [5, 2, 8, 1, 3]:
    bst.insert(k)
print(bst.search(3), bst.search(7))    # True False
print(inorder(bst.root))               # [1, 2, 3, 5, 8] —— 中序即有序
```

## 3.3 平衡树：只需掌握的三个思想

自平衡 BST 在每次修改后维持 $h = O(\log n)$。工程上不需要手写它们（Python 中可用 `sortedcontainers`，C++ 是 `std::map`），但必须掌握三种**思想**：

1. **AVL 树——刚性平衡**：每个节点维护 $|\text{height}(L) - \text{height}(R)| \le 2$（实际为 $\le 1$），失衡时用**旋转**（rotation，局部指针重组）修复。旋转是 $O(1)$ 的"局部手术"，且能保持中序不变——这一"保持有序的局部重组"技巧在 KD 树、Splay 树中通用。插入/删除/查找均严格 $O(\log n)$，查询偏快的场景优选。
2. **红黑树——柔性平衡**：给节点着红/黑，用 5 条着色性质保证**最长路径 ≤ 2 倍最短路径**。修改后至多 $O(1)$ 次旋转（AVL 可能 $O(\log n)$ 次），写多读少的场景（如 Linux 内核、C++ `std::map`）优选。**思想**：把"完全平衡"放松为"有界不平衡"，换取修改代价的摊还降低。
3. **B 树/B+ 树——为磁盘而生**：不是二叉，而是每个节点有 $O(m)$ 个孩子、树高仅 $O(\log_m n)$。一次节点读入 = 一次磁盘/SSD 块读取，树高即 I/O 次数——**把树高摊薄到与块大小倒数成正比**。数据库索引与文件系统全是 B+ 树；《深度学习》参数服务器对大 Embedding 表的分片索引思想同源。例：$m=512$、十亿级键，树高约 4——**4 次 I/O 定位任意一个键**。

**统一视角**：三者都在回答同一问题——"如何在修改中廉价地维持 $\log$ 级高度"。AVL 用高度差、红黑用颜色、B 树用块内多路。掌握这个提问方式，你就可以读懂 Splay、Treap、跳表等一切变体。

## 3.4 堆与优先队列

**优先队列（priority queue）**：出队顺序由优先级决定而非到达顺序。第 4 章 Dijkstra/A*、第 5 章堆排序、调度系统（按长度分桶、按优先级服务）都靠它。

**定义（二叉堆，binary heap）**：用**数组**存储的完全二叉树，满足堆序性质：父 ≤ 子（最小堆）。数组表示：节点 $i$ 的父为 $(i-1)//2$，孩子为 $2i+1, 2i+2$。**完全性使树高恰为 $\lfloor\log_2 n\rfloor$**——堆不需要指针。

**两个核心操作**：

- **上浮（sift-up，$O(\log n)$）**：新元素放末尾，与父比较、小则交换上移——用于插入；
- **下沉（sift-down，$O(\log n)$）**：取走堆顶后把末尾元素放到顶，与较小孩子交换下移——用于弹出堆顶。

```python
"""从零实现最小堆（机制层）；工程层直接用 heapq。"""
class MinHeap:
    def __init__(self):
        self.a = []

    def push(self, x):
        a = self.a; a.append(x)
        i = len(a) - 1
        while i > 0:                       # 上浮
            p = (i - 1) // 2
            if a[p] <= a[i]: break
            a[p], a[i] = a[i], a[p]
            i = p

    def pop(self):
        a = self.a
        if not a: raise IndexError("empty heap")
        top, last = a[0], a.pop()
        if a:
            a[0] = last
            i, n = 0, len(a)
            while True:                    # 下沉
                l, r, m = 2*i + 1, 2*i + 2, i
                if l < n and a[l] < a[m]: m = l
                if r < n and a[r] < a[m]: m = r
                if m == i: break
                a[i], a[m] = a[m], a[i]
                i = m
        return top

h = MinHeap()
for x in [5, 1, 3, 2]: h.push(x)
print([h.pop() for _ in range(4)])     # [1, 2, 3, 5]
```

**定理 3.3（建堆为 $O(n)$）**：从最后一个非叶节点倒序对每个节点下沉，代价为

$$\sum_{h=0}^{\lfloor \log_2 n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil \cdot O(h) \le n \sum_{h\ge0} \frac{h}{2^{h+1}} \cdot O(1) = O(n),$$

其中高度为 $h$ 的节点至多 $\lceil n/2^{h+1}\rceil$ 个，而 $\sum h/2^h = 2$（等比-算术混合级数收敛）。**大多数节点在浅层、干便宜的活**——又是第 1 章"等比求和"的模式。注意对比：用 $n$ 次 `push` 建堆是 $O(n\log n)$，**倒序下沉法严格更快**。

**Python `heapq` 要点**：只有最小堆；元组 `(key, val)` 按字典序比较可实现带优先级队列；无 decrease-key——Dijkstra 中用"懒惰删除"（入堆时允许重复，弹出时跳过已过期项），代价是堆大小 $\Theta(|E|)$，见第 4 章。

**Top-K 范式（AI 高频）**：$n$ 个向量与查询的相似度中取最大 $K$ 个。维护大小 $K$ 的**最小堆**（堆顶 = 当前第 K 大），逐个元素比较堆顶：$O(n\log K)$、内存 $O(K)$——比全排序 $O(n\log n)$ 省，比维护有序列表常数小。KNN 检索（第 7 章）逐查询执行此范式。

## 3.5 Trie：前缀即路径

**定义（Trie，前缀树）**：把字符串的**每个前缀**对应一个节点；边标注字符（或字节）。查找"是否存在以 p 为前缀的词" = 沿 p 逐字符下行走到了几层、该层节点是否被标记为词尾。

- 插入/查找一个长度 $L$ 的词：$\Theta(L)$——**与词表规模 $|V|$ 无关**（对比哈希表的 $O(L)$：同为 $O(L)$，但 Trie 支持哈希表做不到的**前缀与有序遍历**）；
- 空间：字符集 $\Sigma$ 上最多 $\Theta(\text{总字符数})$ 个节点（用 dict 孩子表可省到实际分支数）。

```python
class Trie:
    """dict 实现：孩子表按需创建，省空间。"""
    def __init__(self):
        self.children = {}          # char -> Trie
        self.is_word = False
        self.id = None              # 词表 id（AI 词表的典型附加信息）

    def insert(self, word, wid=None):
        node = self
        for ch in word:
            node = node.children.setdefault(ch, Trie())
        node.is_word, node.id = True, wid

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_word

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

    def complete(self, prefix, limit=5):
        """自动补全：先走到前缀末端，再 DFS 收集词尾。"""
        node = self._walk(prefix)
        if node is None: return []
        out = []
        def dfs(t, path):
            if len(out) >= limit: return
            if t.is_word: out.append(path)
            for ch in sorted(t.children):    # sorted：按字典序给出
                dfs(t.children[ch], path + ch)
        dfs(node, prefix)
        return out

    def _walk(self, s):
        node = self
        for ch in s:
            if ch not in node.children: return None
            node = node.children[ch]
        return node

t = Trie()
vocab = ["deep", "depth", "deer", "dense", "cat"]
for i, w in enumerate(vocab): t.insert(w, wid=i)
print(t.search("deep"), t.search("de"))          # True False
print(t.starts_with("den"), t.starts_with("dx")) # True False
print(t.complete("de"))                          # ['deep', 'deer', 'dense', 'depth']
```

**案例语义（务必掌握）**：

- **自动补全**：`complete` 即交互式输入提示；按词频排序需在节点上挂频次并用第 3.4 节的 Top-K 堆取前 5；
- **分词器前缀匹配**：BPE/WordPiece 编码一个新词时，从当前位置取**最长可匹配前缀**——正是"沿 Trie 贪心下行"的过程（HuggingFace tokenizers 的高效实现即 Trie 变体）；
- **词表去重与统计**：Trie 节点天然聚合共享前缀，适合前缀计数的场景（拼写检查器按编辑距离搜 Trie，见第 6 章与综合项目）。

## 3.6 关键公式速查

| 结论 | 适用条件 |
|---|---|
| $n$ 节点二叉树：$\lceil\log_2(n+1)\rceil - 1 \le h \le n-1$ | 完全二叉树下界、链状上界 |
| BST 操作 $\Theta(h)$；退化插入 $h = n-1$ | 有序插入序列 |
| 完全二叉树：$i$ 的父 $(i-1)//2$，孩子 $2i\pm1$ | 数组表示，无指针 |
| 堆 push/pop $O(\log n)$；peek $O(1)$ | 二叉堆，堆序性质 |
| 建堆 $O(n)$：$\sum_h \frac{n}{2^{h+1}}\,O(h) = O(n)$ | 倒序下沉法 |
| Top-K：$O(n \log K)$，内存 $O(K)$ | 大小 $K$ 的最小堆 |
| Trie 查找 $\Theta(L)$，与 $|V|$ 无关 | $L$ 为键长 |
| 平衡树（AVL/红黑）操作 $O(\log n)$ | 高度有界 |
| B 树高 $O(\log_m n)$，I/O 次数 = 树高 | $m$ 路分裂，块对齐 |

## 3.7 示例与案例

### 案例 1（手算）：一次插入引发的 AVL 双旋（思想演示）

依次插入 3, 2, 1 到普通 BST：1 成为 2 的左孩子，2 成为 3 的左孩子——$h=2$ 起步，继续插入会一直加深。AVL 的修复：在 3 处发现失衡（左-左型），做**右旋**（3 下沉为 2 的右孩子，2 上提），得 2 为根、1/3 为孩子的平衡树。若插入序列是 3,1,2（左-右型），则先对左孩子左旋再右旋（**双旋**）。**记住的只有一件事**：旋转 = "以某个中序不变的方式把一个孩子提上来"，四种情形都能现场推出来，不必背。

### 案例 2（代码）：用堆实现"按长度分桶的批处理调度"

```python
"""训练 DataLoader 的按长度组 batch（模拟）：
   用最小堆按请求长度调度，凑满 batch_size 才发出。
   《深度学习》的 dynamic batching、《模型部署与MLOps》的在线服务同款骨架。"""
import heapq, random

def make_batches(lengths, batch_size, pad_report=False):
    heap = [(L, i) for i, L in enumerate(lengths)]
    heapq.heapify(heap)                      # 建堆 O(n)
    batches, cur = [], []
    while heap:
        L, i = heapq.heappop(heap)           # 最短优先 O(log n)
        cur.append(i)
        if len(cur) == batch_size:
            batches.append(cur); cur = []
    if cur: batches.append(cur)
    if pad_report:
        # 每批 padding 浪费 = batch 内最大长度和 - 各样本长度和
        waste = sum(max(lengths[i] for i in b) * len(b)
                    - sum(lengths[i] for i in b) for b in batches)
        return batches, waste
    return batches

random.seed(0)
lengths = [random.randint(5, 200) for _ in range(1000)]
batches, waste = make_batches(lengths, 32, pad_report=True)
no_sort_waste = sum(max(lengths[i] for i in range(j, min(j+32, len(lengths))))
                    * len(range(j, min(j+32, 1000)))
                    - sum(lengths[i] for i in range(j, min(j+32, 1000)))
                    for j in range(0, 1000, 32))
print("批数:", len(batches))                  # 32（1000/32 向上取整 = 32）
print("按长度分桶 padding 浪费:", waste)      # 约 4000~8000（随机排序的数十分之一量级）
print("随机分桶 padding 浪费:", no_sort_waste) # 约 40000~60000
# 结论：按长度分桶把 padding 浪费降低约一个数量级，
#       直接转化为训练吞吐提升（第 5 章会说明其代价：破坏样本随机性，需再 shuffle 批间顺序）。
```

### 案例 3（代码）：中位数数据流（对顶堆）

```python
"""对顶堆：大顶堆存较小半部，小顶堆存较大半部，中位数 O(log n) 更新。
   监控指标（如流式请求延迟中位数）的在线算法雏形（衔接第 7 章流式算法）。"""
import heapq

class MedianStream:
    def __init__(self):
        self.lo, self.hi = [], []     # lo: 大顶堆（存负数）；hi: 小顶堆

    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))   # 平衡：lo 最大者去 hi
        if len(self.hi) > len(self.lo):                    # 保持 lo ≥ hi
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def median(self):
        if not self.lo: raise ValueError("empty")
        return -self.lo[0] if len(self.lo) > len(self.hi) \
               else (-self.lo[0] + self.hi[0]) / 2

s = MedianStream()
for x in [5, 15, 1, 3]:
    s.add(x)
    print(s.median(), end=" ")
print()
# 预期输出：5 10.0 5 4.0
```

## 3.8 常见误区与陷阱

1. **以为堆能高效"查找任意元素"**：堆只保证堆顶最小，查找是 $O(n)$。需要"查找 + 优先级"时用平衡树或哈希表 + 惰性堆。
2. **`heapq` 无 decrease-key 而硬写**：Dijkstra 的标准工程解法是"允许重复入堆 + 弹出时检查过期"，而不是自己魔改堆内部。
3. **把递归遍历用在大深度树上**：$h$ 可达 $10^5$（退化 BST），Python 默认递归上限约 1000，会 `RecursionError`——用显式栈迭代版遍历（本章 2.3 节栈的又一用武之地）。
4. **混淆完全二叉树与满二叉树**：堆要的是"完全"（层序填满），这保证数组表示无洞；"满"（每节点 0 或 2 孩子）是另一概念。
5. **Trie 的空间失控**：字符集大、前缀共享少时（如哈希过的长 id），Trie 节点数膨胀。此时改用哈希表存全词或**双数组 Trie** 等压缩结构。
6. **Top-K 用最小堆还是最大堆记反**：取**最大** K 个用**最小**堆（堆顶是"守门员"，比它小的都进不来）；取最小 K 个用最大堆（Python 中以负数模拟）。

- 《深度学习》· beam search 与解码：每一步扩展候选并保留 top-K——堆 + 前缀树（Trie 约束合法序列）的组合；学习率调度与早停的优先队列管理；
- 《自然语言处理》· 分词器：BPE/WordPiece 的最长前缀匹配（本章 Trie）+ 合并优先队列；
- 《数据工程》· 流式 Top-K 与会话窗口：堆 + 定长窗口（第 2 章）组合；
- 《模型部署与MLOps》· 在线服务的 batching/调度：本章案例 2 与优先队列；
- 课程内部：第 4 章 Dijkstra/A* 与 Prim 直接消费本章优先队列；第 5 章堆排序复用本章建堆与下沉；第 7 章 HNSW 的多层图搜索是"跳表思想 + 贪心 + 优先队列"的集大成。

## 3.10 拓展阅读

- Cormen et al.《算法导论》第 12、13、19 章（4th ed., MIT Press, 2022）。——BST 随机分析、红黑树完整证明、B 树的 I/O 分析；什么时候读：挑战题需要严格证明时。
- Sedgewick & Wayne.《算法（第 4 版）》§3.1–3.3（平衡查找）、优先队列部分。——AVL/红黑（其 2-3 树推导路径）讲法最直观，配可视化；什么时候读：第一次学平衡树时。
- Knuth《TAOCP》Vol.3 §6.2.1–6.2.4。——树结构研究的百科全书；什么时候读：想了解 Splay 树等自组织结构时。
- Bayer & McCreight. "Organization and Maintenance of Large Ordered Indices"（Acta Informatica, 1972）。——B 树原始论文；什么时候读：接触数据库索引时溯源。
- 文档：`heapq` 官方文档中的"Priority Queue Implementation Notes"与"Theory"小节。——`heapq` 用法与稳定性技巧的一手资料。

## 3.11 进阶方向

- **R 树与四叉树**：BST 思想向空间数据（地理包围盒、图像块）的推广，是计算机视觉与地理系统的索引基础（衔接第 7 章 KD 树）。
- **LSM 树与自适应基数树（ART）**：写优化与内存优化的现代索引，把本章 B 树/Trie 与第 2 章的追加写思想组合，用于流式特征存储。
- **Fenwick 树/线段树**：前缀和与区间统计的 $\log$ 级结构，竞赛与度量监控的常客；从"用完全二叉树管理区间"出发即可入门。
- **学习型索引（learned index）**：用模型替代 B 树的查找路径（Kraska et al., 2018），本章"树高 = 比较次数"的视角正是理解它的钥匙（衔接《机器学习》）。

## 3.12 课后思考与练习

1. **概念辨析**：为什么"用数组实现的完全二叉树"（堆）不需要存指针，而普通二叉树不行？这依赖于哪两条性质？
2. **概念辨析**：哈希表、平衡树、Trie 都能存词表，请从"精确查找 / 前缀查找 / 有序遍历 / 最坏复杂度"四个维度填表对比，并指出 BPE 分词器为什么选 Trie（或其变体）而非哈希表。
3. **计算推导**：含 $n$ 个节点的完全二叉树中，高度为 $h$ 的节点至多有多少个？据此重推建堆 $O(n)$。校验值：至多 $\lceil n/2^{h+1}\rceil$ 个；和为 $2n$。
4. **计算推导**：一棵存有 $10^9$ 个键的 B+ 树，节点扇出 $m=1024$，树高至少多少（根不计）？假设每次 I/O 读 1 个节点，定位一个键需几次 I/O？校验值：高度 3，共 4 次 I/O（含叶子）。
5. **编程实现**：实现 BST 的"第 k 小元素"（中序第 k 个）与"范围查询 $[a,b]$"（输出所有落在区间的键）。输出目标：对 3.2 节的树，第 3 小为 3，范围 $[2,8]$ 输出 `[2,3,5,8]`。
6. **编程实现**：用 `heapq` 实现合并 $k$ 个有序列表（$k$ 路归并，$N$ 总长 $O(N\log k)$），并用它实现"从 1000 个已排序的分片文件中取全局 top-100 词频"。输出目标：与 `sorted` 全量合并结果一致。
7. **编程实现**：给 3.5 节 Trie 增加"按词频的自动补全"：`complete` 返回频次最高的 5 个词（节点挂频次，末端用 Top-K 堆）。输出目标：自测词表上与暴力排序结果一致。
8. **编程实现**：实现对顶堆支持 `delete_median()`，并保持所有操作 $O(\log n)$。输出目标：与"每次重排序求中位数"的朴素实现对拍 1000 组。
9. **开放思考**：第 2 章的哈希表与本章 BST 都是"字典"，MongoDB/B+ 树类数据库选树、Redis 选哈希——从"范围查询需求 + 磁盘 I/O"两个角度写 200 字分析。
10. **挑战题**：证明随机插入序的 BST 期望高度为 $O(\log n)$（提示：期望深度分析，参考 CLRS 12.4 节），再阅读 "Learned Index Structures"（Kraska et al., SIGMOD 2018）摘要，写 200 字：它用模型替换了树路径中的哪一步，为什么可行？
