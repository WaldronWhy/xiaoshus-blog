## 2.1 动态数组：连续内存的威力与代价

在《Python 程序设计》中你每天都在用 `list`，现在补上它"为什么这样快、哪里会变慢"的机制层。

**内存模型直觉**：内存是按地址编号的连续格子。若数组首地址为 $s$、每个元素占 $w$ 字节，则第 $i$ 个元素地址为 $s + i \cdot w$——**下标访问是一次乘法加一次加法**，这就是 $O(1)$ 随机访问的全部秘密。连续存储还带来缓存友好性（cache locality）：读 `a[0]` 时 CPU 会把相邻 64 字节（一个缓存行）一起载入，遍历数组的实际速度远快于逐字节理论值。NumPy 数组快于 Python `list` 的第二个原因（第一是绕过解释器）正在于此：`list` 存的是对象指针，元素本身散落在堆上；NumPy 存的是连续同型数据。

**操作复杂度表**（动态数组，$n$ 为当前长度）：

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 下标读写 `a[i]` | $\Theta(1)$ | 地址算术 |
| 尾部 append/pop | 摊还 $O(1)$ | 扩容见第 1 章 1.4 节 |
| 头部 insert/pop | $\Theta(n)$ | 后续/前移全部元素 |
| 中间 insert/delete | $\Theta(n)$ | 移动插入点之后的元素 |
| 按值查找 | $O(n)$ | 无序时线性扫描 |
| 切片 `a[i:j]` | $\Theta(j-i)$ | 复制区间 |

**一个高频工程陷阱**：在循环里对列表头部 `pop(0)` 做 BFS 或滑动消费，复杂度是 $O(n^2)$。改用 `collections.deque`（双向队列，头尾操作均 $O(1)$）即可。`deque` 的底层是**块状链表**（block of slots，每块约 64 个指针，块间双向链表）：既保住头尾 $O(1)$，又保留相当的局部性——这是"数组与链表折中"的现实案例。

## 2.2 链表：以指针换灵活性

单链表（singly linked list）节点 = 数据 + 后继指针；双向链表再加前驱指针。它放弃了连续性，换来"**已知位置时 $O(1)$ 插入/删除**"与"按需分配内存"。

| 操作 | 链表 | 动态数组 |
|---|---|---|
| 下标访问 | $O(n)$ | $O(1)$ |
| 已知节点处插入/删除 | $O(1)$ | $O(n)$（需移动元素） |
| 按值找到再删除 | $O(n)$ | $O(n)$ |
| 头插/头删 | $O(1)$ | $O(n)$ |
| 内存开销 | 每元素多 1–2 个指针，碎片化 | 有容量冗余 |

**实现要点**（单链表反转，面试与工程均高频）：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val, self.next = val, next

def reverse_list(head):
    """迭代反转单链表。Θ(n) 时间，O(1) 空间。"""
    prev, cur = None, head
    while cur:
        cur.next, prev, cur = prev, cur, cur.next  # 一次完成三步
    return prev

# 验证：1->2->3 反转后为 3->2->1
h = ListNode(1, ListNode(2, ListNode(3)))
h = reverse_list(h)
print(h.val, h.next.val, h.next.next.val, h.next.next.next)  # 3 2 1 None
```

**何时选链表**：真实工程里，"频繁在中间增删"的场景大多可用 `deque`（块状链表）、跳表或哈希 + 链表（LRU 缓存）替代纯链表；纯链表的最大价值在于**作为其他结构的骨架**（哈希桶、图邻接表、LSTM 式的逐节点链接）。

## 2.3 栈与队列：受约束的线性表

**栈（stack）**：后进先出（LIFO），只暴露 push/pop/peek。价值在于约束本身——它能天然"记住路径"：

- 函数调用栈（递归的运行时真相；递归过深触发 `RecursionError` 就是栈溢出）；
- 括号匹配、表达式求值、编辑器撤销；
- **深度优先搜索**（第 4 章）的显式版本；
- **训练循环中的梯度检查点**（gradient checkpointing，见《深度学习》）：牺牲重算换显存，本质是控制"中间结果的入栈量"。

**队列（queue）**：先进先出（FIFO）。变体与用途：

- 普通队列：任务调度、**广度优先搜索**（第 4 章）、DataLoader 的预取缓冲（生产者-消费者）；
- **双端队列 deque**：滑动窗口最大值（本章 2.7 节）；
- **优先队列**：不按到达顺序而按优先级出队——下一章用堆实现。

**两个栈模拟队列**及摊还证明：设栈 A 只管入队、栈 B 只管出队。出队时若 B 空则把 A 全部倒灌进 B。单次"倒灌"代价 $O(|A|)$，但每个元素一生最多被倒灌一次（进入 A 一次、离开 B 一次）——**记账法**：入队时预存 2 个代币（1 个支付本次 push，1 个支付将来的搬家），总代价 $O(n)$，摊还 $O(1)$。

```python
class MyQueue:
    """两栈队列：enqueue/dequeue 摊还 O(1)。"""
    def __init__(self):
        self._in, self._out = [], []

    def enqueue(self, x):
        self._in.append(x)                      # 摊还 O(1)

    def dequeue(self):
        if not self._out:                       # 只在 B 空时倒灌一次
            while self._in:
                self._out.append(self._in.pop())
        if not self._out:
            raise IndexError("empty queue")
        return self._out.pop()                  # O(1)

q = MyQueue()
for x in (1, 2, 3): q.enqueue(x)
print(q.dequeue(), q.dequeue(), q.dequeue())    # 1 2 3（保持 FIFO）
```

## 2.4 哈希表：从 $O(n)$ 到 $O(1)$ 的魔法

哈希表（hash table）是整个 AI 工程栈中被调用次数最多的数据结构：词表（vocabulary）的 token→id 映射、Embedding 查表、`dict` 缓存、去重集合，全是它。

**三要素：**

1. **哈希函数 $h$**：把任意键映射到桶下标。好的哈希函数要均匀（减少冲突）、确定、快。Python 对 `str`/`int` 有内置 `hash()`（注意：出于安全，CPython 默认对 `str` 哈希加盐，跨进程不可复现）。
2. **冲突解决**：键数远大于桶数时，不同键可能落入同一桶。两大流派：
   - **链地址法（separate chaining）**：每个桶挂一条链表/小数组。负载因子 $\alpha = n/m$（$n$ 元素、$m$ 桶）可大于 1，查找期望 $O(1 + \alpha)$。Java `HashMap` 采用此法（桶过长时转红黑树，衔接第 3 章）。
   - **开放寻址（open addressing）**：冲突后按探测序列（线性探测/二次探测/双重哈希）在表内找下一空位。$\alpha$ 必须 $< 1$，通常在 $\alpha$ 超过阈值（如 0.75）时扩容。CPython `dict` 的变体：**紧凑有序字典**——把条目存在稠密数组 `entries` 里，索引数组 `indices` 负责哈希寻址，既省内存又让 `dict` 保持插入序（Python 3.7+ 的语言保证）。
3. **扩容再哈希（rehashing）**：$\alpha$ 超阈值时桶数加倍，所有元素重新哈希分布。单次代价 $O(n)$、摊还 $O(1)$——第 1 章动态数组分析的直接复用。

**期望 $O(1)$ 的前提是简单均匀哈希（simple uniform hashing）假设**：每个键独立等概率地落入每个桶。真实哈希函数不满足独立性，但工程上近似成立；最坏情况（所有键同桶）退化为 $O(n)$，这正是哈希碰撞拒绝服务（HashDoS）攻击的原理，也是各语言给字符串哈希加盐的原因。

**手写一个简化哈希表**（链地址法，揭示机制）：

```python
class SimpleHashMap:
    """链地址法哈希表：set/get/__contains__ 平均 O(1+α)。"""
    def __init__(self, capacity=8, load_factor=0.75):
        self._m = capacity
        self._alpha = load_factor
        self._n = 0
        self._buckets = [[] for _ in range(self._m)]

    def _index(self, key):
        return hash(key) % self._m            # CPython 内置 hash

    def set(self, key, value):
        b = self._buckets[self._index(key)]
        for i, (k, _) in enumerate(b):
            if k == key:
                b[i] = (key, value)           # 覆盖
                return
        b.append((key, value))
        self._n += 1
        if self._n / self._m > self._alpha:
            self._rehash()

    def get(self, key, default=None):
        b = self._buckets[self._index(key)]
        for k, v in b:
            if k == key:
                return v
        return default

    def _rehash(self):
        old, self._m, self._n = self._buckets, self._m * 2, 0
        self._buckets = [[] for _ in range(self._m)]
        for bucket in old:
            for k, v in bucket:
                self.set(k, v)                # 重新哈希：单次 O(n)，摊还 O(1)

hm = SimpleHashMap()
for i in range(100):
    hm.set(f"tok{i}", i)
print(hm.get("tok42"), "tokX" in ("n/a" if False else []), hm.get("tokX", -1))
print(sum(len(b) for b in hm._buckets), len(hm._buckets))
# 预期输出：42 False -1
#          100 256（100 个元素触发了 3 次扩容：8->16->32->64->256? 实际为 8→16→32→64→128→256 中的若干次）
```

**哈希表是词表/Embedding 查找的基础**：BPE 分词器把 token 字符串映射为整数 id，模型再用 id 到 Embedding 矩阵 $\mathbf{E} \in \mathbb{R}^{|V| \times d}$ 中取行——第一步是 `dict` 查找（$O(L)$，$L$ 为 token 长度），第二步是数组下标访问（$O(d)$ 读一行）。训练时每个 batch 都要做数万次这样的查找，哈希表常数因子直接进入数据供给路径。反过来，当键空间大到内存放不下（十亿级 id），就要用第 7 章的布隆过滤器或分布式哈希。

**可变键陷阱**：哈希表要求键不可变（`__hash__` 稳定）。把可变对象（如 `list`）作键会直接 `TypeError`；更隐蔽的是把自定义可变对象作键后修改它——哈希已变、桶位未变，元素"找不到了"。规则：**键只用不可变类型或"永不修改"的自定义类型**。

## 2.5 双指针：有序结构上的 $O(n)$ 扫描艺术

双指针用两个下标协同扫描，把朴素双循环降为单循环。三类范式：

1. **对撞指针**：从两端向中间移动。有序数组两数之和：朴素 $O(n^2)$，对撞 $O(n)$——每步 sum 太大移右端、太小移左端，正确性由有序性保证（被跳过的组合都不可能成解）。
2. **快慢指针**：同向不同速。判环（Floyd 判圈）、原地去重（如有序数组去重：慢指针指向"已保留区间的末尾"）。
3. **同向双指针（滑动窗口雏形）**：见 2.6 节。

```python
def two_sum_sorted(nums, target):
    """有序数组两数之和：对撞指针，Θ(n) 时间 O(1) 空间。"""
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return (lo, hi)
        if s < target:
            lo += 1      # 需要更大的和
        else:
            hi -= 1      # 需要更小的和
    return None

print(two_sum_sorted([1, 3, 5, 8, 10, 14], 15))   # (0, 5)  即 1+14=15
```

**正确性论证**（对撞指针为什么不会漏解）：设唯一解为 $(i^\*, j^\*)$。指针从两端逼近的过程中，第一次出现"一端恰在 $i^\*$ 或 $j^\*$ 上"时，另一端必然也停在对应解的端点上——因为此时区间内其他配对要么和偏大（右端会被左移）要么和偏小（左端会被右移），不可能在错过解的同时越过它。一次移动总是"排除一个不可能成为解的下标"，$n-1$ 次移动后必命中，故不漏不重。

## 2.6 滑动窗口：定长与变长

**滑动窗口（sliding window）** 是双指针的同向特例：维护一段连续区间 $[l, r)$ 及其"窗口统计量"，右端扩张、左端收缩，区间内元素**至多进出各一次**，故为 $O(n)$——注意这里又是一次摊还论证：单步最坏 $O(n)$（左端一次跳很远），序列总代价 $O(n)$。

**变长窗口模板（求和 ≥ target 的最短子数组，元素均为正）**：

```python
def min_len_subarray(nums, target):
    """正数数组中和 ≥ target 的最短连续子数组长度。O(n)。"""
    n = len(nums)
    best, s, l = n + 1, 0, 0
    for r in range(n):                 # 右端每次扩张一格
        s += nums[r]
        while s >= target:             # 满足条件时左端尽量收缩
            best = min(best, r - l + 1)
            s -= nums[l]; l += 1
    return 0 if best == n + 1 else best

print(min_len_subarray([2, 3, 1, 2, 4, 3], 7))    # 2 （子数组 [4,3]）
```

**AI 语境中的窗口**：

- **定长窗口**：N 元统计、token n-gram、流式指标监控（最近 10 分钟错误率）——配合 `deque` 实现 $O(1)$ 更新；
- **变长窗口**：按 token 预算切分文档做 RAG 分块（右扩到长度上限、左收缩到句边界）、视频抽帧的缓冲管理；
- 《深度学习》的卷积与注意力中的"窗口"是另一种含义（局部感受野），但"区间统计量的增量维护"思想一致。

**窗口内最大值（单调 deque，$O(n)$）**——数据供给端按长度分桶时的调度工具：

```python
from collections import deque

def sliding_max(nums, k):
    """长度 k 窗口最大值序列。每个下标至多进出 deque 各一次：O(n)。"""
    dq, out = deque(), []           # dq 存下标，对应值单调递减
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()                # 队尾不可能再成为最大值，淘汰
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()            # 队头滑出窗口
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out

print(sliding_max([1, 3, -1, -3, 5, 3, 6, 7], 3))
# [3, 3, 5, 5, 6, 7]
```

## 2.7 关键公式速查

| 结论 | 适用条件 |
|---|---|
| 数组下标访问 $O(1)$：地址 $= s + i w$ | 连续存储、同型元素 |
| 动态数组 append 摊还 $O(1)$；头插/头删 $\Theta(n)$ | 增长因子 $>1$（第 1 章） |
| 链表已知位置插入/删除 $O(1)$；按位访问 $O(n)$ | 有 prev/next 指针在手 |
| 两栈队列：摊还 $O(1)$，记账 2 代币/元素 | 每元素至多倒灌一次 |
| 链地址查找期望 $O(1+\alpha)$，$\alpha = n/m$ | 简单均匀哈希假设 |
| 开放寻址 $\alpha<1$；$\alpha \to 1$ 时代价发散 | 探测序列均匀 |
| 扩容再哈希：单次 $O(n)$，摊还 $O(1)$ | 桶数按常数倍扩 |
| 滑动窗口 $O(n)$：每元素至多进出窗口各一次 | 指针只单向移动 |
| 单调 deque 窗口最大值 $O(n)$：每下标至多进出一次 | 淘汰"不可能再优"的候选 |

## 2.8 示例与案例

### 案例 1（手算）：哈希表插入与扩容全过程

设桶数 $m=4$、阈值 $\alpha=0.75$、哈希函数 $h(k) = k \bmod 4$（键全为整数）。依次插入键 4, 8, 12, 16, 20：

1. 插 4：$h=0$，桶 0 = [4]，$\alpha = 0.25$。
2. 插 8：$h=0$，桶 0 = [4,8]，$\alpha = 0.5$。
3. 插 12：$h=0$，桶 0 = [4,8,12]，$\alpha = 0.75$ 未超。
4. 插 16：$h=0$，先入桶再检查 $\alpha = 1 > 0.75$，扩容 $m \to 8$，全部按 $k \bmod 8$ 重分布：4,12 → 桶 4；8 → 桶 0；16 → 桶 0。此时桶 0 = [8,16]，桶 4 = [4,12]。
5. 插 20：$h(20) = 20 \bmod 8 = 4$，桶 4 = [4,12,20]。

观察：键 4, 8, 12, 16, 20 是公差 4 的等差数列，在 $m=4$ 时**全部**撞进同一个桶（$h \equiv 0$），扩容到 $m=8$ 后分布到两桶——**这就是扩容的核心价值：给"坏分布"重新洗牌**。同理可解释：为什么让 $m$ 取素数（或用乘法哈希）能打散规律键。

### 案例 2（代码）：滑动窗口统计 n-gram 频次（NLP 预处理）

```python
"""用滑动窗口 + 哈希表统计文本流的 n-gram 频次。
   这是分词/语言模型数据预处理（《自然语言处理》《数据工程》）的原子操作。"""
from collections import defaultdict

def ngram_counts(tokens, n):
    counts = defaultdict(int)          # 哈希表：n-gram 元组 → 次数
    for r in range(len(tokens) - n + 1):     # 窗口右端线性右移
        gram = tuple(tokens[r:r + n])        # 定长窗口切片
        counts[gram] += 1
    return counts

toks = "我 喜欢 自然 语言 处理 我 喜欢 深度 学习".split()
c = ngram_counts(toks, 2)
for gram, k in sorted(c.items(), key=lambda kv: -kv[1])[:3]:
    print(gram, k)
# 预期输出：
# ('我', '喜欢') 2
# ('喜欢', '自然') 1
# ('自然', '语言') 1
print(len(c))     # 8 —— 9 个 token 共 8 个二元组
```

### 案例 3（代码）：LRU 缓存（哈希表 + 双向链表）

```python
"""LRU 缓存：dict 定位 O(1) + 双向链表维护访问序。
   DataLoader 缓存、Embedding 缓存、推理服务 KV 缓存的通用骨架。"""
class Node:
    __slots__ = ("key", "val", "prev", "next")
    def __init__(self, key=None, val=None):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.map = {}                     # key -> Node
        self.head, self.tail = Node(), Node()   # 哨兵，免去边界判断
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, node):
        node.prev.next, node.next.prev = node.next, node.prev

    def _add_front(self, node):           # 挂到 MRU 端
        node.next, node.prev = self.head.next, self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        if key not in self.map: return -1
        node = self.map[key]
        self._remove(node); self._add_front(node)
        return node.val

    def put(self, key, value):
        if key in self.map:
            node = self.map[key]; node.val = value
            self._remove(node); self._add_front(node)
            return
        node = Node(key, value)
        self.map[key] = node; self._add_front(node)
        if len(self.map) > self.cap:
            lru = self.tail.prev            # 淘汰 LRU 端
            self._remove(lru); del self.map[lru.key]

c = LRUCache(2)
c.put(1, 1); c.put(2, 2)
print(c.get(1))     # 1 （1 成为最近使用）
c.put(3, 3)         # 容量超限，淘汰 2
print(c.get(2), c.get(3), c.get(1))   # -1 3 1
```

## 2.9 常见误区与陷阱

1. **在循环里 `list.pop(0)` / `insert(0, x)`**：每次 $\Theta(n)$，整体 $O(n^2)$。用 `collections.deque`。
2. **把可变对象当 dict 键，或键入表后再修改**：`TypeError` 或"元素失踪"。哈希一旦入表不可再变。
3. **误以为 `dict` 查找是"严格 $O(1)$"**：它是平均/期望意义，且最坏 $O(n)$；键哈希质量差（如大量整除关系的整数键）时会明显变慢。
4. **滑动窗口的适用边界**：窗口内统计量必须能"增量撤销"（加减、计数可撤销；最大值不可直接撤销，需单调 deque 这类额外结构）。看到"子数组最值/唯一性"问题就套朴素窗口，会做错。
5. **遍历哈希表时增删元素**：`RuntimeError: dictionary changed size during iteration`。先收集要改的键快照，或用 `list(d.keys())`。
6. **用 `n in list` 做成员判断**（$O(n)$）而不是 `set`（$O(1)$ 期望）——DataLoader 去重、黑名单过滤的隐形慢点。
