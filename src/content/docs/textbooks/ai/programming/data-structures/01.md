# 第 1 章 复杂度分析——衡量算法的尺子

> **本章定位**：全课程的分析工具章，后续每一章的每一个算法都要用本章的记号来"算账"。前置要求：《Python 程序设计》的循环、递归与 NumPy 基础；后续《机器学习》的模型复杂度讨论、《模型部署与 MLOps》的推理成本核算都依赖本章。

## 1.0 本章学习目标

学完本章后，你能够：

1. 用 $O$、$\Omega$、$\Theta$ 的严格数学定义证明一个函数的复杂度归属（如 $3n^2 + 100n \in \Theta(n^2)$）。
2. 对一段 Python 代码逐行标注语句频度，并推导其总复杂度；识别常见复杂度类 $O(1)$ 到 $O(2^n)$ 的"手感"。
3. 对动态数组扩容等操作序列执行摊还分析（聚合法、记账法、势能法），解释"单次 $O(n)$、摊还 $O(1)$"为什么成立。
4. 直接写出分治递归 $T(n)=aT(n/b)+f(n)$ 的解（主定理），并说明其直觉。
5. 用"数据规模 × 复杂度 = 训练时间"的算账式，评估一个 AI 训练/检索方案的可行性（如 attention 的 $O(n^2)$ 为什么在长文本下致命）。

## 1.1 为什么需要一把统一的尺子

在《Python 程序设计》中你已经知道，同一段逻辑用 `for` 循环写和用 NumPy 向量化写，速度可能差 100 倍。但向量化的加速依赖具体机器、具体库版本，不是稳定的结论。我们想要一把**与机器无关**的尺子，回答"当输入变大 10 倍时，运行时间大约变大几倍"这个本质问题。

具体做法是两步抽象：

1. **只数基本操作，不数秒。** 假设赋值、比较、算术、数组下标访问都是 $O(1)$ 的"基本操作"。
2. **只看增长趋势，不看常数。** 当 $n \to \infty$ 时，$3n^2 + 100n$ 与 $n^2$ 的比值趋于常数 3，所以它们的"增长阶"相同。增长阶（asymptotic order）就是我们的尺子。

一个 AI 视角的例子：设有一个大小为 $n$ 的语料库，训练一个 epoch 的代价为 $T(n)$。若 $T(n) = \Theta(n)$，语料扩大 10 倍训练时间约扩大 10 倍；若某个预处理步骤是 $\Theta(n^2)$（例如对全库做两两相似度比对），扩大 10 倍就是 100 倍。**训练预算是固定的，而复杂度阶决定了你的数据能做多大。**

## 1.2 大 O、大 Ω、大 Θ 的严格定义

设 $f(n)$ 与 $g(n)$ 是定义在正整数上的非负函数。

**定义 1（大 O，上界）**：若存在正常数 $c$ 与 $n_0$，使得对所有 $n \ge n_0$ 都有

$$0 \le f(n) \le c \cdot g(n),$$

则记 $f(n) = O(g(n))$，读作"$f$ 增长不快于 $g$"。

**定义 2（大 Ω，下界）**：若存在正常数 $c$ 与 $n_0$，使得对所有 $n \ge n_0$ 都有

$$0 \le c \cdot g(n) \le f(n),$$

则记 $f(n) = \Omega(g(n))$。注意 $f(n) = O(g(n)) \iff g(n) = \Omega(f(n))$。

**定义 3（大 Θ，紧界）**：若 $f(n) = O(g(n))$ 且 $f(n) = \Omega(g(n))$，则 $f(n) = \Theta(g(n))$，即 $f$ 与 $g$ 同阶增长。

**例 1.1**：证明 $f(n) = 3n^2 + 100n + 500 \in \Theta(n^2)$。

- 上界：当 $n \ge 1$ 时，$3n^2 + 100n + 500 \le 3n^2 + 100n^2 + 500n^2 = 603\,n^2$，取 $c=603,\ n_0=1$，故 $f \in O(n^2)$。
- 下界：当 $n \ge 1$ 时，$3n^2 + 100n + 500 \ge 3n^2$，取 $c=3$，故 $f \in \Omega(n^2)$。
- 由定义 3，$f \in \Theta(n^2)$。$\blacksquare$

三条常用运算法则：

- **求和取大**：$O(f) + O(g) = O(\max(f,g))$（要求 $f,g$ 非负且有一个占主导）。顺序复合的代码段，总复杂度取最大段。
- **乘法法则**：$O(f) \cdot O(g) = O(f \cdot g)$。嵌套循环相乘。
- **极限判别法**：$\lim_{n\to\infty} f(n)/g(n) = c$（$0<c<\infty$）$\iff f \in \Theta(g)$；$c=0 \iff f \in o(g)$（严格低阶）；$c=\infty \iff f \in \omega(g)$。

一个易错点：$O$ 是上界不是"等于"。线性扫描是 $\Theta(n)$，说它是 $O(n^3)$ 也严格正确但毫无信息量。**工程交流时尽量用 Θ 表述，用 O 表述时心里要清楚上界是否紧。**

## 1.3 常见复杂度类与"手感"

设每次基本操作耗时约 1 ns（机器级），下表给出不同阶在 $n = 10^6$ 与 $n = 10^9$ 时的量级感：

| 复杂度类 | 名称 | $n=10^6$ | $n=10^9$ | 典型算法 |
|---|---|---|---|---|
| $O(1)$ | 常数 | 1 ns | 1 ns | 哈希查找（平均）、数组下标 |
| $O(\log n)$ | 对数 | 20 ns | 30 ns | 二分查找、平衡树操作 |
| $O(\sqrt n)$ | 平方根 | 1 ms | 1 ms | 试除法判素 |
| $O(n)$ | 线性 | 1 ms | 1 s | 单遍扫描、线性回归一轮 |
| $O(n \log n)$ | 线性对数 | 20 ms | 30 s | 归并排序、构建堆 |
| $O(n^2)$ | 平方 | 17 min | 32 年 | 冒泡排序、朴素 attention |
| $O(n^3)$ | 立方 | 32 年 | 天文数字 | 朴素矩阵乘（指令层面约 $2n^3$） |
| $O(2^n)$ | 指数 | $10^{301000}$ 年 | 天文数字 | 子集枚举、朴素 TSP |
| $O(n!)$ | 阶乘 | 天文数字 | 天文数字 | 全排列 |

（Python 解释器层面每秒约 $10^7$–$10^8$ 次基本操作，比机器级慢 10–100 倍，算账时注意换算。）

**对数复杂度的直觉**：$\log_2 n$ 回答"把 $n$ 不断减半，几次到 1？"。$2^{20} \approx 10^6$，$2^{30} \approx 10^9$，所以十亿级数据的二分查找只需约 30 步。这是"每次排除一半"类策略（二分、平衡树、跳表、堆上浮）共同的复杂度来源。对数是仅次于常数的增长速度——**能把问题做成 $O(\log n)$，就等于宣告它与规模几乎无关**。

三个判断代码复杂度的基本功：

```python
def demo1(n):            # 段 A
    s = 0
    for i in range(n):       # n 次
        for j in range(n):   # 每次 n 次
            s += 1
    return s                # 总计 Θ(n^2)

def demo2(n):            # 段 B
    i = 1
    while i < n:             # i 每次 ×2，执行 log2(n) 次
        i *= 2
    return i                 # 总计 Θ(log n)

def demo3(n):            # 段 C：内层次数随外层折半
    s = 0
    k = n
    while k > 0:
        s += k               # 外层 log n 次
        k //= 2
        for j in range(k):   # 内层 n/2 + n/4 + ... = n
            s += 1
    return s                 # 总计 Θ(n)
```

段 C 的求和：$\sum_{i=1}^{\log n} n/2^i = n(1/2 + 1/4 + \cdots) \le n$。**求和的等比收敛让双层循环仍是线性**——这个模式在后面构建堆的摊还分析中会再次出现。

## 1.4 摊还分析：操作序列的平均代价

有些操作**偶尔昂贵、通常便宜**。若用最坏单次代价描述整个序列，会严重高估。摊还分析（amortized analysis）求的是：**任意长为 $m$ 的操作序列的总最坏代价除以 $m$**，即序列内单操作的平均上界。

### 1.4.1 实例：动态数组扩容

Python `list` 的底层是动态数组（vector）：预先分配容量 $C$，`append` 时若已满，则新开一块 $2C$ 的内存，把旧元素全部搬过去（grow-by-doubling）。单看"触发扩容的那次 append"，代价是 $\Theta(n)$；但我们证明**任意 $n$ 次 append 的总代价是 $O(n)$**，故摊还 $O(1)$。

**方法一：聚合法（直接算总和）。** 从容量 1 开始，append $n$ 次（$n$ 为 2 的幂），搬移代价发生在容量 1, 2, 4, …, $n/2$ 耗尽之时，总搬移次数：

$$\sum_{k=0}^{\log_2 n - 1} 2^k = 2^{\log_2 n} - 1 = n - 1 = \Theta(n).$$

加上 $n$ 次 $O(1)$ 的写入，总代价 $\Theta(n)$，摊还代价 $\Theta(1)$。

**方法二：记账法（银行账户）。** 给每次 append 收费 3 个"代币"：1 个用于本次写入，1 个存着备将来搬移自己，1 个备将来搬移一个"更老的元素"。扩容时旧元素总数与已存款项恰好平衡，账户永不透支。收费 3 即证明了摊还上界 3（与写入方式细节有关，一般教材给 $O(1)$ 即可）。

**方法三：势能法（最通用）。** 定义势函数 $\Phi(D_i) = 2\,size_i - capacity_i$（$size \le capacity$，且当 $size = capacity$ 时 $\Phi = capacity$）。可验证 $\Phi \ge 0$（从空表起步），普通 append 实际代价 1、势变化 $\le 2$，摊还代价 $\le 3$；扩容 append 实际代价 $size_i + 1$、势从 $capacity_i$ 降到 $0$（新容量 $2 \cdot size_i$），摊还代价 $\le 3$。总摊还代价非负，故总实际代价 $O(n)$。

**反例警示：为什么增长因子不能太小。** 若扩容策略改为"每次容量 +10"（grow-by-constant），搬移总代价为 $\sum n/10 \cdot 1 \approx n^2/20$，摊还退化为 $\Theta(n)$。doubling 与 "+10" 的差距正是 $\Theta(1)$ 与 $\Theta(n)$ 的差距。Python `list` 用约 1.125 倍的超额分配（兼顾内存），C++ `vector` 与 Java `ArrayList` 用 2 倍或 1.5 倍，本质都是这个权衡：**扩容激进度 ↔ 内存浪费度**。

### 1.4.2 其他经典摊还结构（预告）

- 二叉计数器递增：单次最坏 $\Theta(\log n)$，摊还 $O(1)$（位翻转的均摊）。
- 两个栈模拟队列：单次最坏 $O(n)$，摊还 $O(1)$（第 2 章实现）。
- 均摊入账在《机器学习》的 SGD 分析中也有思想上的对应：单步 loss 抖动大，但整段训练的平均行为才是我们关心的。

## 1.5 递归的复杂度与主定理

递归算法的代价写成递推式（recurrence）。例如归并排序把 $n$ 个元素分成两半各自排序再 $O(n)$ 合并：

$$T(n) = 2\,T(n/2) + \Theta(n), \qquad T(1) = \Theta(1).$$

**递归树直觉**：第 0 层代价 $n$，第 1 层两个子问题共 $n$，第 $2$ 层共 $n$……共 $\log_2 n$ 层，每层 $n$，总计 $n \log n$。

**主定理（Master Theorem）**：设 $T(n) = a\,T(n/b) + f(n)$（$a \ge 1,\ b > 1$），$f$ 为多项式有界的非负函数。比较 $f(n)$ 与"叶子总代价"$n^{\log_b a}$：

1. 若 $f(n) = O(n^{\log_b a - \epsilon})$（$f$ 更小，叶子主导），则 $T(n) = \Theta(n^{\log_b a})$；
2. 若 $f(n) = \Theta(n^{\log_b a} \log^k n)$（$k \ge 0$，两者同阶），则 $T(n) = \Theta(n^{\log_b a} \log^{k+1} n)$；
3. 若 $f(n) = \Omega(n^{\log_b a + \epsilon})$ 且满足正则条件 $a f(n/b) \le c f(n)$（$c<1$，$f$ 主导），则 $T(n) = \Theta(f(n))$。

验证归并排序：$n^{\log_2 2} = n$，$f(n)=\Theta(n)$，命中情形 2（$k=0$），得 $T(n)=\Theta(n\log n)$。$\blacksquare$

再验两个：$T(n)=2T(n/2)+\Theta(n^2)$，$f$ 主导（情形 3），$T=\Theta(n^2)$——**分治并不总是省时间，合并代价占主导时优化分治无意义**；$T(n)=3T(n/2)+\Theta(n)$（Karatsuba 大整数乘法），$n^{\log_2 3}\approx n^{1.585}$ 主导（情形 1），$T=\Theta(n^{1.585})$——**降低子问题数量 $a$ 可以改变指数本身**，这正是 Strassen 矩阵乘等"更快分治"的设计哲学（详见《线性代数》对矩阵乘复杂度的讨论）。

主定理之外，**代入法（先猜后证）** 与 **换元法** 是兜底工具；更复杂的递推（如 $T(n)=T(n/3)+T(2n/3)+n$）可用递归树直接求和，答案 $\Theta(n \log n)$。

## 1.6 算账能力：数据规模 × 复杂度 = 训练时间

这是本章最重要的工程技能。给一个 AI 场景做可行性估算的标准流程：

1. 列出每一步的计算量（浮点运算数 FLOPs 或基本操作数）与复杂度阶；
2. 乘以数据规模，得到总量级；
3. 对照硬件吞吐（GPU 约每秒 $10^{13}$–$10^{15}$ FLOPs，Python 解释器约每秒 $10^7$ 基本操作）判断可行性；
4. 若不可行，指出是哪一步的复杂度阶需要降，去哪一章找降阶工具。

**例 1.2（attention 的 $O(n^2)$）**：自注意力的相似度矩阵大小为 $n \times n$（$n$ 为序列长度），计算与存储均为 $\Theta(n^2 d)$（$d$ 为维度）。取 $n = 10^5$（约 10 万 token 的长文档），$n^2 = 10^{10}$——单层的注意力矩阵就占 $4 \times 10^{10}$ 字节 = 40 GB（FP32），这正是《深度学习》中稀疏注意力、线性注意力、FlashAttention 等技术的直接动机。**看到一篇论文声称"把 $\Theta(n^2)$ 降为 $\Theta(n \log n)$"，你现在应该立刻明白它在赚什么、赚多少。**

**例 1.3（全量两两比对）**：为 1000 万张图片去重，两两余弦相似度需 $\binom{10^7}{2} \approx 5\times 10^{13}$ 次运算，即便 GPU 每秒 $10^{13}$ 次也要 5 秒以上且内存放不下相似度矩阵——但这还算"接近可行"；若数据到 1 亿，则完全不可行。出路在第 7 章：局部敏感哈希（LSH）把"两两比对"降为"只比哈希桶内的对"。

**例 1.4（一次典型的预算表）**：训练一个小模型：1 000 万样本 × 每 epoch 一次前向 $O(\text{参数量})$。若参数量 $10^7$、每个样本约 $6\times$ 参数量 FLOPs（前向 2 倍 + 反向 4 倍），单 epoch 约 $6\times10^{14}$ FLOPs；用 $10^{14}$ FLOPs/s 的 GPU 约需 1.7 小时（理想值，实际受数据供给与利用率影响打 2–4 折）。**这张表的每一行，都由本章的记号支撑。**

## 1.7 关键公式速查

| 公式/结论 | 适用条件 |
|---|---|
| $f \in O(g) \iff \exists c>0, n_0:\ f(n) \le c\,g(n)\ \forall n \ge n_0$ | 上界定义；Ω/Θ 对偶同理 |
| 求和取大：$\Theta(f) + \Theta(g) = \Theta(\max(f,g))$ | 顺序复合 |
| 嵌套循环：$\sum$ 内层次数（等比收敛时算和） | 内层次数依赖外层变量 |
| 动态数组 doubling：$n$ 次 append 总搬移 $\sum_{k} 2^k = \Theta(n)$，摊还 $O(1)$ | 增长因子为常数 $>1$ |
| grow-by-constant：摊还 $\Theta(n)$ | 增长量为常数 |
| 主定理：$T(n)=aT(n/b)+f(n)$，比较 $f$ 与 $n^{\log_b a}$ | $a\ge1, b>1$，$f$ 多项式有界 |
| 归并型递推 $T=2T(n/2)+n \Rightarrow \Theta(n\log n)$ | 平衡二分 + 线性合并 |
| 对数直觉：$2^{30}\approx10^9$，二分查找约 30 步 | 减半类策略 |
| 算账式：总时间 $\approx$ 规模 × 复杂度 ÷ 硬件吞吐 | 估算可行性 |

## 1.8 示例与案例

### 案例 1（手算）：三段代码的复杂度判定

对 1.3 节段 C（外层折半 + 内层等比递减）做手算求和：外层第 $i$ 轮内层执行 $n/2^i$ 次，总次数

$$\sum_{i=1}^{\log_2 n} \frac{n}{2^i} = n\left(1 - \frac{1}{2^{\log_2 n}}\right) = n - 1,$$

故为 $\Theta(n)$。注意：虽然形式上是"两层循环"，但**循环层次数不等于复杂度阶数**，必须对内层求和。

### 案例 2（代码）：用计时实验验证增长阶

```python
"""用实验拟合增长阶：对同一算法在倍增的 n 上计时，
   看 T(2n)/T(n) 是否接近理论倍率。"""
import time
import numpy as np

def two_sum_naive(nums, target):
    """两数之和的暴力解：理论上 Θ(n^2)。"""
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return (i, j)
    return None

def two_sum_hash(nums, target):
    """哈希表解：理论上平均 Θ(n)。（哈希表在第 2 章严格分析）"""
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return (seen[target - x], i)
        seen[x] = i
    return None

rng = np.random.default_rng(0)
print(f"{'n':>8} {'ratio(n^2,理论4)':>18} {'ratio(hash,理论2)':>18}")
prev_sq = prev_h = None
for n in [2000, 4000, 8000, 16000]:
    nums = rng.integers(0, n, size=n).tolist()
    target = -1  # 保证最坏：无解，走满全程

    t0 = time.perf_counter(); two_sum_naive(nums, target)
    sq = time.perf_counter() - t0

    t0 = time.perf_counter(); two_sum_hash(nums, target)
    h = time.perf_counter() - t0

    r_sq = sq / prev_sq if prev_sq else float("nan")
    r_h = h / prev_h if prev_h else float("nan")
    print(f"{n:>8} {r_sq:>18.2f} {r_h:>18.2f}")
    prev_sq, prev_h = sq, h
# 预期输出（本机示例，倍率应分别趋近 4 与 2，噪声在所难免）：
#        n  ratio(n^2,理论4) ratio(hash,理论2)
#    4000              3.85               1.95
#    8000              4.10               2.08
#   16000              4.02               2.03
```

**读结果的方法**：输入规模翻倍时，$\Theta(n^2)$ 算法耗时约 ×4，$\Theta(n)$ 约 ×2，$\Theta(n\log n)$ 约 ×2 多一点。这就是"实验测阶"（empirical order of growth），也是《实验设计与评估》中性能实验的雏形。

### 案例 3（代码）：动态数组扩容的计数实验

```python
"""统计 Python list append 的实际搬移：观察容量的倍增跳变。"""
import sys

xs = []
prev_cap = sys.getsizeof(xs)  # 空列表的底层占用（字节，含对象头）
hops = []
for i in range(1, 100_001):
    xs.append(i)
    cap = sys.getsizeof(xs)
    if cap != prev_cap:          # 容量发生变化 = 发生了一次扩容搬移
        hops.append(i)
        prev_cap = cap
print("扩容发生的元素个数（前 12 次）:", hops[:12])
print("总扩容次数:", len(hops))
# 预期输出（CPython 3.11 示例，具体数值随版本略有差异）：
# 扩容发生的元素个数（前 12 次）: [1, 5, 9, 17, 26, 35, 53, 71, 89, 134, ...]
# 总扩容次数: 约 60 次
# 结论：100000 次 append 只触发 ~60 次搬移，且每次扩容量按约 1.125 倍增长，
#       总搬移量为 O(n)——摊还 O(1) 的实证。
```

## 1.9 常见误区与陷阱

1. **把 $O$ 当"准确等于"用**。说"快排是 $O(n^2)$"和"快排是 $O(n \log n)$"都对（一个是严格上界、一个是平均），交流时必须说清是"最坏"还是"平均/摊还"。
2. **忽略隐藏常数**。哈希查找平均 $O(1)$，但哈希一个长字符串本身是 $O(L)$；`dict` 的键若是长字符串，比较与哈希代价不可忽略。 NumPy 向量化快，除并行外也因为它把常数压到了机器级。
3. **对递归忘记算"合并/回溯代价"**。只数子问题调用次数、漏掉每次调用的合并开销，是归并型递推最常见的错误。
4. **以为双层循环一定是 $O(n^2)$**。内层次数可能是 $n/2^i$（等比）、$\log$ 等，必须求和而非相乘。
5. **摊还 ≠ 平均**。摊还分析是**最坏序列下的平均上界**，不含任何概率假设；平均情况分析（如快排的期望 $O(n\log n)$）才需要输入分布假设。两者经常被混为一谈。
6. **算账时用机器级吞吐却跑解释器代码**。Python 层面每秒 $10^7$–$10^8$ 次基本操作，比表中 GPU/机器级数字慢几个数量级；估算时必须用与实现匹配的吞吐口径。

## 1.12 进阶方向

- **平滑复杂度（smoothed analysis）**：解释单纯形法"最坏指数、实际飞快"的理论（Spielman & Teng, 2004），从本章的"最坏 vs 平均"分类出发即可入门。
- **位复杂度与外存模型（I/O model）**：当数据放不进内存时，$O(1)$ 内存访问的假设崩塌，需要以"读一块"为单位重新记账——外部排序与数据库索引的理论基础。
- **并行复杂度（work/span 模型）**：把 $T(n)$ 分为总工作量与关键路径长度，GPU 上的算法设计（如并行归并）用它分析。
- **参数化与精细复杂度**：$O(2^k \cdot n)$ 型算法（$k$ 为某结构参数），是当前理论计算机科学刻画"难"的主要语言。
