# 99 综合项目：端到端的数据工程实战

> **本章定位**：把第 1–5 章的技术串成完整可交付的工程作品。三个项目难度递进：项目一是主线（必做），项目二、三任选其一深入（或都做）。每个项目都要求可运行、可复现、有量化报告——这正是《实验设计与评估》与《模型部署与 MLOps》课程对你未来产出的最低标准。

## 99.0 项目总则

- **仓库规范**：每个项目一个 Git 仓库；代码放 `src/`，配置放 `params.yaml`，数据用 DVC 管理（`.dvc` 指针入库、本体推远程），报告放 `reports/`。回想《Python 程序设计》第 7 章：函数有类型注解、每个模块有 docstring、关键清洗规则有单元测试（pytest）。
- **可复现性铁律**：审阅者执行 `git clone` → `pip install -r requirements.txt` → `dvc pull` → `dvc repro` 后，必须得到与报告一致的数字。随机种子全部固定。
- **量化表达**：所有结论给数字不给形容词——"清洗后行数从 412,383 降到 401,207（-2.7%）"而不是"清洗掉了不少脏数据"。
- **建议投入**：项目一约 24–32 学时；项目二、三各约 16–24 学时。

## 99.1 项目一（必做）：端到端数据流水线——从原始网页数据到可训练数据集

### 99.1.1 项目目标

构建一条含 **采集 → 清洗 → 特征 → 划分 → 版本管理 → 质量报告** 的完整流水线，产出一份带 DVC 版本标签的可训练数据集与其质量报告。完成后你将亲手把本课程五章内容连成一条线。

### 99.1.2 数据选择（三选一）

1. **合规爬取**：任选一个 `robots.txt` 允许抓取的网站（如你所在学校官网的新闻列表、某公开数据目录站），爬取 5000–20000 个页面/条目，只取文本与结构化字段。
2. **开放 API**：如政府开放数据平台、GitHub API（注意限流配额）拉取仓库/议题数据。
3. **离线备选**：无网络环境可用 Kaggle 公开数据集的"原始版"（选择明显含缺失/重复/乱码的）。

### 99.1.3 功能规格（必须实现）

- [ ] 采集模块：礼貌爬虫（robots.txt 检查、限速 ≥ 2s、真实 UA）或带退避重试的 API 客户端（第 1 章）；采集进度与失败重试可断点续跑。
- [ ] 清洗模块：缺失/重复/异常处理各至少两种策略并说明选择依据；输出清洗前后对照的质量报告（第 1 章六维度逐项给数字）。
- [ ] 泄漏审计：`leakage_audit` 式检查 + "先切分后变换"的 Pipeline 化特征流程（第 1、2 章）。
- [ ] 特征模块：至少包含数值缩放、类别编码（含一种高基数处理）、周期时间特征，全部封装在 `sklearn.Pipeline` 中并可 pickle（第 2 章）。
- [ ] 划分模块：按数据性质选择随机/分层/时间/群体划分并书面论证（第 5 章）；测试集冻结并单独打 DVC 标签。
- [ ] 质量校验：≥ 10 条断言（硬/软分明），覆盖六维度 + 分布漂移（PSI < 0.25），生成 HTML 或 Markdown 校验报告（第 4 章）。
- [ ] 版本管理：三个阶段数据各有一次 `dvc add` + 提交；`dvc.yaml` 声明完整流水线，`dvc repro` 增量可跑（第 4 章）。
- [ ] 数据卡片：五部分俱全（第 4 章）。

### 99.1.4 任务分解（建议顺序）

1. 周 1：选定数据源，写采集模块并跑通小批量（100 条）验证。
2. 周 2：清洗模块 + 质量报告 v1；同时建立 Git/DVC 骨架。
3. 周 3：特征 Pipeline + 划分 + 泄漏审计；对同一模型（固定一个 GBDT）跑通基线训练。
4. 周 4：质量断言套件 + 数据卡片 + 报告撰写；`dvc repro` 全流程演练与答辩准备。

### 99.1.5 验收标准（可逐条勾选）

- [ ] 审阅者在新环境按 README 四条命令复现，指标偏差 < 0.5%。
- [ ] 质量报告含清洗前后六维度数字对照表。
- [ ] 故意把一处变换移出 Pipeline 后，审计脚本能发出泄漏警告（演示给审阅者）。
- [ ] `git log` 能看到数据三阶段的 DVC 指针演进，`dvc checkout` 可回到任一版。
- [ ] 断言套件在注入脏数据（人工加入 5% 缺失与一个越界值）时至少 3 条报警。

### 99.1.6 挑战扩展（选做）

- 采集端加入增量更新（只抓新条目），流水线自动只重算受影响阶段。
- 为文本数据加 MinHash-LSH 近似去重并报告删除量对下游 AUC 的影响（通向项目三）。

## 99.2 项目二：同一份数据在 CSV / Parquet / DuckDB 上的完整基准测试报告

### 99.2.1 项目目标

用严格的实验方法回答工程问题："我的数据该用什么格式与引擎？"产出一份含多指标、多规模、可复现实验的基准测试报告——它同时是《实验设计与评估》课程"基准测试方法论"的预习。

### 99.2.2 实验设计（必须覆盖）

- [ ] 数据：合成或真实数据，至少 3 个规模档（如 1 GB / 5 GB / 20 GB），记录各档的行数与列构成。
- [ ] 格式：CSV、JSONL、Parquet（含至少两档压缩设置，如 snappy vs zstd）。
- [ ] 引擎：pandas（全量与分块）、Polars（eager 与 lazy）、DuckDB（SQL 直查）。
- [ ] 工作负载：①全量扫描行数；②单列过滤聚合（含选择性 1% / 50% 两档）；③分组聚合（高基数与低基数各一）；④join（大表 × 小表广播、大表 × 大表）；⑤冷/热缓存各跑一遍（重启进程后首跑为冷）。
- [ ] 指标：墙钟时间（报告**中位数与 IQR**，每配置 ≥ 5 次重复）、峰值内存、磁盘占用、压缩比、解析错误数（CSV 的类型推断陷阱记录）。

### 99.2.3 任务分解

1. 生成/获取三档数据并统一 schema，写 `generate_data.py`（参数化）。
2. 实现基准运行器：计时、内存采样（`tracemalloc` 或 `resource`/psutil）、重复次数、结果落 JSON。
3. 按矩阵跑全量实验（建议夜间批跑），生成汇总 CSV。
4. 分析与写作：规模×格式×引擎的时间曲线、内存对比、结论与选型建议（分"分析型查询/管道中间存储/人类交换"三个场景给建议）。

### 99.2.4 验收标准

- [ ] 每个数字都能由 `dvc repro` 复现（报告中的表格由脚本自动生成，非手抄）。
- [ ] 至少验证两个已知结论：Parquet 相对 CSV 的体积优势；DuckDB/Polars-lazy 在过滤聚合上相对 pandas 全量的优势——若某个结论在你的负载上**不成立**，分析原因（这比复现结论更有价值）。
- [ ] 报告明确写出实验边界（硬件、OS、库版本、页缓存状态），并声明哪些对比在本机之外不可外推。

### 99.2.5 挑战扩展（选做）

- 加入 Parquet 行组大小与分区键的调参实验，验证谓词下推裁剪效果。
- 用 multiprocessing/线程池对比 pandas 分块与 DuckDB 多核执行的扩展曲线。

## 99.3 项目三：构建一个经过去重与质量过滤的小型文本语料库，并量化每一步对下游模型的影响

### 99.3.1 项目目标

按第 5 章 5.5 节的流水线，构建一个 5 万–20 万篇文档的小型语料库，并用**受控对照实验**量化"精确去重、近似去重、质量过滤"各自对下游文本分类器的影响——一次迷你版 DataComp。

### 99.3.2 功能规格（必须实现）

- [ ] 数据获取：合规渠道（维基百科 dump、Common Crawl 子集、开放新闻数据集均可），记录原始规模。
- [ ] 提取与精确去重：正文提取 + 文档哈希去重 + 行级重复删除，报告各步删除量。
- [ ] 近似去重：MinHash（n_perm ≥ 128）+ LSH 分桶，阈值 0.8；报告候选对数、最终合并簇数、被删文档比例。
- [ ] 质量过滤：≥ 5 条启发式规则（语言检测、长度、符号占比等）+ 一个轻量分类器过滤器（如"高质量/随机"二分类），报告每条规则的通过率。
- [ ] 下游实验：固定模型（如 TF-IDF + 逻辑回归，种子固定）与算力，在"无处理 / 仅精确去重 / 精确+近似去重 / 全流水线"四种配方上训练，测试集**冻结且来自统一的干净评测划分**。
- [ ] 报告：数据统计表（条数、平均长度、重复率）× 配方 × 下游指标的完整矩阵，并讨论哪一步边际贡献最大。

### 99.3.3 任务分解

1. 周 1：获取数据、提取正文、建立评测集（分层抽样并冻结 DVC 标签）。
2. 周 2：精确去重 + 质量规则（实现 + 单元测试）。
3. 周 3：MinHash-LSH（先在小样本上标定阈值与召回，再跑全量）。
4. 周 4：四种配方 × 3 个随机种子训练与统计检验（5×2 配对 t 检验，衔接《机器学习》第 7 章）、报告。

### 99.3.4 验收标准

- [ ] 全流水线在 20 万文档规模上单机可在 2 小时内跑完（验证第 3 章技术的组合使用是否得当）。
- [ ] 近似去重的精度抽查：人工核对 20 对"被判重复"文档，≥ 16 对确属实质重复。
- [ ] 报告含每个处理步骤的"删除瀑布图"（原始 N → 各步后剩余数）与四种配方的下游指标对比表（均值 ± 标准差）。
- [ ] 数据卡片完整，含去重阈值与过滤规则的可复现参数。

### 99.3.5 挑战扩展（选做）

- 把 MinHash-LSH 换成 SimHash 或精确后缀数组去重，比较召回/精度/耗时三角。
- 引入数据配比维度：两种来源按 3:1 与 1:1 混合，观察下游指标对配比的敏感性。

## 99.4 提交与评审

- **提交物**：Git 仓库（含 `README.md`、`dvc.yaml`、`reports/`）、15 分钟答辩（10 分钟讲设计决策与数字，5 分钟回答"如果数据大 100 倍你的方案哪里先崩"——这道必答题检验你是否真正消化了第 3 章）。
- **评分建议**：可复现性 30%、设计决策的论证质量 25%、量化报告的严谨性 25%、工程质量（测试/结构/文档）20%。
- **自检清单**：随机种子全固定了吗？测试集冻结并打标签了吗？每个结论有数字支撑吗？泄漏审计跑过了吗？数据卡片写了吗？

## 99.5 与前后章节的联系

- **依赖**：项目一调用第 1 章（采集/清洗/泄漏）、第 2 章（Pipeline 特征）、第 4 章（DVC/断言/卡片）与第 5 章（划分决策）；项目二调用第 3 章（格式、单机引擎、IO 分析）与《数据结构与算法》第 1 章复杂度分析；项目三调用第 3 章（规模化处理）与第 5 章（去重/过滤/配比）与《数据结构与算法》第 7 章（MinHash/LSH/蓄水池）；《Python 程序设计》第 7 章的工程规范贯穿三个项目。
- **被使用**：项目一的流水线与版本管理形态将被《实验设计与评估》课程直接扩展为"实验即流水线"的方法论；三个项目产出的冻结测试集、DVC 版本与质量监控体系，是《模型部署与 MLOps》课程中持续训练与线上数据监控的现成演练场。
