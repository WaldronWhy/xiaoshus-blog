# 第 4 章 可复现性与科研诚信

> **本章定位**：本课程（也是整部教材）的收束章——前三章生产的每一份"可信证据"，只有当别人能重新获得它时，才真正进入人类知识。前置：第 1–3 章全部、《数据工程》第 4 章（DVC 数据版本控制）、《Python 程序设计》第 7 章（软件工程实践）。后续：第 99 章所有项目把本章工程逐条落地；《模型部署与 MLOps》的实验追踪与模型注册直接复用本章工具链。

## 4.0 本章学习目标

- 能够区分可复现性的三个层次（可重复/可复现/可推广），并判断一篇论文、一个实验各自的层次。
- 能够实现"随机种子全局控制"：列出深度学习栈中至少 5 个非确定性来源，并写出覆盖 Python/NumPy/深度学习框架的种子控制函数。
- 能够用配置管理（hydra）、实验追踪（MLflow/W&B）、数据版本（DVC）、代码版本（git）搭建一条"一条命令复现"的实验流水线。
- 能够按"读论文 → 复现"的方法论完整复现一个实验，并对其中的每处偏差做出归因分析。
- 能够识别并防范 cherry-picking、p-hacking、HARKing、报告偏倚四类科研不端/失信行为。
- 能够设计主结果表与消融表，并按可复现性清单自查一篇实验报告。

## 4.1 可复现性的三个层次

"可复现性（reproducibility）"在 ML 里被用来指涉至少三件不同的事。ACM 的工件评审政策（2020 年起生效的 artifact badging）给出了精确区分，本课程沿用：

| 层次 | 英文 | 含义 | ML 场景示例 |
|---|---|---|---|
| 可重复 | repeatability | 同一团队、同一环境、重跑同一套流程得到一致结果 | 你自己下周重跑自己的脚本，数字一致 |
| 可复现 | replicability | 不同团队、**相同实验配置**、独立实现，结果一致 | 他人按你论文的超参/划分重新实现，结果在你的误差带内 |
| 可推广 | reproducibility / generalizability | 换到不同配置、不同数据、不同任务，结论依然成立 | 方法从 CIFAR-10 换到 ImageNet、从分类换到检测仍有效 |

三个层次递进：第一层是**工程问题**（本章 4.2–4.3 节），第二层是**实验报告完备性 + 归因问题**（4.4 节，需要第 3 章的消融思想），第三层是**科学问题**（需要第 2 章的评测效度观——换基准仍有效，才是真的有效）。论文引用时最常见的混乱是把第二层的失败归咎于"不可复现"，实际可能是原报告方差的缺失（第 3 章 3.3 节）——复现者拿 3 个种子对原论文 1 个种子的数字，落进噪声带完全正常。

**数量级意识**：Bouthillier et al. (2021) 的实验里，同一配置不同噪声源的单次运行波动可达 ±0.5 个百分点——任何声称复现精度的验收标准（如"偏差 < 0.5%"）都必须在这个背景下解读（第 99 章项目一将要求你显式论证自己的容差）。

## 4.2 工程实现：可复现性四件套

### 4.2.1 随机种子全局控制

深度学习栈的非确定性来源至少包括：Python 内建随机（`random`）、NumPy（全局与 `Generator` 两条线）、框架层（PyTorch 的 CPU/CUDA 生成器）、数据加载器（`shuffle` 与 worker 进程种子）、cuDNN 的非确定性算法（benchmark 模式、原子加法）、以及多线程浮点归约顺序。全局控制函数是每个实验代码库的第一段代码：

```python
"""全局种子控制 + 非确定性来源审计。依赖: numpy (torch 部分为可选)。"""
import os, random
import numpy as np

def set_seed(seed: int, deterministic: bool = True):
    # 1. Python 内建随机
    random.seed(seed)
    os.environ["PYTHONHASHSEED"] = str(seed)     # 影响 dict 迭代/哈希相关随机性
    # 2. NumPy (全局旧接口)
    np.random.seed(seed)
    # 3. NumPy 新接口: 由调用方从主种子派生子种子
    child_rng = np.random.default_rng(seed + 1)
    # 4. 深度学习框架 (安装了才执行)
    try:
        import torch
        torch.manual_seed(seed)
        torch.cuda.manual_seed_all(seed)
        if deterministic:
            torch.backends.cudnn.deterministic = True   # 关闭 cudnn 自选算法
            torch.backends.cudnn.benchmark = False       # 关闭按输入形状自动调优
    except ImportError:
        pass
    return child_rng   # 数据加载等模块用派生子种子, 不共用主种子

if __name__ == "__main__":
    rng1 = set_seed(42); a = rng1.normal(size=3)
    rng2 = set_seed(42); b = rng2.normal(size=3)
    print(a); print(b); print("一致:", bool(np.allclose(a, b)))
    # 预期输出:
    # [-0.61071948  0.41809976 -0.55857746]
    # [-0.61071948  0.41809976 -0.55857746]
    # 一致: True
```

三个工程要点：**(a) 主种子写进配置文件而非硬编码**（4.3 节）；**(b) 各模块用派生子种子**（`np.random.default_rng(seed).spawn` 思想），避免"固定了训练种子却动一下数据加载就把训练顺序也改了"；**(c) 诚实声明确定性边界**——即使全部打开，GPU 原子操作仍可能带来微小非确定性，报告时应注明"deterministic 模式"与否（第 3 章 $\sigma^2_{\text{数值}}$ 的来源）。

### 4.2.2 环境锁定

三个月后的你、审稿人、或同事的机器，必须能重建出**同一软件环境**：

- **依赖锁定**：`pip freeze > requirements.txt` 是底线；更严格用 `pip-tools`/`uv` 生成带传递依赖哈希的锁文件，或 `conda env export`；
- **系统层记录**：CUDA/cuDNN 版本、GPU 型号与驱动、操作系统——这些不被 pip 管理，却是常见差异来源，写进环境报告（`nvidia-smi` 输出存档）；
- **分层记录**：代码库版本（git commit hash）、数据版本（DVC hash，见下）、配置版本（配置文件本身的 hash），三者一起构成实验的"身份证"（4.3.3 落实）。

### 4.2.3 数据版本与代码版本

《数据工程》第 4 章已经建立了 DVC 的完整工作流（数据指针入库、本体推远程、`dvc.yaml` 声明流水线）。在实验语境下补充两条纪律：

1. **每次实验运行记录其数据指纹**：DVC 的 md5 或数据集 hash 应作为参数写进实验追踪记录，"我在哪个数据上训练的"从此可查；
2. **冻结测试集单独打标签**：测试数据一旦冻结（打了 DVC tag），任何训练代码都无法"不小心"重切它——这是第 2 章"测试集只碰一次"的工程保障。

代码版本同理：实验记录必须包含 git commit hash；未提交的修改不允许出现在正式实验里（`git describe --always --dirty` 可以自动拒绝 dirty 状态起跑）。

### 4.2.4 "实验即函数"

把一次实验压缩成"配置 → 确定性流程 → 产物（指标/日志/模型）"的纯函数视图，是所有工具的哲学基础。反模式自查：notebook 单元格乱序执行、手工改了配置忘了记录、"临时"跑了个变体没进版本库。若发现自己依赖"记忆"而非"记录"来还原一次实验，立刻停止实验，先补工程。

## 4.3 可复现性工具链

### 4.3.1 hydra：配置管理

hydra（Meta 开源）解决"配置散落在 argparse 与代码深处"的问题：层级 YAML、配置组合、命令行覆盖、多运行（multirun）扫描。

```yaml
# conf/config.yaml
defaults:
  - _self_
seed: 42
data: {dataset: cifar10, batch_size: 128}
train: {lr: 0.001, epochs: 10}
```

```python
# train.py: python train.py seed=7 train.lr=0.01 即可覆盖
import hydra, random, numpy as np
from omegaconf import OmegaConf

@hydra.main(config_path="conf", config_name="config", version_base=None)
def main(cfg):
    print(OmegaConf.to_yaml(cfg))       # 完整生效配置自动打印并存档
    random.seed(cfg.seed); np.random.seed(cfg.seed)
    # ... 训练 ...
if __name__ == "__main__":
    main()
# 预期输出(节选):
# seed: 7            <- 命令行覆盖生效
# train: {lr: 0.01, epochs: 10}
# hydra 的多运行: python train.py --multirun train.lr=0.001,0.01,0.1
# 自动生成 outputs/<日期>/<时间>/ 下的独立配置+日志目录 (第 3 章 OFAT 扫描的工程实现)
```

hydra 的关键贡献是**把"配置"提升为一等公民**：每次运行落盘一份完整生效配置（含覆盖），与第 3 章 3.2.4"因子是单一开关"的要求天然契合。

### 4.3.2 MLflow / W&B：实验追踪

从零实现一个最小追踪器，理解追踪的本质（几次运行 → JSONL → 聚合），再上成熟工具。

```python
"""从零实现最小实验追踪器 (仅依赖标准库 + numpy)。可直接运行。"""
import hashlib, json, subprocess, time
from pathlib import Path
import numpy as np

class Tracker:
    def __init__(self, root="runs"):
        self.root = Path(root); self.root.mkdir(exist_ok=True)
    def log_run(self, cfg: dict, metrics: dict):
        cfg_json = json.dumps(cfg, sort_keys=True)                # 规范化
        cfg_hash = hashlib.sha256(cfg_json.encode()).hexdigest()[:8]  # 配置指纹
        commit = subprocess.run(["git", "describe", "--always", "--dirty"],
                                capture_output=True, text=True).stdout.strip()
        rec = {"time": time.strftime("%Y-%m-%d %H:%M:%S"), "cfg": cfg,
               "cfg_hash": cfg_hash, "git": commit or "no-git", "metrics": metrics}
        with open(self.root / "runs.jsonl", "a", encoding="utf-8") as f:
            f.write(json.dumps(rec, ensure_ascii=False) + "\n")
        return cfg_hash
    def summary(self, group_key="seed"):
        """按实验条件分组聚合 (默认把 seed 当作重复因子排除在分组键外)。"""
        by_cfg = {}
        for line in open(self.root / "runs.jsonl", encoding="utf-8"):
            r = json.loads(line)
            key = json.dumps({k: v for k, v in r["cfg"].items() if k != group_key},
                             sort_keys=True)
            by_cfg.setdefault(key, []).append(r["metrics"]["acc"])
        for key, accs in sorted(by_cfg.items()):
            a = np.array(accs)
            std = a.std(ddof=1) if len(a) > 1 else float("nan")
            print(f"cfg {key}: n={len(a)}  acc = {a.mean():.4f} ± {std:.4f}")

if __name__ == "__main__":
    tr = Tracker()
    for seed in (0, 1, 2):        # 同一实验条件 (lr=1e-3), 3 个种子 (第 3 章规范)
        np.random.seed(seed)
        acc = 0.87 + np.random.normal(0, 0.01)      # 模拟训练结果
        tr.log_run({"seed": seed, "lr": 0.001}, {"acc": float(acc)})
    tr.summary()
    # 预期输出 (种子固定, 应逐字复现):
    # cfg {"lr": 0.001}: n=3  acc = 0.8799 ± 0.0122
```

**迁移到成熟工具**：MLflow（开源，Databricks 出品）把上述结构升级为服务：`mlflow.start_run()` → `mlflow.log_params(cfg)` / `mlflow.log_metrics(m)` / `mlflow.log_artifact(config_dump.yaml)`；其 `mlflow.models` 还承接训练后登记与部署（《模型部署与MLOps》的模型注册中心即此组件）。W&B（Weights & Biases，商业产品）以实时可视化曲线、团队协作与 sweep（自动超参扫描）见长。选型建议：教学与离线环境用 MLflow；需要团队看板与强可视化时用 W&B。无论哪个，**记录的字段清单**是本质：完整配置、git hash、数据版本、每次指标、产物路径。

### 4.3.3 Docker：环境即代码

环境锁定的终极形态是把整个软件栈（含 CUDA）打包为镜像：

```dockerfile
# Dockerfile: 训练环境的完整声明
FROM pytorch/pytorch:2.3.0-cuda12.1-cudnn8-runtime
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "train.py", "seed=42"]
```

构建一次（`docker build -t exp-v3 .`），镜像 digest 唯一确定软件栈；`docker run` 保证任何人得到相同的 Python/CUDA/依赖组合。注意 Docker 锁定的是"软件环境"，不锁定 GPU 硬件差异——跨硬件的波动仍按第 3 章方差框架对待。无 Docker 条件下（如共享集群），退而求其次：Conda 锁文件 + 环境报告存档。

## 4.4 论文复现的方法论

复现他人论文是研究生的核心训练，也是本课程 99 章项目一。完整流程五步：

1. **精读与"未言明清单"**：按"摘要 → 图表 → 方法 → 实验"的顺序读（图表先行的理由：主结果表决定了你复现的目标量）。读的过程中记录**论文没说但必须决定的每一件事**：划分方式与种子？预处理参数？类别平衡策略？早停标准？——这份"未言明清单"的长度与论文可复现性成反比；
2. **资源盘点**：官方代码？第三方实现？数据集当前版本是否与论文时代一致（第 2 章：数据是活的）？硬件差距（GPU 型号、精度模式）？
3. **冒烟复现（smoke run）**：先小规模（子集数据、1–2 epoch）打通全链路，确认指标"方向正确"；不要第一天就上全量训练；
4. **正式复现与偏差归因**：对不上时，按**方差来源清单**逐项排查（第 3 章 3.3.2 的分解是排查地图）：数据版本/划分 → 预处理 → 超参 → 训练预算 → 硬件/精度。每项做一次受控消融（换掉你的实现、用回论文声明的），把差距逐项归因——这就是一次消融实验；
5. **复现报告**：按 3.8 节模板 + 本章 4.6 节清单撰写，明确写出"复现精度"（自己的误差带）与每处偏差的证据。

配套生态：ML Reproducibility Challenge（社区组织的批量复现活动，报告发表于 ReScience 系列期刊）与 Papers with Code（结果-代码索引）是找"别人怎么实现的"的第一站；Pineau 领导的 NeurIPS 可复现性计划（JMLR 2021 总结论文）定义了"复现承诺"的社区标准——复现结果落在原作者声明的误差带内即算成功，这一标准应内化为你对"复现成功"的定义。

## 4.5 科研诚信：四类失信行为与防范

实验设计的统计素养（第 1–3 章）与诚信是同一枚硬币的两面——多数失信行为并非蓄意造假，而是**研究自由度（researcher degrees of freedom）的滥用**。Gelman & Loken（2013）的"分叉小径的花园（garden of forking paths）"刻画得最准：即便你只报告了一次"诚实"的分析，如果你**本来可以**做出无数种分析选择（换划分、换指标、加/去掉一个数据集、提前停止），而最终报告的是其中最好的一次，结论就被污染了。

- **cherry-picking（摘樱桃）**：只报告最好的种子/划分/数据集。防范：预注册种子集合与划分集合，全部报告（第 3 章模板的附表）；
- **p-hacking**：通过反复检验、切换检验方法、optional stopping（看到显著就停止加数据）把 $p$ 压到 0.05 以下。防范：第 1 章的多重比较校正 + 固定分析计划；迭代探索与确证分离——探索集上发现、冻结集上确证（《数据工程》的冻结测试集在此第二次登场）；
- **HARKing**（Hypothesizing After Results are Known）：把事后发现的模式包装成事前假设。防范：区分探索性/确证性结论并在文中显式标注；
- **报告偏倚（reporting bias）**：负结果与"未决"结果不发表，导致领域只看到幸运的 5%。防范：本课程的标准里，第 3 章判定流程的四个档位**全部**写进报告；社区层面，NeurIPS 等会议的可复现性清单（reproducibility checklist）与 TMLR 的"claims-evidence"评审模式是制度化的应对。

一个实用的心法：**每个自由度都要么被预注册锁死，要么被校正/披露定价**。做到这一点，"分叉的花园"就变成了设计好的正交实验。

## 4.6 实验报告与论文写作要点

**主结果表**（论文 Table 1 的设计规范）：

```markdown
| 方法 | CIFAR-10 | CIFAR-100 | ImageNet-100 | 平均 |
|---|---|---|---|---|
| 基线 (ResNet-18) | 93.6 ± 0.2 | 74.1 ± 0.3 | 81.5 ± 0.2 | 83.1 |
| + 本文方法 (ours) | **94.3 ± 0.2** | **75.0 ± 0.3** | **82.2 ± 0.3** | **83.8** |
| Δ (95% CI, 配对) | +0.7 [0.4, 1.0] | +0.9 [0.5, 1.3] | +0.7 [0.3, 1.1] | +0.8 [0.5, 1.1] |

表注: 5 个划分种子配对运行; ± 为跨种子标准差; bold 表示配对 Holm 校正后显著 (p<0.05);
指标为 top-1 准确率(%); 训练预算统一 200 epoch (附学习曲线)。
```

要点：数字带 ±（标准差）与 CI；Δ 行用**配对**统计（同划分），标注检验与校正方式；表注交代重复数、预算、指标定义——审稿人不用翻正文就能核对。

**消融表**：从完整模型出发逐行移除（或逐行加入），每行是"与主表同协议的一次完整实验"；移除型消融的 Δ 负值表示该组件贡献；交互效应存疑时引用 3.2.2 的因子分析而非逐行相加。**图**：少而精——主学习曲线（均值 ± 带状区间）、多种子抖动图（第 3 章）、超参敏感性曲线。**可复现性声明**：代码仓库、数据版本、环境、种子与运行时长，四件套各一句话。

## 4.7 关键公式速查

| 公式/规则 | 名称 | 适用条件 |
|---|---|---|
| $\text{hash}(\text{cfg})$ + git hash + 数据 md5 | 实验"身份证"三元组 | 每次正式运行必须记录；配置需规范化（键排序）后哈希 |
| $\text{child\_seed} = f(\text{master\_seed}, \text{module\_id})$ | 种子派生 | 各模块独立流；避免共用主种子互相扰动 |
| 复现验收：$\lvert \hat\theta_{\text{rep}} - \hat\theta_{\text{orig}} \rvert \le k \cdot \sigma_{\text{total}}$（$k \approx 2$） | 复现成功的统计判据 | 原报告给出方差信息；$k$ 值需预注册 |
| $P(\text{至少一次误报}) \approx 1-(1-\alpha)^m$ | 自由度定价（第 1 章） | 未预注册的比较次数 $m$ 即隐性自由度 |
| 主表 Δ 用配对差 $\bar d \pm t_{1-\alpha/2}(n-1)s_d/\sqrt n$ | 表格内的推断 | 同划分集合配对；第 1 章 1.4 节公式表 |

## 4.8 示例与案例

### 示例 1（手算）：一次复现偏差的归因

你复现论文 X 的 ResNet-18 on CIFAR-10：论文报告 94.8%，你得到 94.1%。已知：论文未报方差；你的 3 个种子结果为 94.1, 94.3, 93.9（$\bar x = 94.1$，$s = 0.2$）；你发现论文用了 200 epoch 而你按常见默认跑了 100 epoch。归因分析：

1. 你的运行噪声 $\sigma \approx 0.2$，复现差距 0.7 ≈ 3.5σ，**超出纯运行噪声**（按 4.7 表判据 $k=2$），不能简单说"在噪声内"；
2. 可检验嫌疑：训练预算。补跑 200 epoch 的 3 个种子：94.7, 94.9, 94.6（$\bar x = 94.7$）。差距降为 0.1 ≈ 0.5σ，进入噪声带；
3. 结论写法："复现差距主要由训练预算差异解释（100→200 epoch 消融：+0.6 个百分点，95% CI [+0.2, +1.0]，配对 $t(2)=4.9$，$p \approx 0.04$——小样本下功效有限，标注为未决但方向与预算机制一致）；预算对齐后与原文差距 0.1，处于 2σ 复现判据内。"
（校验值：预算消融的 $d_z = 0.6/0.1 \approx 6$?——注意此处 $s_d = 0.1$ 时 $d_z$ 极大但 $n=3$ 自由度仅 2，请同时报告 $n$。）

### 示例 2（代码）：一条命令复现的流水线骨架

```python
"""可复现性四件套的最小集成: 配置 → 种子 → 运行 → 记录(含数据指纹)。
依赖: 标准库, numpy, dvc(可选)。可直接运行。"""
import hashlib, json, subprocess, sys
from pathlib import Path
import numpy as np

def data_fingerprint(path="data/train.csv", chunk=1 << 20):
    """数据文件的 sha256 (流式, 大文件友好)。若用 DVC, 等价于 .dvc 指针的 md5。"""
    h = hashlib.sha256()
    p = Path(path)
    if not p.exists():
        return "missing"
    with open(p, "rb") as f:
        while blk := f.read(chunk):
            h.update(blk)
    return h.hexdigest()[:12]

def run(cfg: dict):
    # 四件套: 代码版本
    git = subprocess.run(["git", "describe", "--always", "--dirty"],
                         capture_output=True, text=True).stdout.strip() or "no-git"
    if git.endswith("dirty"):
        sys.exit("存在未提交修改, 拒绝起跑 (4.2.3 纪律)")
    # 环境记录
    env = {"python": sys.version.split()[0], "numpy": np.__version__}
    # 数据版本
    dhash = data_fingerprint(cfg["data"])
    # 种子控制 (4.2.1 的 set_seed, 此处示意)
    rng = np.random.default_rng(cfg["seed"])
    # ... 真实训练 ...
    acc = cfg["base"] + rng.normal(0, cfg["noise"])
    rec = {"git": git, "env": env, "data": dhash, "cfg": cfg, "acc": round(float(acc), 4)}
    print(json.dumps(rec, ensure_ascii=False, indent=2))
    Path("runs.jsonl").open("a", encoding="utf-8").write(json.dumps(rec) + "\n")

if __name__ == "__main__":
    run({"seed": 42, "data": "data/train.csv", "base": 87.0, "noise": 0.3})
    # 预期输出 (结构固定, 数值/哈希因环境而异):
    # {
    #   "git": "a1b2c3d",
    #   "env": {"python": "3.11.9", "numpy": "1.26.4"},
    #   "data": "e3f1c90aa2b7",
    #   "cfg": {"seed": 42, "data": "data/train.csv", "base": 87.0, "noise": 0.3},
    #   "acc": 87.1287
    # }
```

这条 20 行的骨架把 4.2 节四件套串成了一次运行的完整"身份证"；第 99 章项目三要求你把它扩展为支持多实验、对比与绘图的系统。

## 4.9 常见误区与陷阱

1. **"我固定了种子，所以可复现"**：种子只覆盖随机性的一小部分。数据版本、库版本、硬件、预处理代码任何一项漂移都会改变结果——四件套缺一不可。
2. **实验记录依赖"事后回忆"**：跑了几十个实验后靠记忆和聊天记录还原哪个数字对应哪个配置。追踪器从第一天就要接入（4.3.2 的最小 Tracker 十分钟就能写完）。
3. **复现失败即归咎"原论文造假"**：差距应先按 4.4 步骤 4 的清单归因；多数差距来自数据/预处理/预算等未言明细节。归因完成前下判断是复现者的不专业。
4. **把探索当确证**：在同一份数据上反复尝试不同划分/指标直到显著（p-hacking 的温和形态）。冻结的确证集必须只碰一次。
5. **表格只报最好数字**：主表每个数字都应有 ±、$n$ 与检验标注；"best-of-n"必须显式声明且说明其偏倚。
