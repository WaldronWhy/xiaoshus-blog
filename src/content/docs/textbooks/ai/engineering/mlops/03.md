# 第 3 章 监控、漂移与持续训练

> **本章定位**：模型上线（第 2 章）只是服役的开始。本章处理生产 ML 最独特的难题：**模型会静默退化**——不抛异常、不打错误日志，只是慢慢地变得不准。前置要求：第 2 章（被监控的服务与预测日志）、[概率统计·第 5 章](/xiaoshus-blog/textbooks/ai/math-foundations/probability-statistics/05/)（假设检验与 p 值）、[数据工程·第 4 章](/xiaoshus-blog/textbooks/ai/engineering/data-engineering/04/)（数据质量体系）。本章的监控指标与重训流水线是第 4 章 CI/CD 体系的核心工件。

## 3.0 本章学习目标

学完本章，你能够：

1. 列举至少四种传统软件监控发现不了的 ML 故障模式，并说明"静默失败"的机制；
2. 给出数据漂移与概念漂移的严格定义（在分布 $p(x, y)$ 的分解意义上），并判断一个真实场景属于哪一类；
3. 用 PSI 与 KS 检验对特征分布做漂移检测，并指出两种方法各自的统计陷阱；
4. 在真实标签延迟可得（如信贷逾期 90 天才可见）的场景下，设计一套代理指标监控方案；
5. 设计一个告警分级体系并解释"告警疲劳"的成因与解法；
6. 画出一条包含数据校验、训练、模型校验的持续训练（CT）流水线，给出至少三种自动重训触发条件，并按 Google 的 0/1/2 级框架评估一个团队的 MLOps 成熟度。

## 3.1 生产环境 ML 的独特故障模式

传统软件监控的默认假设是：**代码不变，则行为不变**；出错即抛异常。ML 系统打破了两条假设：

1. **模型 = 代码 + 数据**。数据悄悄变了，行为就变了，而代码与日志毫无异常。Sculley 等人（2015）把这类问题归入"隐藏技术债"：上游特征被未声明的下游依赖（undeclared consumer）、特征之间相互纠缠（CACE：改变任何东西，其余都跟着变）。
2. **失败是统计性的**。服务没有 500 错误，只是准确率从 92% 缓慢滑到 85%——没有一行日志会报告这件事。这是"静默失败（silent failure）"：**基础设施指标全绿，业务价值在流血**。

典型故障清单（每一条都来自真实事故模式）：

- **上游模式变更（schema break）**：上游团队把"年龄"字段从岁改成出生年，模型照常输出"看起来合理"的预测。防御：输入校验（对应 [数据工程·第 4 章](/xiaoshus-blog/textbooks/ai/engineering/data-engineering/04/) 的数据契约）。
- **世界变化（world shift）**：疫情让"通勤支出占比"这个特征的分布一夜突变。模型没有错，是训练时的世界回不来了。
- **反馈回路（feedback loop）**：模型把某类内容推得多 → 用户看到得多 → 训练数据里这类内容更多 → 模型更极端。模型通过自己的输出污染自己的未来训练集。
- **训练-服务偏斜（training-serving skew）**：训练时用离线算的特征（干净、全量），服务时用在线算的特征（延迟、缺省值），同名特征分布不同。这是 3.6 节的主题。
- **依赖模型退化**：你的模型依赖另一个团队的嵌入模型；对方某天默默升级了版本，你的输入分布跟着漂移。

**监控 ML 系统 = 监控三层**：系统层（延迟、错误率、资源——传统 DevOps 范畴，见第 2 章）、数据层（分布与质量——本章重点）、模型层（性能与业务指标）。三层都绿才叫绿。

## 3.2 数据漂移与概念漂移：严格定义

设训练时数据的联合分布为 $p_{\text{train}}(x, y)$，当前线上分布为 $p_s(x, y)$。沿用 [机器学习·第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/machine-learning/01/) 的记号，做条件分解 $p(x,y) = p(x)\,p(y\mid x)$，就能给出严格定义：

- **数据漂移（data drift / 协变量偏移 covariate shift）**：

$$
p_s(x) \ne p_{\text{train}}(x), \qquad p_s(y\mid x) = p_{\text{train}}(y\mid x) \ \text{不变}
$$

输入的分布变了，"输入到输出的映射规则"没变。例：节假日流量激增、用户群体从年轻滑向年长。注意：**数据漂移未必降低模型性能**——如果漂移恰好发生在模型本就成熟的区域，影响可忽略；"分布变了"与"性能掉了"必须区分（前者叫 virtual drift）。

- **概念漂移（concept drift）**：

$$
p_s(y\mid x) \ne p_{\text{train}}(y\mid x)
$$

同样的输入，正确答案变了。例：疫情后"月收入 8000"的还款能力含义不同；"低价卖手机"从正常促销变成诈骗特征。概念漂移**必然**伤害模型（按旧规则学的映射失效了）。

- 另一个有用的中间情形是**标签偏移（label shift / 先验偏移）**：$p(y)$ 变了而 $p(x\mid y)$ 不变（欺诈比例从 0.1% 涨到 1%），它会导致 $p(x)$ 变化但机制不同，校正方法也不同（可推断新先验后加权重训）。

按变化的时间形态，概念漂移又分**突变型（sudden）**、**渐进型（gradual，新旧规则概率混合过渡）**、**增量型（incremental）**与**循环重现型（recurring，季节性来回摆）**（Gama et al., 2014）。形态决定策略：循环重现型不需要每次重训，需要"模式库 + 路由"。

### 3.2.1 检测方法一：PSI（总体稳定性指数）

把训练集的某特征按分位数切成 $B$ 个桶（常用十分位），统计线上样本落入各桶的实际占比 $a_i$ 与训练时期望占比 $e_i$：

$$
\mathrm{PSI} = \sum_{i=1}^{B} (a_i - e_i)\, \ln\frac{a_i}{e_i}
$$

解读（来自信贷行业数十年的经验阈值）：PSI $< 0.1$ 稳定；$0.1 \le \mathrm{PSI} < 0.25$ 需关注；$\mathrm{PSI} \ge 0.25$ 显著漂移。数学上 PSI 是对称化的 KL 散度（Jeffreys 散度）：

$$
\mathrm{PSI} = \sum_i a_i \ln\frac{a_i}{e_i} + \sum_i e_i \ln\frac{e_i}{a_i} = D_{\mathrm{KL}}(a\,\Vert\, e) + D_{\mathrm{KL}}(e\,\Vert\, a)
$$

所以它与你熟悉的信息论语言同源：**PSI 衡量的是两个离散分布的"距离"**，对某个方向上的漂移不偏袒。

### 3.2.2 检测方法二：KS 检验（连续特征）

两样本 Kolmogorov–Smirnov 检验直接比较经验分布函数（ECDF）。设 $F_1, F_2$ 为两组样本的经验分布，检验统计量：

$$
D_{n_1,n_2} = \sup_x \big| F_1(x) - F_2(x) \big|
$$

在原假设"两组同分布"下，$D$ 的抽样分布已知（渐近形式含 $\sqrt{(n_1+n_2)/(n_1 n_2)}$），`scipy.stats.ks_2samp` 一行可算出统计量与 p 值。KS 的优点是无参数、对任意形状的分布差异敏感；缺点恰恰在 3.2.3 节。

### 3.2.3 检测的三个统计陷阱

1. **样本量与效应量脱节**。$n = 10^6$ 时，0.001 的均值差异都能得到 $p < 0.001$——统计显著 ≠ 实际显著。工程做法：**设定 $D$ 或 PSI 的业务阈值作为主判据，p 值只作参考**；或按最小可检测效应反推检测窗口样本量（与《实验设计与评估》的 MDE 思路相同）。
2. **多重检验**。同时监控 200 个特征、每小时测一次，每天做 4800 次检验，按 $\alpha=0.05$ 纯噪声也会"报漂移"上百次。防御：Bonferroni/Benjamini–Hochberg 校正（[概率统计·第 5 章](/xiaoshus-blog/textbooks/ai/math-foundations/probability-statistics/05/) 的多重比较内容），或干脆按效应量阈值而非 p 值告警。
3. **检测器本身被反馈回路污染**。模型上线后改变了用户行为（3.1 节的反馈回路），"线上分布"已不是"没有模型时的分布"。要明确检测基准：是与训练集比（检测输入漂移），还是与昨日比（检测突变）。

### 3.2.4 检测器工程化：窗口、粒度与基准选择

把 PSI/KS 从公式变成在线系统，还要回答三个工程问题：

1. **检测窗口多大**？窗口太短，样本量不足导致统计量抖动（几百条样本的 PSI 天然就在 0.05 上下晃）；窗口太长，检出延迟不可接受。经验起点：以"检测器能容忍的最小样本量"（如每桶 ≥ 100 条 → 十分位需 ≥ 1000 条）定窗口下限，以业务能接受的检出延迟定上限；两者冲突时用**滑动窗口 + 最低样本量门槛**（样本不足时跳过检测并记录，而不是硬算）。
2. **按什么粒度切**？整体漂移可能被分段稀释：若 A/B 两组用户的特征分布反向漂移，合并后 PSI 可能显示"稳定"。重要特征应支持**分段检测**（按用户群/渠道/地域分片，每片各测 PSI）。
3. **和谁比**？三个可选基准，语义不同：(a) 与**训练集**比——检测"输入是否还长训练时的样子"（最常用）；(b) 与**上一个健康窗口**比——检测突发突变（对上游事故最敏感）；(c) 与**一周前的同一时段**比——滤掉周期性（昼夜/周末）的伪漂移。生产系统通常 (a) 为主、(b) 为辅双跑。

另外一个常被遗忘的角落：**类别特征的漂移检测**。PSI/KS 都面向连续值，对高基数类别特征（如城市 ID）应改用占比对比（各 top 类别的占比变化 + "新类别出现率"）或卡方拟合检验；对文本/嵌入特征则比较嵌入分布的中心与散度（如均值向量的漂移量）。检测器库不必统一，**每个特征按类型配检测器**是常态。

## 3.3 模型性能监控：真实指标与代理指标

理想监控是直接盯真实指标（准确率、AUC、营收），但真实标签往往**延迟数天甚至数月**才可得（信贷违约 90 天、用户流失季度末才确认）。间隙期靠**代理指标（proxy metrics）**：

- **输入分布监控**：对每个特征跑 PSI/KS（本章主角）；
- **输出分布监控**：预测的概率分布、正类预测率。若模型把"欺诈率 0.5%"的数据连续三天预测成"5%"，不需要标签也知道出事了；
- **校准监控（calibration）**：预测"70% 违约"的群体实际违约率是否接近 70%。标签到达后画可靠性图（在 [机器学习·第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/machine-learning/07/) 你见过校准曲线）；
- **置信度监控**：预测熵、最大概率的分位数漂移；
- **人工标注流**：定期抽样 N 条线上预测，人工标注，构成"快速真值"通道，用小时级延迟换取覆盖面。

标签最终到达后，要做**滞后归因**：把 p99 延迟（第 2 章的系统层）、漂移告警（数据层）与最终性能下降（模型层）按时间线对齐，回答"为什么退化"——这份数据同时是重训决策的依据。

### 3.3.1 预测日志：监控系统的原料

一切代理指标都来自**预测日志（prediction logging）**，它在第 2 章的服务代码里只是一行"把请求与响应写下来"，却决定了第 3 章所有能力的上限。一条合格的预测日志应包含：

- **特征快照**：模型实际看到的每个特征值（不是"应该是什么"，而是实际进入模型的值——这是排查 train/serve skew 的唯一铁证）；
- **模型版本**：与注册表联动的版本号/工件哈希；
- **预测与置信度**：输出类别、概率向量、（回归任务）点估计与不确定性；
- **关联键与时间戳**：用于日后 join 回真实标签（`prediction_id` 是连接"预测"与"结果"两张表的外键，缺了它标签永远对不上）；
- **采样与脱敏**：全量日志成本高，可按比例采样但**必须保留全量正类预测与全部告警相关的低置信样本**；含个人信息的字段在写入前脱敏（第 4 章 4.7 的合规要求在此落地）。

一个务实的设计权衡：日志写到哪？文件 → 日志聚合（调试期够用）；SQLite/Postgres（中小规模够用）；Kafka → 特征商店/数据湖（生产级，也是把"预测流"回流成"训练数据"的通道）。规模不是起点，**可关联性（prediction_id 贯穿）才是不可妥协项**。

## 3.4 告警设计：避免告警疲劳

监控的产出不是图表，是**行动**。告警设计的反模式极其常见：告警泛滥 → 值班人员麻木（告警疲劳，alert fatigue）→ 真事故被淹没在噪音里。原则：

1. **每个告警必须对应一个可执行动作**。没有动作的告警降级为日志或周报。经典三分级：**page**（现在叫醒人：错误率 > 1% 持续 5 分钟）、**ticket**（下一个工作日处理：PSI > 0.25）、**log**（仅记录供调查）。
2. **按 SLO 的错误预算告警，而不是按原始阈值**。沿用 Google SRE 的多窗口燃烧率（burn rate）方法：例如"1 小时窗口错误消耗速率达到正常 14 倍"或"6 小时窗口达到 6 倍"才 page——双窗口机制天然过滤毛刺。
3. **告警去重与聚合**。200 个特征同时漂移（常见于上游 schema 变更）应聚合成 1 条"疑似 schema 变更"告警，而不是 200 条。
4. **区分告警与仪表盘**。想"了解情况"的指标进仪表盘，"需要行动"的才进告警。

## 3.5 持续训练（CT）流水线与自动重训触发

漂移检测回答"要不要重训"，持续训练（continuous training, CT）回答"怎么自动、安全地重训"。一条 CT 流水线（对应 Google MLOps 白皮书 Level 1 的流水线设计）：

```
新数据/触发 ─▶ 数据提取与校验 ─▶ 数据准备/特征 ─▶ 训练与调参 ─▶ 模型校验 ─▶ 注册与发布
                (schema+分布)      (特征商店, §4.3)   (实验跟踪)     (challenger 评审)  (模型注册表)
```

关键设计点：

- **触发条件（三选一或组合）**：定时（每周）；事件驱动（PSI ≥ 0.25 或性能跌破下限）；数据量驱动（新增标注满 N 万条）。**建议默认定时 + 事件加速**：纯事件驱动会在"漂移检测器自己失灵"时失去保护。
- **模型校验（model validation）是流水线的守门员**：新模型（challenger）必须在**同一份冻结评估集**上不输现任模型（champion），且通过一组冒烟测试（对已知边界输入给出已知合理输出），才允许进入注册表。这沿用《实验设计与评估》的对照原则——比较必须在同基准上做。
- **重训 ≠ 从零重训**。多数场景用"上一版模型热启动 + 新数据微调"，省时且更稳；但注意热启动会继承旧模型的偏见，遇到概念突变时要能切换到从零训练。
- **幂等与可复现**：同一次流水线运行必须可复现（数据版本 + 随机种子 + 超参全记录，见 [数据工程·第 4 章](/xiaoshus-blog/textbooks/ai/engineering/data-engineering/04/)），否则"这次好那次差"永远无法归因。

### 3.5.1 重训的数据策略：窗口、加权与热启动

"用哪些数据训新模型"是 CT 流水线里最容易被省略的设计决策，三个选项各有适用场景：

- **固定时间窗**（如只用最近 90 天数据）：对概念漂移最稳健，但数据量小时方差大；窗口长度应与"概念的有效半衰期"匹配——欺诈类特征几周就过期，而图像风格可能几年不衰。
- **全量历史 + 时间加权**：样本权重随年龄指数衰减（$\ w_i \propto \lambda^{\text{age}_i}$），兼顾样本量与新鲜度；$\lambda$ 的选择本质是偏差-方差权衡（[机器学习·第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/machine-learning/01/) 的老朋友换了个舞台）。
- **热启动微调**：从上一版模型出发、只用新窗口数据微调，训练便宜且平滑；代价是**错误会累积**（上一版的偏见被继承，逐步漂移被"洗白"进权重）。防御：定期（如每 N 次增量重训后）安排一次从零训练对照，确认没有系统性退化。

无论哪种策略，**训练数据必须包含被拒绝的样本**（如被风控拒绝的贷款申请最终是否违约）——反馈回路（3.1 节）会让"模型没见过的区域"越来越大，这是选择偏差（selection bias）在 ML 系统里的标准形态，严重时需要探索流量（故意小比例随机决策）来补数据，这一步要过合规与体验评审。

## 3.6 特征/数据/模型三线一致性

生产 ML 最阴险的 bug 不在模型里，而在"训练看见的世界"与"服务看见的世界"不一致。三条线要分别对齐：

1. **特征线（train/serve skew 的主战场）**：同一特征在训练管道（离线批量计算）与服务管道（在线实时计算）中的定义、单位、缺省值、时间窗必须逐字节一致。例如"用户近 7 天点击数"：离线用 T-1 日快照，在线用实时累加——窗口边界不同就是两个不同的特征。系统化解法是**特征商店**（第 4 章）：离线/在线双存储、同一套特征定义。
2. **数据线**：服务请求的 schema 校验规则、预处理代码必须与训练时**同一份实现**。常见 bug：训练时标准化用了训练集均值（正确），服务时却用了单条请求自身的均值（错误）——这是 [数据工程](/xiaoshus-blog/textbooks/ai/engineering/data-engineering/00/) 数据泄漏问题在服务端的镜像。
3. **模型线**：线上服务的模型工件哈希必须与模型注册表中批准版本的哈希一致。Breck 等人的 ML Test Score（2017）把这类检查列为其 28 项测试的骨架：**spec 声明的特征与实际喂入的特征逐一核对、模型版本可追溯**。

## 3.7 MLOps 成熟度分级（0/1/2 级）

Google 的 MLOps 白皮书给出了被广泛引用的三级框架，用于给团队定位、规划下一步：

| 级别 | 名称 | 特征 | 适用 |
|---|---|---|---|
| **0 级** | 手工流程 | notebook 里训练，手工导出，手动部署，无监控；脚本驱动，发布以月/季计 | 原型验证、问题尚在探索期的项目 |
| **1 级** | ML 流水线自动化 | 训练→校验→注册→部署是**一条自动流水线**；有实验跟踪、数据校验、模型校验；**持续训练**靠新数据触发流水线；有监控闭环 | 生产服务、需要定期重训的单一团队 |
| **2 级** | CI/CD 流水线自动化 | 在 1 级之上，连"流水线本身"的修改也走 CI/CD：改特征/架构 → 自动测试 → 自动构建新流水线 → 部署；多团队、多模型并行迭代 | 平台化组织、大量模型频繁更新 |

两个容易误读的地方：其一，级别不是越高越好——0 级对"一年上线一次的内部报表模型"完全够用，**成熟度应匹配迭代频率**；其二，1 级的关键增量是 CT（本章内容），2 级的关键增量是对流水线本身的 CI/CD（第 4 章内容），两级之间隔着一整章的知识量。

## 3.8 关键公式速查

| 公式 | 含义与适用条件 |
|---|---|
| 数据漂移：$p_s(x) \ne p_{\text{train}}(x)$，$p(y\mid x)$ 不变 | 分布分解意义下的定义；性能未必下降 |
| 概念漂移：$p_s(y\mid x) \ne p_{\text{train}}(y\mid x)$ | 映射规则变化；必然影响性能 |
| $\mathrm{PSI} = \sum_i (a_i - e_i)\ln\frac{a_i}{e_i}$ | 分桶后比较占比；阈值 0.1/0.25 为行业经验值 |
| $\mathrm{PSI} = D_{\mathrm{KL}}(a\Vert e) + D_{\mathrm{KL}}(e\Vert a)$ | Jeffreys 散度分解；对称、无方向偏好 |
| $D_{n_1,n_2} = \sup_x \lvert F_1(x) - F_2(x)\rvert$ | KS 两样本统计量；连续特征、分布无关 |
| 燃烧率 $= \dfrac{\text{实际错误消耗速率}}{\text{SLO 允许消耗速率}}$ | SLO 告警判据；多窗口组合防毛刺（如 1h×14 倍或 6h×6 倍） |

## 3.9 示例与案例

### 案例 1（手算）：PSI 的计算与判读

训练集把某特征切成 4 桶，期望占比 $e = (0.25, 0.25, 0.25, 0.25)$。

**情形 A**（轻微波动）：实际占比 $a = (0.30, 0.30, 0.25, 0.15)$：

$$
\begin{aligned}
\mathrm{PSI} &= 0.05\ln(1.2) + 0.05\ln(1.2) + 0 + (-0.10)\ln(0.6) \\
&= 0.00912 + 0.00912 + 0 + 0.05108 = 0.0693
\end{aligned}
$$

$0.0693 < 0.1$，判定稳定。

**情形 B**（明显漂移）：$a = (0.45, 0.30, 0.15, 0.10)$：

$$
\mathrm{PSI} = 0.20\ln(1.8) + 0.05\ln(1.2) + (-0.10)\ln(0.6) + (-0.15)\ln(0.4) = 0.1176 + 0.0091 + 0.0511 + 0.1374 = 0.3152
$$

$\ge 0.25$，触发 ticket 级告警。注意 PSI 的不对称性细节：**占比低于期望的桶贡献的绝对项更大**（$\ln(0.4)$ 比 $\ln(1.8)$ 绝对值大），所以"某桶突然清空"是 PSI 最敏感的信号之一。

### 案例 2（代码）：注入渐进漂移，用 PSI 与 KS 追踪

模拟"上线后世界逐渐变化"：构造训练分布 $\mathcal{N}(0,1)$，之后每周线上分布的均值偏移 $+0.15\sigma$。同时计算 PSI 与 KS，观察两种检测器的响应。

```python
# ch3_drift_detection.py
# 依赖: numpy, scipy
import numpy as np
from scipy import stats

rng = np.random.default_rng(7)

def psi(expected, actual, eps=1e-6):
    """PSI: expected/actual 为各桶占比数组 (和为 1)。"""
    e = np.asarray(expected, float) + eps
    a = np.asarray(actual, float) + eps
    e, a = e / e.sum(), a / a.sum()
    return float(((a - e) * np.log(a / e)).sum())

# 训练基准: 10000 条 N(0,1), 按十分位分桶
train = rng.normal(0, 1, 10_000)
edges = np.percentile(train, np.arange(0, 101, 10))   # 十分位切分点
edges[0], edges[-1] = -np.inf, np.inf                 # 两端开区间
expected = np.histogram(train, edges)[0] / len(train)

print(f"{'week':>4} {'shift':>6} {'PSI':>7} {'KS_D':>7} {'KS_p':>10}  判定")
for week in range(9):
    shift = 0.15 * week                               # 每周漂移 +0.15 个标准差
    live = rng.normal(shift, 1, 5_000)                # 线上样本
    actual = np.histogram(live, edges)[0] / len(live)
    p = psi(expected, actual)
    d, pval = stats.ks_2samp(train, live)             # 两样本 KS 检验
    verdict = ("稳定" if p < 0.1 else
               "关注" if p < 0.25 else "ALARM")
    print(f"{week:>4} {shift:>6.2f} {p:>7.3f} {d:>7.3f} {pval:>10.2e}  {verdict}")
# 预期输出 (固定种子, 数值可复现, ±10% 抽样波动):
# week  shift     PSI    KS_D       KS_p  判定
#    0   0.00   0.001   0.009   9.7e-01  稳定
#    1   0.15   0.026   0.045   1.2e-02  稳定
#    2   0.30   0.077   0.106   2.7e-13  稳定
#    3   0.45   0.156   0.165   6.6e-30  关注
#    4   0.60   0.247   0.224   1.7e-53  关注
#    5   0.75   0.347   0.280   2.2e-85  ALARM
#    6   0.90   0.456   0.334   4.0e-125 ALARM
#    7   1.05   0.564   0.386   1.1e-172 ALARM
#    8   1.20   0.668   0.437  1.2e-226  ALARM
# 判读: (1) PSI 的 0.1/0.25 阈值大约对应"均值漂移 0.4σ/0.6σ"——行业经验值
#          与统计现实吻合; (2) 从第 1 周起 KS 的 p 值就已显著 (1.2e-02),
#          这演示了 3.2.3 的陷阱: 大样本下 p 值对微小漂移极敏感,
#          判定应以效应量 (PSI/ KS_D) 为主。
```

## 3.10 常见误区与陷阱

1. **把漂移检测当性能监控的替身**。数据漂移是**预警信号**，不是性能本身：有漂移性能未必掉，性能掉了也可能毫无可检测的输入漂移（概念漂移悄悄发生）。两者都要监控。
2. **对所有特征无差别监控**。200 个特征全量监控 = 200 倍噪音 + 没人看。应按特征重要性/业务敏感度分级，重点盯 top 特征与预测输出分布。
3. **用训练集当永久基准**。半年后训练集早已过时，与之比较会天天报警。基准要定期刷新（用最近一个"确认健康"的窗口），并保留多基准对比。
4. **自动重训无门控**。"漂移就重训、训完就上线"的流水线会把噪声当信号，把一个坏数据周期固化成坏模型。重训产物必须过 3.5 节的 champion/challenger 校验。
5. **告警阈值拍脑袋且从不维护**。上线时设的阈值半年后与业务现实脱节；阈值应随告警处置记录复盘调整——告警系统本身也需要运维。

## 3.13 进阶方向

1. **在线漂移检测算法**：ADWIN（自适应窗口，带误报率保证）、CUSUM（变点检测的序贯分析）、Page-Hinkley 检验；补齐序贯分析即可进入流数据场景。
2. **概念漂移下的学习**：滑动窗口、时间加权损失、ensemble-of-experts（按漂移模式切换专家模型）；衔接 [强化学习·第 5 章](/xiaoshus-blog/textbooks/ai/ai-core/reinforcement-learning/05/) 的非平稳环境思想。
3. **无标签场景的性能估计**：利用标签偏移校正、置信度分布对比（BBSD 等方法）在无真值时估计性能变化——这是当前研究热点之一。
4. **反馈回路的因果分析**：用因果推断区分"世界变了"与"模型自己造成的"；需要补干预（intervention）与离线策略评估（OPE）的知识。
