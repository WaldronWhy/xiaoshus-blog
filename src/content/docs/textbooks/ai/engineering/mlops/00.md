# 模型部署与 MLOps · 课程导览

## 一、课程定位：从 notebook 到生产系统的最后一公里

在这门课之前，你已经完成了整部教材中绝大部分内容：数学基础给了你语言，程序设计给了你工具，人工智能核心给了你模型，数据工程给了你数据，实验设计与评估给了你"如何判断一个模型更好"。但所有这些工作的产物——最典型的形态是——**一个在 Jupyter notebook 里跑通、准确率 0.93 的模型文件**。

生产系统不认识 notebook。真实世界对模型的要求是：**7×24 小时在线、毫秒级响应、错误率可控、成本可预算、效果随时间不退化、出了问题能在分钟内回滚**。这门课研究的就是从"模型能跑"到"系统可靠"之间的全部工程学问，即所谓**最后一公里（last mile）**。

这门课的名字是"模型部署与 MLOps"。我们先把三个缩写摆正：

- **DevOps**：软件工程界的实践集合——版本控制、CI/CD、自动化测试、监控、快速回滚。它的核心信念是"频繁的小改动 + 自动化流水线 = 高可靠性"。
- **DataOps**：数据界的对应物——数据版本控制、数据质量校验、数据流水线的自动化与监控（详见 [数据工程](/xiaoshus-blog/textbooks/ai/engineering/data-engineering/00/)）。
- **MLOps**：二者之上再加 ML 特有的复杂度。**MLOps = ML + DevOps + DataOps**，其中"ML 特有"的部分正是本课的主线：模型是数据与代码共同决定的产物、模型会随世界变化而**静默退化**（性能下降不抛异常）、实验本身是流水线的一等公民。

一个必须尽早建立的观念（来自 Sculley 等人的经典论文《Hidden Technical Debt in Machine Learning Systems》）：在一个真实 ML 系统里，**模型本身只是冰山一角**——数据收集、特征工程、服务基础设施、监控、资源配置占据系统绝大部分。这门课教的就是水面以下的部分。

## 二、知识地图

本课程共 5 章 + 1 个综合项目，构成一条"模型的一生"主线：

```
第 1 章 模型导出与推理优化        —— 模型出厂：格式标准化 + 压缩提速
        │  (ONNX / 量化 / 剪枝 / 蒸馏)
        ▼
第 2 章 模型服务化                —— 模型上岗：API + 并发 + 发布策略
        │  (在线/批量/流式 / gRPC / dynamic batching / 灰度与回滚)
        ▼
第 3 章 监控、漂移与持续训练      —— 模型运维：它还在对吗？
        │  (数据/概念漂移 / PSI、KS / 告警设计 / 自动重训 / 成熟度分级)
        ▼
第 4 章 MLOps 平台与全流程 CI/CD  —— 系统集成：让以上一切自动运转
        │  (ML 版 CI/CD / 流水线编排 / 特征商店 / 模型注册表 / 成本与安全)
        ▼
第 5 章 大模型时代的部署专题      —— 新大陆：LLM 改写了哪些规则
        │  (显存墙 / vLLM 与 PagedAttention / 连续批处理 / 量化部署 / RAG / 护栏)
        ▼
综合项目                          —— 三选一或全做：完整闭环
```

各章的知识形态不同：第 1、2 章偏"手艺"（大量可动手的代码与工具），第 3、4 章偏"设计"（决策框架与系统权衡），第 5 章偏"专题"（LLM 时代的新问题域）。综合项目把所有环节串成一个最小可用的闭环系统。

## 五、学习方法

1. **每章必跑代码，且必须动手压测**。本课与数学课不同：结论不是"推导出来"的而是"压出来的"。第 1 章不亲手跑一遍 ONNX 延迟对比，你对"量化为什么快"的理解就停留在口号层面。所有延迟/吞吐数字都应在你的机器上复现并记录。
2. **用"故障注入"代替"功能演示"**。学服务化和监控时，主动制造故障：杀进程、注入脏数据、把模型换成错的。MLOps 的能力本质上是对失败场景的想象力。
3. **保持一条端到端的仓库**。从第 2 章的 FastAPI 服务开始，在同一个 Git 仓库里持续生长：加 Dockerfile（第 2 章）、加监控与重训（第 3 章）、加 CI/CD 与注册表（第 4 章）。课程结束时的这个仓库，就是你最好的求职作品之一。
4. **工具会用即可，思想必须吃透**。TorchServe、Triton、vLLM、Airflow 的具体 API 三年后大概率都换了，但 Little's Law、漂移的形式化定义、PagedAttention 的分页思想是长期的。
5. **读两份"行业地图"**：Chip Huyen 的《Designing Machine Learning Systems》与 Google 的 MLOps 白皮书（见各章拓展阅读）。本课的章节骨架与它们大量互锁，配合阅读事半功倍。

## 六、环境准备

- **Python 3.10+**，依赖：`numpy`、`scipy`、`scikit-learn`、`pandas`、`matplotlib`（本课新增）；
- 第 1 章需 `torch`（CPU 版即可完成全部实验）、`onnx`、`onnxruntime`；
- 第 2 章需 `fastapi`、`uvicorn`、`requests`，以及 **Docker Desktop**（或 podman）；
- 第 5 章鼓励（非必须）安装 `vllm` 或 `llama.cpp`：需要一台显存 ≥ 8 GB 的 GPU，或接受 CPU 上的小模型压测；
- 一切代码均在 Windows / Linux 双平台验证过的思路编写，路径一律使用 `pathlib`。

## 七、拓展阅读

- Chip Huyen, *Designing Machine Learning Systems*, O'Reilly, 2022.——本书最接近本课的"教材版前身"，第 1–2 周配合通读第 1–7 章。
- Google Cloud, *MLOps: Continuous delivery and automation pipelines in machine learning*（白皮书，官方文档站免费）.——第 3、4 章成熟度分级思想的原始出处。
- Chip Huyen, Stanford CS329S: Machine Learning Systems Design 课程讲义（2021，公开）.——比书更精炼的课堂版本，适合快速过一遍全貌。
- D. Sculley et al., "Hidden Technical Debt in Machine Learning Systems", NeurIPS 2015.——开课前必读，理解"为什么 MLOps 是独立学科"。
