## 7.1 解码策略的完整数学

自回归模型每步给出词表上的分布 $p_t = \text{softmax}(z_t)$，其中 $z_t\in\mathbb{R}^{|V|}$ 是 logits。解码策略决定如何从 $p_t$ 选 token——[第 4 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/04/)的贪心与束搜索是确定性策略，本节是**随机策略**的完整定义。

**Temperature 采样**：对 logits 先除以温度再 softmax：

$$
p_t(v) = \frac{\exp(z_t(v)/\tau)}{\sum_{v'} \exp(z_t(v')/\tau)}, \qquad \tau > 0.
$$

数学性质：记 $\tau = e^{\lambda}$，则用温度 $\tau$ 的 softmax 等价于对原分布做**指数倾斜** $p_t(v)\propto p^{(1/\tau)}(v)$。$\tau<1$ 使分布更尖（低熵、更确定），$\tau>1$ 更平（高熵、更多样），$\tau\to 0$ 退化为 argmax。它**只改变分布形状，不改支持集**。

**Top-k**：只在 logits 最大的 $k$ 个候选上重新归一化：

$$
S_k = \{v:\, z_t(v) \text{ 属于前 } k \text{ 大}\}, \qquad p_t^{(k)}(v) = \frac{p_t(v)\,\mathbb{1}[v\in S_k]}{\sum_{v'\in S_k} p_t(v')}.
$$

**Top-p（nucleus）**：Holtzman et al.（2020）提出，取覆盖累计概率超过 $p$ 的**最小**候选集：

$$
S_p = \min\left\{S:\, \sum_{v\in S} p_t(v) \ge p\right\} \quad (\text{按概率降序取前缀}), \qquad p_t^{(p)}(v) = \frac{p_t(v)\,\mathbb{1}[v\in S_p]}{\sum_{v'\in S_p} p_t(v')}.
$$

Top-k 的缺陷是 $k$ 固定：分布尖时引入噪声尾巴，分布平时截掉合理候选；top-p 让候选数**随每步分布的自适应熵变化**（尖时只剩几个词，平时扩到几十个），因此是现代解码的默认选择。常用组合：$\tau\in[0.6, 1.0]$，$p\in[0.9, 0.95]$。

**重复惩罚**：对已出现 token 的 logits 做惩罚，如 $\tilde z(v) = z(v) - \alpha\,\mathbb{1}[v\in \text{已生成}]$（或除法式 $\tilde z(v)=z(v)/\alpha$），$\alpha>1$ 抑制重复。

### 7.1.1 与评价的关系

采样策略没有"最优"：确定性策略利于可复现评测与代码生成（常配 temperature $\approx 0$ 即 greedy），开放创作需要较高温度。评测协议里必须**固定并报告解码参数**（呼应[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)）。

## 7.2 推理加速 I：KV 缓存

生成第 $t$ 个 token 时，注意力只需要 $q_t$（当前步的 query）与全部历史的 $k_{1:t}, v_{1:t}$。历史 token 的 key/value **不随新 token 改变**（因果掩码保证了这一点，见[第 5 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/05/)示例 4 的数值验证），因此把它们缓存起来：

$$
\text{每步计算：}\; q_t = x_t W_q,\quad \text{softmax}\!\left(\frac{q_t K_{1:t}^\top}{\sqrt d}\right)V_{1:t}, \qquad K_{1:t} \leftarrow \text{append}(k_t).
$$

**复杂度**：无缓存时每生成一个 token 需对全长序列重算注意力，$n$ 步总代价 $O(n^4)$ 级的重复计算；有缓存时每步 $O(n\,d)$（对新 query 与 $t$ 个历史 key 的点积），$n$ 步总计 $O(n^2 d)$——即每个新 token 线性于当前长度。代价是显存：每层每头需存 $2\times$ 序列长 $\times$ 头维度的浮点数，总量

$$
M_{\text{KV}} = 2\, L_{\text{层}} \times n \times d_{\text{model}} \times b_{\text{bytes}},
$$

与 batch 成正比。例如 7B 模型（32 层、$d=4096$、FP16）在 4096 token 上下文下，KV 缓存约 $2\times32\times4096\times4096\times2\,\text{B} = 2\,\text{GB}$ 每 batch 条。多 batch 服务时 KV 缓存常常**比权重更占显存**，由此产生了 PagedAttention（把 KV 像操作系统分页一样管理）等系统工作。

## 7.3 推理加速 II：量化

量化把 FP16 权重压到 INT8/INT4，省显存、提带宽受限场景的吞吐。 Transformer 的难点是**离群值（outlier）**：少数激活通道数值极大，朴素按张量取缩放因子会把其余权重压成噪声。两条代表性路线：

- **GPTQ**（Frantar et al., 2022）：逐层把量化视为最小化 $\|W X - \hat W X\|^2$（$X$ 为该层输入的校准集）。利用 Hessian $H = 2XX^\top$，每次量化一列权重，并**把该列的量化误差按 Hessian 的逆实时补偿到尚未量化的列**（OBS 经典思想的工程化），使端到端输出误差最小。4-bit 下几乎无损，需要校准数据。
- **AWQ**（Lin et al., 2024）：观察是"约 1% 的权重通道对应大激活、对性能至关重要"。量化误差应按**激活大小**而非权重大小加权，因此对每个通道学一个缩放因子 $s$，把重要通道的等效权重量化误差转移走：$y = (W \cdot \text{diag}(s))(x / s)$，数学上输出不变，但量化难度被重新分配。无需反向传播，泛化到分布外数据更好。

工程速记：显存极限优先 GPTQ/INT4，精度与泛化优先 AWQ；更激进的 FP8/权重-激活同量化见部署课程。

## 7.4 推理加速 III：FlashAttention 与推测解码

**FlashAttention**（Dao et al., 2022）。精确注意力的瓶颈不是 FLOPs 而是显存读写：标准实现把 $n\times n$ 的注意力矩阵写入 HBM（显存）再读回。FlashAttention 的思想是**分块（tiling）+ 在线 softmax**：把 Q、K、V 分块载入高速 SRAM，在块上增量维护 softmax 的归一化统计量（运行最大值 $m$ 与运行和 $\ell$），从而**一次遍历算出精确注意力**，从不物化 $n\times n$ 矩阵。它不改变数学结果（仍是精确 softmax），只是重排计算次序，IO 复杂度从 $O(n^2)$ 降为 $O(n^2 d^2 / M)$ 级（$M$ 为 SRAM 大小），长序列下常见 2–4 倍实测加速。核心算法在线 softmax 的更新规则：

$$
m^{\text{new}} = \max(m,\ m^{(j)}), \qquad \ell^{\text{new}} = e^{m - m^{\text{new}}}\ell + e^{m^{(j)} - m^{\text{new}}}\ell^{(j)}.
$$

**推测解码（speculative decoding）**（Leviathan et al., 2023；Chen et al., 2023）。用小模型 $q$ 一次草拟 $\gamma$ 个 token，再用大模型 $p$ 并行验证。关键是一个**拒绝采样修正**：对草拟 token $x$，以概率

$$
\min\!\left(1,\ \frac{p(x)}{q(x)}\right)
$$

接受；若拒绝，则以**残差分布** $\max(0, p(x)-q(x))$ 归一化后重采样。可以严格证明：由此得到的输出分布与直接从大模型采样**完全相同**（correctness theorem），只是把大模型的串行 $n$ 次前向压缩为约 $n/(\gamma+1)$ 次并行验证。加速比取决于小大模型的"一致率" $\alpha = E[\min(1, p/q)]$，理论上限约为 $(1-\alpha^{\gamma+1})/((1-\alpha)(\gamma+1))$ 的倒数增益。要点：**无损加速**，与量化这类有损手段正交。

## 7.5 长上下文：位置编码外推

RoPE（Su et al., 2021）把相对位置以旋转矩阵形式注入注意力：对位置 $m$ 的向量按频率 $\theta_i = 10000^{-2i/d}$ 旋转角度 $m\theta_i$，使内积自然只依赖相对距离 $m-n$。训练时见过的最大位置是 $L$；推理时若输入超过 $L$，模型要外推到从未见过的旋转角——注意力分数崩坏，长文本质量骤降。主流补救：

- **位置插值（PI）**：把位置 $m$ 线性压到 $m \cdot L/L'$（$L'$ 为目标长度），用少量长文本继续微调；
- **NTK-aware 缩放**：不改 $m$ 而改基频（把 $10000$ 调大），让高频维度（编码局部相对位置）不动、低频维度（编码远距离）被压缩，微调需求更小；
- **滑动窗口/局部注意力**：超出窗口的位置直接不参与注意力（配合 KV 缓存窗口化）。

教训值得提炼：**位置编码是模型对"序列坐标"的先验，外推就是分布外泛化**——先理解坐标语义，再选修复手段。

## 7.6 检索增强生成：RAG

### 7.6.1 完整架构

参数化知识（权重）容量有限且过时；RAG（Lewis et al., 2020）把知识放到**非参数化的外部语料**，推理时检索后拼进上下文。完整流水线：

1. **离线索引**：文档 → 清洗 → **分块（chunking，如 256–1024 token，带重叠）** → 用嵌入模型（第 5 章的 BERT 类双编码器）编码 → 存入向量库（ANN 索引如 HNSW）；
2. **在线检索**：查询改写/扩展 → 嵌入 → ANN 召回 top-$k$ → **重排（rerank，用 cross-encoder 精排）**；
3. **生成**：把检索片段以规定格式拼进提示 → 生成，最好带**引用溯源**（标注每句依据哪一片段）。

检索质量指标用[第 3 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/03/)的 IR 标准件：Recall@k、MRR、nDCG。

### 7.6.2 失败模式清单（工程价值最高的一节）

- **检索失败**：查询与文档词汇不匹配（"报销"vs"发票 refund"）→ 混合检索（关键词 BM25 + 向量）、查询改写；**分块切断语义**（一个表格/一条规则被切成两半）→ 结构感知分块；
- **"失去中间"（lost in the middle）**：长上下文中模型偏爱开头结尾、忽略中部证据（Liu et al., 2023）→ 把最相关片段放两端、控制上下文长度；
- **上下文冲突**：检索片段与参数知识或彼此矛盾 → 生成前做一致性检查、明确"以检索为准"指令；
- **检索到相关但无用**（topically similar, answer-missing）→ 重排、按问题类型路由（摘要类 vs 事实类）；
- **无证据时仍编造**：检索为空或低相关时应触发"拒答/澄清"分支，而不是硬答。

### 7.6.3 与微调的选型

知识频繁变化或需溯源 → RAG；风格/格式/流程对齐 → 微调（第 6 章）；两者正交，生产系统常常 RAG + 微调叠加。

## 7.7 Agent 概览：工具调用与 ReAct

**Agent** = 以 LLM 为决策核心、能**调用外部工具并按观察迭代决策**的系统。基础是**工具调用（function calling）**：把工具的 JSON Schema 放进提示，模型输出结构化调用请求，运行时执行后把结果回填上下文。**ReAct 范式**（Yao et al., 2022）把推理与行动交替：

```
Thought: 我需要先查文档库中关于退货政策的条款
Action: search("退货政策 7天")
Observation: 《用户协议》第 5.2 条：商品自签收之日起 7 日内可无理由退货……
Thought: 已找到答案，可以作答并引用条款
Final Answer: 根据《用户协议》5.2 条……
```

思维（Reason）决定下一步行动（Act），观察（Observe）反馈回上下文——它把"内心独白"变成了显式的、可审计的轨迹，也天然支持纠错循环。Agent 的可靠性问题（多步误差累积、工具幻觉调用、循环打转）是当前研究热点；安全边界（最小权限、沙箱执行、人工确认高危操作）在[《模型部署与 MLOps》](/xiaoshus-blog/textbooks/ai/engineering/mlops/00/)的安全与监控部分展开。

## 7.8 幻觉：成因与缓解

**定义**：生成内容与事实或给定证据不符，且表现为自信陈述。二分类（Ji et al., 2023）：**事实性幻觉**（与世界不符，如错误日期）与**忠实性幻觉**（与用户提供的文档/指令不符，如总结里捏造条款）。

**成因**（按层次）：

1. **目标函数层**：预训练目标是"像语料的下文"而非"真"；RLHF 偏好流利自信（第 6 章已埋伏笔）；
2. **知识层**：参数化知识有截止日期、长尾事实必然稀疏；Transformer 无法可靠区分"我知道"与"我在编"；
3. **解码层**：高温度采样会放大低概率（可能错误）token；
4. **系统层**：检索错误、提示矛盾、无拒答机制。

**缓解对照表**：

| 层次 | 手段 |
|---|---|
| 训练期 | 混入"拒答"数据、RLHF 中惩罚无证据断言、R-Tuning 类"知道自己不知道"训练 |
| 推理期 | 降低温度、思维链分解、自我一致性（多次采样投票）、引诱模型先列证据再下结论 |
| 系统期 | RAG 提供证据 + 强制引用、检索相关性阈值触发拒答、输出后置校验（规则/小模型事实核查） |

重要观念：幻觉不是"bug 修完就消失"，而是概率生成模型的本征性质——工程目标是**把幻觉率压到与场景风险匹配**（医疗问答 vs 创意写作的容忍度完全不同）。

## 7.9 关键公式速查

| 公式 | 含义 | 适用条件 |
|---|---|---|
| $p_t(v)\propto \exp(z_t(v)/\tau)$ | temperature 采样 | $\tau\to0$ 退化为贪心；只改形状不改支持集 |
| $S_p=\min\{S:\sum_{v\in S}p_t(v)\ge p\}$ | top-p 截断集 | 按概率降序取前缀；重归一化后采样 |
| $M_{\text{KV}}=2Ln d\, b$ | KV 缓存显存 | 与 batch、精度字节数 $b$ 成正比 |
| $\min(1, p(x)/q(x))$ 接受，残差 $\max(0,p-q)$ 重采 | 推测解码拒绝采样 | 输出分布严格等于大模型采样 |
| $m^{\text{new}}=\max(m,m^{(j)})$，$\ell^{\text{new}}=e^{m-m^{\text{new}}}\ell+e^{m^{(j)}-m^{\text{new}}}\ell^{(j)}$ | 在线 softmax 增量更新 | FlashAttention 分块精确计算 |
| $\theta_i=10000^{-2i/d}$，旋转角 $m\theta_i$ | RoPE | 外推需 PI/NTK 缩放或窗口化 |
| $\mathcal{L}_{\text{GPTQ}}=\|WX-\hat W X\|^2$ 逐列 + Hessian 补偿 | GPTQ 逐层量化目标 | 需校准数据；INT4 常近无损 |

## 7.10 示例与案例

### 示例 1（手算）：top-p 截断

某步 logits 归一化后（降序）：$p = [0.42, 0.28, 0.15, 0.08, 0.04, 0.03]$。取 $p=0.9$：累计 $0.42 \to 0.70 \to 0.85 \to 0.93 \ge 0.9$，故 $S_p$ 含前 4 个候选，重归一化得 $[0.452, 0.301, 0.161, 0.086, 0, 0]$（即 $0.42/0.93=0.4516$ 等）。取 $p=0.95$：第 4 个候选累计 $0.93<0.95$，第 5 个 $0.97\ge0.95$，故 $S_p$ 有 5 个候选。可见**同一 $p$ 在尖峰分布下自动缩小候选集**——这正是 top-k 做不到的自适应性。

### 示例 2（代码）：从零实现 temperature / top-k / top-p 采样（torch）

```python
# 需要: pip install torch
import torch
import torch.nn.functional as F

def sample_next(logits, temperature=1.0, top_k=None, top_p=None):
    """按 7.1 节的严格定义实现组合采样。logits: (V,) 张量"""
    logits = logits / max(temperature, 1e-6)          # temperature 倾斜
    if top_k is not None:                              # top-k: 保留前 k 大
        kth = torch.topk(logits, top_k).values[-1]
        logits = logits.masked_fill(logits < kth, float("-inf"))
    if top_p is not None:                              # top-p: 覆盖累计概率 p 的最小前缀
        probs = F.softmax(logits, dim=-1)
        sorted_probs, sorted_idx = torch.sort(probs, descending=True)
        cum = torch.cumsum(sorted_probs, dim=-1)
        cutoff = cum > top_p                           # 第一个超过 p 的位置仍保留
        cutoff[1:] = cutoff[:-1].clone()               # 右移一位: 保留跨过阈值的那一项
        cutoff[0] = False
        logits = logits.index_fill(0, sorted_idx[cutoff], float("-inf"))
    probs = F.softmax(logits, dim=-1)
    return torch.multinomial(probs, num_samples=1).item()

torch.manual_seed(0)
logits = torch.randn(50)
counts = {}
for _ in range(20000):
    v = sample_next(logits, temperature=1.0, top_k=10, top_p=0.9)
    counts[v] = counts.get(v, 0) + 1
top = sorted(counts.items(), key=lambda kv: -kv[1])[:5]
print("top5 sampled tokens:", top)
print("候选集:", torch.topk(logits, 10).indices.tolist())
# 预期输出: top5 的 token 全部落在候选集（logits 最大的前 10 个）之内;
# 实际采出的不同 token 数约 8 个 —— top-p=0.9 自适应地截掉了 10 个候选中
# 概率最小、累计超出 p 的尾巴（这也是它与固定 top-k 的差别）。
```

### 示例 3（代码）：KV 缓存的最小实现与数值验证（numpy）

```python
# 需要: pip install numpy
# 在一个 toy 单头注意力上验证: 带缓存逐步生成 == 一次性全序列因果注意力。
import numpy as np
np.random.seed(0)

d, T = 4, 6
X = np.random.randn(T, d)                 # "生成"用的输入序列(教学上一次给定)
Wq = np.random.randn(d, d); Wk = np.random.randn(d, d); Wv = np.random.randn(d, d)

K_cache, V_cache = [], []
outs = []
for t in range(T):
    q = X[t] @ Wq                          # 只算当前 query
    K_cache.append(X[t] @ Wk)              # 增量写入缓存
    V_cache.append(X[t] @ Wv)
    K = np.array(K_cache); V = np.array(V_cache)
    scores = K @ q / np.sqrt(d)            # (t+1,)
    scores -= scores.max()                 # 数值稳定
    w = np.exp(scores) / np.exp(scores).sum()
    outs.append(w @ V)
outs = np.array(outs)

# 对照: 一次性全序列因果注意力。注意 S[j,t]=k_j·q_t(行=key, 列=query),
# 因果性要求 key 下标 j 大于 query 下标 t 的项被屏蔽 -> 即 S 的严格下三角。
Q, K, V = X @ Wq, X @ Wk, X @ Wv
S = K @ Q.T / np.sqrt(d)
mask = np.tril(np.ones((T, T), bool), k=-1)   # [j,t]=True 当 t<j, 即 key 在 query 之后 -> 屏蔽
S[mask] = -1e9
S = S - S.max(axis=0, keepdims=True)
W = np.exp(S) / np.exp(S).sum(axis=0, keepdims=True)
ref = (V.T @ W).T

print("max abs diff:", np.abs(outs - ref).max())
# 预期输出: max abs diff: < 1e-12 —— 缓存增量计算与全量重算数学等价。
```

### 示例 4（代码）：推测解码的分布正确性模拟

```python
# 需要: pip install numpy
# 用两个离散分布模拟大/小模型, 统计拒绝采样输出的经验分布, 验证它等于大模型分布。
import numpy as np
np.random.seed(0)

p = np.array([0.35, 0.25, 0.20, 0.12, 0.08])   # 大模型分布
q = np.array([0.50, 0.20, 0.15, 0.10, 0.05])   # 小模型分布(有偏)

def residual_sample():
    r = np.maximum(p - q, 0)
    return np.random.choice(len(p), p=r / r.sum())

def speculative_one():
    x = np.random.choice(len(p), p=q)            # 小模型草拟
    if np.random.rand() < min(1.0, p[x] / q[x]):
        return x                                  # 接受
    return residual_sample()                      # 拒绝后按残差重采

N = 400_000
samples = [speculative_one() for _ in range(N)]
emp = np.bincount(samples, minlength=len(p)) / N
print("经验分布:", np.round(emp, 4))
print("大模型 p:", p)
print("最大偏差  :", np.abs(emp - p).max())
# 预期输出: 经验分布与 p 的最大偏差 < 0.01（随 N 增大趋近 0）,
# 证明拒绝采样修正使输出严格服从大模型分布 —— 这就是"无损加速"的数学保证。
```

### 示例 5（代码）：最小可运行的 RAG（TF-IDF 检索 + 模板拼接）

```python
# 需要: pip install numpy（向量库与嵌入模型在第 99 章项目三中用真实组件替换）
# 教学版 RAG: 展示 分块 -> 检索 -> 拼提示 的骨架。检索用 TF-IDF 余弦代替嵌入模型。
import numpy as np
import re
from collections import Counter

docs = [
    "本店商品自签收之日起 7 日内可无理由退货，需保持商品完好。",
    "会员积分有效期为 12 个月，过期自动清零。",
    "发票可在订单完成 30 天内申请开具，逾期不予受理。",
]

def tokenize_zh(s):                       # 极简中文分词: 2-gram, 仅为演示
    s = re.sub(r"\s", "", s)
    return [s[i:i+2] for i in range(len(s) - 1)] if len(s) > 1 else [s]

corpus = [tokenize_zh(d) for d in docs]
vocab = sorted({w for doc in corpus for w in doc})
idf = np.array([np.log(len(docs) / sum(w in doc for doc in corpus) + 1e-9)
                for w in vocab]) + 1e-9

def tfidf(text):
    c = Counter(tokenize_zh(text))
    v = np.array([c.get(w, 0) for w in vocab], float)
    return (v * idf) / (np.linalg.norm(v * idf) + 1e-9)

def retrieve(query, k=1):
    qv = tfidf(query)
    sims = np.array([qv @ tfidf(d) for d in docs])
    top = sims.argsort()[::-1][:k]
    return [(docs[i], float(sims[i])) for i in top]

query = "买了 5 天想退货可以吗？"
chunks = retrieve(query, k=1)
prompt = ("请仅依据以下资料回答，资料中没有的信息请回答“资料未提及”:\n"
          f"资料: {chunks[0][0]}\n问题: {query}\n答:")
print(prompt)
# 预期输出: 资料命中"7 日内可无理由退货"那条，问题被正确回应。
# 失败模式演示: retrieve("积分过期会怎样") 会命中积分条目 —— 换成与退货无关的
# 查询如"退货运费谁出"时，仍会硬命中某条目，这正是 7.6.2 所说"相关但无用"的检索陷阱。
```

## 7.11 常见误区与陷阱

1. **把 temperature 当"创造力旋钮"神化**：它只是指数倾斜；$\tau$ 过高输出退化为高频词噪音。改分布形状之外，多样性更多取决于 top-p 与提示。
2. **忘记 KV 缓存显存与 batch 成正比**：服务容量规划只看权重大小是新手事故的头号来源；先算 $M_{\text{KV}}$ 再定并发。
3. **把 INT4 量化当免费午餐**：量化后应跑一遍回归评测集；激活离群严重的模型（尤其某些多语言模型）INT4 掉点明显，需 AWQ 或更高位宽。
4. **RAG 检索质量不做独立评测**：端到端"感觉变好"掩盖检索召回问题；应先单独测 Recall@k / MRR，再谈生成。
5. **用"多次重试"掩盖幻觉**：自一致性投票降低方差但不消除系统性错误；高 stakes 场景必须有外部校验（引用、规则、检索证据）。
6. **推测解码随便选草稿模型**：一致率 $\alpha$ 低时反而更慢；选与目标模型同源/蒸馏的小模型，并动态调 $\gamma$。
