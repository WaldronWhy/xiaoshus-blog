# 第 5 章 预训练语言模型：BERT 与 GPT

> **本章定位**：本章是全书的"分水岭"——在此之前的 NLP 是"一个任务一个模型"，从此以后是"一个基座适配一切任务"。前置要求：[《深度学习·第 5 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/05/)（自注意力、多头、位置编码的完整推导）、[《深度学习·第 7 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/07/)（自监督目标、LoRA）、本课程[第 2 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/02/)（词向量的静态局限）、[第 4 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/04/)（语言模型与解码）。本章的 BERT/GPT 两大基座是第 6 章（指令微调与 RLHF）、第 7 章（LLM 工程与 Agent）以及 99 章综合项目的直接对象。

## 5.0 本章学习目标

- 能够说出自回归语言建模与掩码语言建模两种目标函数在数学形式、信息流方向和适用场景上的本质差异。

## 5.1 预训练范式的统一视角：目标函数决定世界观

### 5.1.1 从"表示学习"说起

在[第 2 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/02/)你已经看到：Word2Vec 用"预测邻居词"这个自监督任务学到了静态词向量，但它对同一个词只给一个向量，无法处理多义（"苹果"是水果还是公司取决于上下文）。在[《深度学习·第 7 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/07/)你已经学过自监督学习的一般框架：**构造代理任务 → 在无标注数据上训练 → 迁移表示**。预训练语言模型（pre-trained language model, PLM）就是把这套框架套在 Transformer 上：Transformer 的自注意力天然能融合双向上下文，于是"上下文相关的动态表示"成为可能。

一切差异都始于一个选择：**预训练目标函数**。

### 5.1.2 两种目标函数

给定词序列 $w_{1:n}$，所有 PLM 都是某个 Transformer 参数 $\theta$ 加上一个训练目标：

**（A）自回归语言建模（autoregressive LM）**——GPT 家族：

$$
\mathcal{L}_{\text{AR}}(\theta) = -\sum_{t=1}^{n} \log p_\theta\!\left(w_t \mid w_{1:t-1}\right).
$$

这是[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)n-gram 语言模型的神经网络升级版：链式法则不变，只是条件分布从查表变成了深层网络。

**（B）掩码语言建模（masked LM, MLM）**——BERT 家族：随机选约 15% 的位置集合 $M$，只预测这些位置：

$$
\mathcal{L}_{\text{MLM}}(\theta) = -\sum_{t \in M} \log p_\theta\!\left(w_t \mid \tilde{w}\right),
$$

其中 $\tilde{w}$ 是把 $M$ 中位置替换为 `[MASK]`（80%）、随机词（10%）、保持原词（10%）后的损坏序列。

两者蕴含的世界观截然不同：

| 维度 | 自回归（GPT） | 掩码（BERT） |
|---|---|---|
| 信息流 | 单向（左到右） | 双向 |
| 每个样本的训练信号 | $n$ 个位置 | $\approx 0.15n$ 个位置 |
| 天然适配任务 | 生成（翻译、摘要、对话） | 理解（分类、抽取、检索） |
| 能否直接做条件生成 $p(y\mid x)$ | 能（把 $x$ 拼进前缀） | 不能（需额外解码器或改目标） |
| 后续演化 | GPT-2 → GPT-3 → ChatGPT 一条路走到通用 | 主要作为编码器用于表示与检索 |

**一个关键洞察**：自回归目标在数学上更强——它训练的模型本身就是完整语言模型 $p_\theta(w_{1:n})$，因此可以无差别地做生成、条件生成（把指令放进前缀）乃至few-shot 学习；MLM 训练出的只是"双向编码器 + 输出头"，不是概率模型。这就是为什么大模型时代最终由自回归路线主导，而 BERT 路线收缩到表示/检索等理解型场景。

## 5.2 子词分词：BPE 与 WordPiece 从零实现

### 5.2.1 为什么需要子词

[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)我们纠结过"分到什么粒度"：字符级词表小但序列长、语义弱；词级语义强但词表爆炸且遇到未登录词（out-of-vocabulary, OOV）。**子词（subword）**是折中：高频词保持完整，低频词拆成有意义的片段（如 `unbelievable → un + believ + able`），理论上任何字符串都能被编码（退路是字符）。

### 5.2.2 BPE：字节对编码

字节对编码（byte-pair encoding, BPE）源于 1994 年的数据压缩算法，被 Sennrich 等人（2016）引入 NMT，GPT-2 之后成为主流。训练过程：

1. 把语料切成最小单位（GPT-2 用**字节**，即 256 个初始符号；教学版可先用字符），并统计每个**词**（按空白切分）的频次；
2. 统计所有相邻符号对的出现频次（按词频加权）；
3. 把频次最高的对 $(a,b)$ 合并成新符号 $ab$，记录这条合并规则；
4. 重复 2–3，直到词表达到预设大小 $V$。

编码一个新词：按训练顺序**重放**合并规则；解码：把子词拼接即可（字节级 BPE 保证无损可逆）。

### 5.2.3 WordPiece 与 Unigram

BERT 用的 **WordPiece** 与 BPE 几乎同构，唯一区别是合并准则：BPE 选**频次**最大的对，WordPiece 选使互信息增益最大的对，即

$$
(a,b)^\star = \arg\max_{(a,b)} \frac{P(ab)}{P(a)\,P(b)},
$$

偏爱"组合后出现得比独立组合更频繁"的对。Google 的 **SentencePiece Unigram** 则反过来：先放一个过大的候选子词集，用 EM 迭代删掉对语料似然损害最小的子词（概率化分词，可输出多个分词方案）。工程上 `transformers` 对 `BertTokenizer`（WordPiece）、`GPT2Tokenizer`（字节 BPE）、`LlamaTokenizer`（BPE+SentencePiece）都有实现。

### 5.2.4 特殊符号与工程细节

- BERT 在输入前加 `[CLS]`、句间加 `[SEP]`；GPT-2/LLaMA 用文档分隔符与对话模板（第 6 章会展开模板）。
- **注意**：不同模型的分词不通用——"token 数"因此取决于分词器；英文一个 token 平均约 0.75 个词，中文通常一字一 token 或一 token 多字（取决于训练语料配比，这也是早期中文 token 效率低的来源）。

## 5.3 BERT：双向编码器

### 5.3.1 结构与输入

BERT（Devlin et al., 2019）就是[《深度学习·第 5 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/05/)的 Transformer 编码器（去掉因果掩码）直接堆叠：BERT-base 12 层、$d=768$、12 头、110M 参数；BERT-large 24 层、$d=1024$、340M。输入是三部分相加：

$$
h_i^{(0)} = \text{TokenEmb}(w_i) + \text{SegEmb}(s_i) + \text{PosEmb}(i).
$$

注意 BERT 用**可学习的绝对位置嵌入**（不是正弦编码），最大长度 512。

### 5.3.2 MLM 的严格形式

设 $M$ 为被选中预测的位置集合，模型在每个位置输出词表上的分布。MLM 损失即交叉熵：

$$
\mathcal{L}_{\text{MLM}}(\theta) = -\mathbb{E}_{w \sim \mathcal{D}}\left[\sum_{t \in M} \log \frac{\exp\!\left(e_{w_t}^\top h_t^{(L)}\right)}{\sum_{v \in V} \exp\!\left(e_v^\top h_t^{(L)}\right)}\right],
$$

其中 $e_v$ 是输出投影（与输入嵌入共享权重的做法很常见）。80/10/10 的替换策略是为了缓解预训练与微调的不匹配：`[MASK]` 在下游任务中不出现，若全用 `[MASK]`，模型会学成"只在看到特殊符号时才认真预测"。

### 5.3.3 NSP 与它的下台

原版 BERT 还加了**下一句预测**（next sentence prediction, NSP）：二分类判断句对 $B$ 是否真是 $A$ 的下文。后续研究（RoBERTa 的消融）发现 NSP 任务太简单（靠话题词即可判对），去掉后下游反而更好；ALBERT 等用更难的**句序预测**（SOP）替代。教训值得记住：**预训练任务的难度必须与目标能力匹配，太容易的任务是噪声**。

## 5.4 GPT：自回归解码器

### 5.4.1 因果掩码的数学意义

在[《深度学习·第 5 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/05/)你见过缩放点积注意力。GPT 在每个注意力层给分数矩阵加一个上三角掩码 $-10^9$（近似 $-\infty$）：

$$
A_{ij} = \frac{\exp\!\left(q_i^\top k_j/\sqrt{d_k} + M_{ij}\right)}{\sum_{j'} \exp\!\left(q_i^\top k_{j'}/\sqrt{d_k} + M_{ij'}\right)}, \qquad
M_{ij} = \begin{cases} 0, & j \le i, \\ -\infty, & j > i. \end{cases}
$$

它带来两个严格的数学性质：

1. **每个位置的输出是前缀的函数**：$h_t = f_\theta(w_{1:t})$，于是 $\text{softmax}(e^\top h_t)$ 严格等于条件分布 $p_\theta(w_{t+1}\mid w_{1:t})$，自回归分解在架构层面被精确实现（这不是近似，是恒等）；
2. **训练可并行**：虽然语义是逐步生成，但 $n$ 个位置的条件分布可以用一次前向（矩阵形式）同时算出——这正是它与 RNN 的本质区别（回忆[《深度学习·第 4 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/04/)中 RNN 必须串行）。

GPT 损失就是 5.1.2 的 $\mathcal{L}_{\text{AR}}$。GPT-1（2018）证明"生成式预训练 + 判别式微调"可行；GPT-2（2019）把零样本多任务作为可能提出；GPT-3（2020）把参数推到 175B，发现了**上下文学习**（见 5.6）。

### 5.4.2 缩放定律一句话

Kaplan 等（2020）发现：在足够大的数据下，测试损失随参数量 $N$、数据量 $D$、算力 $C$ 呈平滑幂律，例如 $L(N) \approx (N_c/N)^{\alpha_N}$。这为"大力出奇迹"提供了定量依据，也解释了为什么自回归路线值得无限加码（Chinchilla 修正后来指出数据与参数应等比扩张）。细节在[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)的拟合与外推主题中还会回到。

## 5.5 微调下游任务的三种方式

在[《深度学习·第 7 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/07/)你已掌握冻结/微调/LoRA 的通用配方。NLP 里按任务形态有三种标准接法：

**方式一：[CLS] / 特殊 token 池化做分类。** 取 BERT 顶层 `[CLS]` 位置的向量 $h_{[\text{CLS}]}^{(L)}$（或全序列平均池化），接一个线性分类头：

$$
p(y \mid x) = \text{softmax}\!\left(W\, h_{[\text{CLS}]}^{(L)} + b\right), \qquad \mathcal{L} = -\log p(y \mid x).
$$

适合单句/句对分类（情感、NLI、检索重排）。预训练-微调不一致的老问题：`[CLS]` 在预训练中只参与 NSP（或什么都不做），微调初期它的表示并不"知道自己要被池化"。

**方式二：每个 token 一个分类头做序列标注。** 对 NER/词性标注（[第 3 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/03/)），在第 $t$ 个 token 的顶层表示上接 $\text{softmax}(W h_t + b)$，逐位置交叉熵；也可以接[第 3 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/03/)的线性链 CRF 层以显式建模标签转移约束（如 `I-PER` 不能跟在 `B-LOC` 后）。这体现了本课程的一条主线：经典结构（HMM/CRF）没有消失，而是成为神经栈的一个模块。

**方式三：转成生成任务。** 对 GPT 类模型，把输出也变成文本序列："情感分类：这条评论是正面的还是负面的？答：正面"。训练即对答案 token 做交叉熵（通常对输入部分做 loss mask，只算答案部分）。它统一了所有任务的形式，是第 6 章指令微调的直接前身。

三种方式的选型逻辑：标注量小且是理解任务 → 方式一/二；任务输出是文本或希望一个模型包打天下 → 方式三；参数预算紧张 → 在任一方式上叠加 LoRA。

## 5.6 上下文学习与提示工程基础

### 5.6.1 zero-shot 与 few-shot

GPT-3（Brown et al., 2020）的惊人发现：足够大的自回归模型**不改一个参数**，仅靠在输入前缀里给示例就能执行新任务：

- **zero-shot**：只给任务指令，"把这句话翻译成法语：……"；
- **one-shot / few-shot**：在指令后附 $k$ 个输入-输出示例，再给新输入。

数学上，few-shot 把模型用作条件分布 $p_\theta(y \mid \text{instruction}, (x_1,y_1),\dots,(x_k,y_k), x)$。它与微调的本质区别：**不更新 $\theta$，"学习"发生在前向传播内部**。机制目前仍有争论，主流假说包括：隐式梯度/贝叶斯推断视角（前缀相当于对任务做隐式后验更新）、诱导头（induction head）视角——双层注意力回路实现"复制前面出现过的模式"（Olsson et al., 2022）。

### 5.6.2 提示工程的工程原则

- **指令要具体、给输出格式约束**（"只输出 JSON，键为 …"），格式约束对可解析性影响巨大；
- **few-shot 示例的顺序、格式一致性、多样性都影响结果**（示例顺序造成的方差可以很大，这是真实的工程坑）；
- **思维链（chain-of-thought, Wei et al., 2022）**：提示"让我们一步步思考"或给带推理过程的示例，能显著提升算术/推理类任务表现——本质是给了模型更多的"中间 token 算力"；
- 提示是脆弱的：换措辞、换分隔符都可能翻车，严肃应用应把提示纳入版本管理与评测集（这个习惯将在[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)正式化）。

## 5.7 关键公式速查

| 公式 | 含义 | 适用条件 |
|---|---|---|
| $\mathcal{L}_{\text{AR}}=-\sum_t \log p_\theta(w_t\mid w_{1:t-1})$ | 自回归 LM 损失 | 因果掩码 Transformer；每位置都有监督 |
| $\mathcal{L}_{\text{MLM}}=-\sum_{t\in M}\log p_\theta(w_t\mid\tilde w)$ | 掩码 LM 损失 | 编码器；$M\approx 15\%$ 位置，80/10/10 替换 |
| $M_{ij}=0\ (j\le i),\ -\infty\ (j>i)$ | 因果掩码 | 加在每层注意力分数上；保证 $h_t$ 只依赖前缀 |
| $h_i^{(0)}=E(w_i)+E(s_i)+E(i)$ | BERT 输入嵌入 | 绝对可学习位置嵌入；最大 512 |
| $(a,b)^\star=\arg\max \frac{P(ab)}{P(a)P(b)}$ | WordPiece 合并准则 | 词表构建；BPE 用频次 $\arg\max N(ab)$ |
| $p(y\mid x)=\text{softmax}(Wh_{[\text{CLS}]}+b)$ | 分类微调 | BERT 类模型；句级任务 |
| few-shot: $p_\theta(y\mid \text{instr},(x_i,y_i)_{i\le k},x)$ | 上下文学习 | 自回归大模型；不更新参数 |

## 5.8 示例与案例

### 示例 1（手算）：BPE 的前三步合并

语料（词与频次）：`low`×5, `lower`×2，初始按字符切分（词尾用 `</w>` 标记以便区分词中/词尾片段）：`l o w </w>` ×5，`l o w e r </w>` ×2。

- 相邻对计数：`(l,o)`=7，`(o,w)`=7，`(w,</w>)`=5，`(w,e)`=2，`(e,r)`=2，`(r,</w>)`=2。
- 最大对并列，取先出现者 `(l,o)`：合并出 `lo`。语料变为 `lo w </w>` ×5，`lo w e r </w>` ×2。
- 下一轮：`(lo,w)`=7 最大，合并出 `low`。语料变为 `low </w>` ×5，`low e r </w>` ×2。
- 下一轮：`(low,</w>)`=5 最大，合并出 `low</w>`。至此 `low` 成为完整 token，而 `lower` 仍是 `low + e + r + </w>`——这正是 BPE"高频完整、低频拆分"的设计意图。

### 示例 2（代码）：从零实现 BPE（训练 + 编码 + 解码）

```python
# 从零实现 BPE：理解机制。无第三方依赖。
import re
from collections import Counter

def get_pair_stats(vocab):
    """vocab: {tuple(symbols): freq} -> 每个相邻对的加权频次"""
    stats = Counter()
    for word, freq in vocab.items():
        for i in range(len(word) - 1):
            stats[(word[i], word[i + 1])] += freq
    return stats

def merge_pair(pair, vocab):
    new_vocab = {}
    bigram = pair
    replacement = pair[0] + pair[1]
    for word, freq in vocab.items():
        new_word, i = [], 0
        while i < len(word):
            if i < len(word) - 1 and (word[i], word[i + 1]) == bigram:
                new_word.append(replacement); i += 2
            else:
                new_word.append(word[i]); i += 1
        new_vocab[tuple(new_word)] = freq
    return new_vocab

def train_bpe(corpus, num_merges):
    vocab = {}
    for word in corpus.split():
        # 词尾标记 </w> 作为一个独立符号，区分词中片段与完整词
        symbols = tuple(list(word) + ['</w>'])
        vocab[symbols] = vocab.get(symbols, 0) + 1
    merges = []
    for _ in range(num_merges):
        stats = get_pair_stats(vocab)
        if not stats:
            break
        best = max(stats, key=stats.get)
        vocab = merge_pair(best, vocab)
        merges.append(best)
    return merges

def bpe_encode(word, merges):
    symbols = list(word) + ['</w>']
    for pair in merges:                 # 严格按训练顺序重放合并规则
        i, out = 0, []
        while i < len(symbols):
            if i < len(symbols) - 1 and (symbols[i], symbols[i + 1]) == pair:
                out.append(symbols[i] + symbols[i + 1]); i += 2
            else:
                out.append(symbols[i]); i += 1
        symbols = out
    return symbols

corpus = "low low low low low lower lower"
merges = train_bpe(corpus, num_merges=3)
print(merges)
# 预期输出: [('l', 'o'), ('lo', 'w'), ('low', '</w>')]
print(bpe_encode("lower", merges))
# 预期输出: ['low', 'e', 'r', '</w>']   —— low 复用高频 token，er 被拆开
print(bpe_encode("low", merges))
# 预期输出: ['low</w>']
```

### 示例 4（代码）：因果掩码的数值验证

```python
# 验证因果掩码的数学意义：h_t 只依赖前缀。需要: pip install torch
import torch, torch.nn.functional as F
torch.manual_seed(0)

d, T = 4, 5
x = torch.randn(T, d)
Wq = torch.randn(d, d); Wk = torch.randn(d, d); Wv = torch.randn(d, d)

def forward(x, positions):
    """只在给定的前缀位置上做因果注意力，返回各位置输出"""
    q = x[positions] @ Wq
    k = x[: positions[-1] + 1] @ Wk
    v = x[: positions[-1] + 1] @ Wv
    scores = q @ k.T / d**0.5
    mask = torch.zeros_like(scores)
    for r, t in enumerate(positions):          # 位置 t 只能看到 j <= t
        mask[r, t + 1:] = float("-inf")
    return (F.softmax(scores + mask, dim=-1)) @ v

full = forward(x, list(range(T)))
trunc = forward(x[:3], [0, 1, 2])              # 只喂前 3 个 token
print(torch.allclose(full[:3], trunc, atol=1e-6))
# 预期输出: True
# 结论：截断前缀不改变前 3 个位置的输出 —— 这就是"第 t 个分布只依赖 w_{1:t}"的架构实现。
```

## 5.9 常见误区与陷阱

1. **"BERT 是语言模型"**：严格说 MLM 目标下 BERT 不是概率模型——$p_\theta(w_t\mid\tilde w)$ 的条件是损坏序列而非真实前缀，各位置预测不构成 $w_{1:n}$ 的联合分解。说"预训练语言模型"时要注意 BERT 属于泛化的"PLM"，而非自回归 LM。
2. **以为 MLM 的 15% 是独立采样后全替换为 `[MASK]`**：80/10/10 策略是刻意设计，忽略它会高估 BERT 对"原词保持"情形的建模。
3. **微调时学习率照搬预训练**：预训练用 $10^{-4}$ 量级，微调通常 $10^{-5}\sim 5\times10^{-5}$ + 线性预热；直接大学习率会灾难性遗忘。分层学习率（底层小、顶层大）也常见。
4. **把分词器的 token 数当"字数"**：计费、上下文窗口、截断都按 token 计；中文文本在不同分词器下 token 数可差数倍。
5. **few-shot 示例顺序随手排**：示例顺序与格式带来的方差常超过模型间差异；报告结果时应多序平均（呼应[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)的方差意识）。
