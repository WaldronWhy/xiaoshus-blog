# 综合项目：从困惑度对比到 LoRA 微调与 RAG 问答

> **本章定位**：本课程的毕业关卡——把[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)的语言模型、[第 4 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/04/)的生成与评价、[第 5 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/05/)的预训练/微调、[第 6 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/06/)的对齐与评估、[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)的 RAG/解码工程串成三个完整项目。前置要求：前三项目对应章节的全部正文与练习；工具依赖 torch / transformers /（可选）faiss-cpu、peft，均需 `pip install`。完成后，项目一、三的推理服务化可直接延伸为[《模型部署与 MLOps》](/xiaoshus-blog/textbooks/ai/engineering/mlops/00/)的期末载体，项目二的实验方法论延续到[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)。

## 项目总则：如何做综合项目

- **三个项目难度递进**：项目一（约 16–20 学时）训练"从零实现 + 系统评测"的基本功；项目二（约 16 学时）练习"在真实基座上做受控实验 + 错误分析"；项目三（约 20–24 学时）是完整系统工程。学有余力做全部三个，只做两个也请完成项目一 + 项目三。
- **报告模板**（每个项目通用）：任务与动机 → 数据与预处理 → 方法（含基线） → 实验设置（随机种子、解码参数、硬件） → 结果表 → 消融与分析 → 失败案例（至少 5 个，逐条归因） → 结论与局限。
- **复现性纪律**（预告[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)）：固定并记录 `torch.manual_seed`、解码参数（temperature/top-p，参照[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)）、依赖版本；所有评测集不参与任何训练决策。

## 项目一：从零训练字符级语言模型，并系统对比 n-gram / RNN / Transformer 的困惑度

### 1.1 任务与动机

在同一个语料上，从零实现三代语言模型并只用**困惑度（perplexity）与生成质量**说话——这是对本课程前半程（[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)的 n-gram 与平滑、[《深度学习·第 4 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/04/)的 RNN、[第 5 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/05/)的自回归 Transformer）的一次全面验收，也是理解"缩放与架构到底各贡献了什么"的第一手体感。

### 1.2 任务分解

1. **数据**：选一个中等规模字符级语料（如 Tiny Shakespeare，约 1 MB）或中文小说文本；切分 train/val/test（8:1:1，按文档切分避免重叠泄漏）。
2. **基线 n-gram**：实现 1-gram 到 5-gram，平滑用拉普拉斯、回退（Kneser–Ney 可作选做，参照[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)1.4）；计算 test 困惑度（log 空间计算，注意[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)的推导）。
3. **RNN/LSTM 基线**：1–2 层 LSTM，嵌入维 128–256，hidden 256–512；按[《深度学习·第 4 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/04/)的 BPTT 与梯度裁剪实现，可手写可调用 `nn.LSTM`（两者各做一次更佳）。
4. **Transformer 基线**：参考[《深度学习·第 5 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/05/)从零实现 4–6 层因果 Transformer（$d=256$，8 头，RoPE 或可学习位置编码），配 KV 缓存的增量解码（[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)）。
5. **统一评测**：三个模型在同一 test 集上报告 bits/char 与困惑度；用相同解码参数（temperature ∈ {0.5, 1.0}）各生成 5 段 200 字符文本。
6. **规模消融**（选做加分）：Transformer 的层数 ×2、参数 ×4 时的困惑度曲线，对照[第 5 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/05/)缩放定律的形状。

### 1.3 验收标准

- [ ] 三类模型全部从零实现（n-gram 纯 Python；RNN/Transformer 可用 `torch` 但不得用 `nn.TransformerEncoder` 整体黑盒）；
- [ ] 报告含困惑度表：n-gram（各阶）+ LSTM + Transformer，且相对大小符合预期（示例量级：Tiny Shakespeare 上 3-gram 带平滑约 3–5 bits/char，LSTM 约 1.5–1.7，Transformer 约 1.3–1.5；你的具体数字允许偏移，但排序不应颠倒）；
- [ ] 生成样本附主观质量注记 + 一次"重复/跑题"失败案例的定量描述（如 3-gram 序列中最长重复片段长度）；
- [ ] 困惑度计算通过单元测试：对"模型完美预测每个字符（p=1）"的构造样本给出困惑度 1；对均匀分布 $|V|$ 上长度 $n$ 的序列给出困惑度 $|V|$。

### 1.4 提示与常见坑

- 困惑度务必在 log 空间累加再指数化，防止下溢（[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)示例 3 的做法直接复用）；
- RNN 训练不裁剪梯度会炸（观察梯度范数并记录）；
- Transformer 的学习率预热（warmup）缺了会不收敛——这是复现经典 Transformer 最常见失败；
- 中文语料注意[第 1 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/01/)的 Unicode 规范化（全半角、繁简一致性）。

## 项目二：用 LoRA 微调开源小模型完成指令跟随，并做系统性错误分析

### 2.1 任务与动机

拿一个 0.5B–3B 的开源小模型（如 Qwen2.5-0.5B-Instruct 或 TinyLlama-1.1B），用 LoRA（[《深度学习·第 7 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/07/)）在自建指令数据上做 SFT（[第 6 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/06/)），然后回答一个研究式问题：**什么样的数据改动最能改善指令跟随？** 重点不在"调通"，而在受控对比与归因。

### 2.2 任务分解

1. **数据构建**：从公开指令集（如 Alpaca 格式数据）抽 2000 条为种子；自写 200 条针对 3 个目标能力的高质量数据（如：严格 JSON 输出、分步骤解题、拒答无依据问题）；构造测试集 100 条（不参与训练）。
2. **SFT 训练**：实现聊天模板渲染与 loss mask（[第 6 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/06/)示例 4）；LoRA r=8、alpha=16、只挂 attention 投影层；基线（未微调）与 2–3 个数据配方对比：
   - 配方 A：仅公开 2000 条；
   - 配方 B：A + 自写 200 条；
   - 配方 C：B 且对自写部分过采样 ×3。
3. **评测协议**：对测试集用固定解码参数（temperature=0，或 top-p=0.9 记录方差）；两种评测各做一次：(a) 规则自动评测（JSON 可解析率、步骤编号存在率、拒答触发正确率）；(b) 用强模型当裁判打 1–5 分（[第 6 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/06/)6.6 的 LLM-as-a-judge 协议，交换顺序去位置偏差）。
4. **错误分析**（本项目灵魂）：对失败案例逐条标注错误类型（格式违反 / 理解错误 / 事实错误 / 拒答误触发 / 遗漏约束），统计各配方下的类型分布，回答"数据配方改变了哪类错误、又引入了哪类错误"。
5. **（选做）DPO 续航**：用 (SFT 模型输出, 人工标记好坏对) 构造 200 对偏好数据，实现[第 6 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/06/)的 DPO 损失续训，对比规则评测指标变化。

### 2.3 验收标准

- [ ] 训练与推理的聊天模板完全一致（提供渲染样例对照）；
- [ ] 三个配方在同一测试集上的结果表 + 至少一项显著差异的判定（多随机种子 ×3，报告均值与极差）；
- [ ] 错误分析表：≥ 30 个失败案例、≥ 5 类错误标注、每类给 1 个典型样例与归因；
- [ ] 讨论题有答案：自写数据的质量提升能否被公开数据堆量替代？过采样是否引入了对其他能力的对齐税（用非目标能力的测试子集验证）？

### 2.4 提示与常见坑

- 显存不足时开启 4-bit 量化基座（QLoRA，参照[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)量化一节），并把 batch 减到 1 + 梯度累积；
- loss mask 忘记写是"模型学不会停止"的头号原因（输出永不终止或复述指令）；
- 裁判模型偏好长回答——报告裁判分数时同时报告平均回答长度，防止"变长≠变好"的假提升；
- 小模型指令跟随方差极大，单种子结论一律不作数。

## 项目三：搭建完整 RAG 问答系统（含检索评测与失败案例分析）

### 3.1 任务与动机

以[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)7.6 的架构为蓝图，端到端搭建"文档问答"系统，并把工程重心放在**检索的独立评测**与**失败模式归因**上——这两个习惯是把 RAG 从 demo 变成系统的分水岭，也是[《模型部署与 MLOps》](/xiaoshus-blog/textbooks/ai/engineering/mlops/00/)监控指标的雏形。

### 3.2 任务分解

1. **语料与索引**：选 20–50 份结构化文档（如公司制度、产品手册、课程讲义 PDF/Markdown）；清洗 → 分块（对比 256 / 512 token + 重叠 10% 两种切法）→ 嵌入（`sentence-transformers` 中文模型）→ FAISS 索引（`pip install faiss-cpu`）。
2. **检索评测先行**：人工构造 30–50 个（问题, 应命中文档块）对；报告 Recall@1/@3/@5 与 MRR（指标定义见[第 3 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/03/)3.4 的评测件与[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)）；对比：
   - 向量检索 vs BM25 关键词检索 vs 混合（分数归一化后加权）；
   - 原始查询 vs 查询改写（用小模型把口语问题改写为文档风格）。
3. **生成端**：检索 top-3 拼提示（格式含来源编号），强制"仅依据资料作答，否则回答'资料未提及'"；用 7B 级开源模型或 API 均可。
4. **端到端评测**：50 个测试问题的三元组评测：检索是否命中、答案是否正确、答案是否可溯源；对"检索命中但答错"的案例单独归因（这是 RAG 特有的错误层）。
5. **失败案例系统分析**：按[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)7.6.2 清单逐项检查——检索失败 / 分块切断语义 / 失去中间 / 上下文冲突 / 相关但无用 / 应拒答未拒答，每类至少 1 例并给出修复实验（如：对"分块切断"案例改用结构感知分块后复测）。
6. **（选做）Agent 化**：给系统加一个 `search(query)` 工具，用 ReAct 循环（[第 7 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/07/)7.7）替代一次性拼接，比较多跳问题的回答率。

### 3.3 验收标准

- [ ] 检索评测独立成节：分块与检索方式的 Recall/MRR 对比表（≥ 2×2 组合）；
- [ ] 端到端结果表：命中率 / 正确率 / 溯源率，且给出"检索失败"与"生成失败"的错误分解比例；
- [ ] 失败案例分析 ≥ 10 例，覆盖 ≥ 5 种失败模式，每例含修复实验或修复方案；
- [ ] 系统回答永不输出无出处的事实断言（抽查 10 例验证引用编号真实指向来源）；
- [ ] 报告结尾给出该系统的 3 个可监控指标定义（如检索命中率、拒答率、引用一致率），作为[《模型部署与 MLOps》](/xiaoshus-blog/textbooks/ai/engineering/mlops/00/)的接入接口。

### 3.4 提示与常见坑

- PDF 抽取是隐形大坑：表格与多栏会乱序，优先用 Markdown/PDF→文本工具后**人工抽检 5 页**；
- 嵌入模型与文档语言不匹配（用英文嵌入模型索引中文）是检索差的常见静默原因；
- 检索 top-1 分数与 top-3 分数差距很小（嵌入空间饱和）时，重排器（cross-encoder）收益最大；
- "拒答"分支要有专门测试问题（语料中没有答案的问题 ≥ 5 个），否则系统会学会硬编。

## 推荐参考资料（真实来源）

- Jurafsky & Martin, *Speech and Language Processing*（免费草稿，https://web.stanford.edu/~jurafsky/slp3/）—— n-gram、评测、预训练各章与本项目一一对应。
- Karpathy, *nanoGPT*（GitHub 开源仓库）与视频课 *Neural Networks: Zero to Hero* —— 项目一 Transformer 基线的参考实现粒度与本教材"从零实现"原则一致。
- Stanford CS224n 课程（主页公开讲义）—— 与三个项目对应的作业（语言模型、NMT、预训练）。
- Hu et al., *LoRA: Low-Rank Adaptation of Large Language Models*, ICLR 2022；Rafailov et al., *Direct Preference Optimization*, NeurIPS 2023 —— 项目二的微调与选做 DPO 的原始论文。
- Lewis et al., *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*, NeurIPS 2020；Karpukhin et al., *Dense Passage Retrieval*, EMNLP 2020 —— 项目三的检索原文与密度检索基线。
- Papineni et al., *BLEU*, ACL 2002（呼应[第 4 章](/xiaoshus-blog/textbooks/ai/ai-core/nlp/04/)）与 Zhang et al., *Benchmarking Large Language Models for News Summarization*（TAC-style 评测讨论）—— 文本评价的边界讨论。
