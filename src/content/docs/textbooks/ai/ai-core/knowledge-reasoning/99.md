# 综合项目：知识表示与推理

> **本章定位**：本课程的验收环节。三个项目分别对应课程的三大主线——**符号工程与表示学习**（项目一：第 2、3 章）、**概率化知识**（项目二：第 4 章）、**神经符号融合**（项目三：第 5 章）。做透任意一个，你就完成了一次"从数据到系统"的完整工程；有余力则串做两个。方法论要求（基线、消融、误差分析）参照[《实验设计与评估·第 1 章》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/01/)的精神执行。

## 项目一：小型领域知识图谱 + KGE 链接预测完整实验

### 任务描述

选定一个你熟悉的领域（推荐：电影、学术文献、电竞战队、本地美食），构建一个 300–1000 三元组规模的知识图谱，完成从数据到链接预测报告的全流程。

### 任务分解

1. **模式设计（第 2 章）**：定义 3–5 种实体类型、5–10 种关系，写明每种关系的定义域/值域约束（一份 20 行以内的模式文档）；
2. **数据采集**：从 Wikidata SPARQL 端点查询（推荐）或人工整理。实体数 ≥ 150、三元组 ≥ 300；为每个实体记录来源 URI；
3. **清洗与对齐**：字符串归一化 + 明显同名实体消歧；记录合并日志（合并了哪些、依据什么）；
4. **图结构分析**：连通分量、度分布、每种关系的头尾实体数——检查是否 1-N/N-1 关系占多数（影响 KGE 选型，见第 3 章 3.3 表）；
5. **KGE 实验**：按 80/10/10 划分训练/验证/测试三元组；用 PyKEEN（`pip install pykeen`）训练 TransE、ComplEx、RotatE 三模型（相同训练预算）；报告 MRR、Hit@1/3/10（过滤式协议）；
6. **案例分析**：挑 3 个测试三元组，展示模型排名前 5 的候选尾实体，人工判断错误候选"错得有无道理"（是否语义相近）。

### 验收标准

- [ ] 模式文档 + 三元组 CSV（含来源列）入库，字段可追溯；
- [ ] 度分布图与连通分量数报告，孤岛实体 ≤ 5%；
- [ ] 三模型指标表 + 训练曲线；测试集 Hit@10 至少有一个模型 > 0.3（300+ 三元组的稠密子图通常可达成；达不到请在报告中分析稀疏原因）；
- [ ] 3 个案例的三元组级误差分析（模型推荐了什么、为何错、KG 数据质量是否有责）。

### 提示

- 划分时按三元组随机划分即可，但要确认测试三元组的头尾实体都出现在训练集（否则是实体外推任务，难度量级不同，需单独声明）；
- 关系若严重偏斜（一种关系占 80%），做按关系分层的划分；
- RotatE 的 `negative_adversarial_sampling=True` 是默认可开的（第 3 章 3.3）；
- 陷阱预警：别把字面值（年份、票房）当实体嵌入（第 2 章误区 2）。

## 项目二：贝叶斯网络诊断系统与近似推断对比

### 任务描述

构建一个疾病诊断贝叶斯网络（自选症状/疾病集，或复刻经典"心脏病风险"网络结构），实现多种推断算法并系统对比。

### 任务分解

1. **建模（第 4 章 4.2）**：8–15 个节点（风险因素→疾病→症状三层较自然）；CPT 来源二选一并声明：专家手编（需做行归一化断言）或从合成数据学习；
2. **结构合理性论证**：画出网络，对 3 组 $(X, Y, Z)$ 做 d-分离判定（手画道德图 + 代码验证），确认没有"不合医学直觉的强关联"；
3. **精确推断基线**：用 `pgmpy`（`pip install pgmpy`）的变量消元，作为金标准；
4. **近似推断实现（第 4 章 4.3，从零手写）**：拒绝采样、似然加权、吉布斯采样（满条件分布只取马尔可夫毯——第 4 章 4.5 表）；
5. **系统对比**：5 组典型证据（含一组稀有证据 $P(e) < 10^{-3}$），每组算法报告：与金标准的绝对误差、同预算（10⁵ 次采样）下的标准误差、墙钟时间；
6. **UI 简化（可选加分）**：命令行交互——输入症状勾选，输出各疾病后验排序。

### 验收标准

- [ ] 网络 DAG 无环、CPT 全部行归一化（有断言代码）；
- [ ] d-分离手算与代码结论一致；
- [ ] 三种采样算法在常规证据上误差 < 0.02；稀有证据上拒绝采样的失效被定量展示（标准误差爆炸）；
- [ ] 一页讨论：三种算法各适合什么证据结构，与第 4 章正文的理论预期是否一致。

### 提示

- 吉布斯采样的 burn-in 与间隔采样别省略（[《概率统计·第 6 章》](/xiaoshus-blog/textbooks/ai/math-foundations/probability-statistics/06/)的自相关问题）；
- 罕见病的 CPT 极小概率会导致似然加权权重全押在极少数样本上——这本身就是报告素材；
- 陷阱预警：先检查 DAG 再写 CPT，"儿子指向父亲"式的因果颠倒不会报错但会毁掉 d-分离结论（第 4 章误区 1）。

## 项目三：KG-RAG 原型——知识图谱增强的小型问答系统

### 任务描述

在项目一的图谱（或第 2 章规模的自选图谱）上，构建一个"检索 + 约束生成 + 符号验证"的问答原型。为避免依赖在线 API，LLM 环节提供两条路线：接入任意可用接口，或用"模板生成 + 规则改写"模拟弱 LLM——评分看知识层设计，不看语言模型大小。

### 任务分解

1. **问题理解**：从自然语言问题中抽取实体与意图关系（规则模板起步；有条件则用 LLM 结构化输出，输出 JSON 约束）；
2. **检索层**：实体链接（别名表 + 第 3 章 KGE 最近邻兜底）→ 子图扩展（第 2 章多跳查询，限 2 跳）→ 若直接三元组缺失，用 KGE 链接预测给出候选并**明确标注"模型推测"**；
3. **生成层**：把检索到的三元组序列化为证据文本，模板生成答案；标注每句依据的三元组 ID；
4. **验证层（第 5 章 5.4）**：对答案中每个事实性声明做三元组存在性检查；"模型推测"类声明必须带置信度（KGE 打分，声明"非知识库事实"）；
5. **评测集**：手写 20 个问题，分三类——单跳可答（≥8）、多跳可答（≥6）、知识库无法回答（≥6）；报告按类的准确率与**拒答正确率**；
6. **误差分析**：对每道错题标注错误归因（实体链接错/检索漏/生成偏离证据/验证漏判）。

### 验收标准

- [ ] 端到端：问题字符串进，带依据标注的答案字符串出；
- [ ] 单跳问题准确率 ≥ 90%，多跳 ≥ 70%，"不可答"问题的拒答率 ≥ 60%（宁拒勿错是验收核心）；
- [ ] 每个答案可追溯：依据三元组 ID 列表 + 每个"推测"声明的 KGE 分数；
- [ ] 误差分析表覆盖全部错题，且归因类别与系统模块对应。

### 提示

- "拒答"是你的朋友：验证层拦截的答案宁可转成"知识库中没有可依据的事实"，也不要放行（第 5 章 5.6 的证成原则）；
- 多跳问题先做查询分解（"A 的球队所在城市" → 两跳），比让生成层硬扛容易得多；
- 陷阱预警：字符串匹配做实体链接会在别名上翻车（第 2 章误区 3）；验证层只查直接三元组会漏掉可由路径推出的正确答案（第 5 章练习 3）；
- 若接入真实 LLM，务必保留符号验证层——并设计 3 个"诱导幻觉"的测试问题展示其价值（第 5 章案例 1 的方法）。

## 三项目共通要求

1. **代码仓库结构**：`data/`（可追溯来源）、`src/`（模块化）、`notebooks/`（实验）、`report.md`（报告）；
2. **报告格式**：问题定义 → 方法（回指课程章节）→ 实验设置 → 结果表 → 误差分析 → 局限与未来工作，4000 字以内；
3. **可复现性**：固定随机种子、记录库版本（`pip freeze`）、给出一条可跑通全部实验的命令；
4. **基线意识**：每个"聪明"组件都要报告与朴素基线（随机/字符串匹配/先验分布）的差距——没有基线的结果无法评估（[《实验设计与评估》](/xiaoshus-blog/textbooks/ai/engineering/experiment-design/00/)）。
