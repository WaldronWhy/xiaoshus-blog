# 第 1 章 逻辑基础：命题与一阶逻辑

> **本章定位**：本课程与整部教材中一切"严格推理"的原点。你将在《数据结构与算法》里写过搜索、在《机器学习》里算过概率，但"从已知前提出发、每一步都可被机械地验证正确性"的推理，只有逻辑学能提供。本章建立的命题逻辑、SAT、合一与归结，将在第 5 章以"可验证推理"的身份回到大模型时代。

## 1.0 本章学习目标

完成本章后，你应当能够：

1. 用递归定义写出命题逻辑的语法，并对任意公式构造真值表、判断其可满足性（satisfiability）与有效性（validity）；
2. 手工把任意命题公式化为合取范式（CNF），并解释 DPLL 算法如何用"变量决策 + 单元传播 + 纯文字消除 + 回溯"把指数搜索剪到实用规模；

4. 手工完成一个 3–5 步的归结反演（resolution refutation）证明；
5. 用 Python 从零实现命题逻辑求值器与真值表生成器，并说清穷举法为何对真实问题不可行；
6. 陈述逻辑表示的三条根本局限（表达力边界、计算复杂性、非单调性缺失），并说明它们如何 motivate 后续章节。

## 1.1 为什么从逻辑开始

知识表示（knowledge representation）要回答：把"知道的东西"写成什么形式，机器才能在上面做推理（reasoning）？历史上第一个、也是最严格的答案是**逻辑**：

- **表示**：用形式语言写句子（公式），如"所有的人都会死"；
- **推理**：按保真的语法规则变换句子——只要前提为真，结论必为真。推理的正确性不依赖语义直觉，只依赖符号操作的合法性。

这带来一个连接主义系统至今难以完全提供的性质：**可验证性（verifiability）**。一条推理链要么正确要么错误，可以逐机械步骤审计。第 5 章我们会看到，思维链的"看起来对"与归结证明的"机械上对"之间隔着什么。

## 1.2 命题逻辑

### 1.2.1 语法：公式是递归结构

命题逻辑（propositional logic）的最小单位是**命题原子**（atomic proposition）——取值为真或假的陈述，记作 $P, Q, R, \dots$。公式（合式公式，well-formed formula, wff）递归定义如下：

1. 每个原子是公式；
2. 若 $\varphi$ 是公式，则 $\lnot\varphi$（非）是公式；
3. 若 $\varphi, \psi$ 是公式，则 $(\varphi \land \psi)$（与）、$(\varphi \lor \psi)$（或）、$(\varphi \rightarrow \psi)$（蕴含）、$(\varphi \leftrightarrow \psi)$（当且仅当）是公式；
4. 只有以上来源的符号串是公式。

递归定义直接对应程序里的递归数据结构——这正是 1.7 节代码用嵌套元组表示公式的原因。在[《Python程序设计·第 1 章》](/xiaoshus-blog/textbooks/ai/programming/python/01/)你已经见过"代数数据类型用元组模拟"的技巧，这里再次使用。

### 1.2.2 语义：真值表与五个联结词

公式的含义由**赋值**（assignment，又称模型 model，即从原子到 $\{\text{真}, \text{假}\}$ 的映射）确定，联结词语义如下表：

| $P$ | $Q$ | $\lnot P$ | $P \land Q$ | $P \lor Q$ | $P \rightarrow Q$ | $P \leftrightarrow Q$ |
|---|---|---|---|---|---|---|
| T | T | F | T | T | **T** | T |
| T | F | F | F | T | **F** | F |
| F | T | T | F | T | **T** | F |
| F | F | T | F | F | **T** | T |

最常引起初学者不适的是**实质蕴含**（material implication）：$P \rightarrow Q$ 仅在 $P$ 真 $Q$ 假时为假。它不是"因果"，而是"排除 $P$ 真且 $Q$ 假"这一承诺。

三个核心语义概念：

- **可满足（satisfiable）**：存在赋值使 $\varphi$ 为真；
- **有效/重言式（valid / tautology）**：所有赋值下 $\varphi$ 都为真，记 $\models \varphi$；
- **逻辑蕴含（entailment）**：$\Gamma \models \varphi$，指满足 $\Gamma$ 中全部公式的赋值都满足 $\varphi$。

**定理（蕴含与可满足的对偶）**：$\Gamma \models \varphi$ 当且仅当 $\Gamma \cup \{\lnot \varphi\}$ 不可满足。这条对偶性是一切"反证式自动定理证明"的种子——它把"证明"化归为"找矛盾"。

### 1.2.3 重要的重言式与等价

推理规则 building blocks（均可用真值表机械验证）：

$$
\text{假言推理（Modus Ponens）：} \quad (P \rightarrow Q) \land P \models Q
$$
$$
\text{假言三段论：} \quad (P \rightarrow Q) \land (Q \rightarrow R) \models P \rightarrow R
$$
$$
\text{德摩根（De Morgan）：} \quad \lnot(P \land Q) \equiv \lnot P \lor \lnot Q, \qquad \lnot(P \lor Q) \equiv \lnot P \land \lnot Q
$$
$$
\text{蕴含展开：} \quad P \rightarrow Q \equiv \lnot P \lor Q
$$

## 1.3 范式与 SAT：DPLL 思想

### 1.3.1 合取范式

**文字（literal）**是原子或其否定；**子句（clause）**是文字的析取；**合取范式（conjunctive normal form, CNF）**是子句的合取。例如 $(\lnot P \lor Q) \land (\lnot Q \lor R)$。任何命题公式都有逻辑等价的 CNF（算法：消 $\leftrightarrow$、消 $\rightarrow$、德摩根内移、分配律 $\varphi \lor (\psi \land \chi) \Rightarrow (\varphi \lor \psi) \land (\varphi \lor \chi)$；Tseitin 变换可在**线性**时间内得到可满足性等价而非逻辑等价的 CNF）。

**SAT 问题**：给定 CNF，问是否存在满足所有子句的赋值。它是历史上第一个被证明的 NP 完全问题（Cook–Levin 定理，1971）。NP 完全意味着最坏情形没有已知多项式算法——但绝不意味着实际问题解不动，这正是 DPLL 的意义。

### 1.3.2 DPLL：用结构剪指数

朴素 SAT 求解器枚举 $2^n$ 个赋值。DPLL（Davis–Putnam–Logemann–Loveland, 1962）在这个树上做三类系统性剪枝：

1. **单元传播（unit propagation）**：若某子句只剩一个未赋值文字（单元子句），该文字被迫为真，立即赋值并简化整个公式——这是约束传播，在[《数据结构与算法·第 6 章》](/xiaoshus-blog/textbooks/ai/programming/data-structures/06/)的意义上，它和数独求解器是同一类推理；
2. **纯文字消除（pure literal elimination）**：若某符号在所有子句中只以同一极性出现，直接给它使其子句全被满足的值；
3. **回溯（backtracking）**：某分支出现空子句（冲突）则整棵子树被剪掉。

现代 SAT 求解器（CDCL，conflict-driven clause learning）在 DPLL 上加入"冲突子句学习与非时序回溯"，使其能处理数十万变量的工业实例（芯片验证、软件包依赖求解）。**启示**：复杂类是关于最坏情形的陈述；好的启发式与问题结构可以让"理论上指数"的问题在实践中线性。这个模式在第 4 章（精确推断 vs 近似推断）会再次出现。

## 1.4 一阶谓词逻辑

命题逻辑把 "Socrates 是人" 记为原子 $P$，则推不出"苏格拉底会死"——原子内部结构被黑盒化。一阶逻辑（first-order logic, FOL）打开这个盒子。

### 1.4.1 项、谓词与量词

- **常量**：$socrates$；**变量**：$x$；**函数**：$motherOf(x)$——三者合成**项（term）**；
- **谓词**：$Human(x)$、$Mortal(x)$，作用在项上形成原子公式；
- **量词**：$\forall$（全称）、$\exists$（存在）。经典知识库：

$$
\forall x \, (Human(x) \rightarrow Mortal(x)), \qquad Human(socrates)
$$

由一阶逻辑推理规则可机械地导出 $Mortal(socrates)$。

量词与否定、蕴含的交互规则（务必记牢，第 5 章讨论 LLM 逻辑错误时会回来对照）：

$$
\lnot \forall x\, \varphi \equiv \exists x\, \lnot \varphi, \qquad \lnot \exists x\, \varphi \equiv \forall x\, \lnot \varphi
$$
$$
\forall x \,\varphi \equiv \forall x\, \varphi' \ \ (\text{若 } \varphi' \text{ 仅改名约束变量}), \qquad \exists x\,(P(x) \rightarrow Q) \equiv \forall x\, P(x) \rightarrow Q \ (\text{当 } x \text{ 在 } Q \text{ 中不自由})
$$

**自由变量与约束变量**的区分，对应程序语言中[《Python程序设计·第 1 章》](/xiaoshus-blog/textbooks/ai/programming/python/01/)讲过的词法作用域——约束变量是"局部变量"，自由变量是"引用外部名字"。

### 1.4.2 合一：让两个项同一是怎么算的

**合一（unification）**：寻找代入（substitution）$\theta$ 使 $t_1\theta = t_2\theta$。例如 $Knows(John, x)$ 与 $Knows(y, Jane)$ 合一得 $\theta = \{y/John,\ x/Jane\}$（记号 $v/t$ 表示"把 $v$ 替换成 $t$"）。

**算法**（Robinson 1965，递归）：

```
Unify(a, b, θ):
  a = aθ, b = bθ                     # 先应用已有代入
  若 a 与 b 相同：返回 θ
  若 a 是变量：返回 θ ∪ {a/b}（b 中不含 a，否则"发生检查"失败）
  若 b 是变量：对称处理
  若 a, b 是复合项 f(a1..an), g(b1..bn)：
      若 f ≠ g 或参数个数不同：失败
      依次对每对参数 (ai, bi) 调 Unify(ai, bi, θ)，累积代入
```

**最一般合一者（most general unifier, MGU）**：合一者不唯一（$\{x/John\}$ 与 $\{x/John,\ y/John\}$ 都行），MGU 是"约束最少"的那个——它保留最多的通用性，是归结推理正确性的关键。

### 1.4.3 归结原理与反演证明

**归结（resolution）**是一条单一而完备的推理规则（对子句形式）：由含互补文字的两条子句推出合并后的子句：

$$
\frac{A \lor P, \quad B \lor \lnot P}{A \lor B}
$$

直觉：$P$ 与 $\lnot P$ 必有一个为假， whichever 为假，其所在子句的真值就靠剩余文字支撑，故 $A \lor B$ 必真。一阶情形先对两子句做合一，再对合一后的互补文字消解。

**反演证明（refutation）**流程，用于证明 $KB \models \alpha$：

1. 把 $KB$ 全部子句化 + $\lnot\alpha$ 子句化（对 FOL：消蕴含 → 内移否定 → 变量标准化 → Skolem 化消存在量词 → 全称化 → 分配成子句）；
2. 反复归结：用合一在新子句间寻找互补对，生成新子句加入集合；
3. 若推出**空子句**（$\square$，即矛盾），则原 $KB \cup \{\lnot\alpha\}$ 不可满足，故 $KB \models \alpha$。

**手算示例**：证明"苏格拉底会死"。子句集：

$$
\text{(1) } \lnot Human(x) \lor Mortal(x), \qquad \text{(2) } Human(socrates), \qquad \text{(3) } \lnot Mortal(socrates) \ \text{（结论的否定）}
$$

- 归结 (1)(2)：合一 $\{x/socrates\}$，得 (4) $Mortal(socrates)$；
- 归结 (4)(3)：互补对 $Mortal(socrates)$ 与 $\lnot Mortal(socrates)$，得空子句 $\square$。∎

归结是**反证**而非构造：它告诉你命题为真，但（对非 Horn 子句）不直接给出"怎么用"这个事实。Horn 子句（至多一个正文字）上的 SLD 归结正是 Prolog 的执行模型——逻辑变成了一门编程语言。

## 1.5 逻辑作为知识表示：表达力与局限

| 维度 | 命题逻辑 | 一阶逻辑 |
|---|---|---|
| 可满足性判定 | NP 完全（SAT） | 半可判定（无算法保证停机；归结在一阶情形是半可判定的） |
| 表达力 | 命题间的真值约束 | 对象、关系、量化的全称/存在陈述 |
| 典型系统 | SAT/CDCL 求解器 | Prolog、定理证明器 |

逻辑表示的**四条根本局限**，它们正是后续各章的存在理由：

1. **脆弱性（无不确定性）**：经典逻辑只有真/假，没有"0.7 可信"。医疗诊断里"发烧通常但不必然意味着感染"无法直接书写——这引出第 4 章概率图模型；
2. **封闭世界假设难题**：知识库里没写的算不算"假"？开放世界（数据库未记录 ≠ 不存在）与封闭世界（未记录即假）的选择在不同领域各有利弊，经典逻辑本身无法编码"未知的未知"；
3. **知识获取瓶颈**：手写公式的代价高昂且易出矛盾——1980 年代专家系统的教训。第 2、3 章用"从文本自动抽取 + 从数据学习嵌入"回应它；
4. **无法与感知结合**：逻辑推理器不会看图、不会读自然语言。第 5 章神经符号方法的全部动机由此而来。

## 1.6 关键公式速查

| 公式/规则 | 内容 | 适用条件 |
|---|---|---|
| 实质蕴含 | $P \rightarrow Q \equiv \lnot P \lor Q$ | 经典（二值）逻辑 |
| 对偶定理 | $\Gamma \models \varphi \iff \Gamma \cup \{\lnot\varphi\}$ 不可满足 | 经典逻辑，$\Gamma$ 可数 |
| 德摩根 | $\lnot(P \land Q) \equiv \lnot P \lor \lnot Q$ | 命题与一阶均成立 |
| 量词否定 | $\lnot\forall x\,\varphi \equiv \exists x\,\lnot\varphi$ | 经典逻辑 |
| 归结规则 | $\dfrac{A \lor P,\ B \lor \lnot P}{A \lor B}$ | 子句形式；一阶时需先合一 |
| 合一存在性 | 有限项对的 MGU 存在且（在换名意义下）唯一 | 项中无循环（发生检查保证） |
| Cook–Levin | SAT 是 NP 完全的 | 命题逻辑可满足性 |
| Church–Turing（逻辑形式） | 一阶逻辑有效性不可判定；归结是半可判定的 | 一阶逻辑 |

## 1.7 示例与案例

### 案例 1（手算）：把公式化为 CNF 并归结

把 $(P \rightarrow Q) \rightarrow (\lnot Q \rightarrow \lnot P)$ 化为 CNF：

1. 消外层蕴含：$\lnot(\lnot P \lor Q) \lor (\lnot\lnot Q \lor \lnot P)$；
2. 德摩根与双否：$(P \land \lnot Q) \lor (Q \lor \lnot P)$；
3. 分配：$(P \lor Q \lor \lnot P) \land (\lnot Q \lor Q \lor \lnot P)$；
4. 化简：两子句各含互补对，恒真。最终 CNF 为空合取，公式是重言式（这正是逆否命题律 $(P \rightarrow Q) \equiv (\lnot Q \rightarrow \lnot P)$ 的另一种验证方式）。

### 案例 2（代码）：命题逻辑求值器与真值表生成器

从零实现（仅用标准库），体现"公式 = 递归数据结构，语义 = 递归求值"：

```python
# 运行环境：Python 3.8+，无第三方依赖
import itertools

# ---------- 语法：嵌套元组表示公式 ----------
# ('atom','P') | ('not', φ) | ('and',φ,ψ) | ('or',φ,ψ)
#           | ('implies',φ,ψ) | ('iff',φ,ψ)

def atoms(f):
    """收集公式中的全部原子（集合）。"""
    t = f[0]
    if t == 'atom': return {f[1]}
    if t == 'not':  return atoms(f[1])
    return atoms(f[1]) | atoms(f[2])

def evaluate(f, model):
    """在赋值 model（dict: 原子名 -> bool）下递归求公式真值。"""
    t = f[0]
    if t == 'atom':    return model[f[1]]
    if t == 'not':     return not evaluate(f[1], model)
    if t == 'and':     return evaluate(f[1], model) and evaluate(f[2], model)
    if t == 'or':      return evaluate(f[1], model) or evaluate(f[2], model)
    if t == 'implies': return (not evaluate(f[1], model)) or evaluate(f[2], model)
    if t == 'iff':     return evaluate(f[1], model) == evaluate(f[2], model)
    raise ValueError(f"未知联结词: {t}")

def truth_table(f):
    """生成全部赋值及对应真值；n 个原子 -> 2^n 行。"""
    vs = sorted(atoms(f))
    rows = []
    for bits in itertools.product([False, True], repeat=len(vs)):
        model = dict(zip(vs, bits))
        rows.append((model, evaluate(f, model)))
    return vs, rows

def is_valid(f):       return all(v for _, v in truth_table(f)[1])  # 重言式
def is_satisfiable(f): return any(v for _, v in truth_table(f)[1])

P, Q = ('atom', 'P'), ('atom', 'Q')
print("P→(Q→P) 是重言式吗？",
      is_valid(('implies', P, ('implies', Q, P))))
print("德摩根等价式是重言式吗？",
      is_valid(('iff', ('not', ('or', P, Q)),
                      ('and', ('not', P), ('not', Q)))))
print("(P→Q)↔(¬P∨Q) 是重言式吗？",
      is_valid(('iff', ('implies', P, Q), ('or', ('not', P), Q))))
print("P∧¬P 可满足吗？", is_satisfiable(('and', P, ('not', P))))

# 预期输出：
# P→(Q→P) 是重言式吗？ True
# 德摩根等价式是重言式吗？ True
# (P→Q)↔(¬P∨Q) 是重言式吗？ True
# P∧¬P 可满足吗？ False
```

### 案例 3（代码）：极简 DPLL

```python
# 承接上段：子句用"文字元组"表示，文字为 (符号名, 极性)。
# 例：((P∨Q), ¬P, R∨¬Q, S) 写作：
KB = [
    (('P', True),  ('Q', True)),   # P ∨ Q
    (('P', False),),               # ¬P
    (('R', True),  ('Q', False)),  # R ∨ ¬Q
    (('S', True),),                # S
]

def substitute(clauses, lit):
    """对文字 lit 赋真值后化简子句集；返回 None 表示冲突（空子句）。"""
    out = []
    for cl in clauses:
        if lit in cl:            # 子句被满足，删除
            continue
        neg = (lit[0], not lit[1])
        new = tuple(l for l in cl if l != neg)
        if not new:              # 空子句 -> 冲突
            return None
        out.append(new)
    return out

def dpll(clauses, assign=None):
    """返回满足子句集的一个赋值 dict，不可满足时返回 None。"""
    assign = assign or {}
    clauses = list(clauses)
    changed = True
    while changed:                      # 单元传播
        changed = False
        for cl in clauses:
            if len(cl) == 1:
                lit = cl[0]
                clauses = substitute(clauses, lit)
                if clauses is None: return None
                assign[lit[0]] = lit[1]
                changed = True
                break
    if not clauses:                     # 全部子句被满足
        return assign
    sym = clauses[0][0][0]              # 简单启发式：取第一个符号
    for val in (True, False):           # 决策 + 回溯
        res = dpll(substitute(clauses, (sym, val)), {**assign, sym: val})
        if res is not None:
            return res
    return None

print("DPLL 找到的模型:", dpll(KB))
print("矛盾子句集:", dpll([(('A', True),), (('A', False),)]))

# 预期输出：
# DPLL 找到的模型: {'P': False, 'Q': True, 'R': True, 'S': True}
# 矛盾子句集: None
```

注意 DPLL 输出的是一个**模型**而非全部模型，且具体值依赖于启发式——这与第 3 章 KGE 训练中"得到一个可行嵌入而非唯一嵌入"是同构的现象。

## 1.8 常见误区与陷阱

1. **把实质蕴含读成因果**。$P \rightarrow Q$ 为真不表示 $P$ 导致 $Q$，甚至不表示 $P$、$Q$ 之间有任何联系——"$2+2=5 \rightarrow$ 月亮是奶酪"是真命题。第 4 章的贝叶斯网络才是表达"导致"的工具。
2. **忽视量词辖域**。$\forall x \exists y\, Loves(x,y)$（每个人都有所爱）与 $\exists y \forall x\, Loves(x,y)$（有一个人被所有人爱）天差地别。混淆辖域是 LLM 在逻辑题上翻车的高频原因。
3. **合一忘做发生检查**。允许 $x$ 与 $f(x)$ 合一会构造出无限项，程序静默死循环。上面算法中"b 中不含 a"一行删掉后 bug 极难察觉。
4. **认为 NP 完全等于"不能用"**。CDCL 求解器每天在解决工业级 SAT 实例。复杂类是最坏情形陈述，不是工程判决书。
5. **归结证明写"正着推"**。反演证明的方向感是反的：你从"结论的否定"出发找矛盾。初学者常把待证结论当成新公理加入子句集——那证明的是 $KB \cup \{\alpha\}$ 一致，而非 $KB \models \alpha$。

## 1.12 课后思考与练习

**基础**

1. 用真值表验证：$(P \rightarrow Q) \land (Q \rightarrow R) \models P \rightarrow R$（假言三段论）。给出 8 行完整真值表。
2. 判断下列公式哪些可满足、哪些有效：(a) $(P \lor Q) \land \lnot P$；(b) $\lnot(P \rightarrow Q) \lor Q$；(c) $(P \rightarrow Q) \land P \land \lnot Q$。最终校验：(a) 可满足但非有效；(c) 不可满足。
3. 把 $\lnot(P \land (Q \rightarrow R))$ 化为 CNF，写出每一步的变换依据（最终结果校验：$(\lnot P \lor Q) \land (\lnot P \lor \lnot R)$，可用 1.7 的求值器验证等价性）。
4. 对 $Loves(x, y)$ 与 $Loves(y, x)$ 执行合一算法，逐步写出 $\theta$ 的演化。

**进阶**

5. 手工完成 1.4.3 节知识库下 "$\exists x\, Mortal(x)$" 的反演证明（提示：$\lnot\exists x\,Mortal(x)$ 化为 $\forall x\,\lnot Mortal(x)$，再 Skolem 化）。

7. 编程：给 1.7 的 DPLL 加入纯文字消除规则，并在随机生成的 3-SAT 实例（$n=10,20,30$，子句/变量比 4.3）上统计求解时间，观察"相变"现象附近耗时的陡增。

**开放与挑战**

8. 开放思考：封闭世界假设下，"数据库中无 $Fly(tweety)$" 蕴含 $\lnot Fly(tweety)$。这如何在经典逻辑中**不可**表达？它与你了解的 LLM "用训练分布代替事实核查"的行为有何结构相似性？
