## 5.1 符号与神经之争：一部六十年简史

| 时期 | 主导路线 | 标志事件 |
|---|---|---|
| 1956–1974 | 符号主义兴起 | 达特茅斯会议；Logic Theorist（1956）；LISP（1958） |
| 1974–1993 | 符号主义成熟与受挫 | 专家系统 XCON 盈利（1980s）；知识获取瓶颈显形；日本第五代计算机计划落空 |
| 1986–2012 | 连接主义复苏 | 反向传播（Rumelhart, Hinton, Williams, 1986）；深度学习三波浪潮起点 |
| 2012–2019 | 连接主义全面胜出 | AlexNet；Transformer（2017）；BERT/GPT |
| 2017 至今 | **神经符号回归** | AlphaGo（搜索+神经）；思维链（2022）；RAG（2020）；KG-LLM 混合系统成为工业标配 |

历史教训不是"谁打败了谁"，而是**两条路线的缺陷互补**：符号系统有推理无学习（知识获取瓶颈，第 1 章 1.5 节），神经系统有学习无保证（黑箱、幻觉，本章 5.6 节）。当前所有"混合系统"都在回答同一个问题：**让神经负责感知与泛化，让符号负责知识与验证**——分工的具体形式，就是本章的技术版图。

## 5.2 神经符号系统代表方法

神经符号（neuro-symbolic, NeSy）系统没有统一范式，但可按"接口方向"分三类：

1. **逻辑之上加神经**（逻辑是骨架）：符号推理器为主，神经模块填补感知缺口；
2. **神经之中嵌逻辑**（神经是骨架）：把逻辑约束/证明过程做成可微运算，梯度照常流动；
3. **双系统协作**（LLM+符号工具）：LLM 提议、符号系统验证，5.4 与 5.7 的 KG-RAG 与 Agent 属此类。

### 5.2.1 Neural Theorem Prover：软合一

Rocktäschel & Riedel（2017）把第 1 章的归结/后向链证明"软化"：硬合一要求 $Human(x)$ 与 $Human(socrates)$ 中 $x$ 精确绑定 $socrates$，而 NTP 用嵌入向量的相似度给出**软真值**

$$
\mathrm{match}(\mathbf{e}_1, \mathbf{e}_2) = \exp\big(-\lVert \mathbf{e}_1 - \mathbf{e}_2 \rVert\big)
$$

证明的置信度 = 沿途各步软匹配与软真值的乘积（模糊逻辑的 t-范数），从而**证明过程本身可微**——第 3 章的 KGE 打分提供嵌入，第 1 章的证明结构提供计算图，两章在此合流。

### 5.2.2 DeepProbLog：梯度流过证明搜索

Manhaeve 等（2018）在概率逻辑程序语言 ProbLog 中加入**神经谓词**：如 `digit(Img, N)::N` 的真值由 CNN 输出的 softmax 给出。查询 $P(q)$ 时，ProbLog 枚举所有证明并把概率累加：

$$
P(q) = \sum_{\text{证得 } q \text{ 的世界 } w} P(w)
$$

由于 $P(w)$ 依赖神经谓词的概率，这个和是神经参数的**可微函数**——用自动微分即可端到端训练"感知 + 逻辑"整体。经典演示：仅凭"两张手写数字之和为标签"的弱监督，同时学会识别数字（神经）与加法（符号）。这是"神经之中嵌逻辑"的样板。

### 5.2.3 其他代表（概念级了解）

- **语义损失（semantic loss）**：把逻辑公式作为约束加进神经网络损失，输出违反约束则受罚（Xu et al., 2018）；
- **逻辑张量网络（LTN）**：一阶逻辑的实数逻辑（real logic）版本，公理变成可微的张量运算；
- **工具调用型双系统**：LLM 生成符号查询（SQL/SPARQL/PDDL），由确定引擎执行——工业界事实上的主流。

## 5.3 大模型的知识存储机制：参数化知识 vs 外部知识

LLM 的"知识"以**参数化知识（parametric knowledge）**形式存在：训练语料中的事实在梯度下降中被压进数百亿权重，成为"下一词分布"中的统计偏好。用[《深度学习·第 7 章》](/xiaoshus-blog/textbooks/ai/ai-core/deep-learning/07/)的语言说：预训练做的是**知识压缩**，微调做的是**知识改写**。两种知识来源的工程对比：

| 维度 | 参数化知识 | 外部知识（KG/数据库/文档） |
|---|---|---|
| 写入成本 | 预训练/微调，昂贵且不可控 | 插入一条记录，即时 |
| 更新 | 改一条事实需重训练，且可能"牵连崩塌" | 直接更新，天然版本化 |
| 审计 | 无法逐条列出"它知道什么" | 每条事实有出处（provenance） |
| 规模上限 | 参数量（有限记忆容量） | 磁盘（TB 级无压力） |
| 推理 | 隐式、不可验证 | 可走第 1、2 章的机械推理 |
| 擅长 | 相似性、语言、常识泛化 | 精确事实、多跳、计数、时效 |

（"牵连崩塌"：模型编辑研究——如 ROME 方法（Meng et al., 2022）可以修改单条事实的存储位置，但后续研究发现编辑会损害无关知识——说明参数化知识是**纠缠分布**而非可寻址数据库。）

**结论（本章的操作原则）**：参数化知识管"怎么说话"，外部知识管"说了什么事实"。5.4 的 KG-RAG 是这条原则的最小实现。

## 5.4 知识图谱增强 LLM（KG-RAG）

### 5.4.1 从 RAG 到 KG-RAG

RAG（retrieval-augmented generation，Lewis et al., 2020）把"知识注入"变成推理时检索：用户问题 → 向量检索相关文档 → 拼入提示词 → 生成。KG-RAG 把检索对象从**文档片段**升级为**结构化子图**：

1. **意图/实体识别**：从问题中抽出实体与关系（[《自然语言处理·第 3 章》](/xiaoshus-blog/textbooks/ai/ai-core/nlp/03/)的 NER，或用 LLM 抽取）；
2. **子图检索**：以实体为种子在 KG 上扩展 $k$ 跳（第 2 章的多跳查询）或用 KGE 打分召回（第 3 章）；
3. **约束生成**：把序列化的三元组作为证据放进提示，要求模型**只依据证据作答**；
4. **符号验证（可选但关键）**：对生成文本中的每个事实性声明，检查其对应三元组是否在 KG（或可由路径推出）——不在则标记/拒答。

### 5.4.2 迷你 KG-RAG 原型

```python
# pip install networkx
import networkx as nx

kg = nx.MultiDiGraph()
for h, r, t in [
    ("姚明", "出生于", "上海"), ("姚明", "效力过", "休斯顿火箭"),
    ("休斯顿火箭", "位于", "休斯顿"), ("姚明", "身高", "2.26米"),
    ("上海", "属于", "中国"),
]:
    kg.add_edge(h, t, relation=r)

def retrieve(kg, question, max_hops=2, topk=6):
    """极简检索：问题中出现的实体作种子，BFS 扩路径作证据。
       真实系统：LLM 抽实体 + 向量检索 + 多跳扩展。"""
    seeds = [n for n in kg.nodes if n in question]
    evidence = []
    for s in seeds:
        paths, stack = [], [(s, [])]
        while stack and len(paths) < topk:
            node, path = stack.pop()
            if len(path) >= max_hops:
                continue
            for _, v, d in kg.out_edges(node, data=True):
                paths.append(path + [(node, d['relation'], v)])
                stack.append((v, path + [(node, d['relation'], v)]))
        evidence.extend(paths)
    return evidence

def generate(question, evidence):
    """约束生成：答案模板只允许引用证据内容（演示"接地"）。"""
    if not evidence:
        return "知识库中没有可依据的事实（拒答）。"
    best = evidence[0]
    return "根据知识库：" + " -> ".join(f"{h} --{r}--> {t}" for h, r, t in best)

def verify(claims, kg):
    """符号验证：每条声明必须在 KG 中存在对应三元组。"""
    out = []
    for h, r, t in claims:
        ok = kg.has_edge(h, t) and any(d['relation'] == r
                                       for _, _, d in kg.out_edges(h, data=True))
        out.append(((h, r, t), ok))
    return out

q = "姚明出生于哪里？"
ev = retrieve(kg, q)
print("检索证据:", ev[:2])
print("生成:", generate(q, ev))
print("验证:", verify([("姚明", "出生于", "上海"),
                       ("姚明", "出生于", "北京")], kg))   # 模拟 LLM 一对一错

# 预期输出：
# 检索证据: [[('姚明', '出生于', '上海')], [('姚明', '效力过', '休斯顿火箭')]]
# 生成: 根据知识库：姚明 --出生于--> 上海
# 验证: [(('姚明', '出生于', '上海'), True), (('姚明', '出生于', '北京'), False)]
```

三个函数分别修复 LLM 的三种病：检索治"知识过期/缺失"，约束生成治"自由发挥"，符号验证治"无法审计"。真实 KG-RAG 系统里，`generate` 换成 LLM（提示词要求逐句给出依据三元组），`verify` 换成第 1 章的实体消解 + 三元组匹配或表上推理——骨架不变。

## 5.5 思维链与推理形式化讨论

### 5.5.1 思维链在做什么

思维链（chain-of-thought, CoT；Wei et al., 2022）：在提示中加入"逐步推理"的示例，让模型在给出答案前先生成中间步骤，对大模型在数学/常识推理基准上带来显著提升。机制解释（当前共识的近似）：

- **工作记忆外化**：自回归模型每步生成的 token 会进入上下文、参与后续注意力——CoT 把"单次前向能算完的隐式计算"摊开成多步显式计算，等效于增加了串行计算深度；
- **分布聚焦**：中间步骤约束了后续 token 的条件分布，减少"一步登天"式的错误分支。

### 5.5.2 CoT 是推理吗——用本课程的标尺衡量

正方：CoT 是**过程**，与数学家的草稿纸同构；self-consistency（多路径投票）、思维树（Tree of Thoughts）进一步引入搜索，更像第 1 章 DPLL 的"决策+回溯"。

反方（本课程立场）：**CoT 的每一步都不承担证明责任**。归结反演中任何一步错了就推不出空子句；符号验证中每条声明可被机械否决。而 CoT 步骤错了，模型常能"将错就错"得出"正确"答案，或步步顺畅地得出错误答案——即推理文本与真实计算过程**不忠实（unfaithful）**。形式化地说：

- 严格演绎：$\Gamma \models \varphi$ 有可机械验证的证明对象（第 1 章）；
- CoT：一段高概率文本 $\pi$，使得 $P(\text{answer} \mid \pi)$ 大——**$\pi$ 与 answer 之间没有逻辑必然，只有统计相关**。

工程含义：CoT 适合"提高正确率"，不可单独承担"保证正确率"。需要保证时，让 CoT 生成**可执行/可验证的对象**——程序、SQL、SPARQL、证明步骤——交由确定引擎执行（5.2.3 的第三类双系统）。

## 5.6 幻觉的知识论分析

**定义**：幻觉（hallucination）= 模型生成与事实不符或与给定证据不符、却呈现为可信陈述的内容。二分法（Huang et al., 2023 综述的通行口径）：

- **事实性幻觉（factuality）**：与客观世界冲突（不存在的论文、错误年份）；
- **忠实性幻觉（faithfulness）**：与用户的输入/给定文档冲突（摘要里捏造原文没有的内容）。

**知识论视角**：经典知识定义是"得到证成的真信念（justified true belief）"。LLM 的参数化知识是**信念**（高概率输出）且多为**真**（训练分布内），但缺乏**证成（justification）**——没有可追溯的证据链，"为什么这是对的"在系统内没有答案。幻觉的本质：**在没有证成的位置上表现出了有证成的语言形态**。流利度与确证度解耦，是人类读者被骗的机制。

**本课程的缓解地图**（每章技术在幻觉治疗中的位置）：

| 缺陷 | 缓解技术 | 来自 |
|---|---|---|
| 事实错误、知识过期 | KG 检索注入（RAG） | 第 2 章 |
| 无法验证生成内容 | 符号验证、逻辑检查 | 第 1 章 |
| 缺少置信度语义 | 概率化知识、校准 | 第 4 章 |
| 相似实体混淆 | KGE 打分与消歧 | 第 3 章 |
| 多步推理失控 | 规划器 + 验证回路 | 5.7 |

**没有被任何技术完全治愈的部分**：外部知识库自身的不完整（第 2 章开放世界问题）与 LLM"何时该查库"的元判断。幻觉是知识表示的根本难题在生成模型上的再现，而非一个可以"修掉"的 bug。

## 5.7 Agent 与规划：PDDL 思想概览

**规划（planning）**问题：给定初始状态、目标状态与动作集，求动作序列。经典语言 PDDL（Planning Domain Definition Language，源自 STRIPS，1971）用逻辑原子描述一切：

- **状态**：原子命题的集合（闭世界：不在集合中即为假——呼应第 1 章练习 8）；
- **动作** $a$：前置条件 $\mathrm{pre}(a)$（必须为真的原子）、加效果 $\mathrm{add}(a)$、删效果 $\mathrm{del}(a)$；
- **转移**：$s \xrightarrow{a} (s \setminus \mathrm{del}(a)) \cup \mathrm{add}(a)$，当 $\mathrm{pre}(a) \subseteq s$。

与强化学习的分工（[《强化学习·第 1 章》](/xiaoshus-blog/textbooks/ai/ai-core/reinforcement-learning/01/)）：RL 处理**转移模型未知**、靠交互学习；经典规划处理**模型已知**（专家或 LLM 给出）——此时 BFS/A* 直接在状态图上找最优解，无需试错。LLM Agent 的现代架构（如 ReAct，2022）正是两者合流：LLM 负责把模糊任务翻译成符号动作与状态（"接地"），确定性规划器/环境负责执行与反馈，形成"提议—执行—观察—修正"循环。

```python
# ---------- STRIPS 风格前向搜索规划器（标准库即可运行） ----------
from collections import deque

def plan(actions, init, goal, max_depth=20):
    """BFS 前向搜索：状态为 frozenset(谓词)，返回最短动作序列。"""
    init, goal = frozenset(init), frozenset(goal)
    if goal <= init:
        return []
    seen, q = {init}, deque([(init, [])])
    while q:
        state, path = q.popleft()
        if len(path) >= max_depth:
            continue
        for name, pre, add, dele in actions:
            if pre <= state:                       # 前置条件全部满足
                nxt = frozenset((state - dele) | add)
                if nxt in seen:
                    continue
                if goal <= nxt:
                    return path + [name]
                seen.add(nxt)
                q.append((nxt, path + [name]))
    return None

# ---- 领域建模：快递机器人 ----
def move(a, b):
    return (f"move({a}->{b})", {("at", a)}, {("at", b)}, {("at", a)})
def pickup(p, loc):
    return (f"pickup({p}@{loc})", {("at", loc), ("pkg_at", p, loc)},
            {("in_bag", p)}, set())
def dropoff(p, loc):
    return (f"dropoff({p}@{loc})", {("at", loc), ("in_bag", p)},
            {("pkg_at", p, loc)}, {("in_bag", p)})

actions = [move("仓库", "客户"), move("客户", "仓库"), move("仓库", "站点"),
           move("站点", "客户"), pickup("包裹1", "仓库"),
           dropoff("包裹1", "客户"), dropoff("包裹1", "站点")]
init = {("at", "仓库"), ("pkg_at", "包裹1", "仓库")}
goal = {("pkg_at", "包裹1", "客户")}
print("计划:", plan(actions, init, goal))
print("不可达目标:", plan(actions, init, {("pkg_at", "包裹1", "月球")}))

# 预期输出：
# 计划: ['pickup(包裹1@仓库)', 'move(仓库->客户)', 'dropoff(包裹1@客户)']
# 不可达目标: None
```

BFS 的状态空间是谓词集合的幂集——指数的（对照第 1 章 SAT）。工业规划器（如 Fast Downward）用启发式搜索与删除 relaxation 压缩它；LLM Agent 场景下状态空间更常由 LLM 的"常识剪枝"隐式缩小。

## 5.8 关键公式速查

| 概念 | 内容 | 来自 |
|---|---|---|
| 软合一 | $\mathrm{match}(e_1,e_2)=\exp(-\lVert \mathbf{e}_1-\mathbf{e}_2\rVert)$，证明置信度 = 各步乘积 | NTP |
| 神经谓词 | 逻辑原子的真值由神经网络的输出（softmax）给出 | DeepProbLog |
| 参数化知识 | 事实以权重中的统计偏好存储；不可寻址、更新昂贵 | 5.3 |
| KG-RAG 四步 | 实体识别 → 子图检索 → 约束生成 → 符号验证 | 5.4 |
| CoT 机制 | 工作记忆外化 + 分布聚焦；无证明责任 | 5.5 |
| 幻觉二分 | 事实性（对世界）vs 忠实性（对输入） | 5.6 |
| 证成缺失 | 流利（信念形态）≠ 有据（justification） | 5.6 |
| STRIPS 动作 | $s \xrightarrow{a} (s \setminus \mathrm{del}) \cup \mathrm{add}$，需 $\mathrm{pre} \subseteq s$ | 5.7 |

## 5.9 示例与案例

### 案例 1（手算）：用符号验证审计一段思维链

问题："姚明效力过的球队所在的城市属于哪个省？"LLM 的 CoT 摘录："姚明效力于休斯顿火箭；休斯顿火箭位于休斯顿；休斯顿属于德克萨斯州；所以答案与德克萨斯州有关。"用 5.4.2 的 `verify`（把 KG 换成含中国知识的那份）逐条审计：

1. （姚明， 效力过， 休斯顿火箭）——KG 中存在，**通过**；
2. （休斯顿火箭， 位于， 休斯顿）——存在，**通过**；
3. （休斯顿， 属于， 德克萨斯州）——KG 无此三元组，**未通过**（本玩具 KG 只含中国知识）。

审计结论：该 CoT 有两步可证、一步不可证——不可证的那步恰是幻觉最可能藏身的位置。**符号验证不能证明陈述为真（KG 可能不全），但能精确标出"没有证据"的位置**——这是"可审计性"的准确含义。若第 3 步换成（上海， 属于， 中国），则可由 KG 直接证实。

### 案例 2（代码）：DeepProbLog 思想的最小可微示例

不引入 ProbLog 解释器，用 50 行模拟其核心：神经谓词 + 逻辑规则 + 梯度。规则：`grandparent(A,C) :- parent(A,B), parent(B,C)`，其中"parent"是神经谓词（由图像预测的亲子概率）：

```python
# pip install numpy
import numpy as np
rng = np.random.default_rng(0)

# 知识底座：符号事实 grandparent(y, c) 已知，反推神经谓词 parent
entities = ["a", "b", "c"]
parent_prob = rng.random(9)                     # 待学：P(parent(e_i, e_j))，参数化
target = {("a", "c"): 1.0}                      # 仅知：a 是 c 的祖辈
supervision = [("a", "c")]

def proof_prob(a, c):
    """P(grandparent(a,c)) = Σ_b P(parent(a,b))·P(parent(b,c)) —— 可微的证明和。"""
    s = 0.0
    for i, b in enumerate(entities):
        if b not in (a, c):
            s += parent_prob[entities.index(a) * 3 + i] * \
                 parent_prob[i * 3 + entities.index(c)]
    return s

for step in range(2001):
    loss = 0.0
    for (a, c) in supervision:                  # 逻辑损失：证明概率逼近标签
        p = proof_prob(a, c)
        loss += (p - target[(a, c)]) ** 2
    grad = np.zeros(9)
    for (a, c) in supervision:                  # 手写梯度（链式法则穿过证明和）
        ia, ic = entities.index(a), entities.index(c)
        for i, b in enumerate(entities):
            if b not in (a, c):
                g = 2 * (proof_prob(a, c) - target[(a, c)]) * \
                    parent_prob[i * 3 + ic]
                grad[ia * 3 + i] += g
                grad[i * 3 + ic] += 2 * (proof_prob(a, c) - target[(a, c)]) * \
                    parent_prob[ia * 3 + i]
    parent_prob -= 0.5 * grad
print("学到的 P(parent)：")
for i in range(3):
    for j in range(3):
        print(f"  parent({entities[i]},{entities[j]}) = {parent_prob[3*i+j]:.3f}")
# 预期输出（seed=0，节选）：
#   parent(a,b) = 1.000    parent(b,c) = 1.016    parent(a,c) = 0.041
# 即 a->b 与 b->c 的概率显著高于其余组合（未截断的"概率"可能略超 1，
# 见练习 7 的讨论）；梯度穿过 Σ_b parent(a,b)·parent(b,c) 的证明和，
# 这正是 DeepProbLog 的核心机制。
```

监督信号只有"祖辈"事实，模型却必须把 credit 分配到看不见的中间变量 $b$ 上——这与神经定理证明器/DeepProbLog 把梯度分配到证明各步是同一件事。运行后检查 `parent(a,b)` 与 `parent(b,c)` 应显著高于 `parent(a,c)`（直接假设 a 是 c 的父辈无法证明 grandparent… 等等——若 (a,c) 是祖辈，(a,b),(b,c) 是父辈链条；注意 (a,c) 直接父子关系概率不受约束，这正是符号约束的辨析点，见练习 7）。

## 5.10 常见误区与陷阱

1. **把 KG-RAG 当成"有 KG 就不会幻觉"**。检索注入只约束了证据内的陈述；模型仍可在证据外自由发挥。没有第 4 步符号验证的 KG-RAG，幻觉只会在"证据覆盖不到的问题"上复发。
2. **用 CoT 的流畅度评估推理正确性**。人类评审极易被流畅文本说服。评估 CoT 系统的正确性必须落到可执行对象（程序/查询/证明）或与真值比对，不能让模型自评。
3. **认为参数化知识可以"就地编辑"**。单条事实编辑（ROME 类方法）会损伤无关知识——把 LLM 当可寻址数据库用是范畴错误。
4. **规划域建模时忘记闭世界假设**。STRIPS 里"不在状态中 = 假"，与第 2 章知识图谱的开放世界语义相反；两者混用会造成"目标看似不可达"或"前置条件永远满足"的静默错误。
5. **神经符号 = 神经网络 + if-else 规则**。接口方式决定系统能力：软接口（NTP/DeepProbLog）可端到端训练，硬接口（工具调用）可验证但梯度断流。选型前先问"我要学习还是要保证"。
