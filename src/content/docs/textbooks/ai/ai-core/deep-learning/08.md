# 第 8 章 深度学习训练工程

> **本章定位**：把"能训练"变成"训练得起、训练得稳、可复现"。GPU 与显存预算、混合精度的数值分析、梯度累积与裁剪、分布式数据并行（DDP）、系统化的调试方法论、实验管理——这些是第 3–7 章所有实验在生产规模上的支撑技术，也是通往《模型部署与 MLOps》的桥梁。数值基础来自《线性代数》第 6 章。

学完本章，你能够：

3. 说明梯度累积如何等效大 batch，梯度裁剪防什么、怎么选阈值；

6. 估算一次训练的算力成本（FLOPs → GPU 时）。

## 8.1 GPU 与显存：训练的资源账本

### 8.1.1 为什么 GPU 快

神经网络的计算以**矩阵乘法**为主（第 1 章批量线性层、第 5 章注意力全是 GEMM）——高度并行、算术强度高。GPU 的设计（数千核心 + 高带宽显存 HBM）恰好匹配：现代数据中心卡（如 A100/H100 量级）提供 $10^{14}$–$10^{15}$ FLOPS（半精度含张量核心）与 1.5–3 TB/s 显存带宽。但**瓶颈经常在显存带宽而非算力**（算术强度 $=$ FLOPs/字节数，低于机器比值时受"墙"限制）——FlashAttention 的本质就是减少 HBM 往返（第 5 章进阶方向）。

### 8.1.2 显存预算（必须会心算）

以混合精度训练、Adam 优化器、参数量 $P$、激活字节数 $A$ 计（每参数字节数：fp16 参数 2B、fp32 主权重 4B、fp32 梯度 4B、Adam 的 $m, v$ 各 4B）：

| 项目 | 字节 | 说明 |
|---|---|---|
| fp16 权重 | $2P$ | 前向用 |
| fp32 主权重 | $4P$ | 精确更新用 |
| fp16 梯度 | $2P$ | 反传产生 |
| Adam 状态 $m, v$ | $8P$（fp32） | 优化器状态 |
| 激活 | $\approx$ 与 batch、深度成正比 | 反传需存中间量 |

合计固定开销 $\approx 16P$ 字节（fp16 + Adam）。**例**：GPT-2 中型（$P = 1.5 \times 10^9$）→ $16P = 24$ GB 权重相关，激活另计——这正是"单卡放不下、需要分布式"的定量来源。（若纯 fp32 + SGD + 动量：$4P + 4P + 4P = 12P$。）

**激活的账**：每层约需保存输入（反传时算局部梯度用），总激活 $\propto$ batch × 序列长 × 深度 × $d$。控制手段：梯度检查点（checkpointing，用重算换显存，时间 +30% 左右）、梯度累积（batch 拆小）、激活 offload。第 99 章项目将要求你实际测量这些数字。

### 8.1.3 算力账本：FLOPs、MFU 与训练时长估算

显存之外还有第二本账——**算力**。经验公式：Transformer 前向每 token 约 $2P$ FLOPs（每参数一次乘加），前向 + 反传合计约 **$6P$ FLOPs/token**（《最优化方法》挑战题 9 的雅可比分析给出理论注脚；GB300 级的纸面峰值到不了，见下）。一次预训练的算力：

$$\mathrm{FLOPs} \approx 6 \times P \times D \quad (D \text{ 为训练 token 数}), \qquad t = \frac{6PD}{N_{\mathrm{GPU}} \cdot \mathrm{FLOPS}_{\mathrm{peak}} \cdot \mathrm{MFU}}.$$

**MFU（模型算力利用率）** = 实际有效 FLOPS ÷ 硬件峰值，健康训练约 30–50%——其余消耗在通信、数据加载、小算子与访存受限算子。**例**：$P = 1.5\times10^9$、$D = 3\times10^{10}$（Chinchilla 最优配比约 20 token/参数），8 张 A100（峰值 312 TFLOPS/bf16、MFU 40%）：$\mathrm{FLOPs} = 2.7\times10^{20}$，8 卡有效 $10^{15}$ FLOPS → 约 75 小时。这套心算让你在下任何训练决定之前知道"要几天、几卡、多少钱"——第 8 章练习 10 会把这套账写成一个预测器并校验。

## 8.2 混合精度训练：数值分析视角

### 8.2.1 浮点格式（[《线性代数》第 6 章](/xiaoshus-blog/textbooks/ai/math-foundations/linear-algebra/06/)的浮点系统回顾）

IEEE 754 浮点 = 符号 + 指数 + 尾数。关键格式：

| 格式 | 位分配（符/指/尾） | 有效十进制位 | 动态范围 |
|---|---|---|---|
| fp32 | 1/8/23 | ~7 位 | $\pm 10^{38}$ |
| fp16 | 1/5/10 | ~3.3 位 | $\pm 65504$（易上溢！） |
| bf16 | 1/8/7 | ~2.4 位 | 与 fp32 同量级 $10^{38}$ |

**bf16 的哲学**：牺牲尾数换指数——精度低但**不溢出**；梯度噪声本身大于 bf16 尾数误差（SGD 是随机近似，《最优化方法》第 5 章），因此丢精度通常无害。现代训练（尤其大模型）默认 bf16；fp16 需要损失缩放（见下）。

### 8.2.2 混合精度的完整流程

纯 fp16 训练的两个数值事故：**下溢**（梯度 $< 6\times10^{-8}$ 归零，学习信号丢失）与**上溢**（激活/loss 无穷大）。混合精度（micikevicius et al., 2018）的对策是**分工 + 补偿**：

1. **fp32 主权重**：参数更新（$w \leftarrow w - \eta \Delta$，当 $\eta\|\Delta\| \ll \|w\|$ 时 fp16 会把增量"吃掉"——[《线性代数》第 6 章](/xiaoshus-blog/textbooks/ai/math-foundations/linear-algebra/06/)"大数吃小数"的现世报）在 fp32 副本上做；
2. **前向/反传用 fp16/bf16**：GEMM 用张量核心，速度翻倍、显存减半；
3. **损失缩放（fp16 only）**：反向开始前把 loss 乘 $S$（如 $2^{16}$），梯度整体放大 $S$ 倍以逃出下溢区；优化器更新前再除回。$S$ 动态调节：遇到 inf/nan 跳过该步并减半 $S$，连续安全则倍增；
4. **归一化与 softmax 等敏感算子内部用 fp32** 累计（PyTorch 自动处理）。

**数量级感受**：fp16 能表示的最小正规数 $\approx 6.1\times10^{-5}$，非正规数延到 $\approx 6\times10^{-8}$；而典型梯度分量 $10^{-7}$–$10^{-4}$——缩放不是锦上添花，是必需。

## 8.3 梯度累积与梯度裁剪

### 8.3.1 梯度累积：用时间换 batch

显存放不下大 batch 时：把 batch 拆成 $k$ 个微批（micro-batch），依次前向-反向、**梯度累加**（不 step），每 $k$ 步做一次优化器更新。数学上完全等效大 batch：

$$\nabla_{\mathrm{accum}} = \frac{1}{k}\sum_{i=1}^{k} \nabla_i \;=\; \nabla\Big(\frac{1}{k}\sum_i \ell_i\Big).$$

（实现要点：`loss = loss / k` 后 `backward()` 累加，或对梯度做平均——与《最优化方法》5.1 的 mini-batch 梯度定义一致。）注意 batch norm 的统计量在微批上算，累积不等于真大 batch 的 BN 行为（LayerNorm 无此问题）。

### 8.3.3 数据加载管线：被忽视的第一瓶颈

GPU 饥饿（starvation）是小规模实验最常见的时间浪费，且完全隐形——曲线照常下降，只是慢一倍。数据管线的健康标准：**GPU 前向等待时间 ≈ 0**。四个标准手段：

1. **多进程预取**：`DataLoader(num_workers=N)` 让 CPU 侧解码/增强与 GPU 计算流水线化（N ≈ CPU 核数，典型 4–16）；
2. **pin_memory + non_blocking**：页锁定内存使 Host→Device 拷贝走 DMA 异步通道，与计算重叠；
3. **预读与持久化**：`prefetch_factor`、`persistent_workers=True` 避免每个 epoch 重启 worker；
4. **在线增强的成本意识**：随机裁剪/翻转几乎免费，但高斯模糊、弹性形变可能成为瓶颈——必要时把重增强离线预计算存盘。

诊断方法（第 8.5 节调试阶梯的"性能分支"）：把一个 batch 的 `(数据加载 + to(device))` 与单步训练分别计时；若加载占比 > 20%，先修管线再谈优化模型。

### 8.3.2 梯度裁剪

第 4 章 RNN 已引入：$\mathbf{g} \leftarrow \mathbf{g} \cdot \min\big(1, \theta / \|\mathbf{g}\|_2\big)$（全局范数裁剪，Transformer 常用 $\theta = 1.0$）。三个要点：(i) 裁剪**只防爆炸**（保训练不 nan），对消失无作用；(ii) 裁剪改变优化轨迹（等效自适应信任域），小模型上通常无碍、原则上应记录被裁频率作为诊断信号（频繁触发 = 学习率过大或有 bug）；(iii) 与混合精度的缩放配合：先除回缩放系数再裁剪，否则阈值失真。

## 8.4 分布式训练：数据并行（DDP）

### 8.4.1 原理：同步数据并行的等价性

**数据并行（DDP）**：每张卡持有完整模型副本，各吃不同微批，反传后**对梯度做 all-reduce（求和再平均）**，所有卡得到相同的平均梯度后同步更新——数学上与小批合并后的梯度完全一致：

$$\bar{\mathbf{g}} = \frac{1}{N}\sum_{i=1}^{N} \nabla \ell_i = \nabla \Big(\frac{1}{N} \sum_i \ell_i\Big).$$

由此"同步 DDP ≈ 大 batch SGD"（配合第 2 章《最优化方法》的线性缩放法则：batch × $N$，学习率 × $N$，warmup 相应延长）。通信原语 all-reduce 用**环状算法**实现（ring all-reduce：每卡只与邻居通信两次，总通信量 $2(N-1)/N \times$ 梯度大小，与卡数近无关——PSC/NCCL 的核心）。

### 8.4.2 效率与扩展

- **计算/通信重叠**：梯度按层逆序就绪，就绪一层立即发起该层的 all-reduce，与其余层的反传重叠——DDP 默认行为；
- **扩展边界**：全局 batch 增大后学习率缩放失效（临界 batch size，《最优化方法》5.6.2）、通信占比上升——更大规模需要**模型并行/流水线并行/ZeRO 切分优化器状态**（把 $16P$ 字节的账本按卡切分）：这超出本章，属于大模型训练专题，但显存账本（8.1.2）是理解 ZeRO 的钥匙；
- **实现层级**：`torchrun --nproc_per_node=8` + `DistributedDataParallel` + `DistributedSampler`（每卡不重叠数据）。多机还要 `nccl` 后端与稳定的节点编排——工程复杂度主要在故障恢复与慢节点（straggler）。

## 8.5 调试神经网络：系统方法

深度学习的调试之所以难：**错误不抛异常，只让结果变差**。方法论的核心是**控制变量 + 由小到大**：

**流程 8.1（调试阶梯）**：

1. **单批次过拟合测试**：取 1–10 个 batch，关闭正则（dropout=0、weight decay=0），训练到 loss ≈ 0——**任何训练代码的第一道闸门**。过拟合不了 = 必有 bug（数据管线、损失实现、梯度被意外置零、train/eval 模式错误……）；
2. **初始损失体检**（第 2 章）：分类初始 loss ≈ $\ln K$；回归初始量级 ≈ 目标方差。不符 → 初始化或最后一层 bug；
3. **数值梯度核对**（第 1 章）：新写的层/损失，用中心差分核对解析梯度（相对误差 $< 10^{-6}$）；
4. **过拟合 1 个 epoch 的子集**：千级样本跑到训练准确率接近 1，验证模型容量与数据管线在"正常规模"下健康；
5. **逐步扩规模**：加数据、加深度/宽度、开正则——每步只改一件事（第 2 章消融纪律），每步记录曲线；
6. **反向排查清单**（常见静默错误）：忘记 `optimizer.zero_grad()`（梯度跨步累加）；`model.eval()` 未切（BN/dropout 泄漏）；标签错位（`CrossEntropyLoss` 要类别 id 不是 one-hot）；数据归一化用了测试集统计量（信息泄漏）；loss 用 sum、优化器按 mean 调学习率（尺度错 10–1000 倍）。

**性能 bug 与正确性 bug 分开查**：正确性用上述阶梯；性能用 profile 工具（`torch.profiler`）看算子耗时与 GPU 利用率（nvidia-smi 的利用率 ≠ 真饱和，要看的是算力占用与数据加载是否成为瓶颈：`num_workers`、pin_memory、预取）。

## 8.6 实验管理：可复现性的工程

1. **随机种子与确定性**：种子 Python/NumPy/Torch 三处 + CUDA；确定性算法开关（`torch.use_deterministic_algorithms(True)`）可能显著减速——实践中"记录种子 + 固定环境"优先于绝对确定；
2. **Checkpoint 规范**：存模型、优化器状态（恢复训练必需！只有权重无法续训 Adam 的动量/二阶矩）、调度器位置、epoch、随机数状态；定期存 best 与 last；
3. **实验追踪**：TensorBoard / Weights & Biases 类工具记录超参、曲线、系统指标（GPU 占用）；给每个实验一个可检索的名字与一句话结论——"实验管理 = 让三个月后的自己能看懂今天"；
4. **配置管理**：超参用配置文件/命令行而非散落魔法数（hydra/argparse）；代码版本与数据版本绑定（git hash + 数据 hash）；
5. **多随机种子重复**：深度学习结果的方差不小（尤其小数据），报告"均值 ± 标准差（≥3 种子）"是《实验设计与评估》课程的基本要求，从本课最后一次实验开始执行。

## 8.7 关键公式速查

| 公式 | 含义 | 适用条件 |
|---|---|---|
| 显存 $\approx 16P$ 字节 | fp16+Adam 训练固定开销 | 不含激活 |
| 激活 $\propto B \cdot n \cdot L \cdot d$ | 反传存储主体 | Transformer 量级 |
| $\mathbf{g} \leftarrow \mathbf{g}\min(1, \theta/\|\mathbf{g}\|)$ | 全局范数裁剪 | 训练稳定化 |
| $\nabla_{\mathrm{accum}} = \frac1k \sum_i \nabla_i$ | 梯度累积 ≡ 大 batch | loss 均值口径一致 |
| $\bar{\mathbf{g}} = \frac1N \sum_i \nabla \ell_i$ | DDP 平均梯度 | 同步数据并行 |
| 线性缩放：$\eta' = \eta \cdot N$ | batch 扩大 $N$ 倍的学习率 | 不越过临界 batch |
| fp16 最小正规数 $\approx 6\times10^{-5}$ | 损失缩放的必要性 | IEEE 754 half |

## 8.8 示例与案例

### 案例 1（数值算例与心算练习）

1. **显存预算**：$P = 125\mathrm{M}$（GPT-2 小）混合精度 Adam 训练：$16P = 2$ GB 权重相关；激活：batch 8、序列 1024、12 层、$d=768$，粗估 $\approx 8 \times 1024 \times 12 \times 768 \times 4\mathrm{B} \times c$（$c$ 为每层每 token 存储因子，约 10–20）$\approx 2$–5 GB。总 4–7 GB → 单张 8 GB 卡可训。**若改 fp32 + Adam：$16P \to (4+4+8)P = 2$ GB 权重相关不变？错——fp32 参数 4B + 梯度 4B + Adam 8B = 16B/参数同为 16P，但激活翻倍**。请列式核对。（校验值：fp32+Adam 激活约翻倍，总 5–9 GB。）
2. **损失缩放**：梯度典型分量 $10^{-7}$。fp16 最小正规数 $6.1\times10^{-5}$。不缩放时该分量立即下溢归零；缩放 $S = 2^{16} = 65536$ 后变为 $6.6\times10^{-3}$，安全落在 fp16 区间；更新前除回。若最大梯度 $10^{1} \times 65536 = 6.6\times10^{5} < 65504$？**超了**——所以动态缩放会在溢出时自动减半 $S$：这就是"动态"的含义。
3. **DDP 通信量**：$P = 125\mathrm{M}$，fp16 梯度 250 MB。8 卡环 all-reduce 每卡收发 $\approx 2 \times 250\mathrm{MB} \times 7/8 \approx 437$ MB；若 HBM-NVLink 带宽 300 GB/s，通信 $\approx 1.5$ ms，而一步计算（$6P$ FLOPs/样本 × batch）通常数十 ms——通信可被重叠掩盖，这就是 DDP 在多卡上近线性加速的原因。

### 案例 2（PyTorch：混合精度 + 梯度累积 + 裁剪 + DDP 的训练骨架）

```python
# pip install torch; 单卡骨架(DDP 版见注释)
import torch, torch.nn as nn, math

torch.manual_seed(0); torch.cuda.manual_seed_all(0)   # 三处种子之一部分
device = "cuda" if torch.cuda.is_available() else "cpu"

from torchvision import datasets, transforms
from torch.utils.data import DataLoader
ds = datasets.CIFAR10("./data", train=True, download=True,
                      transform=transforms.ToTensor())
ld = DataLoader(ds, batch_size=64, shuffle=True, num_workers=2, pin_memory=True)

model = nn.Sequential(nn.Flatten(), nn.Linear(3072, 256), nn.ReLU(),
                      nn.Linear(256, 10)).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
scaler = torch.cuda.amp.GradScaler(enabled=(device == "cuda"))  # fp16 损失缩放
ACC, clip = 4, 1.0                                    # 累积 4 微批 ≡ batch 256

model.train()
for step, (xb, yb) in enumerate(ld):
    xb, yb = xb.to(device, non_blocking=True), yb.to(device, non_blocking=True)
    with torch.cuda.amp.autocast(enabled=(device == "cuda"), dtype=torch.float16):
        logits = model(xb)
        loss = nn.functional.cross_entropy(logits, yb) / ACC   # 口径: 除以累积数
    scaler.scale(loss).backward()                    # 缩放后的反向
    if (step + 1) % ACC == 0:
        scaler.unscale_(opt)                         # 先除回缩放...
        torch.nn.utils.clip_grad_norm_(model.parameters(), clip)  # ...再裁剪(顺序!)
        scaler.step(opt)                             # fp32 主权重更新
        scaler.update()                              # 动态调整缩放系数
        opt.zero_grad(set_to_none=True)
    if step >= 200: break

# ---- 显存实测 ----
if device == "cuda":
    print(f"峰值显存 {torch.cuda.max_memory_allocated()/2**30:.2f} GiB")
# 预期输出(单卡): 峰值显存 < 1 GiB (小模型); 用大模型/长序列可观察激活占比

# ---- DDP 版骨架(8 卡机器上) ----
# $ torchrun --nproc_per_node=8 train.py
# import torch.distributed as dist
# dist.init_process_group("nccl")
# model = nn.parallel.DistributedDataParallel(model.to(rank), device_ids=[rank])
# sampler = torch.utils.data.distributed.DistributedSampler(ds)  # 每卡不重叠分片
# DataLoader(..., sampler=sampler, ...)   # 其余训练循环与单卡版完全相同:
# DDP 在 backward 内部自动对梯度 all-reduce —— 数学上等效 batch×8(见 8.4.1)
```

## 8.9 常见误区与陷阱

1. **checkpoint 只存权重**。恢复训练后 Adam 的 $m, v$ 从零开始，等价于一次"优化器重置"——loss 常反弹且不收敛回原轨迹。必须存优化器与调度器状态。
2. **分布式下忘记 DistributedSampler 或每卡都 shuffle 全量数据**。前者导致数据重复训练；后者让各卡吃到重叠样本，等效 batch 减小且破坏统计。多卡实验务必打印各卡首样本核对不重叠。
3. **以为 `nvidia-smi` 利用率 100% = 训练高效**。它只表示"有 kernel 在跑"；真瓶颈可能是数据加载（CPU→GPU 拷贝）或小算子碎片化。用 profiler 定位，而不是看仪表盘。
4. **混合精度"全开"当银弹**。bf16 无需损失缩放（动态范围大），fp16 必须；某些算子（log、exp 大参数域、统计量）在半精度下天然不稳，框架的自动白名单不完美——出现 nan 先检查精度切换边界。
5. **随机种子只设了一处**。DataLoader 的 shuffle 用 Python 全局随机、增强用 NumPy、模型初始化用 Torch、CUDA 另有独立流——四处全设才可复现；多进程 DataLoader 还需 `worker_init_fn`。

## 8.13 课后思考与练习

**基础题**

1. 心算：$P = 7\mathrm{B}$ 模型，混合精度 + Adam，权重相关显存多少 GB？需要激活约 10 GB 时单张 80 GB 卡放得下 batch 多大的训练？（校验值：$16 \times 7 = 112$ GB —— 放不下，引出 ZeRO/分卡的必要性。）
2. 计算：batch 从 256 扩到 4096（16 倍），按线性缩放法则学习率应如何调整？warmup 步数呢？（校验值：×16；warmup 相应延长。）
3. 解释损失缩放中"跳过不更新"步骤为何安全（把这一步对优化器状态的影响写出来），以及为什么缩放系数用 2 的幂。
4. 梯度累积 $k = 8$、微批 32：等效 batch 多少？若用同步 DDP 在 4 卡上再各跑同样配置，等效 batch 又是多少？（校验值：256；1024。）

**进阶题**

5. 编程：实现"单批次过拟合测试"脚本（对案例 2 的模型，只取 1 个 batch，关正则，训 500 步），验证最终 batch 内准确率 = 100%。再故意埋三个 bug（不 zero_grad / eval 模式 / 除错批量），报告各自症状并说明如何从诊断阶梯定位。
6. 推导：混合精度下"fp16 梯度 + fp32 更新"相比"全 fp32"的舍入误差来源清单（前向激活、反传链、梯度存储、参数增量四段），指出哪一段用了"fp32 主权重"补救、哪一段无人补救（反传链的 fp16 激活误差——这就是 bf16 更受青睐的深层原因之一）。
7. 推导 ring all-reduce 的通信量公式 $2\frac{N-1}{N}S$（$S$ 为总数据量），并用 2 卡与 4 卡各验证一次；说明为什么它比"每卡把梯度发给 0 号卡再广播"（树形）在带宽上更优。
8. 编程：测量激活占比——固定模型加深度的同时记录 `max_memory_allocated`，拟合"显存 ≈ $aP + bBnLd$"中的 $b$；再用 `torch.utils.checkpoint` 包一层，报告显存省多少、时间慢多少。（输出目标：给出四个数字 + 一句结论。）

**挑战题**

9. （研究生层次）实现一个迷你同步数据并行（两进程，gloo 后端，各吃一半 batch），在 MNIST 上验证"两进程平均梯度 ≡ 合并 batch 梯度"到数值精度（输出目标：梯度相对差 < $10^{-6}$）；再引入一次人为的进程延迟，测量无重叠 DDP 的等待时间占比，并实现按层 all-reduce 重叠，报告加速比。
10. （研究生层次）写一个"训练成本预测器"：输入模型配置（层数/宽度/序列长/词表）、硬件（FLOPS、带宽、卡数、互联带宽），输出理论训练时间与显存需求（用 $6P$ FLOPs/样本近似 + 8.4 的通信模型），并对照一个真实配置（如 GPT-2 在 8×V100 的公开训练时长）校验量级；写一页报告列出你的模型在哪里失效（激活重算、慢节点、MFU 未达峰值……）。
