## 9.1 项目一：从零实现 autograd 引擎（micrograd 思路）并训练 MLP

**背景**：Karpathy 的 micrograd（约 100 行核心代码）证明：反向传播引擎的全部本质是"标量值 + 拓扑排序 + 局部导数"。你将实现其张量升级版。

### 任务分解

1. **`Value` 类**：封装标量（先做标量版再做张量版），字段：`data`、`grad`、`_backward`（闭包）、`_prev`（子节点集）。支持：`+`、`*`、`**`（含负指数）、`tanh`、`exp`、`relu`、`matmul`（张量版）、`sum`、广播（张量版——梯度需按广播方向求和还原，这是最难的 20%）；
2. **反向传播**：`backward()` 对计算图做拓扑排序（[《数据结构与算法》第 4 章](/xiaoshus-blog/textbooks/ai/programming/data-structures/04/)），逆序执行各节点的 `_backward`；**同一节点被多次使用时梯度必须累加**（第 1 章推论 B）；
3. **三层 MLP + 训练循环**：用引擎搭 MLP（第 1 章结构），在 `sklearn.datasets.make_moons` 或 digits 上训练，手写 SGD 与动量（《最优化方法》5.4）；
4. **验证三件套**：与数值梯度核对（< $10^{-6}$）；与 PyTorch 同结构同种子对照最终 loss（差 < 5%）；单元测试覆盖每个算子的梯度；
5. **加分项**：实现梯度检查点重算；实现一个计算图可视化（导出 dot/png）；报告标量版 vs 张量版的速度比。

### 验收标准

- [ ] `Value` 支持 ≥ 8 个算子，每个都有梯度单元测试；
- [ ] 数值梯度核对最大相对误差 < $10^{-6}$；
- [ ] make_moons 测试准确率 ≥ 97%；digits 测试准确率 ≥ 95%；
- [ ] 与 PyTorch 对照实验：同结构、同初始化、同超参，最终训练 loss 相对差 < 5%（写明剩余差异来源：浮点顺序、实现细节）；
- [ ] README 含 5 行内复现命令。

### 提示

- 广播的反传：`c = a + b`（a: (3,1), b: (1,4)）时，`a.grad += c.grad.sum(axis=1, keepdims=True)`——先想清楚"梯度形状必须等于参数形状"（第 1 章形状检查）；
- 拓扑排序用 DFS 或 Kahn 算法；不要在递归里做 `backward` 的核心逻辑（深图会栈溢出）；
- `matmul` 的梯度是 $\frac{\partial L}{\partial A} = G B^\top,\ \frac{\partial L}{\partial B} = A^\top G$——第 1 章核心公式的引擎版；
- 参考实现顺序：先标量全通 → 数值核对 → 再张量化。一次到位张量版是新手陷阱。

**常见失败模式（按出现频率排序）**：

1. **梯度覆盖而非累加**：`self.grad = out.grad` 写成 `=`——多次使用的节点（如案例 1 中 $z_2$ 出现两次）梯度错误，数值核对会立刻抓住（这正是核对先行的原因）；
2. **广播梯度形状还原遗漏**：标量版全对、张量版一跑就错——99% 出在"梯度形状 ≠ 参数形状"，检查每个算子的 sum-to-shape 逻辑；
3. **拓扑排序把参数当叶子漏掉**：`_prev` 只记了值节点没记参数节点，某些参数梯度恒零——用"所有可训参数梯度非全零"的断言自检；
4. **只测了 loss 却没对每个算子单独测**：复合错误相互抵消导致核对比对"碰巧"通过——单元测试必须逐算子进行。

## 9.2 项目二：从零实现 Transformer 语言模型并在小数据集上训练文本生成

**背景**：第 5 章案例 2 的"成年版"——完整 tokenize、可配置、规范的训练与评估，在 tiny shakespeare（1 MB）上训练一个字符级 GPT。

### 任务分解

1. **数据层**：读文本 → 字符级词表 → train/val 切分（**先切后用**，杜绝验证集泄漏到训练统计里）→ 批次采样器（随机窗口）；
2. **模型层**：不使用 `nn.Transformer*`，手写嵌入 + $N$ 个 pre-LN 块（MHA + 因果掩码 + GELU FFN + 残差）+ final LN + tied 输出投影（第 5 章全部公式）；配置：$d = 128$–256、4–6 层、4 头、上下文 128–256；
3. **训练层**：AdamW + warmup + 余弦（第 2 章）、梯度裁剪 1.0、混合精度（第 8 章）、checkpoint 每 N 步、loss 曲线实时记录（TensorBoard 或自制日志）；
4. **评估与生成**：train/val loss 与 ppl 曲线；温度采样 + top-k 生成若干段；训练长度外的外推实验（加分）；
5. **消融（至少三组，单变量）**：去掉缩放 $1/\sqrt{d_k}$；去掉位置编码；pre-LN vs post-LN；加深（2→6 层）——每组 3 种子，表格呈现。

### 验收标准

- [ ] val ppl 达到量级目标：tiny shakespeare 字符级，1M 参数内模型 20–30 分钟单卡训练后 val ppl < 2.0（参考量级；不同配置允许浮动，报告中给出你自己的收敛证据）；
- [ ] 生成样本拼写正确、句读节律与语料一致（报告中附 3 段生成 + 你的评述）；
- [ ] 初始 loss 在 $\ln V$ 的 ±0.2 内（体检通过的证据）；
- [ ] 三组消融表格完整（均值 ± 标准差）且方向与第 5 章理论一致（例如去位置编码应显著变差——请解释为何仍能学到部分局部规律）；
- [ ] 显存峰值记录在案（第 8 章账本核对：实测 vs 你的理论估算，误差解释）。

### 提示

- 先跑通最小配置（2 层、$d=64$、上下文 32）再扩——"逐步扩规模"阶梯（第 8 章）的直接应用；
- 生成质量与温度强相关：0.5 过保守、1.2 开始胡言——把温度当超参报告；
- 训练崩了先看曲线形状对照第 2 章决策树，再查代码；mask 加错位置的典型症状：loss 下降但生成从句中乱接；
- 参考资源：Karpathy "Let's build GPT"（视频 + nanoGPT 仓库）——允许看思路，逐行抄写需在报告中声明并解释每一行。

**常见失败模式**：

1. **掩码加在 softmax 之后**或用 0 填充掩码位置——前者梯度路径错误、后者未来 token 仍以小权重泄漏；症状是"训练 loss 正常、生成时胡言乱语"。正确做法只有一种：softmax 前 `masked_fill(-inf)`；
2. **学习率一上来就给满**：无 warmup 的大学习率让 Adam 早期把嵌入层"打飞"，loss 飙到 15+ 后再也下不来（第 2 章诊断第 2 问的 Transformer 特化版）；
3. **采样时未调 `model.eval()`**：若网络里混有 dropout，生成结果随机性远超温度能解释的范围；
4. **上下文窗口溢出**：生成时 `idx` 超过训练长度后位置编码索引越界——采样循环中始终取 `idx[:, -maxlen:]`。

## 9.3 项目三：VAE 与扩散模型在 MNIST 上的生成质量对比

**背景**：第 6 章两个模型的受控对比实验——同一数据、同一容量预算、同一评价协议，回答"什么时候选 VAE、什么时候选扩散"。

### 任务分解

1. **模型 A（VAE）**：第 6 章案例 2 的扩展——卷积编码/解码器、$d_z = 32$、高斯似然；KL 权重做 $\beta \in \{0.1, 1, 10\}$ 消融；
2. **模型 B（DDPM）**：全卷积 U-Net 简化版（或含时间嵌入的 ResNet MLP；MNIST 上不需要完整 U-Net）、$T = 500$、余弦日程、$\epsilon$-预测；实现训练与完整采样链；
3. **容量对齐**：两模型参数量对齐在 ±20%（报告实测数），训练步数对齐——这是对比公平性的关键设计；
4. **评价协议**（各 3 种子）：定性（各采 64 张样图网格）；定量——FID（用 torchvision 的 Inception 权重或轻量代理：真实/生成特征的高斯 Fréchet 距离）、重构误差（VAE）/去噪误差（扩散）各自曲线、以及**多样性指标**（生成样本两两特征距离的均值——模式坍缩探测器，对 VAE 应高、对差 GAN 应低）；
5. **分析题（报告核心）**：VAE 样本为何糊、扩散为何锐利但慢（采样 500 步 vs 1 步）；用"似然 vs 采样质量"与"单步 vs 迭代"两个轴给两者画像；讨论：若给你 100 倍算力，各自的瓶颈如何移动。

### 验收标准

- [ ] VAE：生成样本可辨认为手写数字（附网格图）；KL 权重消融呈现"锐利度—先验匹配"的权衡证据；
- [ ] DDPM：MNIST 生成质量达到"随手可辨"级别（FID 相对基线合理，报告绝对值并说明其噪声下界）；采样链代码正确（从 $x_T$ 到 $x_0$ 无 nan，中间步可视化呈现"由糊到清"）；
- [ ] 容量对齐表 + 三种子均值 ± 标准差的指标表；
- [ ] 分析回答三个预设问题（糊的原因、慢的原因、算力加倍的预期收益），每问有数据或文献支撑。

### 提示

- 扩散训练前期 loss 看似"不降"是正常的（预测单位高斯噪声本身难），看后期与采样质量，别提前弃疗——第 2 章曲线诊断的反例教学；
- 先在**双高斯一维玩具**上把 DDPM 采样链跑对（第 6 章练习 8），再上 MNIST——调试阶梯的跨章应用；
- FID 对小数据集/低分辨率有偏，报告时写明协议（样本数、特征来源），并与"人眼评述"三角验证；
- 时间预算：DDPM 训练约 3–8 GPU 时（MNIST, 小网络）；安排好 checkpoint 与断点续训（第 8 章规范的实践场）。

**常见失败模式**：

1. **VAE 输出全黑或全灰**：KL 权重过大导致后验坍缩（$q \to p$、解码器被无视）——先看 KL 分项曲线（若骤降到 ~0 即确认），再调 $\beta$ 或用 KL 退火（前 N 步 $\beta$ 从 0 线性升起）；
2. **DDPM 采样结果与训练分布完全无关**：多半是 $\bar\alpha_t$ 查表算错（用了 $\alpha_t$）或采样公式里 $\sigma_t$ 用了 $\beta_t$ 而最后一步未置零——回到一维玩具核对；
3. **训练 loss 一直 ~1.0 不动就放弃**：$\epsilon$-预测的 MSE 目标在均匀随机 $\epsilon$ 下的初始 loss 就应接近 1.0（方差归一化），下降发生在中后期——这是第 2 章"初始 loss 体检"的反例，看曲线要对照目标的量纲；
4. **定量指标跑在训练集生成样本上**：FID 必须用"模型从未见过的对比协议"（与训练无关的先验采样 × 真实测试分布），否则指标虚高且不可比。

## 9.5 示例与案例

### 案例 1（项目一的"最小可行骨架"：20 行引擎 + 数值验证）

```python
import numpy as np

class Value:
    def __init__(self, data, _children=(), _op=""):
        self.data, self.grad, self._op = data, 0.0, _op
        self._prev, self._backward = set(_children), lambda: None
    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad += out.grad; other.grad += out.grad   # 累加! 多路径
        out._backward = _backward; return out
    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad += other.data * out.grad; other.grad += self.data * out.grad
        out._backward = _backward; return out
    def tanh(self):
        out = Value(np.tanh(self.data), (self,), "tanh")
        def _backward(): self.grad += (1 - out.data ** 2) * out.grad
        out._backward = _backward; return out
    def backward(self):
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for c in v._prev: build(c)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo): v._backward()          # 逆拓扑序 = 反向传播
    def __repr__(self): return f"Value({self.data:.4f}, grad={self.grad:.4f})"

# 验证: 第1章案例1的同款网络 w1*x -> tanh -> w2 -> L
w1, w2, x = Value(1.0), Value(1.0), Value(1.0)
L = 0.5 * (w2 * w1.tanh() * x) * (w2 * w1.tanh() * x)   # L = (z2)^2 / 2, y=0
# 注: 0.5*(z2)*(z2) 构图后 z2 被使用两次, 反向时其梯度自动累加 —— 引擎的核心考点
L.backward()
print(w1, w2)
# 预期输出: Value(0.6803, grad=0.3197) Value(0.4200, grad=0.5800)
# (与第1章手算完全一致: dL/dw1 ≈ 0.3197, dL/dw2 ≈ 0.5800)
```

**用法说明**：这是项目一的"验收地基"。把 `Value` 换成张量、加 `matmul`/`sum`/广播，就是完整项目；第 1 章 1.7 节案例 2 的训练循环可直接搬来当驱动代码。

## 9.6 常见误区与陷阱

1. **项目一直接开写张量版**。广播梯度与 reshape 的反传是引擎最难的部分，跳过标量验证阶段的失败率极高；"标量全通 + 数值核对"是必经台阶。
2. **项目二把验证集泄漏给训练**（val 文本混入语料、用全语料统计归一化）。字符级小数据尤其隐蔽——先切分、后处理，是一切序列实验的铁律。
3. **项目三只报一张最好看的热图**。没有种子重复与容量对齐的生成对比不构成证据；定性图必须配定量指标，且写明采样协议。
4. **三个项目共同的大坑：先写"完整版"再调**。所有项目的正确节奏都是"最小配置端到端跑通 → 逐项扩规模"（第 8 章调试阶梯）；相反节奏的项目几乎都死于中期的"改不动"。
5. **忽视报告的可复现性**。别人（和三个月后的你）能用 README 命令一键复现，是验收的硬条件；种子、版本、硬件、训练时长四要素缺一不可。

## 9.9 进阶方向

完成三个项目后，自然的下一步：

- **把项目二升级为真 LLM**：BPE 分词、10⁸ 级 token 语料、多卡 DDP（第 8 章）、评估基准（困惑度→下游任务）——《自然语言处理》课程的实验底座；
- **把项目三升级为条件生成**：文本条件 cross-attention（第 5 章）+ latent diffusion（第 6 章）→ 复现 Stable Diffusion 的最小化版本；
- **给项目一加功能**：反向模式 + 前向模式混合、二阶导（Hessian-vector 积）、JIT 编译算子融合——通往 MLsys；
- **科研训练**：从三个项目中挑一个现象（如"位置编码外推失败"或"VAE 后验坍缩"）做系统实验并写成 workshop 短文——这就是"会做研究"的第一步。

## 9.10 课后思考与练习

**基础题**

1. 在案例 1 的引擎中手工展开 $L = \frac12 (w_2 \tanh(w_1 x))^2$ 的梯度计算，与程序输出核对。（校验值：$\partial L/\partial w_1 \approx 0.3197$。）
2. 计算 mini-GPT（$d=128, 4$ 层，词表 65，tied embedding）的参数量。（校验值：嵌入 $65 \times 128 = 8320$ + 每块约 $12 \times 128^2 \approx 196{,}608$ ×4 + LN ≈ 总计约 79.5 万。）
3. 解释容量对齐为什么是项目三对比实验的前提；若 VAE 1M、DDPM 10M 参数，结论会向哪个方向偏？

**进阶题**

4. 给案例 1 的引擎添加 `exp` 与除法，并推导它们的 `_backward` 闭包；用数值梯度验证。
5. 项目二中实现"训练 128 长度、生成 256 长度"的外推实验，报告 ppl 随生成位置的退化曲线，并用位置编码理论（第 5 章 5.4）解释。
6. 项目三中实现一维双高斯玩具的 DDPM（第 6 章练习 8），把采样链每 100 步的分布画在同一张图上，回答"扩散模型的生成是渐进还是跳变"。
7. 为项目二设计一个数据泄漏检测：构造一个"验证集 n-gram 在训练集的出现率"统计，报告泄漏率并解释为什么字符级任务泄漏更隐蔽。

**挑战题**

8. （挑战）项目一加分：为引擎实现二阶导（`backward` 的可重入化或双 Value 嵌套），并用它计算一维函数的 Hessian 对角；讨论标量引擎做二阶导的复杂度瓶颈。
