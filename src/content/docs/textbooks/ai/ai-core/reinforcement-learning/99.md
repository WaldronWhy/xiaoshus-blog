# 强化学习 · 综合项目

> **项目定位**：本课程的毕业设计。三个项目分别锻造三种能力：**项目一**锻造"算法对比与实验方法论"（强化学习最稀缺的素养）；**项目二**锻造"环境工程"（从消费者变成生产者）；**项目三**锻造"大模型时代的完整技术栈"（RLHF 端到端）。每个项目都给出任务分解、验收标准与提示——但**不给参考答案**，因为调试 RL 系统的过程本身就是学习目标。

## 0. 项目通用要求

在开始任何一个项目之前，建立以下工程习惯（它们在三个项目中通用，也是《实验设计与评估》与《模型部署与 MLOps》的预演）：

1. **固定与记录随机种子**：`numpy`、`random`、`torch`（及 `torch.cuda`）全部设置；每个实验记录种子、超参、硬件环境；
2. **多种子重复**：RL 实验至少 3–5 个种子；报告均值 ± 标准差，而不是最好的一次（第 3、4 章已见过方差有多大）；
3. **训练曲线可视化**：回报曲线（含滑动平均）、Q 值/损失曲线、探索率曲线——先看曲线再下结论；
4. **代码结构**：环境、算法、实验脚本三层分离；算法之间共享评估函数与绘图代码；
5. **诚实的对照**：每次只改一个变量；负结果（某算法在某设置下失败）也是有效结果，如实报告。

依赖安装：`pip install numpy matplotlib gymnasium[classic-control] torch scikit-learn`（项目三需要预训练语言模型时可选用 `transformers`，极小规模下也可用自训练的小模型替代，见项目三提示）。

## 项目一：三种算法系统对比（Q-learning / DQN / PPO）

### 1.1 任务描述

在 FrozenLake-v1 与 CartPole-v1 两个 gymnasium 环境上，实现并对比表格 Q-learning、DQN、PPO 三种算法，并完成超参敏感性实验。目标不是"跑通三个算法"，而是产出一篇**小规模但方法论严谨的对比报告**。

- FrozenLake-v1（4x4, `is_slippery=True`）：离散状态 16 个、随机转移——表格法的舒适区 + 随机性压力测试；
- CartPole-v1：连续状态、离散动作——DQN 与 PPO 的主场，表格法失效（第 3 章 3.1 节的结论在此验证）。

### 1.2 任务分解

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | 实现表格 Q-learning（可复用第 2 章 Cliff Walking 代码骨架），在 FrozenLake 上调参至稳定通过 | 训练曲线 + 最优策略可视化 |
| 2 | 实现标准 DQN（复用第 3 章代码），在 CartPole 上训练至 475+ | 训练曲线 + 消融（有/无目标网络） |
| 3 | 实现简化 PPO（复用第 4 章代码），在 CartPole 上训练至 475+ | 训练曲线 + 与 DQN 的样本效率对比 |
| 4 | **超参敏感性实验**（见 1.3） | 敏感性表格/热力图 |
| 5 | 撰写对比报告（1500–2500 字） | 报告 md/PDF |

### 1.3 必做实验：超参敏感性

任选两个算法完成如下扫描（每个配置至少 3 种子）：

1. **Q-learning @ FrozenLake**：学习率 $\alpha \in \{0.05, 0.1, 0.5, 1.0\}$ × 探索率 $\varepsilon \in \{0.01, 0.1, 0.3\}$ 的 12 格网格热力图（指标：500 轮时的平均回报）；预期你会发现"高 α + 低 ε"与"低 α + 高 ε"以不同方式失败——报告失败模式；
2. **DQN @ CartPole**：目标网络同步频率 $C \in \{100, 500, 2000, 10000\}$ 步，观察训练曲线方差与崩溃频率；
3. **PPO @ CartPole**：clip 系数 $\epsilon \in \{0.05, 0.2, 0.5\}$，监控近似 KL 与 clipfrac，验证"过小 clip 学得慢、过大 clip 不稳定"（第 4 章 4.5.2 的行为验证）。

### 1.4 验收标准

- [ ] 三个算法均从零实现（允许参考课程代码骨架，但每行核心更新公式自己写）；
- [ ] FrozenLake 上 Q-learning 通过率（100 轮评估中到达目标的次数）≥ 70%；
- [ ] CartPole 上 DQN 与 PPO 均达到 100 轮平均回报 ≥ 475；
- [ ] 敏感性实验覆盖完整网格且每个配置 ≥ 3 种子，报告含均值 ± 标准差；
- [ ] 报告回答：样本效率（达到 475 分所需交互步数）DQN vs PPO 谁更优？与第 4 章 4.1 节的理论预期一致吗？

### 1.5 提示

- FrozenLake 的 `is_slippery=True` 使转移随机——这恰好检验"价值函数是对期望的估计"（第 1 章 1.4 节）；若收敛困难，先在 `is_slippery=False` 上验证代码正确性再开随机性；
- 评估与训练分离：训练用 ε-greedy，评估用纯贪心，分开报告（第 2 章 2.8 节的教训）；
- DQN 训练曲线崩溃时，先查 $Q$ 值是否飙升（过估计螺旋），再查学习率，最后才怀疑随机性——按这个顺序排查；
- 报告的图表规范参考《实验设计与评估》：坐标轴单位、种子数、滑动平均窗口都要标注。

## 项目二：从零实现网格世界环境并用三种算法求解

### 2.1 任务描述

遵循 gymnasium 接口规范，从零实现一个自设计的网格世界游戏环境（自定义布局、奖励与机制），然后分别用**表格 Q-learning**、**DQN（状态 one-hot 或坐标特征化）**、**PPO** 求解它，并回答"三种表示—算法组合各自的甜点区在哪里"。

环境设计要求（自由发挥，但必须包含以下要素）：

- 网格 ≥ $6 \times 6$；至少一个目标（正奖励）与一个陷阱（负奖励，终止或扣分弹回）；
- 至少一个"动态元素"使问题非平凡（如：每 $k$ 步移动一次的巡逻怪、单向门、会衰减的时限奖励）；
- 随机性可选（`slip_prob` 参数控制"打滑"概率，默认 0）；
- **可解释性**：最优策略应能被人一眼检查（目标周围价值高、陷阱周围形成回避梯度——第 1 章价值地形图的自我复用）。

### 2.2 任务分解

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | 设计并实现环境类：`reset()`, `step(action) -> (obs, reward, terminated, truncated, info)`, `render()` | 可 import 的模块 `my_gridworld.py` |
| 2 | 写环境的**单元测试**：手工计算一条轨迹的总回报、手工验证最优路径存在（第 1 章 1.7.2 的 88.296 式锚点） | 测试文件 + 通过截图 |
| 3 | 用价值迭代求出**参照最优解**（模型已知，第 1 章方法） | 最优 $v^*$ 与 $\pi^*$ 可视化——这是后面所有算法的"标准答案" |
| 4 | 表格 Q-learning 求解（若状态空间大，考虑降低网格或特征化） | 与参照解的逐状态价值误差曲线 |
| 5 | DQN 求解：观测用坐标归一化向量或 one-hot（自选并论证） | 训练曲线 + 贪心策略可视化 |
| 6 | PPO 求解（同样特征化） | 训练曲线 + 贪心策略可视化 |
| 7 | 对比分析 + 报告 | 报告 md/PDF |

### 2.3 验收标准

- [ ] 环境严格遵循 gymnasium 5 元组返回约定（`terminated` 与 `truncated` 语义正确——第 3 章 3.8 节的陷阱不要再踩）；
- [ ] 价值迭代解存在且可视化后人工检查通过（陷阱回避、目标趋近）；
- [ ] Q-learning 收敛后 $\max_a Q(s,a)$ 与 $v^*(s)$ 的最大误差 < 0.1（$\gamma$ 相同）；
- [ ] DQN 与 PPO 的学得策略可视化后与最优策略的一致率 ≥ 80%（逐状态比较贪心动作）；
- [ ] 报告包含一张"三算法 × 三指标（样本效率 / 最终精度 / 代码复杂度）"对比表。

### 2.4 提示

- 动态元素（如巡逻怪）会让状态空间爆炸（怪的位置也是状态）——这正是"状态设计"的一课：把怪的位置编入状态（马尔可夫） vs 只看自己格子（非马尔可夫）各试一次，比较性能差距（第 1 章 1.2 节的马尔可夫性讨论落地）；
- DQN 在小离散状态空间上打不过表格法是**正常且预期**的结果——把它作为"函数近似的固有代价"写进报告（第 3 章 3.2.2 节的投影损耗），不要怀疑人生；
- 想增加难度（选做）：把网格改成随机生成（每次 reset 新布局），检验三种算法的泛化能力——这将引出第 3 章练习 8 与 5.7 节"评估危机"的深水区。

## 项目三：最小可用的 RLHF 流水线

### 3.1 任务描述

在极小规模上实现完整的 RLHF 三段流水线：**用预训练（或自训练的）字符级小语言模型 + 合成人类偏好数据训练奖励模型，再用 PPO 微调该模型**。这是《自然语言处理》第 6 章的微缩预演——规模缩小 5 个数量级，但**每个组件、每个坑都真实存在**。

### 3.2 任务分解

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | **基础模型**：训练一个字符级小 LM（如 2 层 Transformer、词表 ~50 字符，数据可用任一公开短文本集，衔接《深度学习》第 5 章），在合成任务上能生成通顺短句；或直接采用 `transformers` 中 ≤ 10M 参数的现成模型 | 可生成的基础模型 |
| 2 | **任务定义**：例如"生成以指定字符开头/包含关键词的短句"（可验证的偏好信号），或"生成不带重复字符的句子" | 任务规范 + 自动评估器（作为"真值偏好"） |
| 3 | **合成偏好数据**：用任务规范给 (prompt, 回答对) 打真值分，按 Bradley-Terry 采样生成 $\sim 5000$ 条偏好对（模拟人类标注的噪声：5–15% 标签翻转） | 偏好数据集 + 数据卡（格式、噪声率） |
| 4 | **奖励模型**：LM 主干 + 标量头，按 $P(y_w \succ y_l) = \sigma(r_\phi(x,y_w) - r_\phi(x,y_l))$ 训练（第 5 章 5.9.2 的放大版） | RM 在验证集上的偏好准确率（目标 ≥ 85%） |
| 5 | **PPO 微调**：rollout 生成 → RM 打分 → KL 惩罚 → PPO clip 更新（第 4 章 4.5 节的全部组件就位） | 训练曲线：RM 分数、KL、生成样本定性对比 |
| 6 | **评估**：自动评估器（步骤 2 的真值）打分对比微调前后；监控奖励黑客（RM 分数上升但真值分数不升 = 危险信号） | 前后对比表 + 奖励黑客案例分析 |
| 7 | 报告（含：若 KL 系数 $\beta$ 从 0.1 改为 0.001 会发生什么） | 报告 md/PDF |

### 3.3 验收标准

- [ ] RM 偏好验证准确率 ≥ 85%（噪声 10% 时理论上限 ~90%，超过它说明泄漏——自查数据构造）；
- [ ] PPO 微调后：真值指标相对基础模型提升 ≥ 20%，且 KL(微调 ‖ 基础) 有界（如平均每 token < 2 nats）；
- [ ] 展示至少一个"RM 分数上升但真值不升"的奖励黑客案例（若你的 RM 健壮到 hacking 不发生，证明并解释为什么——这也是满分答案）；
- [ ] $\beta$ 扫描（0.001 / 0.01 / 0.1）曲线：小 $\beta$ → 分数高但语言崩坏，大 $\beta$ → 几乎不更新——与第 5 章 5.6 节论述一致；
- [ ] 全流程可一键复现（`python run_all.py --seed 0`）。

### 3.4 提示

- **规模至上原则**：先把整个流水线在"词表 20 字符、模型 1 层"上跑通，再逐级放大——RLHF 的 bug 与规模无关，流水线通 > 单点精；
- 步骤 2 的"可验证真值"是本项目安全绳：没有它，你无法区分"RM 真学到了偏好"与"RM 被过拟合的噪声骗了"（第 5 章 5.9.2 练习 6 的结论）；
- PPO 部分若在纯 PyTorch 手写中挣扎，可以退而求其次：用 REINFORCE + KL 惩罚（无 critic）完成主实验，然后在报告中论证"PPO 的 critic 会在哪里帮上忙"——诚实的简化优于虚假的完整；
- 奖励黑客的经典复现思路：RM 训练数据里长度与偏好相关 → 策略学会输出超长垃圾 → RM 分数高、真值崩。主动在步骤 3 埋入这种相关性，然后在步骤 6 捕获它；
- 想升级（选做）：把合成偏好换成真实标注（找 3–5 位同学给 200 对样本标注），体验"人类偏好不一致"带来的真实噪声结构。
